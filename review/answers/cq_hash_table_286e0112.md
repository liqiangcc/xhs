# 哈希表如何处理 Hash 冲突？

## 核心结论

哈希表用 hash 把 key 映射到桶，冲突主要用拉链法或开放寻址处理；平均 O(1) 依赖均匀 hash 和受控负载因子，最坏情况可退化。

## 1 分钟版

- 拉链法每桶保存链表/树，删除简单但有节点和指针开销。
- 开放寻址在数组内探测空槽，缓存友好但删除需墓碑且高负载时探测增长。
- 扩容要分配新表并重哈希/迁移，容量与 hash 取模策略共同决定桶位。

## 3 分钟版

key 相等契约必须稳定，恶意碰撞需随机化或树化等防护。选择线性、二次探测或双重哈希要权衡聚集。 按“目标—核心数据结构—主流程—保证机制—开销—版本边界”复述，并指出失败或退化路径。

## 常见追问

- 问：为什么负载因子重要？答：越高越省空间但冲突和探测成本增加，超过阈值需扩容。
- 问：开放寻址如何删除？答：使用墓碑保持探测链，后续重整时清理。
- 问：最坏复杂度是什么？答：大量冲突可退化 O(n)，树化等实现可改善特定场景。
