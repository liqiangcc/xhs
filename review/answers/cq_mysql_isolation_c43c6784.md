# MySQL 事务隔离级别及其解决的问题

## 核心结论

SQL 标准隔离级别从低到高是 READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE，逐步限制脏读、不可重复读和幻读；InnoDB 的实际行为还取决于 MVCC、锁定读、索引和语句类型。

## 1 分钟版

- RU 可读未提交数据，可能脏读。
- RC 每次一致性读通常创建新 Read View，避免脏读但同一事务两次读取可能不同。
- InnoDB RR 通常在事务内复用 Read View，普通快照读可重复；当前读通过记录锁/next-key lock 等处理并发范围修改。
- SERIALIZABLE 强化读写互斥，隔离更强但并发和死锁代价更高。

## 3 分钟版

隔离问题需要用具体调度说明：脏读是读到未提交后又回滚的数据；不可重复读是同一行前后值变化；幻读是同一谓词结果集合变化。MVCC 让一致性读读取可见历史版本，锁定读和 DML 读取最新可用版本并加锁，因此同一事务里“快照读后当前读”可能观察到不同结果。RR 不等于解决所有业务并发问题，丢失更新、库存扣减等仍需条件更新、乐观锁或显式锁。默认隔离级别和具体锁行为要结合 MySQL/InnoDB 版本验证。

## 关键细节

- RC 与 RR 的 Read View 创建时机不同是常见实现差异。
- next-key lock 是记录锁与间隙锁组合，范围和是否退化取决于索引命中。
- 无合适索引的锁定语句可能扩大扫描和锁范围。
- 隔离越高不必然越正确，业务不变量仍需单独设计。

## 原理机制

Read View 根据事务 ID 判断版本链中的行是否可见；锁系统约束当前读和写之间的并发。MVCC 提高读写并发，锁负责不能只靠历史版本解决的写冲突和范围保护。

## 项目经验版

项目映射提示：用真实扣库存或状态机案例画出并发时序，说明隔离级别、SQL 条件、索引、重试和幂等。没有压测与死锁日志时不虚构冲突率。

## 常见追问

- 问：RR 下完全没有幻读吗？答：普通快照读有一致视图，锁定范围读可用 next-key lock；混合快照读和当前读、无索引等场景仍需具体分析。
- 问：RC 与 RR 的主要 MVCC 差别？答：RC 通常每条语句新建 Read View，RR 通常事务内复用首次一致性读视图。
- 问：提高到 SERIALIZABLE 能解决库存超卖吗？答：可能通过更强互斥避免部分竞态，但吞吐代价大，仍应设计原子条件更新和幂等。
- 问：什么是当前读？答：读取最新可见并可能加锁的读，如 `SELECT ... FOR UPDATE` 和 DML 的读阶段。

## 易错点

- 不要只背隔离级别表格而不区分快照读和当前读。
- 不要把 RR 说成万能串行化。
- 不要脱离索引讨论间隙锁范围。
