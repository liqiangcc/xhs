# 协程与线程的区别及适用场景

## 核心结论

协程是由语言运行时或用户态调度的轻量任务，切换通常无需每次进入内核，适合大量 I/O 并发；线程由 OS 调度并可利用多核，阻塞调用和 CPU 密集任务仍需合适线程资源。

## 1 分钟版

- 多个协程可复用少量线程，栈可增长或更轻，但不是零成本。
- 协程切换若遇到未适配的阻塞调用，会阻塞承载线程和同线程其他协程。
- CPU 密集任务要控制并行线程数，协程数量增加不会突破核心数。

## 常见追问

- 问：协程一定比线程快吗？答：不一定，优势主要在高并发等待与切换成本，CPU 密集仍受核心限制。
- 问：什么是 pinning/阻塞承载线程？答：某些同步或本地调用让轻量任务无法卸载，承载线程被占住。
- 问：ThreadLocal 还能用吗？答：不同运行时语义不同，大量轻量线程的 ThreadLocal 成本和上下文传递要评估。
