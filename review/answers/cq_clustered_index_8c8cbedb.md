# 聚簇索引和非聚簇索引的区别

## 核心结论

在 InnoDB 中，聚簇索引叶子保存完整行，表数据按主键 B+ 树组织；二级索引叶子保存索引列加主键值，查询非覆盖列时通常要按主键回表。一个表只有一份聚簇组织，但可有多个二级索引。

## 1 分钟版

- 有主键时 InnoDB 选择主键作聚簇索引；没有显式主键会寻找合适唯一非空索引，否则生成隐藏行 ID。
- 二级索引不保存物理行地址，而保存主键，因此主键越宽，所有二级索引越大。
- 覆盖索引包含查询所需列时可直接在二级索引返回，避免回表。
- 主键随机写会造成页分裂、低填充和写放大，递增且稳定的窄主键通常更友好，但也要考虑热点。

## 3 分钟版

聚簇描述的是数据与索引的物理组织关系，不等于“主键索引”这一抽象概念在所有数据库实现中都相同。InnoDB 主键范围查询沿叶子链顺序读取，局部性好；二级索引定位主键后再访问聚簇树，可能产生随机 I/O。优化器会根据选择性、回表成本和统计信息决定走二级索引还是全表扫描。联合二级索引遵循最左前缀等规则，叶子隐含主键还会影响覆盖和排序能力。

## 关键细节

- InnoDB 二级索引叶子携带主键，不是传统固定物理地址。
- 回表次数取决于命中行数和是否覆盖，不是“用了二级索引就一定两次 I/O”。
- `SELECT *` 更难形成覆盖索引，并放大回表成本。
- MyISAM 等引擎的索引组织不同，回答要限定 InnoDB。

## 原理机制

B+ 树非叶子页保存导航键，叶子页有序链接。聚簇叶子直接承载行，二级叶子先得到主键；这种设计让行移动不必更新固定地址，但把主键宽度复制到每个二级索引。

## 项目经验版

项目映射提示：索引设计应结合真实 SQL 的过滤、排序、返回列和基数，通过 EXPLAIN/执行指标验证回表量。不要声称“加覆盖索引必然更快”，还要计入写放大和空间。

## 常见追问

- 问：没有主键怎么办？答：InnoDB 选合适唯一非空索引，否则生成隐藏行 ID 组织聚簇树。
- 问：什么是回表？答：先从二级索引得到主键，再访问聚簇索引取得未覆盖列。
- 问：为什么主键不宜太宽？答：主键会存入每个二级索引叶子，放大空间、缓存和写成本。
- 问：覆盖索引一定不回表吗？答：逻辑上所需列已覆盖时通常可避免取整行，但还需看可见性检查和执行计划细节。

## 易错点

- 不要脱离存储引擎谈实现。
- 不要说一张表只能有一个“索引”；只能有一份聚簇组织。
- 不要把二级索引叶子描述成完整数据行。
