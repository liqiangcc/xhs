# 如何理解 Java 的封装、继承与多态？

## 核心结论

封装隐藏可变状态并维护不变量，继承表达稳定的 is-a 关系和代码复用，多态让调用方依赖抽象、运行时选择实现；工程上通常优先组合，避免脆弱继承层次。

## 1 分钟版

- 封装不是写 getter/setter，而是限制非法状态并提供语义方法。
- 继承会耦合父类实现和生命周期，只有满足里氏替换时才合理。
- 多态依赖方法重写和动态分派；字段、static 和重载不是同一种运行时多态。

## 3 分钟版

以支付策略为例，接口定义能力，不同实现由工厂/DI 注入；若只为复用几行代码而继承，父类变化会影响所有子类。不可变对象是强化封装的常见方式。 回答时先统一比较维度，再给选择条件与反例；定义本身不是终点，必须说明代价和不适用边界。

## 常见追问

- 问：为什么优先组合？答：组合依赖更小接口，可运行时替换，不暴露父类受保护状态。
- 问：重载是多态吗？答：重载在编译期按参数静态选择，面试通常讨论的运行时多态来自重写。
- 问：如何判断继承合理？答：子类应能在不破坏调用方预期的前提下替换父类。
