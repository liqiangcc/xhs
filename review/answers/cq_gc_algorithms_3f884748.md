# JVM 常见垃圾回收算法

## 核心结论

常见算法有标记-清除、复制、标记-整理；实际收集器会按分代/分区、并发与停顿目标组合使用，不能把“新生代复制、老年代整理”当成所有现代 JVM 的固定实现。

## 1 分钟版

- 标记-清除：标记存活对象后清掉死亡对象，额外空间少但容易产生碎片。
- 复制：把存活对象复制到另一块区域，分配快、无碎片，但需要额外空间，适合存活率低的区域。
- 标记-整理：标记后移动存活对象并整理连续空间，避免碎片但移动和引用更新成本高。
- 可达性分析从 GC Roots 出发；引用计数难处理循环引用，不是 HotSpot 主体算法。

## 3 分钟版

算法选择取决于存活率、对象移动成本、可用空间和停顿目标。传统分代利用“多数对象朝生夕死”和“少数对象长期存活”的假设，新生代常用复制，老年代用标记清除/整理。G1 以 Region 管理堆，选择收益高的区域回收并复制存活对象；ZGC 等并发收集器借助染色指针、转发表和屏障把大量工作并发化。任何移动算法都要修正引用，任何并发标记都要处理业务线程修改对象图的问题。

## 关键细节

- GC Roots 包括活跃线程栈、本地引用、类静态字段等特定根集合。
- Stop-The-World、并发、并行是不同维度：并行指 GC 线程协作，并发指与应用重叠。
- 分代引用通过 remembered set/card table 等减少全堆扫描。
- 收集器参数和默认值随 JDK 版本变化，结论需绑定版本。

## 原理机制

所有追踪式回收都要回答三件事：哪些对象存活、如何回收死亡对象、如何修复因移动或并发造成的引用关系。不同算法是在时间、空间、碎片和停顿之间取舍。

## 项目经验版

项目映射提示：选择收集器要基于 JDK 版本、堆大小、吞吐与 P99 停顿目标，再用 GC 日志和压测验证。没有真实调优数据时，不编造某算法“提升百分之多少”。

## 常见追问

- 问：复制算法为什么适合新生代？答：典型存活率低，只复制少量存活对象，换取快速连续分配。
- 问：标记-清除的问题是什么？答：可能产生空间碎片，分配大对象时即使总空闲足够也找不到连续区域。
- 问：并发 GC 是否没有 STW？答：不是，通常仍有短暂停顿阶段，只是把更多工作与应用并发。
- 问：G1 属于哪一种算法？答：它按 Region 工作，整体有标记和选择回收，区域回收时会转移存活对象，是多种思想的组合。

## 易错点

- 不要把算法和具体收集器一一等同。
- 不要混淆并发、并行和无停顿。
- 不要脱离 JDK 版本背默认收集器结论。
