# Java 浅拷贝与深拷贝的区别

## 核心结论

浅拷贝复制对象顶层字段，引用字段仍指向同一子对象；深拷贝递归复制可变对象图，使副本修改不影响原对象，但要处理共享引用、环、不可变对象和资源句柄。

## 1 分钟版

- 基本类型值直接复制，引用类型在浅拷贝中只复制引用。
- 深拷贝可用显式 copy constructor/mapper，序列化方式通用但慢且受类型/安全限制。
- File、Socket、线程等外部资源通常不能靠深拷贝复制语义。

## 3 分钟版

真正深拷贝需用 identity map 记录已复制节点，既防循环递归，也保持原图中共享子对象在副本里仍共享。不可变对象可安全复用。 回答时先统一比较维度，再给选择条件与反例；定义本身不是终点，必须说明代价和不适用边界。

## 常见追问

- 问：clone 是深拷贝吗？答：Object.clone 默认字段级浅拷贝，深度取决于重写实现。
- 问：序列化深拷贝有什么问题？答：性能、版本兼容、安全、瞬态字段和不可序列化资源。
- 问：如何处理环？答：按对象身份缓存原对象到副本的映射，重复遇到时复用副本。

## 易错点

- 不要只背定义而不说明选择条件。
- 不要把常见实现说成跨版本唯一结论。
- 不要把新建了顶层对象就称为深拷贝。
