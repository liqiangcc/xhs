# 百亿级短 URL 如何生成无冲突短码？

## 核心结论

短 URL 核心是把长 URL 映射到唯一 ID 再做 Base62 编码，或用随机短码加唯一约束重试；百亿规模要计算码空间、分片、热点缓存、滥用治理和过期回收。

## 1 分钟版

- 62^7 约 3.5 万亿空间，需按预期记录量、保留期和安全余量选择长度。
- 发号器生成全局唯一 ID，Base62 只是编码；随机方案必须依赖数据库唯一约束判冲突。
- 跳转读多写少，可 CDN/Redis 缓存；数据库按短码哈希分片并保留原 URL、状态和过期时间。

## 3 分钟版

创建链路先规范化/安全校验长 URL，再生成短码、唯一写入和缓存。跳转链路防开放重定向、钓鱼和撞库，热点短码要限流。自定义别名需要独立命名空间。 先澄清规模、QPS、数据量、一致性、延迟和故障目标，再画主链路，补齐幂等、容量、降级、对账、观测和替代方案。

## 常见追问

- 问：Base62 能避免冲突吗？答：不能，它只把唯一 ID 编码；唯一性来自发号器或约束。
- 问：如何隐藏递增 ID？答：可用可逆置换、随机 ID 或带密钥映射，仍需防枚举和滥用。
- 问：热点短链怎么办？答：本地/分布式多级缓存、CDN、限流，并防单 key 回源击穿。

## 易错点

- 不要只罗列组件而没有数据流和容量。
- 不要只设计成功路径，必须说明超时、重试、降级和对账。
- 不要用普通 hash 后截断却不处理碰撞。
