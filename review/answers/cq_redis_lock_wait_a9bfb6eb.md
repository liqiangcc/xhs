# 分布式锁竞争失败后如何等待与唤醒？

## 核心结论

分布式锁失败后不应无界忙轮询；可用带随机退避的短轮询，或 Redis Pub/Sub/信号量、ZooKeeper watcher 等通知后重新竞争，但通知只是提示，仍必须重新校验锁状态。

## 1 分钟版

- 等待有总超时、可中断、随机退避和最大重试，避免惊群。
- Redisson 常以订阅解锁消息配合本地同步器等待，收到通知后再次执行原子加锁。
- 通知可能丢失或提前到达，因此等待流程还需超时兜底，业务必须幂等。

## 3 分钟版

## 常见追问

- 问：为什么收到通知不能直接进入？答：其他等待者也可能被唤醒，必须重新原子竞争并确认所有权。
- 问：轮询多久合适？答：按临界区 P99 和负载设置指数退避加抖动，并有总 deadline。
- 问：Pub/Sub 丢消息怎么办？答：超时后重新检查锁；通知只优化等待延迟，不作为唯一正确性保证。
