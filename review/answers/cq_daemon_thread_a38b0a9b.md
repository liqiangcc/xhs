# Java 守护线程的特点与应用边界

## 核心结论

Java 守护线程不会阻止 JVM 在只剩守护线程时退出，适合辅助性后台工作；不能承担必须完成、必须持久化或必须释放的关键任务，因为 JVM 不保证给它 finally 收尾机会。

## 1 分钟版

- 必须在 start 前调用 setDaemon，启动后修改会抛异常。
- 子线程默认继承创建它的线程的 daemon 属性。
- JVM 退出应依赖显式生命周期、shutdown hook 和可等待的资源关闭，不依赖守护线程自然完成。

## 常见追问

- 问：守护线程 finally 一定执行吗？答：不保证，只剩守护线程时 JVM 可直接结束。
- 问：主线程结束 JVM 就退出吗？答：只要还有非守护线程存活，JVM 通常继续运行。
- 问：关键刷盘任务能用 daemon 吗？答：不应，应使用可等待的非守护执行器和明确关闭协议。

- 不要把 daemon 理解为优先级更低的线程。
