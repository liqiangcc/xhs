# 算法手撕：三色球连续三格不能同时出现三种颜色，求放置方案数

## 核心结论

原始面经给出的约束是：只有红、黄、蓝三种颜色；长度为 `n` 的序列中，只要任意连续三个球恰好包含三种不同颜色，就会“爆炸”。因此合法序列等价于：**每个长度为 3 的窗口至少有两个球同色**。

决定下一格是否合法，只需要知道前两格颜色，所以定义 `dp[a][b]` 为当前长度下、最后两格颜色分别为 `a,b` 的合法方案数。尝试新颜色 `c` 时，如果 `a,b,c` 两两不同就丢弃；否则转移到 `next[b][c]`。三种颜色只有 9 个“最后两格”状态和 27 种常数级转移，所以时间复杂度是 `O(n)`，额外状态空间是 `O(1)`。

原题没有给 `n` 的范围和取模要求。下面的练习实现因此用 `BigInteger` 返回精确计数；并把 `n=0` 明确定义为 1 个空序列，这只是实现边界，不冒充原题条件。

## 1 分钟版

- 爆炸条件不是某一个固定字符串，而是连续三格出现红、黄、蓝的任意排列；也就是三格颜色两两不同。
- 第 `i` 格能不能放某种颜色，只取决于第 `i-2`、`i-1` 格，因此状态保存“最后两格颜色”就足够。
- 初始长度为 2 时，`3 * 3 = 9` 个颜色对都合法，每个状态计数为 1。
- 从状态 `(a,b)` 枚举当前颜色 `c`；如果 `a,b,c` 三者都不同则禁止，否则累加到 `(b,c)`。
- `n=3` 时总数是 `27 - 3! = 21`，可作为最小手算校验。
- 固定三种颜色时每层只有 9 个状态、27 次尝试，因此时间 `O(n)`，滚动两层后空间是常数。

## 3 分钟版

如果直接用一维 `dp[i]`，无法判断新增颜色是否和前两格共同形成红黄蓝三色窗口；所以状态必须带上足以判断下一个窗口的信息。完整写法可以看成：

```text
dp[i][a][b] = 放满前 i 格，且第 i-1 格颜色为 a、第 i 格颜色为 b 的合法方案数
```

其中 `a,b ∈ {R,Y,B}`。

长度为 2 时所有 9 个颜色对都合法：

```text
dp[2][a][b] = 1
```

之后枚举新颜色 `c`：

```text
if a,b,c 不是三种互不相同的颜色:
    dp[i+1][b][c] += dp[i][a][b]
```

为什么这个状态是充分的？新加入第 `i+1` 格之后，唯一新出现的长度 3 窗口就是 `(i-1,i,i+1)`；更早的窗口在前一状态里已经验证合法，所以不需要记整个前缀。

还可以做一个等价的二状态手算校验。把合法前缀按“最后两格相同 `E` / 不同 `D`”分类。若最后两格相同，新颜色有 1 种保持 `E`、2 种进入 `D`；若最后两格不同，新颜色只能选后一个颜色进入 `E`，或选前一个颜色继续 `D`，第三种颜色会爆炸。因此：

```text
E' = E + D
D' = 2E + D
```

从 `n=2` 的 `E=3,D=6` 得到 `n=3` 总数 21、`n=4` 总数 51。仓库测试还用穷举独立枚举器核对 `n=0..10`，并用该二状态递推核对到 `n=200`。

## 关键细节

- “红黄蓝的某种排列”意味着只要连续三格三种颜色各出现一次就非法，而不是只禁 `R,Y,B` 这个固定顺序。
- 仅保存“上一格颜色”不够，因为是否合法需要同时知道前两格。
- 保存最后两格就是最小直接状态；保存整个前缀会造成不必要的指数状态。
- 原题没有数据范围。如果用 `long`，计数会很快溢出；练习实现用 `BigInteger` 避免把未给出的取模条件硬编码进答案。
- 若面试官补充“答案对某个模数取模”，只需把每次加法改成模加，状态和转移不变。
- 若颜色种类从 3 扩展为 `k`，而禁用条件仍是“连续三格三种颜色全不同”，状态仍可用最后两格，但转移数会随 `k` 增长；本题的 `O(n)` 依赖颜色数固定为 3。
- `n=1`、`n=2` 时不存在长度 3 窗口，因此分别有 3、9 种合法序列。

## 原理机制

DP 的不变量是：`dp[a][b]` 只统计已经验证过所有长度 3 窗口的前缀，并且精确记录该前缀最后两格颜色。加入新颜色 `c` 时，旧窗口不会变化，只需检查唯一的新窗口 `(a,b,c)`。

如果三者两两不同，这个窗口就是红、黄、蓝的一种排列，必须拒绝；否则该前缀仍合法，并且下一轮唯一需要保留的信息变成 `(b,c)`。这保证转移既不会漏掉合法序列，也不会重复计数：任意合法长度 `i+1` 序列都有唯一的长度 `i` 前缀和唯一最后一格颜色，因此恰好从一个旧状态转移而来。

## Java 复习实现

```java
import java.math.BigInteger;

public final class SafeColorSequences {
    private static final int COLORS = 3;

    private SafeColorSequences() {}

    public static BigInteger countWays(int n) {
        if (n < 0) {
            throw new IllegalArgumentException("n must be non-negative");
        }
        if (n == 0) {
            return BigInteger.ONE;
        }
        if (n == 1) {
            return BigInteger.valueOf(COLORS);
        }

        BigInteger[][] dp = new BigInteger[COLORS][COLORS];
        for (int first = 0; first < COLORS; first++) {
            for (int second = 0; second < COLORS; second++) {
                dp[first][second] = BigInteger.ONE;
            }
        }

        for (int length = 3; length <= n; length++) {
            BigInteger[][] next = zeroMatrix();
            for (int previous = 0; previous < COLORS; previous++) {
                for (int last = 0; last < COLORS; last++) {
                    for (int current = 0; current < COLORS; current++) {
                        if (allDistinct(previous, last, current)) {
                            continue;
                        }
                        next[last][current] =
                                next[last][current].add(dp[previous][last]);
                    }
                }
            }
            dp = next;
        }

        BigInteger total = BigInteger.ZERO;
        for (int previous = 0; previous < COLORS; previous++) {
            for (int last = 0; last < COLORS; last++) {
                total = total.add(dp[previous][last]);
            }
        }
        return total;
    }

    private static boolean allDistinct(int a, int b, int c) {
        return a != b && b != c && a != c;
    }

    private static BigInteger[][] zeroMatrix() {
        BigInteger[][] matrix = new BigInteger[COLORS][COLORS];
        for (int i = 0; i < COLORS; i++) {
            for (int j = 0; j < COLORS; j++) {
                matrix[i][j] = BigInteger.ZERO;
            }
        }
        return matrix;
    }
}
```

## 项目经验版

这是纯算法计数题，不应虚构生产经历。面试中更有价值的是把状态充分性讲清楚，再用 `n=3` 的 21 个方案、穷举对照和复杂度证明验证实现，而不是套“线上压测/监控”模板。

## 常见追问

- 问：为什么只记最后两格就够？答：新增一个球只会新产生一个长度 3 窗口，而这个窗口恰好由“前两格 + 新颜色”决定；更早窗口已经在旧状态中验证过。
- 问：`n=3` 为什么是 21？答：总共有 `3^3=27` 种序列，非法的正好是红黄蓝各一次的 `3!=6` 种排列，所以合法数是 21。
- 问：能不能进一步压缩状态？答：可以按最后两格“相同/不同”聚合成两个计数，得到 `E'=E+D`、`D'=2E+D`；但 3×3 状态更直接对应原题和代码。
- 问：如果题目要求取模怎么办？答：状态与合法性判断完全不变，只把计数累加改成模加；模数必须由题目明确给出，不能自行假设。
- 问：如何证明没有重复计数？答：每个合法序列去掉最后一格后只有一个前缀，且最后一格颜色唯一，所以它只会由唯一旧状态通过唯一一次转移产生。

## 易错点

- 把“某种排列”误读成只禁止 `红-黄-蓝` 一个顺序，漏掉另外 5 种排列。
- 只用 `dp[i][lastColor]`，丢失判断三格窗口所需的信息。
- 忘记 `n<3` 时没有任何爆炸窗口。
- 在没有题目约束时直接用 `int/long` 或擅自取模，导致答案依赖未给出的假设。
- 用三重循环后误报 `O(n^3)`；颜色数固定为 3，内层最多 27 次常数转移，复杂度是 `O(n)`。
