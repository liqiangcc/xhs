# 两个不相交无序链表：按节点值找出全部匹配对

## 核心结论

仓库最强原始来源只保留了“两个无序链表如何找出其值相等的节点，两个链表不相交”。它明确区分了**节点值相等**与**链表节点相交**，但没有规定值类型、重复值、返回第一对还是全部结果，也没有给语言/API。因此这里不把它改写成经典“两个链表的交点”问题，而是显式选择一个可验证接口：节点值为 `int`；两个输入链表按节点身份互不相交；返回所有 `(leftIndex, rightIndex, value)` 匹配对；如果某个值在左表出现 `a` 次、右表出现 `b` 次，就返回该值的 `a*b` 个配对；结果按左索引、再按右索引排序。`null` 头节点表示空链表，算法不修改输入。

实现时先把右链表按值建立 `value -> right positions` 哈希表，再顺序扫描左链表并展开匹配位置。若左右长度分别为 `n`、`m`，输出匹配对数量为 `k`，时间复杂度为 `O(n+m+k)`；除输出外的辅助空间是 `O(m)`。

## 1 分钟版

这题首先要避免答成“链表相交”：来源已经说两个链表**不相交**，目标是找**值相等的节点**。

在当前候选 API 中，我把“找出”定义为返回全部匹配节点对。先扫描右链表，用哈希表记录每个值出现的所有索引；再扫描左链表，对当前值取出右侧索引列表并生成匹配对。重复值不能只保留一个索引，否则会丢掉合法配对。

因此构表 `O(m)`、扫描左表 `O(n)`、产出结果 `O(k)`，总时间 `O(n+m+k)`，辅助哈希空间 `O(m)`。测试再用最直接的双重循环 `O(n*m)` 作为独立 oracle 做差分验证。

## 3 分钟版

来源能确认的是三点：两个链表无序、结构上不相交、匹配条件是节点值相等。来源不能确认的是返回形态和重复语义，所以实现前必须把这些变成**候选接口约定**，不能把熟悉题型的隐含规则冒充成原题。

当前约定返回全部匹配对，并用链表中的位置来标识节点。这样既保留“节点”层面的配对关系，也能精确定义重复值。例如左表 `[2,2]`、右表 `[2,2,2]` 会返回 6 对，而不是只返回值 `2` 或任意第一对。

算法的不变量是：右侧哈希表在扫描左节点前已经完整记录右链表中每个值的全部位置；因此处理左索引 `i` 时，哈希命中的位置集合恰好等于所有满足 `left[i].value == right[j].value` 的 `j`。把这些 `j` 全部加入结果，就不会漏掉或额外制造匹配。顺序扫描左表、每个右位置列表按自然插入顺序展开，因此输出稳定为左索引优先、右索引次优先。

## 关键细节

- **题源边界**：原始来源只支持“无序链表、值相等、链表不相交”；值类型、返回全部匹配对、重复值笛卡尔配对和 Java API 都是显式候选选择。
- **不是交点题**：不能比较节点身份来寻找共享节点；来源反而说明两个链表不相交。
- **重复值语义**：右侧哈希值必须映射到“所有位置”，而不是单个位置。左侧同值节点也分别展开，因此重复值产生完整笛卡尔匹配对。
- **空链表**：`null` 头节点视为空链表，返回空结果。
- **无序性**：不依赖排序；若为了双指针先排序，需要复制或修改结构，而且会改变节点位置语义，不适合当前候选 API。
- **不修改输入**：只读遍历两个链表。
- **复杂度**：`O(n+m+k)` 时间；哈希索引 `O(m)` 辅助空间；返回结果本身占 `O(k)`。
- **可验证性**：7 组固定边界用例加 5000 组确定性随机链表，与双重循环 oracle 完全比较，包括重复值和负数值。

## 原理机制

```java
public static List<Match> findAll(Node leftHead, Node rightHead) {
    Map<Integer, List<Integer>> rightPositionsByValue = new HashMap<>();
    int rightIndex = 0;
    for (Node node = rightHead; node != null; node = node.next) {
        rightPositionsByValue
                .computeIfAbsent(node.value, ignored -> new ArrayList<>())
                .add(rightIndex++);
    }

    List<Match> matches = new ArrayList<>();
    int leftIndex = 0;
    for (Node node = leftHead; node != null; node = node.next) {
        List<Integer> rightPositions = rightPositionsByValue.get(node.value);
        if (rightPositions != null) {
            for (int position : rightPositions) {
                matches.add(new Match(leftIndex, position, node.value));
            }
        }
        leftIndex++;
    }
    return List.copyOf(matches);
}
```

仓库内的确定性夹具用双重循环作为独立 oracle：对每个左索引 `i` 和右索引 `j` 直接判断值是否相等，并按同样的稳定顺序收集结果。固定用例覆盖双空、单侧空、无匹配、多个不同值匹配、重复值笛卡尔配对和负数值；随后生成 5000 组长度 `0..30`、取值 `-6..6` 的链表做差分。预检输出为：

```text
PASS fixed=7 randomized=5000 oracle=nested-loop duplicateSemantics=cartesian-pairs order=left-then-right
```

## 项目经验版

这是算法面试题，仓库来源没有生产项目背景，因此不编造项目经验。若真实工程只关心“是否存在共同值”、只要去重后的共同值集合，或只要任意第一对匹配节点，应把返回契约改窄；那会直接改变输出规模和数据结构选择，但不改变“不要把值相等误答成节点相交”的核心边界。

## 常见追问

- **为什么不用双指针？** 两个链表无序；直接双指针无法利用顺序关系。排序会引入 `O(n log n + m log m)` 成本，并且如果原地排序还会改动节点结构。
- **如果只要是否存在共同值呢？** 右侧只需 `HashSet<Integer>`，扫描左侧第一次命中即可返回，时间 `O(n+m)`、空间 `O(m)`。
- **如果只要去重后的共同值呢？** 两侧按值做集合交集即可；这和当前“所有节点配对”是不同返回契约，不能混在一起。
- **重复值为什么是笛卡尔积？** 因为当前 API 返回“所有节点对”，每个左侧同值节点都与每个右侧同值节点构成一对满足条件的节点。
- **“两个链表不相交”有什么用？** 它排除了通过共享节点身份解释题目；当前算法只比较值，即使实现层能处理共享节点，也不把那种情况当作来源要求。

## 易错点

- 把题目答成经典链表交点，比较节点引用而不是值。
- 哈希表只记录每个值的一个节点/索引，导致重复值匹配丢失。
- 没有声明“第一对 / 全部节点 / 去重值集合”中的哪一种返回语义。
- 忽略输出规模 `k`，错误声称任何情况下都是纯 `O(n+m)` 时间。
- 为了使用双指针擅自排序或改写链表，却没有说明输入是否允许修改。
