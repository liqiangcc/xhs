# SQL：仅当所有 a 都等于 '1' 时返回 b='2' 的前两条

## 核心结论

这道题有一个**全表前置条件**：只有 `table1` 的每一条记录都满足 `a = '1'`，才允许返回 `b = '2'` 的记录。最直接的写法是把“所有行都满足”改写成“**不存在任何不满足的行**”，因此用 `NOT EXISTS` 做全表守卫，再按 `c` 排序并 `LIMIT 2`。

本答案把 `a IS NULL` 视为“不等于字符串 `'1'`”，因为来源要求“都等于 `'1'`”；如果业务对 NULL 有别的定义，需要单独修改这个契约。来源也没有规定 `c` 相同时如何稳定选前两条，因此不虚构额外主键。

## 1 分钟版

- 外层先筛 `b = '2'` 的候选行。
- 内层用 `NOT EXISTS` 检查全表：只要存在 `a <> '1'` 或 `a IS NULL` 的行，整个查询就返回 0 行。
- 全表条件成立时，按 `c ASC` 排序，再 `LIMIT 2`。
- “所有行都满足 P”与“不存在一行不满足 P”是等价的，这比 `COUNT` 写法更直接，也能显式处理 NULL。
- 如果 `c` 有并列且题目要求稳定的两条记录，需要面试官再给唯一键，然后追加第二排序键。

## 3 分钟版

在题目给出的 `table1(a,b,c,...)` 上，可以写：

```sql
SELECT t.*
FROM table1 AS t
WHERE t.b = '2'
  AND NOT EXISTS (
      SELECT 1
      FROM table1 AS x
      WHERE x.a IS NULL OR x.a <> '1'
  )
ORDER BY t.c ASC
LIMIT 2;
```

逻辑分两层。内层子查询不是在找要返回的数据，而是在找“反例”：任何 `a` 为空或不等于 `'1'` 的行都会让 `NOT EXISTS` 变成 false，于是外层所有候选行都被挡掉。只有找不到反例时，外层才正常筛 `b='2'`、排序、截取前两条。

如果数据库不是 MySQL/PostgreSQL/SQLite 这类使用 `LIMIT` 的方言，最后的 Top-N 语法要按目标数据库改写，例如 SQL Server 常见 `TOP`/`OFFSET FETCH`。来源只给 SQL 语义，没有给数据库版本，因此这里不把某一方言说成唯一写法。

## 关键细节

- **全表条件不能只检查返回行**：`a='1'` 的约束针对“所有元组”，即使违规行的 `b` 不是 `'2'`，也必须让查询整体不返回数据。
- **NULL 边界**：SQL 的 `x.a <> '1'` 对 NULL 结果是 UNKNOWN，不会被 WHERE 选中；所以若按“NULL 也不是等于 `'1'`”的契约，必须显式写 `x.a IS NULL OR x.a <> '1'`。
- **空表**：逻辑上“没有反例”成立，但外层也没有 `b='2'` 的行，因此结果仍为空。
- **排序方向**：题目只说“按 c 排序”而未写升降序。本答案声明使用常见的升序 `ASC` 作为答案侧选择；若面试官要求降序则改为 `DESC`。
- **并列顺序**：若多行 `c` 相同，只有 `ORDER BY c` 不能保证其中哪两行进入前 2；要稳定结果需要题目提供唯一键后再追加 tie-breaker。
- **复杂度/执行计划**：语义上有全表反例检查和候选排序。优化器可能改写执行计划；真实数据量大时应查看执行计划，并根据 `a`、`b`、`c` 的选择性和索引设计验证成本，不能只凭 SQL 文本断言扫描次数。

## 原理机制

关键是把全称量词转成反例检测：`∀ row, row.a = '1'` 等价于 `¬∃ row, row.a != '1'`。SQL 最自然的表达就是 `NOT EXISTS`。这样“全局是否允许返回”与“具体返回哪些行”被分开：内层决定全局门禁，外层决定 `b='2'` 的结果集、顺序和 Top-N。

## 项目经验版

来源没有真实表规模、索引、数据库版本或生产执行计划，不能虚构项目结论。实际落地时我会先确认 NULL 语义、`c` 的排序方向和并列规则，再在目标数据库用 `EXPLAIN`/执行计划验证 `NOT EXISTS` 是否被优化成高效的反连接或提前终止扫描，并按真实数据分布决定索引，而不是机械地为三个字段都建索引。

## 常见追问

- 问：为什么不能直接写 `WHERE a='1' AND b='2'`？答：那只保证“返回的行”满足 `a='1'`，无法阻止表里另一条 `a='0'`、`b='9'` 的违规行；题目要求的是全表条件。
- 问：能不能用 `COUNT(*)`？答：可以，例如比较总行数与满足 `a='1'` 的行数，但需要谨慎处理 NULL 和空表；`NOT EXISTS` 直接表达“没有反例”，语义更清楚。
- 问：为什么要单独判断 `a IS NULL`？答：因为 `NULL <> '1'` 在 SQL 三值逻辑中不是 TRUE；如果 NULL 应视为“不满足等于 `'1'`”，必须显式纳入反例条件。
- 问：`c` 相同怎么办？答：题目没给唯一键，不能凭空添加字段；如果要求稳定 Top-2，应在拿到主键/唯一键后写 `ORDER BY c, id` 之类的确定性顺序。
- 问：如果要求 c 降序呢？答：把 `ASC` 改成 `DESC`；来源没有保留方向，本答案只是明确声明了升序选择。
- 问：为什么不用 `HAVING MIN(a)=MAX(a)`？答：它对 NULL、空表以及字符串比较都需要额外定义，而且不能直接表达“唯一允许值必须是 `'1'`”；反例检测更贴近题意。

## 易错点

- 把 `a='1'` 写在外层，只检查被返回的 `b='2'` 行，漏掉全表其他违规记录。
- 写 `NOT EXISTS (... WHERE a <> '1')` 却忘记 NULL，导致含 NULL 的表被误判为全部等于 `'1'`。
- 题目没有给排序方向或唯一键，却把 `ASC` 和某个 `id` 当成来源事实。
- 用聚合计数时忽略空表/NULL 语义，得到和题意不同的边界行为。
- 只给 `LIMIT 2`，却没有先完成全局门禁与排序。
