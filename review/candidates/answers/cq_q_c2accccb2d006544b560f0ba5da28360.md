# 二叉树的所有路径：DFS + 回溯

## 核心结论

来源只写了“二叉树的所有路径”，没有给节点定义、返回格式和遍历顺序。这里明确采用一个最小面试契约：输入二叉树根节点，返回所有**从根到叶子**的节点值路径；每条路径用 `List<Integer>` 表示，结果按“先左子树、后右子树”的 DFS 顺序返回；空树返回空列表。核心做法是维护当前根到当前节点的路径，到叶子时复制一份加入结果，回溯时删除刚加入的节点。

## 1 分钟版

- 先声明契约：这里把“所有路径”解释为所有根到叶子的路径；来源没有规定字符串格式，所以返回 `List<List<Integer>>`。
- DFS 进入节点时把 `node.val` 加到当前 `path`。
- 当 `left == null && right == null` 时说明到达叶子，必须把当前路径**复制**后加入结果。
- 递归处理左、右子树，返回前删除当前节点，恢复父层路径，这就是回溯不变量。
- 若有 `N` 个节点，遍历节点本身是 O(N)；考虑把每条路径复制到输出的成本，总时间是 O(N + S)，`S` 是所有返回路径长度之和；除输出外递归栈和当前路径占 O(H)，`H` 为树高。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.List;

public final class BinaryTreePaths {
    public static final class TreeNode {
        final int val;
        TreeNode left;
        TreeNode right;

        public TreeNode(int val) {
            this.val = val;
        }
    }

    public static List<List<Integer>> allRootToLeafPaths(TreeNode root) {
        List<List<Integer>> result = new ArrayList<>();
        if (root == null) {
            return result;
        }
        dfs(root, new ArrayList<>(), result);
        return result;
    }

    private static void dfs(
            TreeNode node,
            List<Integer> path,
            List<List<Integer>> result) {
        path.add(node.val);

        if (node.left == null && node.right == null) {
            result.add(new ArrayList<>(path));
        } else {
            if (node.left != null) {
                dfs(node.left, path, result);
            }
            if (node.right != null) {
                dfs(node.right, path, result);
            }
        }

        path.remove(path.size() - 1);
    }
}
```

这个实现维护的关键不变量是：进入 `dfs(node)` 后，`path` 表示从根到 `node` 的完整路径；离开该调用前，必须把 `path` 恢复到进入当前节点之前的状态。因为兄弟子树共享同一个 `path` 对象，所以叶子处不能直接保存 `path` 引用，必须 `new ArrayList<>(path)` 固化当时的路径快照。

## 关键细节

- **叶子判断**：只有左右孩子都为空才是叶子。只有一个孩子为空的节点仍然是中间节点，不能提前输出路径。
- **为什么要复制路径**：`path` 会继续被回溯修改；如果把同一个引用直接放进 `result`，最终多条结果会指向同一个可变列表并被清空或改写。
- **重复值不是重复路径**：路径由树结构决定，不由值集合决定。两个不同叶子即使节点值序列恰好相同，也代表两条结构上不同的根到叶路径，不能按值去重。
- **顺序是实现契约**：来源没要求结果顺序。这里选择左子树优先，因此测试也只验证这个显式契约，不把它说成题目要求。
- **复杂度**：每个节点访问一次；叶子时复制当前路径，因此精确时间上界应写为 O(N + S)，`S` 为输出中所有节点值的总个数。额外工作空间 O(H)，输出空间 O(S)。
- **深树风险**：高度接近 N 的退化树可能触发 Java 调用栈上限；若输入可能极深，可改成显式栈并把“节点 + 当前路径状态”放入工作栈。

## 原理机制

回溯可以理解为对 DFS 状态的“做选择 → 递归 → 撤销选择”。当前状态只有一条从根到当前节点的路径，所以进入节点时追加一个值，离开节点时删除一个值，就能让同一个列表安全地复用于不同分支。

这比“每到一个节点都创建一份新路径”更节省中间对象；但在真正产出一条答案时仍必须复制，因为结果需要独立保存。若改成字符串路径，状态转移仍一样，只是路径表示和复制成本不同。

## 项目经验版

来源没有真实项目背景，不能虚构“线上用过这段算法”。项目映射时可以把它类比为树形目录、组织树或规则树的根到终点路径枚举，但需要先确认“终点”是否真的等价于叶子、是否允许提前终止、路径是否要携带边属性，以及树是否可能非常深；这些都会影响 API 和遍历实现。

## 常见追问

- 问：为什么到叶子时要 `new ArrayList<>(path)`？答：因为 `path` 是所有递归层共享的可变状态，后续回溯会修改它；复制后才能把当前路径冻结成独立结果。
- 问：如果只想返回 `1->2->5` 这种字符串怎么办？答：遍历和回溯不变量不变，只在叶子处把当前节点序列格式化成字符串；不要把格式问题和路径搜索逻辑耦合在一起。
- 问：如果要所有“根到任意节点”的路径呢？答：终止条件变了；每进入一个节点就可以产出当前路径，而不是只在叶子处产出。
- 问：能不能不用递归？答：可以，用显式栈保存待访问节点以及对应路径状态；它避免调用栈溢出，但需要自己管理状态复制或入栈/出栈过程。
- 问：两个不同分支的值序列完全相同，要去重吗？答：原题没有去重要求。按“树中的路径”理解，它们是不同结构路径，默认都应保留；若题目只关心值序列集合，需要额外明确去重契约。

## 易错点

- 把“只有一个孩子为空”误判成叶子，漏掉后续节点。
- 把可变 `path` 本身直接加入结果，导致所有结果被后续回溯修改。
- 递归返回后忘记删除当前节点，导致兄弟分支混入上一条路径。
- 只写 O(N) 而忽略把路径复制进输出所需要的 O(S) 成本。
- 来源没有规定输出格式或遍历顺序，却把某种字符串格式、左优先顺序说成唯一正确要求。
