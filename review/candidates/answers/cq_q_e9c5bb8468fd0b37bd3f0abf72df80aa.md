# SQL：从学生表和成绩表查询学号、姓名、平均成绩

## 核心结论

来源只保留“学生表 + 成绩表，查询学生学号、姓名、平均成绩”，没有给真实表名、列名、主外键、无成绩学生是否保留，也没有要求排序或小数位数。先声明一个最小可执行假设：`students(student_id, name)` 保存学生，`grades(student_id, score)` 每行是一条该学生的成绩；本答案只返回至少有一条成绩的学生。按 `student_id` 连接两表，再以学生为粒度分组并对 `score` 求 `AVG`。

## 1 分钟版

- 先明确表结构是假设，不把 `JOIN`、`GROUP BY` 或字段名冒充成来源要求。
- 用学生主键把 `students` 与 `grades` 连接，避免只按姓名等非稳定字段关联。
- 结果粒度是一名学生，所以按 `student_id` 和 `name` 分组，对该学生的 `score` 求平均值。
- 来源没说要包含“还没有成绩”的学生；这里明确采用“至少有一条成绩才返回”的契约，因此使用 `INNER JOIN`。
- 来源也没给排序、四舍五入和精度规则，因此正式 SQL 不额外添加这些约束。

## 3 分钟版

假设学生表是 `students(student_id, name)`，成绩表是 `grades(student_id, score)`，且 `grades.student_id` 指向学生。每条成绩记录都参与该学生平均分；只有有成绩的学生出现在结果中：

```sql
SELECT
    s.student_id,
    s.name,
    AVG(g.score) AS average_score
FROM students AS s
JOIN grades AS g
  ON g.student_id = s.student_id
GROUP BY s.student_id, s.name;
```

如果题目进一步要求“没有成绩的学生也要展示”，契约就变了：应考虑 `LEFT JOIN`，此时无成绩学生的 `AVG(g.score)` 通常为 `NULL`，是否转成 `0` 仍要继续确认业务口径。若要求固定小数位，也应按目标数据库和精度规则显式处理，而不是默认四舍五入。

## 关键细节

- **结果粒度**：一名学生一行；平均值在该学生所有成绩记录上计算。
- **关联键**：示例使用 `student_id`，因为来源只说“学生表和成绩表”，实际键名必须以真实 schema 为准。
- **无成绩学生**：当前候选明确采用只返回有成绩学生的最小契约；需要全量学生时改用外连接并定义空集语义。
- **重复记录**：若成绩表存在业务重复数据，普通 `AVG` 会把每行都计入。是否去重必须由成绩记录的业务唯一性决定，不能擅自 `DISTINCT score`。
- **精度**：`AVG` 的返回类型和小数精度受数据库与列类型影响。来源没有规定展示精度，不应把某个数据库的隐式转换当成通用事实。
- **排序**：来源没有要求顺序，因此答案不把 `ORDER BY` 写成必需条件；若面试官指定顺序，再在最终结果上排序。

## 原理机制

这道题先把两个关系按学生标识做匹配，得到“学生信息 × 该学生成绩”的行集合；随后 `GROUP BY` 把这些行重新收缩到“每个学生一个分组”，`AVG(score)` 在每个分组内部聚合。关键是先确认最终输出粒度和无匹配行的语义：`INNER JOIN` 表示只保留能匹配到成绩的学生，`LEFT JOIN` 则保留学生侧全部行。这是关系语义差异，不只是 SQL 写法差异。

来源没有提供真实项目、表规模、索引或执行计划数据，不能虚构。我在真实系统里会先查看 schema、主外键、成绩记录唯一性和空值规则，再用目标数据库的 `EXPLAIN` 与样本数据验证连接和聚合成本；这些是落地验证步骤，不是本题来源事实。

## 常见追问

- 问：为什么用 `student_id` 连接？答：这里把它作为最小 schema 假设；实际题目若给出别的主外键，应按真实键连接，不能把示例字段名当成来源。
- 问：没有成绩的学生要不要显示？答：来源没说明。本候选明确只返回有成绩学生；若要求保留全部学生，改成 `LEFT JOIN` 并确认无成绩时返回 `NULL`、`0` 还是其他值。
- 问：为什么不能写 `AVG(DISTINCT score)`？答：相同分数可能来自两门不同课程，值相同不代表记录重复；是否去重要基于业务唯一键，而不是分数值本身。
- 问：要不要按平均分或学号排序？答：来源没有排序要求；只有题目明确提出时再增加 `ORDER BY`。
- 问：平均分保留两位小数怎么做？答：需要先确认数据库方言和舍入规则，再用相应函数或类型转换；不能在来源没有要求时默认一种精度策略。

## 易错点

- 把自定义表名、字段名、`JOIN/GROUP BY` 写成“原题已经给出”。
- 只按姓名连接，忽略姓名可能不唯一。
- 没定义无成绩学生语义，却在 `INNER JOIN` 和 `LEFT JOIN` 之间随意切换。
- 用 `AVG(DISTINCT score)` 错误消掉不同课程但分数相同的合法成绩记录。
- 题目没要求排序、精度或四舍五入，却把实现偏好扩张成题目约束。
