# 算法：轮转数组（LeetCode 189），O(1) 额外空间、O(n) 时间

## 核心结论

题目来源明确指向 LeetCode 189，并要求 `O(1)` 额外空间和 `O(n)` 时间。LeetCode 的原题契约是把整数数组向右轮转 `k` 步，`k` 非负。最稳妥的原地做法是三次反转：先把整个数组反转，再反转前 `k` 个元素，最后反转剩余元素；先做 `k %= n`，避免 `k > n` 时做无意义轮转。

## 1 分钟版

- 设数组长度为 `n`，先归一化 `k %= n`。
- 反转整个数组，把原来的后 `k` 个元素整体移到前面，但两段内部顺序都被反了。
- 再分别反转 `[0, k-1]` 和 `[k, n-1]`，恢复两段内部顺序。
- 每个元素只参与常数次交换，所以时间是 `O(n)`；只用几个下标和临时变量，所以额外空间 `O(1)`。
- 原题的 `k` 是非负数。面试官若追问 Java 负数取模，应把它当作语言语义/扩展输入讨论，不要反过来声称原题要求负 `k`。

## 3 分钟版

以 `[1,2,3,4,5,6,7]`、`k=3` 为例。完整反转后得到 `[7,6,5,4,3,2,1]`；前 3 个再反转得到 `[5,6,7,4,3,2,1]`；后 4 个反转得到 `[5,6,7,1,2,3,4]`，正好是向右轮转 3 步。

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        if (n <= 1) return;
        k %= n;
        if (k == 0) return;
        reverse(nums, 0, n - 1);
        reverse(nums, 0, k - 1);
        reverse(nums, k, n - 1);
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            int tmp = nums[left];
            nums[left++] = nums[right];
            nums[right--] = tmp;
        }
    }
}
```

这里不需要辅助数组，也不需要把元素逐个右移 `k` 轮。后者最坏会到 `O(nk)`，不满足来源给出的 `O(n)` 时间要求。

## 关键细节

- `k %= n` 必须在三次反转之前做；比如 `n=7, k=10` 与 `k=3` 等价。
- `n <= 1` 可直接返回；LeetCode 当前约束保证 `n >= 1`，这个判断只是让实现更稳健。
- `k == 0` 时直接返回，避免虽然正确但无意义的三次反转。
- 三次反转都在原数组上交换，额外空间是常数级；不能把复制数组再写回说成 `O(1)`。
- Java 的 `%` 保留被除数符号；如果面试官额外扩展到负 `k`，必须先定义“负数表示向左还是仍按右移折算”的契约，再用 `((k % n) + n) % n` 一类方式得到非负余数。原题本身的 `k` 非负，因此正式实现无需引入这个扩展语义。

## 原理机制

把原数组写成 `A B`，其中 `B` 是最终应移动到前面的后 `k` 个元素。整个数组反转得到 `reverse(B) reverse(A)`；再分别反转两段，就得到 `B A`。所以三次反转不是经验技巧，而是利用“整体反转会同时交换两段位置并反转段内顺序，再用两次局部反转消掉段内反序”的等价变换。

## 项目经验版

来源没有提供真实生产项目经历，不应虚构性能数据。若在工程里实现，我会把大 `k`、`k=0`、单元素、重复值以及随机数组与一个清晰的辅助数组 oracle 对拍，并在目标语言里确认整数取模语义；这些是验证步骤，不是题目来源中已经发生过的项目事实。

## 常见追问

- 问：为什么三次反转是 `O(n)` 而不是 `O(3n)` 之外更高？答：三次线性扫描的常数因子会被大 O 忽略，总交换次数仍与 `n` 成正比。
- 问：能不能每次把最后一个元素挪到开头，做 `k` 次？答：可以得到正确结果，但每次移动要 `O(n)`，最坏 `O(nk)`，不满足题目要求。
- 问：`k` 比数组长度大怎么办？答：右移 `n` 步回到原状态，因此只需要 `k % n`。
- 问：面试官问 Java 里 `-1 % 7` 呢？答：结果是 `-1`；如果扩展契约允许负 `k`，要先约定负数方向，再把余数规范化到 `[0,n)`，但不要把这个追问冒充成 LeetCode 189 的原始输入约束。

## 易错点

- 忘记 `k %= n`，导致分段下标越界。
- 反转顺序或分段边界写错，例如把第二段从 `k-1` 开始。
- 使用额外 `O(n)` 数组，却声称满足 `O(1)` 额外空间。
- 逐步右移 `k` 次，正确但最坏时间复杂度退化为 `O(nk)`。
- 把负数取模追问误写成原题必须支持负 `k`，造成来源边界膨胀。
