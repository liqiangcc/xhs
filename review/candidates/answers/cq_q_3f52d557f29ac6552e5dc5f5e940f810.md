# 算法：零钱兑换（LeetCode 322）

## 核心结论

把 `dp[x]` 定义为凑出金额 `x` 所需的最少硬币数。`dp[0]=0`，其余状态先设为“不可达”；对每个金额 `x=1..amount`，枚举所有面额 `coin`，若 `coin<=x`，就用 `dp[x-coin]+1` 更新 `dp[x]`。最终 `dp[amount]` 仍不可达时返回 `-1`。时间复杂度 `O(amount * coins.length)`，空间复杂度 `O(amount)`。

## 1 分钟版

- 题目目标是**最少硬币数**，每种硬币可以使用无限次；凑不出目标金额返回 `-1`，金额为 `0` 时答案是 `0`。
- 状态：`dp[x]` 表示“恰好凑出 `x` 的最少硬币数”；`dp[0]=0`，其他位置初始化为 `amount+1` 作为不可达哨兵。
- 转移：若 `coin<=x`，最后一枚硬币可以选 `coin`，于是候选答案是 `dp[x-coin]+1`，取所有候选的最小值。
- 按金额从小到大计算即可，因为 `coin>0`，每次只依赖更小金额 `x-coin`；最后若 `dp[amount]==amount+1`，说明不可达，返回 `-1`。

## 3 分钟版

这题最重要的是先把“组合数量”和“最少数量”区分开。LeetCode 322 要的是最少硬币数，不是组合数。因为每种硬币数量无限，可以把任意最优方案的最后一枚硬币单独拿出来：假设最后一枚是 `coin`，那么前面的硬币必须以最少数量凑出 `x-coin`，否则替换成更优子解就能得到更少硬币，与最优性矛盾。因此有：

`dp[x] = min(dp[x], dp[x - coin] + 1)`。

初始化时 `dp[0]=0`。其他状态不能初始化成 `0`，否则会把不可达金额误认为已经凑出；可以用 `amount+1` 作为哨兵。因为官方约束下所有硬币面额都是正整数，如果金额 `amount` 可达，任何最少方案使用的硬币数都不会超过 `amount`，所以 `amount+1` 一定严格大于合法答案。

```java
import java.util.Arrays;

public final class CoinChange {
    private CoinChange() {}

    public static int coinChange(int[] coins, int amount) {
        if (coins == null) {
            throw new IllegalArgumentException("coins must not be null");
        }
        if (amount < 0) {
            throw new IllegalArgumentException("amount must be non-negative");
        }

        int unreachable = amount + 1;
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, unreachable);
        dp[0] = 0;

        for (int current = 1; current <= amount; current++) {
            for (int coin : coins) {
                if (coin > 0 && coin <= current) {
                    dp[current] = Math.min(dp[current], dp[current - coin] + 1);
                }
            }
        }
        return dp[amount] == unreachable ? -1 : dp[amount];
    }
}
```

官方示例 `[1,2,5], 11` 返回 `3`，`[2], 3` 返回 `-1`，`[1], 0` 返回 `0`。仓库内的独立代码检查还用 BFS 按“使用硬币枚数”逐层搜索作为 oracle，对面额集合 `{1,2,3,4,5}` 的所有非空子集、金额 `0..30` 共 961 个用例进行了对照，结果全部一致。

## 关键细节

- `dp[x]` 的语义必须是“**恰好**凑出金额 `x` 的最少硬币数”，否则不可达状态和最优状态会混在一起。
- `amount=0` 时无需任何硬币，答案为 `0`；这是整个递推的基础状态。
- 每种硬币可无限使用，因此同一面额可以在不同状态中反复参与转移；这里按金额递增遍历，自然允许重复使用。
- 官方约束中面额是正整数，所以 `x-coin<x`；这保证金额递增时依赖已经计算完成，没有环。
- 面额可能远大于 `amount`，此时直接跳过即可；代码使用 `coin<=current` 避免无效下标。
- 时间复杂度是 `O(amount * n)`，其中 `n=coins.length`；一维 DP 空间是 `O(amount)`。
- 这里额外检查 `null` 和负金额只是让独立 Java 方法的行为明确；LeetCode 322 的正式输入本身满足题目约束。

## 原理机制

从最优子结构看，设一个最优方案凑出 `x`，最后一枚硬币面额为 `coin`。删掉这枚硬币后，剩余部分凑出 `x-coin`。如果剩余部分不是 `x-coin` 的最少硬币方案，就可以换成更短的方案，从而让原方案更短，产生矛盾。因此只要枚举“最后一枚硬币是谁”，所有最优方案都会被覆盖。

从计算顺序看，硬币都是正数，所以 `dp[x]` 只依赖 `dp[x-coin]` 这样的更小下标。金额从 `0` 向 `amount` 推进形成有向无环依赖。不可达状态保持哨兵值；一旦某条路径可达，取最小值就保留当前最优硬币数。最终哨兵是否被替换，同时给出了“可达/不可达”的判断。

## 常见追问

- 问：为什么这是完全背包语义？答：每种硬币可以使用无限次，所以同一面额能被重复选择；但本题目标函数是“最少个数”，不是求可行组合数量。
- 问：为什么 `dp[0]=0`？答：凑出金额 0 的最少硬币数就是 0；所有可达正金额最终都从这个基础状态通过若干次“加一枚硬币”得到。
- 问：为什么不能把其他 `dp` 初始成 0？答：0 表示已经用 0 枚硬币凑出该金额，会让不可达状态参与最小值比较并污染结果，所以必须使用明显大于所有合法答案的哨兵。
- 问：和 LeetCode 518 零钱兑换 II 有什么区别？答：322 求最少硬币数，状态值取 `min`；518 求组合数量，状态值做计数累加，且遍历顺序还承担“是否重复计数不同排列”的语义。
- 问：能用 BFS 吗？答：可以把金额看成节点、加一枚硬币看成一条单位权边，按层 BFS 第一次到达 `amount` 的层数就是最少硬币数；DP 更直接，BFS 很适合作为小规模独立 oracle。

## 易错点

- 把题目写成“有多少种组合”，混淆 LeetCode 322 和 518。
- 忘记不可达状态，导致 `[2], amount=3` 之类用例得到错误结果。
- `dp[0]` 初始化错误，后续所有状态都失去合法起点。
- 把“每种硬币无限次”误写成每枚只能使用一次。
- 使用 `Integer.MAX_VALUE` 后无条件做 `+1`，带来溢出风险；使用 `amount+1` 哨兵更简单。
- 只背“完全背包”标签，没有说明 `dp[x]` 的精确定义、最后一枚硬币的转移依据和不可达语义。
