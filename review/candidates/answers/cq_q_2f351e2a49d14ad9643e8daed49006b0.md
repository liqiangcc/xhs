# 算法/手撕：将堆抽象成类，实现获取/删除等操作

## 核心结论

仓库来源只明确保留了“将堆抽象成类，实现获取元素、删除元素等的操作方法”，没有规定最小堆还是最大堆、语言、构造方式、重复元素、空堆行为或方法名。这里显式采用一个候选契约：用 Java 实现 `int` **最小堆**；`peek()` 获取堆顶但不删除，`poll()` 获取并删除堆顶，额外提供 `add()`、`size()`、`isEmpty()` 使类可以完整使用；允许重复值；空堆 `peek/poll` 抛 `NoSuchElementException`；数组构造会复制输入而不是修改原数组。

数组堆的关键不变量是：对每个非根节点 `i`，父节点下标为 `(i - 1) / 2`，且最小堆始终满足 `heap[parent(i)] <= heap[i]`。插入时把新元素放到末尾后向上调整；删除堆顶时用最后一个元素补到根，再向下调整。这样 `peek()` 是 `O(1)`，`add()` 和 `poll()` 是 `O(log n)`，从数组自底向上建堆是 `O(n)`。

## 1 分钟版

我会先固定契约：这里实现一个 `int` 最小堆，重复值允许；`peek()` 只看最小值，`poll()` 返回并删除最小值；空堆访问抛异常。最小堆用数组存储，核心关系是：

- 父节点：`(i - 1) / 2`
- 左孩子：`2 * i + 1`
- 右孩子：`2 * i + 2`
- 不变量：父节点值不大于孩子值

`add(x)` 先把 `x` 放到数组末尾，再不断和父节点比较并上浮，所以是 `O(log n)`。`poll()` 先保存根，把最后一个元素移到根，再和更小的孩子交换并下沉，也是 `O(log n)`。`peek()` 直接读根，是 `O(1)`。如果从已有数组构造，可以从最后一个非叶子节点向前做 `siftDown`，整体 `O(n)`。

## 3 分钟版

题源没有要求具体堆方向，因此不能把“最小堆”冒充成原题事实。我选择最小堆只是为了给出一份完整、可执行的候选实现；如果面试官要最大堆，只需要把比较方向反过来，数据结构和调整过程不变。

内部用连续数组保存完全二叉树。只要数组下标满足完全二叉树映射，就不需要显式节点和指针。对于 `add`，新元素先追加到末尾；新增位置之外的堆原本已经满足不变量，所以唯一可能失效的路径是“新节点到根”的祖先链。沿这条链向上比较，直到父节点已经不大于新值，或到达根即可。

`poll` 删除的是根。删掉根后如果直接移动数组会很贵，因此把最后一个元素搬到根并缩短有效长度。此时除“根到某个叶子”的路径外，其他位置仍然保持原来的堆关系。每一步都选择左右孩子里更小的那个；如果当前值已经不大于这个孩子就停止，否则把更小孩子上移，继续向下，最终恢复最小堆不变量。

重复元素没有特殊问题，因为不变量使用 `<=`。空堆行为则必须写进 API 契约；这里选择抛 `NoSuchElementException`，而不是返回哨兵值，避免和合法 `int` 值混淆。数组构造函数会复制输入，再做自底向上的 Floyd heapify，因此不会修改调用者的数组。

复杂度上，`peek` 是 `O(1)`；一次上浮或下沉最多经过树高，因此 `add/poll` 是 `O(log n)`；数组建堆虽然会调用多个 `siftDown`，但大量节点都靠近叶子，所有下沉高度总和为 `O(n)`，不是 `O(n log n)`。内部数组扩容是摊销成本，候选实现按约 1.5 倍扩容。

## 关键细节

- **题源边界**：来源只支持“堆类 + 获取/删除等操作”。最小堆、Java、`int`、`peek/poll/add` 命名、重复值和异常行为都是候选选择。
- **核心不变量**：任一有效孩子都不能小于其父节点；测试会在每次随机操作后直接检查这个数组不变量。
- **插入只需上浮**：新增前旧堆是合法的，只有新节点到根的祖先链可能破坏顺序。
- **删除只需下沉**：根被最后一个元素替换后，只有从根向下的一条路径可能破坏顺序。
- **下沉要选更小的孩子**：如果只固定和左孩子交换，可能把一个更小的右孩子留在父节点下面而继续违反不变量。
- **重复值**：允许重复；比较使用 `<=`，不需要去重。
- **空堆**：`peek()` / `poll()` 抛 `NoSuchElementException`；这属于显式 API 设计，不是题源条件。
- **构造输入不修改**：数组构造先复制，再原地 heapify 复制品。
- **复杂度**：`peek O(1)`，`add O(log n)`，`poll O(log n)`，数组建堆 `O(n)`，保存 `n` 个元素需要 `O(n)` 空间。
- **可验证性**：固定用例覆盖空堆、空数组、单元素、重复值、负数、`int` 极值、扩容、构造输入不变和混合操作；5000 组确定性随机操作与 Java `PriorityQueue<Integer>` 对照，并在每一步检查堆不变量。

## 原理机制

```java
import java.util.Arrays;
import java.util.NoSuchElementException;

public final class IntMinHeap {
    private int[] elements;
    private int size;

    public IntMinHeap() {
        this.elements = new int[8];
    }

    public IntMinHeap(int[] values) {
        if (values == null) {
            throw new NullPointerException("values");
        }
        this.elements = Arrays.copyOf(values, Math.max(8, values.length));
        this.size = values.length;
        for (int i = (size >>> 1) - 1; i >= 0; i--) {
            siftDown(i);
        }
    }

    public int size() {
        return size;
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public void add(int value) {
        ensureCapacity(size + 1);
        elements[size] = value;
        siftUp(size);
        size++;
    }

    public int peek() {
        ensureNotEmpty();
        return elements[0];
    }

    public int poll() {
        ensureNotEmpty();
        int result = elements[0];
        int last = elements[--size];
        if (size > 0) {
            elements[0] = last;
            siftDown(0);
        }
        return result;
    }

    private void siftUp(int index) {
        int value = elements[index];
        while (index > 0) {
            int parent = parent(index);
            if (elements[parent] <= value) {
                break;
            }
            elements[index] = elements[parent];
            index = parent;
        }
        elements[index] = value;
    }

    private void siftDown(int index) {
        int value = elements[index];
        int half = size >>> 1;
        while (index < half) {
            int left = left(index);
            int right = left + 1;
            int smallest = left;
            if (right < size && elements[right] < elements[left]) {
                smallest = right;
            }
            if (elements[smallest] >= value) {
                break;
            }
            elements[index] = elements[smallest];
            index = smallest;
        }
        elements[index] = value;
    }

    private void ensureCapacity(int target) {
        if (target <= elements.length) {
            return;
        }
        int next = elements.length + (elements.length >>> 1);
        if (next < target) {
            next = target;
        }
        elements = Arrays.copyOf(elements, next);
    }

    private void ensureNotEmpty() {
        if (size == 0) {
            throw new NoSuchElementException("heap is empty");
        }
    }

    private static int parent(int index) {
        return (index - 1) >>> 1;
    }

    private static int left(int index) {
        return (index << 1) + 1;
    }
}
```

`poll()` 的 `siftDown` 每轮比较左右孩子，选择较小者；如果当前值已经 `<=` 较小孩子就结束，否则把孩子上移并继续。`add()` 的 `siftUp` 则反过来沿父链上移。

```text

```

随机测试的 oracle 使用 JDK `PriorityQueue<Integer>`；同时测试直接读取候选堆的内部快照，逐节点验证 `parent <= child`，因此既检查外部行为，也检查内部堆不变量。

## 常见追问

- 问：为什么选择最小堆，不是最大堆？答：题源没有指定；最小堆是本候选的显式选择。最大堆只需反转比较方向。
- 问：为什么删除堆顶后要把最后一个元素放到根？答：这样仍保持完全二叉树的紧凑数组形态，只需要沿一条路径恢复顺序，而不需要整体移动元素。
- 问：下沉时为什么必须选两个孩子中更小的那个？答：最小堆要求父节点同时不大于两个孩子；先和更大的孩子交换不能保证对更小孩子满足不变量。
- 问：重复元素怎么处理？答：允许重复，`<=` 已经能维护不变量；`poll` 会逐个取出相同最小值。
- 问：为什么数组建堆是 `O(n)` 而不是 `O(n log n)`？答：自底向上 heapify 时，绝大多数节点离叶子很近；把各节点可能下沉的高度求和是线性级别。
- 问：如果要删除任意一个值怎么办？答：先定位其下标，再用末尾元素替换，并根据与父/子的关系选择上浮或下沉；若要求高效定位，还需要额外索引结构，这超出了题源只明确的“获取/删除等操作”范围。

## 易错点

- 把 Java 内存里的“heap”概念误答成数据结构堆。
- 没先声明最小堆/最大堆和空堆行为，导致 API 契约含糊。
- `poll` 后只替换根而不下沉，破坏堆不变量。
- 下沉时不比较两个孩子，错误选择交换方向。
- 插入先自增/写错有效长度，造成新元素没有参与正确的上浮范围。
- 把自底向上建堆复杂度写成 `O(n log n)`，忽略不同节点的实际下沉高度。
- 声称题源指定 Java、`int`、方法名或异常类型，而仓库来源并没有这些信息。
