# 下一个排列：原地求下一个字典序排列

## 核心结论

来源只有“算法题：下一个排列”，没有给 API、是否允许原地修改、重复元素语义或最大排列是否回绕。下面把这些都明确为**答案侧契约**：给定 `int[]`，原地改成按数值字典序严格更大的最小排列；如果当前已经是最大排列，则回绕到最小的升序排列；允许重复值；`null` 或长度小于 2 时不做修改。

在线性时间、常数额外空间内可以完成三步：从右向左找到第一个下降转折 `i`，使 `nums[i] < nums[i+1]`；再从右端找到第一个严格大于 `nums[i]` 的元素交换；最后反转后缀 `i+1..n-1`。

## 1 分钟版

- 从右往左找第一个 `nums[i] < nums[i+1]`。它右边的后缀此时一定是非递增的；这个 `i` 是还能让整体变大的最右位置。
- 如果找不到这样的 `i`，说明整个数组已经非递增，也就是当前多重集合的最大字典序，直接整段反转得到最小升序排列。
- 如果找到 `i`，从右往左找第一个 `nums[j] > nums[i]`。因为后缀非递增，这个元素就是“能让第 i 位变大的最小可用值”。
- 交换 `i` 和 `j` 后，把后缀反转成非递减，就得到在新前缀下最小的后缀。
- 因此前缀只在最右可变位置增加了最小幅度，后缀又取最小，整体正好是下一个字典序排列。
- 两次线性扫描加一次反转，总时间 `O(n)`，额外空间 `O(1)`。

## 3 分钟版

```java
public final class NextPermutation {
    public static void nextPermutation(int[] nums) {
        if (nums == null || nums.length < 2) return;

        int i = nums.length - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            int j = nums.length - 1;
            while (nums[j] <= nums[i]) j--;
            swap(nums, i, j);
        }

        reverse(nums, i + 1, nums.length - 1);
    }

    private static void reverse(int[] nums, int left, int right) {
        while (left < right) swap(nums, left++, right--);
    }

    private static void swap(int[] nums, int i, int j) {
        int t = nums[i];
        nums[i] = nums[j];
        nums[j] = t;
    }
}
```

例如 `[1,2,3]` 得到 `[1,3,2]`；`[3,2,1]` 找不到转折点，整段反转得到 `[1,2,3]`；`[1,1,5]` 得到 `[1,5,1]`，重复元素不需要特殊去重逻辑。

## 关键细节

- **为什么找最右转折点**：要得到“刚好大一点”的排列，应尽量保持更高位前缀不变，所以修改位置必须尽可能靠右。
- **为什么从右端找第一个更大值**：转折点右侧已经非递增，从右端向左遇到的第一个 `> nums[i]` 的值，就是后缀中严格大于它的最小值；重复值也自然满足这个结论。
- **为什么交换后只需反转后缀**：原后缀非递增；选中最右侧严格大于 pivot 的元素交换后，剩余后缀仍可通过反转得到其最小非递减排列，无需排序。
- **最大排列回绕**：来源未写回绕规则；这里采用循环式 next-permutation 契约，最大排列变成最小排列。如果调用方希望“没有下一个排列”返回状态，需要改 API，而不是悄悄改变语义。
- **重复元素**：pivot 搜索用 `>=`、successor 搜索用 `<=`，这样要求真正的严格增加，不会把相等值当作下一排列。
- **输入修改**：本答案选择原地修改，是答案侧接口约定；如果题目要求不可变输入，可先复制再执行同一算法。
- **复杂度**：pivot 扫描、successor 扫描、后缀反转都至多线性，总时间 `O(n)`；只用若干下标和临时变量，额外空间 `O(1)`。

## 原理机制

字典序比较先看第一个不同位置。为了找当前排列之后的最小排列，就要让这个“第一个不同位置”尽量靠右，并且只增加到刚好能增加的最小值。最右转折点 `i` 正是这样的边界：它右边已经是该后缀的最大排列（非递增），单独改后缀不可能再变大，所以必须提升 `nums[i]`。

提升 pivot 时，又必须选择后缀中严格大于它的最小值，避免前缀增加过多。完成这一步后，前缀已经确定为“所有更大前缀中的最小一个”；因此剩余后缀必须排成最小顺序，也就是非递减。由于后缀已有单调结构，交换后直接反转即可线性完成。

## 项目经验版

来源是纯算法题，没有真实项目背景，因此不虚构生产使用经历。工程实现时应先确认 API 是否采用“最大排列回绕”、是否允许原地修改，以及元素比较是否只是整数自然序；若元素是对象或需要自定义 comparator，这些都属于接口契约扩展，算法的不变量仍是“最右可提升位置 + 最小提升值 + 最小后缀”。

## 常见追问

- 问：为什么不能直接排序后找下一种？答：那通常至少要 `O(n log n)`，而当前后缀的单调结构足以在线性时间直接构造下一排列。
- 问：为什么 pivot 条件是 `<` 而不是 `<=`？答：相等值交换不会让字典序变大；必须找到一个能被右侧更大元素严格提升的位置。
- 问：重复元素会漏掉排列吗？答：不会。successor 只要求严格大于 pivot，并选取后缀中的最小更大值；相等元素保持在同一多重集合中，反转后缀得到对应的最小排列。
- 问：最大排列怎么办？答：本答案侧契约定义为回绕到最小升序排列；如果题目要求返回“无下一个”，需要把这一点改成显式返回状态。
- 问：为什么后缀不是 sort？答：找 pivot 时已经证明原后缀非递增；交换后反转即可得到最小后缀，不需要一般排序。
- 问：空数组或单元素数组呢？答：本 API 把它们定义为 no-op；它们只有一个可观察排列状态。

## 易错点

- pivot 搜索写成 `nums[i] > nums[i+1]`，导致重复值边界错误。
- successor 搜索允许 `nums[j] == nums[i]`，交换后字典序并没有变大。
- 交换 pivot 后忘记把后缀变成最小顺序，得到的只是某个更大排列，不一定是“下一个”。
- 最大排列时只返回不处理，和“循环到最小排列”的答案侧契约不一致。
- 用排序处理后缀，虽然可能正确，却把可利用的单调结构和 `O(n)` 目标浪费掉。
