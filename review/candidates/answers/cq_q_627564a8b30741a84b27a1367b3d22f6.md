# 第 K 个缺失的正整数

## 核心结论

题源只保留“第 K 个缺失的正整数”，并标注了“二分查找”，没有保存完整输入契约。为了给出可执行答案，这里明确采用常见的最小契约：`arr` 是严格递增的正整数数组，`k >= 1`，目标是从正整数序列 `1,2,3,...` 中找第 `k` 个没有出现在 `arr` 里的数。在下标 `i` 之前（含 `arr[i]` 这个位置）已经缺失的正整数个数是 `missing(i) = arr[i] - (i + 1)`；它随 `i` 单调不减，因此可以二分找到第一个 `missing(i) >= k` 的位置 `lo`，答案直接是 `lo + k`。

## 1 分钟版

- 先声明契约：数组严格递增、元素为正数、`k >= 1`；这些约束没有完整保存在题源里，所以不能冒充原题已明确给出。
- 如果没有缺数，理想情况下下标 `i` 应该放 `i + 1`；实际是 `arr[i]`，因此到这里累计缺失数就是 `arr[i] - (i + 1)`。
- 这个缺失计数随着下标增加不会下降，所以二分第一个“累计缺失数至少为 `k`”的位置。
- 二分结束得到 `lo`：前 `lo` 个数组元素中缺失数仍不足 `k`，把这 `lo` 个实际存在的正整数跳过去后，第 `k` 个缺失值就是 `lo + k`。
- 空数组时 `lo = 0`，自然返回 `k`；若 `k` 大于数组范围内的缺失数，`lo = arr.length`，同样返回 `arr.length + k`。

## 3 分钟版

```java
final class KthMissingPositive {
    static long kthMissing(int[] arr, long k) {
        if (arr == null) {
            throw new IllegalArgumentException("arr must not be null");
        }
        if (k <= 0) {
            throw new IllegalArgumentException("k must be positive");
        }

        int left = 0;
        int right = arr.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            long missing = (long) arr[mid] - (mid + 1L);
            if (missing >= k) {
                right = mid;
            } else {
                left = mid + 1;
            }
        }
        return left + k;
    }
}
```

二分区间用半开区间 `[left, right)`。不变量是：`left` 左侧的位置都满足 `missing(i) < k`，`right` 及其右侧如果在数组范围内则是仍待搜索的“可能达到 `k`”区域。循环结束时 `left == right == lo`，它就是第一个 `missing(i) >= k` 的位置；如果整个数组都达不到，`lo == arr.length`。

为什么答案是 `lo + k`？在答案值 `x` 之前共有 `x` 个正整数候选，其中恰好有 `lo` 个来自数组并且不缺失，所以缺失数是 `x - lo`。令它等于 `k`，得到 `x = lo + k`。

## 关键细节

- **单调性来源**：严格递增正整数数组满足 `arr[i+1] >= arr[i] + 1`，因此 `arr[i] - (i+1)` 不会下降，这是二分成立的前提。
- **为什么不是直接二分答案值**：也可以在值域上二分，但按数组下标搜索 `missing(i)` 更直接，搜索空间只有 `n` 个位置。
- **空数组**：当前候选把空数组定义为合法输入，此时所有正整数都缺失，所以第 `k` 个缺失值就是 `k`。这是候选接口选择，不是题源保存的事实。
- **尾部答案**：如果数组内部累计缺失数小于 `k`，二分会落到 `arr.length`，公式 `arr.length + k` 仍成立。例如 `[1,2,3,4]`、`k=2` 得到 `6`。
- **数值类型**：`k` 和返回值用 `long`，避免“数组长度 + k”在更宽的调用契约下被 `int` 限制；数组元素仍按 `int` 示例处理。
- **输入校验边界**：为了保持核心算法 O(log n)，示例方法不额外 O(n) 扫描验证“严格递增且为正”。这被当作调用方前置契约；若是不可信外部输入，应在接口边界先校验，整体复杂度会变成 O(n)。

## 原理机制

把完整正整数序列想成基准序列：第 `i` 个数组位置如果一个数都没缺，应该看到 `i+1`。实际看到 `arr[i]`，多出来的偏移量正好代表此前有多少个正整数没有出现在数组里。因此 `missing(i)=arr[i]-(i+1)` 把“缺失第几个”的问题转换成一个单调计数函数上的 lower bound：寻找第一个计数达到 `k` 的位置。

lower bound 找到的 `lo` 还不是答案值，而是答案之前实际存在于数组里的元素数量。最终值 = “缺失的 `k` 个数” + “在它们之前穿插的 `lo` 个存在数”，所以得到 `lo+k`。这也解释了为什么同一公式同时覆盖答案落在数组中间和数组尾部之后两种情况。

## 项目经验版

题源没有真实项目、线上数据规模或性能指标，不能虚构。实际工程里如果输入来源不可信，我会把“严格递增、正数、k>0”的验证放在 API 边界，并明确区分验证成本 O(n) 与核心查询 O(log n)。如果同一个固定数组要处理大量不同 `k` 查询，可以复用数组本身和 `missing(i)` 的单调性质，不必为每次查询重新构造额外结构。

## 常见追问

- 问：为什么 `missing(i) = arr[i] - (i + 1)`？答：如果前面完全不缺，第 `i` 个位置应是 `i+1`；实际值比它大多少，就说明之前跳过了多少个正整数。
- 问：为什么能二分？答：在严格递增正整数契约下，相邻数组值至少增加 1，所以 `arr[i]-(i+1)` 单调不减。
- 问：为什么最后是 `lo + k`，不是 `arr[lo]`？答：`lo` 表示答案前有多少个“不缺失”的数组元素；答案值由“k 个缺失数 + lo 个存在数”共同占据前缀位置，所以是 `k+lo`。
- 问：如果第 k 个缺失数在最后一个数组元素后面呢？答：二分返回 `lo=n`，公式直接变成 `n+k`；例如 `[1,2,3,4], k=2` 得到 `6`。
- 问：数组不是严格递增怎么办？答：当前二分不再有单调性保证；需要先明确是否允许重复、乱序、非正数，再决定排序去重或使用其他方法，不能沿用本契约的 O(log n) 结论。
- 问：能不能 O(n)？答：可以线性扫描累计缺口，代码更直观；当只查询一次且数据很小时也完全合理。题源标注了二分查找，所以这里重点展示单调计数 + lower bound 的做法。

## 易错点

- 没声明“严格递增正整数”前提，却直接使用 `arr[i]-(i+1)` 的单调性。
- 把 `arr[i]-i` 写成缺失数，产生一个 off-by-one。
- 二分寻找最后一个 `< k` 时边界处理混乱；使用“第一个 `>= k`”的 lower bound 更容易保持不变量。
- 当答案在数组尾部之后时仍尝试访问 `arr[lo]`，导致越界。
- 为了防御性校验先完整扫描数组，却仍声称整个方法只有 O(log n)。
