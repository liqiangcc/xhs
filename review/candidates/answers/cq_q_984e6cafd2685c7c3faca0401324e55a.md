# 打家劫舍

## 核心结论

来源只保留“算法：打家劫舍”，没有给出输入类型、房屋是否成环、金额是否非负、空输入语义或返回类型。这里采用一个明确的线性版本契约：房屋按一条直线排列，不能选择相邻两间；输入是 `int[]`，允许负数并允许一间都不选；`null` 或空数组返回 `0`；返回 `long`，避免普通 `int` 累加溢出。这个契约是为了让实现可执行而补充的，不是来源原文已经规定的条件。

在线性契约下，用动态规划即可：扫描到第 `i` 间房时，最优解只有两个互斥选择——不选当前房，沿用前一位置的最优值；或选当前房，只能接上 `i-2` 位置之前的最优值。因此状态转移是 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`。转移只依赖前两个状态，所以可以压缩到两个变量，时间 `O(n)`、额外空间 `O(1)`。

## 1 分钟版

- 先确认这里讨论的是**线性**打家劫舍；若首尾相邻成环，状态要改，不能直接套同一答案。
- 维护 `prev1` = 扫描到上一间房时的最优值，`prev2` = 扫描到上上间房时的最优值。
- 当前房 `x` 有两种选择：跳过，得到 `prev1`；选择，得到 `prev2 + x`。
- 所以 `cur = max(prev1, prev2 + x)`，再滚动状态。
- 允许全部跳过，因此初始 `prev1 = prev2 = 0`；负金额不会把答案拉成负数。
- 每间房只处理一次，时间 `O(n)`；只保存两个状态，额外空间 `O(1)`。

## 3 分钟版

```java
static long rob(int[] nums) {
    if (nums == null || nums.length == 0) return 0L;

    long prev2 = 0L;
    long prev1 = 0L;
    for (int money : nums) {
        long take = prev2 + (long) money;
        long skip = prev1;
        long cur = Math.max(skip, take);
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

状态含义要保持稳定：处理当前房之前，`prev1` 表示“前面已经处理完的房屋中的最大合法收益”，`prev2` 表示“再少一间前缀中的最大合法收益”。如果选择当前房，就必须跳过上一间，因此只能接 `prev2`；如果不选择当前房，就直接继承 `prev1`。更新完成后，这两个变量继续对应新的两个前缀。

例如 `[2, 7, 9, 3, 1]`：最优方案可以选择 `2 + 9 + 1 = 12`。算法并不是枚举某个固定组合，而是在每个位置保留“到目前为止的最优前缀结果”，因此后续只需要两个数字，不需要保存所有选择历史。

## 关键细节

- **来源边界**：只有“打家劫舍”这个题名被保留下来；线性、允许跳过全部房屋、`int[] -> long`、负数以及空输入行为都是本候选显式补充的执行契约。
- **为什么状态足够**：当前选择只会影响“上一间能不能选”，而 `dp[i-1]` 与 `dp[i-2]` 已经分别概括了两种前缀边界下的最优结果，不需要记住具体选过哪些房。
- **滚动更新顺序**：必须先算 `cur`，再执行 `prev2 = prev1; prev1 = cur;`，否则会覆盖当前转移还需要的旧状态。
- **允许负数**：因为允许不选任何房，初值设为 0；例如 `[-5, -1]` 返回 0。若题目要求“至少选一间”，初始化和边界就需要重新定义。
- **数值范围**：输入单项是 `int`，返回值用 `long` 承接多项求和；如果题目金额本身可以超过 `int`，应继续扩大输入契约。
- **复杂度**：每个元素只做常数次运算，时间 `O(n)`；额外只保存三个 `long` 局部变量，空间 `O(1)`。
- **环形变体**：如果首尾也不能同时选，通常拆成“不选最后一间”和“不选第一间”两个线性区间分别求解再取最大值；这属于另一个契约。
- **树形变体**：若房屋按树组织，状态需要变为“当前节点选/不选”两种树 DP，不能沿用线性滚动状态。

## 原理机制

这个问题满足最优子结构：对前 `i` 间房的最优方案，最后一间只有“选”或“不选”两种情况。若不选第 `i` 间，答案就是前 `i-1` 间的最优值；若选第 `i` 间，第 `i-1` 间必须不选，所以能与当前金额组合的最好前缀只能来自前 `i-2` 间。两种情况覆盖全部合法方案且互斥，因此取最大值就得到完整最优解。

把二维“决策历史”压缩成两个前缀最优值的前提是：后续决策只依赖这两个聚合结果，而不依赖更早的具体选择路径。这里正好满足，因此从数组 DP 压到两个变量不会丢失信息。

## 常见追问

- 问：为什么只保存两个状态就够？答：当前转移只读取 `dp[i-1]` 和 `dp[i-2]`，更早的信息已经被这两个最优前缀值汇总，所以可以滚动压缩。
- 问：为什么不能贪心地总选当前更大的房？答：局部较大的金额可能阻塞两个后续选择；例如 `[2, 7, 9, 3, 1]` 的最优解需要综合跨位置组合，简单相邻贪心不能保证全局最优。
- 问：如果所有金额都是负数呢？答：本候选允许一间都不选，因此返回 0；若题目要求至少选一间，就必须改变契约与初始化。
- 问：如果房屋首尾相邻呢？答：这是环形版本，可分别计算区间 `[0,n-2]` 和 `[1,n-1]` 的线性答案再取最大值，单元素需要单独处理。
- 问：为什么返回 `long`？答：来源没有数值范围；使用 `long` 可以避免多个 `int` 金额累加时发生普通 32 位整数溢出，但如果输入本身允许更大整数仍需重新定义类型。
- 问：能不能恢复具体抢了哪些房？答：可以，但只保留两个滚动值不足以回溯路径；需要保存 DP 数组或额外的选择信息，再从末尾反推。

## 易错点

- 没确认线性还是环形版本，就把同一段转移套到所有“打家劫舍”题目。
- 写成 `prev2 = prev1` 后才计算 `take`，把旧的 `prev2` 提前覆盖掉。
- 题目允许负数时把第一间金额直接作为初始答案，导致结果被迫为负。
- 用 `int` 保存总收益，却没有核对金额范围和累加溢出。
- 只背 `max(dp[i-1], dp[i-2] + nums[i])`，却说不清两项为什么覆盖全部合法方案。
- 做空间压缩后又声称可以直接恢复具体选择路径，忽略了历史信息已经被丢弃。
