# 打印 101~200 之间所有的素数并统计个数

## 核心结论

这道题的核心只有两步：对区间内每个整数判断“是否为素数”，是素数就输出并把计数加一。素数是大于 1、且除 1 和自身外没有其它正因子的整数。判断一个正整数 `n` 是否为素数时，不需要试除到 `n-1`；如果 `n` 是合数，必然存在一个因子不超过 `sqrt(n)`，所以试除到平方根即可。

原题只保存了固定范围“101~200”，没有保存语言/API、边界是否按开闭区间描述等额外约束。这里明确采用答案侧契约：扫描闭区间 `[101, 200]`。在这个解释下素数共有 21 个，101 是第一个，199 是最后一个。

## 1 分钟版

- 从 101 循环到 200。
- 对每个 `n`，先排除 `<2`；2 单独是素数，偶数大于 2 都不是素数。
- 对剩余奇数，只试除奇数因子 `3,5,7,...`，直到 `d*d > n`；代码里可以用 `d <= n/d` 避免 `d*d` 的整数溢出。
- 若没有任何因子整除 `n`，它就是素数：打印并 `count++`。
- 最后打印总数。闭区间 `[101,200]` 的结果共有 21 个素数。

## 3 分钟版

关键依据是“因子成对出现”。若 `n = a*b` 且 `a>sqrt(n)`、`b>sqrt(n)`，那么 `a*b>n`，矛盾。因此一个合数一定能在 `2..sqrt(n)` 内找到至少一个因子。

```java
import java.util.ArrayList;
import java.util.List;

public final class PrimeRange {
    private PrimeRange() {}

    public static boolean isPrime(int n) {
        if (n < 2) return false;
        if (n == 2) return true;
        if ((n & 1) == 0) return false;
        for (int d = 3; d <= n / d; d += 2) {
            if (n % d == 0) return false;
        }
        return true;
    }

    public static List<Integer> primesInclusive(int low, int high) {
        List<Integer> result = new ArrayList<>();
        for (int n = low; n <= high; n++) {
            if (isPrime(n)) result.add(n);
        }
        return result;
    }

    public static void main(String[] args) {
        List<Integer> primes = primesInclusive(101, 200);
        for (int p : primes) System.out.println(p);
        System.out.println("count=" + primes.size());
    }
}
```

这段实现输出：`101, 103, 107, 109, 113, 127, 131, 137, 139, 149, 151, 157, 163, 167, 173, 179, 181, 191, 193, 197, 199`，总数是 `21`。

## 关键细节

- **1 不是素数**：素数定义要求整数大于 1。
- **平方根边界要包含**：例如 `121 = 11*11`、`169 = 13*13`；如果循环条件错误写成严格小于平方根，就会把完全平方数误判为素数。
- **只枚举奇数因子**：2 已单独处理后，偶数因子无需再试。
- **避免 `d*d` 溢出**：固定范围 200 不会溢出，但可复用实现用 `d <= n/d` 更稳健；这是实现选择，不是原题附加约束。
- **固定范围复杂度**：题目范围只有 100 个整数，实际成本很小。若把区间推广为 `[L,R]`，试除法时间上界约为 `O((R-L+1)*sqrt(R))`，额外空间取决于是否保存结果；边判断边打印可以做到 `O(1)` 辅助空间。
- **输出与计数必须来自同一个判断**：不要先写一套打印逻辑、再用另一套统计逻辑，否则容易产生不一致。

## 原理机制

对每个候选数 `n`，算法维持的不变量是：在已经检查过的因子范围内，没有任何因子能整除 `n`。当试除上界超过 `sqrt(n)` 后，如果仍未找到因子，就可以推出不存在更大的“新”因子，因为任何大因子都会与一个不超过平方根的小因子配对；因此 `n` 是素数。

先排除偶数只是常数优化，不改变正确性。对固定 `[101,200]` 范围，也可以用埃氏筛一次性筛出所有素数；但范围很小且题目只要求完成打印和计数，逐个试除更直接，代码和证明都更短。

## 常见追问

- 问：为什么只检查到平方根？答：合数的因子成对出现，至少一个因子不超过平方根；超过平方根仍没找到因子，就不可能再出现一个全新的因子对。
- 问：为什么 121、169 要特别关注？答：它们分别是 `11^2`、`13^2`，最容易暴露“平方根边界没有包含”的 off-by-one 错误。
- 问：为什么先判断偶数？答：除 2 外所有偶数都不是素数，先排除后只枚举奇数因子，可以减少大约一半试除次数。
- 问：`d*d <= n` 不行吗？答：本题最大只有 200，当然安全；推广到任意 `int` 时 `d*d` 可能溢出，所以示例用 `d <= n/d` 表达同一上界。
- 问：能不能用埃氏筛？答：可以。若要一次得到较大连续范围内的全部素数，筛法更合适；但本题只有 101~200，逐个平方根试除已经足够简单清晰。
- 问：101~200 一共有多少个？答：按这里声明的闭区间解释，一共 21 个；200 是合数，101 是素数，因此是否包含 101 会影响计数，面试时最好把区间解释说清楚。

## 易错点

- 把 1 当成素数。
- 试除条件漏掉 `sqrt(n)` 本身，把 121、169 之类完全平方数误判为素数。
- 输出了素数却忘记同步计数，或者计数逻辑与打印逻辑分离。
- 把“只试除到平方根”“只试奇数”说成原题给定条件；它们是答案选择的实现策略。
- 为了展示复杂算法直接上筛法，却没有先给出最直接、可证明的固定区间解法。
