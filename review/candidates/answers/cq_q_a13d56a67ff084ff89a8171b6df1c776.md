# LeetCode 1769：移动所有球到每个盒子的最少操作数

## 核心结论

LeetCode 1769 给定长度为 `n` 的二进制字符串 `boxes`：`boxes[i]='1'` 表示第 `i` 个盒子有一个球；一次操作只能把一个球移动到相邻盒子。对每个目标盒子 `i`，答案就是所有初始球位置 `j` 到 `i` 的距离和 `Σ|i-j|`。直接枚举是 O(n²)；利用相邻目标位置之间的增量关系，左右各扫一遍即可在 O(n) 时间、除答案外 O(1) 空间内求完全部位置。

## 1 分钟版

- 对固定 `i`，每个球从 `j` 移到 `i` 至少且恰好需要 `|i-j|` 次相邻移动，所以总成本是距离和。
- 左扫时维护 `balls` = 当前点左侧（含已处理点）的球数，`moves` = 这些球移动到当前点的总代价；把 `moves` 加到 `answer[i]`。
- 从 `i` 走到 `i+1`，左侧每个球都多走一步，因此下一位置成本增加 `balls`：`moves += balls`。
- 右扫完全对称，把右侧球贡献再加到 `answer[i]`。
- 每个位置只处理常数次，总时间 O(n)。官方约束 `n<=2000`，最大距离和远小于 Java `int` 上限。

## 3 分钟版

```java
public int[] minOperations(String boxes) {
    int n = boxes.length();
    int[] answer = new int[n];

    int balls = 0;
    int moves = 0;
    for (int i = 0; i < n; i++) {
        answer[i] += moves;
        if (boxes.charAt(i) == '1') {
            balls++;
        }
        moves += balls;
    }

    balls = 0;
    moves = 0;
    for (int i = n - 1; i >= 0; i--) {
        answer[i] += moves;
        if (boxes.charAt(i) == '1') {
            balls++;
        }
        moves += balls;
    }
    return answer;
}
```

左扫进入位置 `i` 时，`moves` 只表示所有严格位于 `i` 左侧的球移动到 `i` 的成本；先写入 `answer[i]`，再把当前位置的球加入 `balls`，最后执行 `moves += balls`，得到这些球移动到 `i+1` 的成本。右扫建立镜像不变量，因此两次贡献相加就是所有球到 `i` 的距离和。

## 关键细节

- **为什么可以逐球相加**：题目要求每个 `answer[i]` 都从同一初始状态独立计算；球之间不会改变彼此的最短距离，因此总最少操作数就是各球最短移动次数之和。
- **更新顺序**：必须先 `answer[i] += moves`，再统计当前位置球并为下一格更新 `moves`。否则会把当前位置的球错误计入“移动到自己”的成本。
- **空盒/单球**：没有球时结果全 0；只有一个球时答案就是各位置到该球的距离。
- **多球可同盒**：题目允许移动后一个盒子出现多个球，所以不需要处理容量冲突或匹配问题。
- **整数范围**：官方约束 `n<=2000`。极端情况下至多 `n` 个球，每个距离小于 `n`，总成本小于 `n²<=4,000,000`，`int` 足够。
- **空间**：返回数组本身是题目输出；算法额外只维护 `balls/moves` 两个整数，因此额外空间 O(1)。

## 原理机制

关键是把“每个目标点重新算一遍距离和”改写成“相邻目标点之间如何增量更新”。目标从 `i` 右移到 `i+1` 时，位于左侧的每个球距离都增加 1，因此左侧总贡献增加“左侧球数量”；相反，若单独从右往左观察，目标左移一格时右侧每个球距离增加 1。两次线性扫描分别累计左右贡献，就不需要为每个目标重新遍历所有球。

也可以把它理解成前缀统计：左贡献由“左侧球数 + 上一个位置左贡献”递推，右贡献对称。这里把两个方向直接累加进同一个 `answer`，省掉两个额外数组。

## 项目经验版

来源是一道明确的算法题，没有真实项目背景，不能虚构“线上用过”。工程上值得迁移的是增量思想：当一批目标位置的代价彼此只差一个可维护的局部增量时，优先寻找前缀/后缀累计，而不是重复做全量扫描。

## 常见追问

- 问：为什么不是 BFS？答：一维相邻移动的最短距离已经是 `|i-j|`，没有障碍和不同边权；BFS 只会重复求已知距离，无法利用所有目标点之间的增量关系。
- 问：为什么两次扫描就能覆盖全部球？答：左扫只累计目标左侧球贡献，右扫只累计目标右侧球贡献；当前位置的球到自己距离为 0，两侧互不重叠且合起来覆盖所有球。
- 问：`moves += balls` 为什么放在循环最后？答：当前 `moves` 是“到当前位置”的成本；只有准备移动目标到下一位置时，每个已统计球才额外增加一步。
- 问：能不能只扫一遍？答：单方向扫描只能直接得到一侧贡献；若预先计算全部球数量和初始总距离，可以用一个全局递推做单次主扫描，但本质上仍依赖同一个距离增量关系。双扫描更直观且仍是 O(n)。
- 问：如果一次操作允许跨多个盒子怎么办？答：成本模型就不再是单位相邻距离 `|i-j|`；必须根据新的边权/跳跃规则重新定义最短成本，当前递推不再自动成立。

## 易错点

- 为每个目标盒子再次遍历所有球，写成 O(n²) 后就停止优化。
- 在把 `moves` 写入当前答案前就把当前位置球的下一步成本加进去，导致 off-by-one。
- 左右两次扫描都把当前位置球计成 1 步，破坏“移动到自己成本为 0”。
- 忘记题目每个 `answer[i]` 都基于初始状态独立计算，错误地把前一个目标的实际移动结果带到下一个目标。
- 把返回数组算作“额外 O(n) 空间”而忽略它本身是必需输出；应区分输出空间和辅助空间。
