# 手撕螺旋矩阵（Spiral Matrix）

## 核心结论

原始面试笔记只保留“手撕螺旋矩阵（Spiral Matrix）”，没有保存具体函数签名、语言、输入是否一定为矩形，也没有明确是“按螺旋顺序遍历矩阵”还是“生成螺旋矩阵”。本候选把常见的**顺时针螺旋遍历**作为明确的参考契约：输入一个矩形整数矩阵，从左上角开始按右→下→左→上的顺序逐层收缩边界，返回所有元素且每个元素恰好一次。若面试官实际要求的是生成矩阵，应先切换题目契约而不是强行套用本实现。

## 1 分钟版

- 用 `top / bottom / left / right` 表示当前还没访问的矩形边界。
- 每轮依次遍历上边、右边、下边、左边，每走完一条边就把对应边界向内收缩。
- 遍历下边之前检查 `top <= bottom`，遍历左边之前检查 `left <= right`；否则单行或单列的最后一层会被重复访问。
- 本参考实现约定：空矩阵或首行为空返回空结果；输入必须是矩形矩阵，ragged matrix 不在本契约内。
- 时间复杂度 `O(m*n)`，每个元素访问一次；除返回结果外额外空间 `O(1)`。

## 3 分钟版

这里采用 Go 作为参考语言，但语言不是来源要求。函数契约是：输入矩形 `[][]int`，按顺时针螺旋顺序返回扁平结果；空输入返回空切片；非矩形输入显式拒绝。

```go
func spiralOrder(matrix [][]int) []int {
    if len(matrix) == 0 || len(matrix[0]) == 0 {
        return []int{}
    }

    cols := len(matrix[0])
    for _, row := range matrix {
        if len(row) != cols {
            panic("ragged matrix unsupported")
        }
    }

    top, bottom := 0, len(matrix)-1
    left, right := 0, cols-1
    ans := make([]int, 0, len(matrix)*cols)

    for top <= bottom && left <= right {
        for c := left; c <= right; c++ {
            ans = append(ans, matrix[top][c])
        }
        top++

        for r := top; r <= bottom; r++ {
            ans = append(ans, matrix[r][right])
        }
        right--

        if top <= bottom {
            for c := right; c >= left; c-- {
                ans = append(ans, matrix[bottom][c])
            }
            bottom--
        }

        if left <= right {
            for r := bottom; r >= top; r-- {
                ans = append(ans, matrix[r][left])
            }
            left++
        }
    }

    return ans
}
```

循环不变量是：进入每一轮时，`[top..bottom] × [left..right]` 恰好表示尚未输出的矩形区域；区域外的元素都已按正确螺旋顺序输出且不会再访问。走完上边和右边后，剩余区域可能已经没有“下边”或“左边”，所以必须在后两段遍历前重新判断边界。

例如：

```text
1 2 3
4 5 6
7 8 9
```

输出为：

```text
1 2 3 6 9 8 7 4 5
```

对于 `1×N`，第一段走完上边后 `top > bottom`，不会再走下边；对于 `N×1`，走完右边后 `left > right`，不会再走左边。这两个边界正是很多重复访问 bug 的来源。

## 关键细节

- **题意歧义**：来源只有“Spiral Matrix”标题。顺时针遍历是本候选的参考契约，不冒充为原题保存下来的完整 I/O。
- **边界收缩顺序**：上边走完 `top++`，右边走完 `right--`，然后重新判断是否还有下边和左边。
- **单行/单列**：如果无条件执行四条边，会重复访问最后一层；两个条件判断用于保护退化矩形。
- **矩形输入**：Go 的 `[][]int` 可以是 ragged。本实现显式检查列数一致，避免越界或静默产生不完整结果。
- **是否修改输入**：本实现只读矩阵，不需要 `visited` 标记，因此不会修改原数组。
- **复杂度**：边界只向内移动，每个位置进入结果一次，所以时间 `O(m*n)`；四个边界变量是常数额外空间，返回数组本身是 `O(m*n)`。

## 原理机制

螺旋遍历可以看成不断剥离矩形外圈。当前未访问区域由四条边唯一描述，因此不需要额外 `visited[m][n]`。每剥掉一条边，相应边界朝内部移动；当 `top > bottom` 或 `left > right` 时未访问区域为空，算法结束。

正确性的关键不是“四个 for 循环”本身，而是防止退化后的最后一层被第二次访问。假设只剩一行：上边遍历已经覆盖这一行，`top++` 后 `top > bottom`，所以下边必须跳过。只剩一列同理，右边遍历后 `right--` 可能让 `left > right`，左边必须跳过。

## 项目经验版

来源没有真实项目背景，不虚构线上使用经历。面试现场我会先确认对方要的是“遍历”还是“生成”，再确认输入是否保证矩形以及空输入期望。写完后优先手测 `0×0`、`1×1`、`1×N`、`N×1`、`2×3`、`3×2` 和奇数中心点，这些用例比只测 `3×3` 更容易暴露边界重复问题。

## 常见追问

- 问：为什么不用 `visited` 数组？答：矩形螺旋遍历的未访问区域始终还是一个矩形，用四个边界就能完整描述，额外 `visited` 不是必要条件。
- 问：为什么下边和左边要再次判断？答：前两条边执行后矩形可能退化为空；不判断会让单行或单列最后一层被重复加入。
- 问：如果要逆时针呢？答：仍可以维护四个边界，只是每轮的边遍历顺序和方向要调整，循环不变量仍是“边界内是未访问区域”。
- 问：如果题目是 Spiral Matrix II，要求生成 `n×n` 矩阵怎么办？答：那是不同 I/O 契约；可以复用四边界收缩思想，但要把连续数字写入矩阵，而不是读取并返回遍历序列。
- 问：Go 的二维切片一定是矩形吗？答：不一定，每行长度可以不同，所以本候选明确检查矩形；如果题目保证矩形，可以把检查视为接口前置条件。

## 易错点

- 只看到“Spiral Matrix”就把“遍历”和“生成”混为同一道题，未先声明契约。
- 四条边无条件都走一次，导致单行/单列中心层重复。
- 边界更新时机错误，例如先 `right--` 再仍用旧逻辑访问右列。
- 用 `m*n` 之外的固定计数控制循环，却没有证明边界不会越界。
- 默认 Go `[][]int` 天然矩形，忽略 ragged 输入可能越界。
