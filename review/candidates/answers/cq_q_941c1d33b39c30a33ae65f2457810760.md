# 算法：最长回文子串（空间复杂度优化）

## 核心结论

来源只保留“最长回文子串（空间复杂度优化）”，没有给语言、空输入、并列答案或 Unicode 语义。若目标是把常见 `O(n^2)` DP 的额外空间从 `O(n^2)` 降下来，中心扩展可以直接做到：枚举每个字符中心和每个字符间隙中心，向两侧扩展，只保存当前最优区间，因此时间 `O(n^2)`、额外空间 `O(1)`。下面采用 Java `String` 的 UTF-16 `char` 单元作为比较单位；`null` 拒绝，空串返回空串；多个最长答案并列时返回起点最小的那个。

## 1 分钟版

- 每个回文子串都有一个中心：奇数长度中心是某个字符，偶数长度中心是两个字符之间的缝隙。
- 对每个位置分别做 `expand(i, i)` 和 `expand(i, i + 1)`，只要左右字符相等就继续向外。
- 每次扩展结束得到一个最大区间 `[left+1, right-1]`；长度更长就更新答案，并列时按更小起点更新，明确 tie-break。
- 不需要 DP 表，只维护 `bestStart` 和 `bestLen`，所以除返回字符串之外额外空间是 `O(1)`。
- 最坏情况下（例如全是同一字符）每个中心都能扩展很远，所以时间仍是 `O(n^2)`；空间优化不等于时间也变成线性。

## 3 分钟版

```java
static String longestPalindrome(String s) {
    if (s == null) {
        throw new IllegalArgumentException("s must not be null");
    }
    if (s.length() < 2) {
        return s;
    }

    int bestStart = 0;
    int bestLen = 1;

    for (int center = 0; center < s.length(); center++) {
        int[] odd = expand(s, center, center);
        int oddLen = odd[1] - odd[0] + 1;
        if (oddLen > bestLen || (oddLen == bestLen && odd[0] < bestStart)) {
            bestStart = odd[0];
            bestLen = oddLen;
        }

        int[] even = expand(s, center, center + 1);
        if (even[0] <= even[1]) {
            int evenLen = even[1] - even[0] + 1;
            if (evenLen > bestLen || (evenLen == bestLen && even[0] < bestStart)) {
                bestStart = even[0];
                bestLen = evenLen;
            }
        }
    }

    return s.substring(bestStart, bestStart + bestLen);
}

static int[] expand(String s, int left, int right) {
    while (left >= 0
            && right < s.length()
            && s.charAt(left) == s.charAt(right)) {
        left--;
        right++;
    }
    return new int[]{left + 1, right - 1};
}
```

例如 `babad` 中会找到 `bab` 和 `aba` 两个长度为 3 的答案；本契约显式选择起点更小的 `bab`。`cbbd` 的最长回文来自偶数中心，结果是 `bb`。中心扩展同时覆盖两类中心，才能覆盖所有回文子串。

## 关键细节

- **为什么两个中心都要枚举**：`aba` 的中心落在 `b` 上，而 `abba` 的中心落在两个 `b` 之间；只处理一种会漏掉另一种长度奇偶性。
- **扩展结束后的边界**：循环停止时 `left/right` 已经越过最后一对匹配字符，所以真实回文区间是 `[left + 1, right - 1]`。
- **并列答案必须定义**：很多题只接受任意最长回文，但来源没有说明。为了让验证确定，本实现采用“起点最小”；如果在线判题允许任意一个，tie-break 不影响正确性。
- **空间复杂度口径**：这里只保存常数个整数；`substring` 返回结果本身不计入算法辅助空间。如果 JVM/语言实现复制返回字符串字符，那么那部分属于输出空间 `O(L)`，其中 `L` 是答案长度。
- **最坏时间**：`aaaa...a` 会让很多中心扩展到边界，累计比较次数是平方级，因此中心扩展是 `O(n^2)`，不是 `O(n)`。
- **Unicode 边界**：Java `charAt` 比较 UTF-16 code unit。若题目要求按 Unicode code point 或 grapheme cluster 判断回文，必须先明确文本单位，不能把 `char` 版本冒充成完整 Unicode 语义。
- **更快方案**：若面试官继续要求时间优化，可以讨论 Manacher 的 `O(n)` 时间 / `O(n)` 辅助数组；但“空间复杂度优化”本身并不自动意味着必须上 Manacher。

## 原理机制

任意非空回文串都有唯一的几何中心。奇数长度回文的中心对应一个整数位置，偶数长度回文的中心对应相邻字符之间的半整数位置。中心扩展枚举所有这两类中心，并对每个中心求“以此中心为约束能达到的最大回文半径”。因此任意候选最长回文一定会在其中心被完整扩展出来，不会因为不保存 DP 表而丢失信息。

DP 通常定义 `dp[i][j]` 表示 `s[i..j]` 是否回文，并依赖 `s[i] == s[j] && dp[i+1][j-1]`，直观但需要 `O(n^2)` 状态。中心扩展换了枚举维度：不再记住所有区间的真假，而是对每个中心直接验证向外的对称关系。它牺牲不了最坏 `O(n^2)` 时间，却把额外存储压缩为常数状态，这正是本题“空间复杂度优化”的核心取舍。

## 项目经验版

来源没有真实业务场景，不能虚构线上字符串处理经验。如果真实文本可能包含 emoji、组合字符或跨语言文本，我会先定义“字符”的业务语义，再选择 UTF-16 code unit、Unicode code point 或 grapheme cluster；如果输入长度很大且 `O(n^2)` 不可接受，再根据延迟和内存约束评估 Manacher。算法选择应由真实数据规模和文本语义驱动，而不是只看一道面试题的模板。

## 常见追问

- 问：为什么空间是 `O(1)`？答：搜索过程中只保存中心、左右边界和当前最优区间，不建立随 `n` 增长的 DP 数组；返回结果本身属于输出。
- 问：为什么时间还是 `O(n^2)`？答：有 `O(n)` 个中心，每个中心最坏可能扩展 `O(n)` 距离，例如全相同字符。
- 问：能把 DP 空间压到 `O(n)` 吗？答：可以做滚动/一维 DP，但中心扩展在这个问题上更直接，辅助空间还能到 `O(1)`；两者时间仍可为 `O(n^2)`。
- 问：怎么处理 `babad`？答：会找到 `bab` 和 `aba`；本契约按更小起点返回 `bab`，若题目允许任意最长答案，两者都可以。
- 问：怎么处理偶数长度？答：额外从 `(i, i+1)` 作为中心扩展，例如 `cbbd` 的两个 `b`。
- 问：还能更快吗？答：Manacher 可以在线性时间求最长回文半径，但需要 `O(n)` 辅助数组，代码和证明复杂度也更高。
- 问：emoji 会不会有问题？答：Java `char` 是 UTF-16 code unit；如果题目按 code point 或用户可见字符定义回文，需要改文本表示和比较单位。

## 易错点

- 只做 `(i, i)` 奇数中心，漏掉 `abba` 一类偶数长度回文。
- 扩展循环退出后直接使用 `left/right`，忘了它们已经越过最后匹配边界。
- 声称中心扩展时间 `O(n)`，忽略全相同字符串的平方级扩展。
- 说“空间 `O(1)`”却把返回字符串的输出空间与辅助空间混为一谈。
- 来源未规定并列答案，代码和测试却隐含不同 tie-break 导致结果不稳定。
- 默认 Java `char` 等同于完整 Unicode 字符，在 emoji/组合字符场景产生语义错误。
