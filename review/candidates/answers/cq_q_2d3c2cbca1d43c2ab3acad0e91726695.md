# 算法：判断两棵树是否相等

## 核心结论

仓库原始来源只保留了“给两个树判断是否相等”，没有规定节点值类型、具体语言、空树语义、对象身份语义或函数签名。这里显式采用候选契约：比较两棵**二叉树**的结构和值；节点值为 `int`；两个空树相等；只有一个为空时不相等；不修改输入树。

最直接的递归判断是按对应位置同时向下比较：两个当前节点都为空返回 `true`；只有一个为空返回 `false`；值不同返回 `false`；否则左子树必须相等且右子树也必须相等。这个判断把“树相等”拆成了同一递归不变量：当前位置相等，当且仅当当前位置状态一致、节点值一致、左右对应子树分别相等。

## 1 分钟版

我先把“相等”定义清楚：这里比较的是结构和值，不比较 Java 对象是否是同一个引用。

递归函数 `sameTree(a, b)` 只有三类判断：

1. `a == null && b == null`：这个位置两边都没有节点，返回 `true`。
2. 只有一个为 `null`：结构已经不同，返回 `false`。
3. 两边都有节点：先比较 `value`，再递归比较 `left` 和 `right`。

因此代码就是：当前值相等，并且左边相等，并且右边相等。最坏情况下要看完所有对应节点；若两棵树规模分别为 `m` 和 `n`，时间上界是 `O(m+n)`，递归辅助空间是实际递归深度 `O(h)`，最坏退化树为线性。

## 3 分钟版

原题没有给在线题库签名，也没有说“相等”指引用相等、序列化相等还是结构和值相等，所以候选答案必须把契约写出来。这里选面试中最常见且与题源不冲突的定义：两棵二叉树在每一个对应位置都同时存在或同时为空，并且对应节点值相同。

递归的正确性可以按树结构说明。对任意一对当前位置 `(a, b)`：如果都为空，这个子问题显然相等；如果只有一个为空，结构不同；如果都非空，那么当前层要先满足 `a.value == b.value`，再分别要求左子树对和右子树对满足同样定义。由于每个递归子问题都严格进入更小的子树，最终一定到达空节点终止。

这也解释了为什么不能只比较遍历值序列。不同结构可能产生相同的某种遍历值序列；结构和值相等必须把空位置也纳入判断。也不应该用 `a == b` 作为总体答案，因为两个内容完全相同、但分别构造出来的树对象通常不是同一个引用。

实现会短路：一旦发现空状态不一致、节点值不同或某个子树不等，就不再访问后续分支。最坏情况下两棵树完全相同，需要比较所有节点。若两树节点数为 `m`、`n`，可给出安全上界 `O(m+n)`；对于完全相等的两棵 `n` 节点树就是 `O(n)`。递归栈最多等于实际比较路径的深度，记为 `O(h)`。

## 关键细节

- **题源边界**：来源只支持“给两个树判断是否相等”；`int`、Java API、空树行为和“结构+值”语义都是显式候选选择，不冒充原题隐藏条件。
- **空节点必须先判断**：在读取 `value` 前先处理 `null`，同时完成结构比较。
- **不能只比值集合或遍历结果**：相同值可以出现在不同结构中；树相等要求对应位置一致。
- **不能把引用相等当答案**：`a == b` 只能说明两个引用指向同一对象，不能覆盖两个独立构造但内容相同的树。
- **短路顺序**：先做空状态和值判断，再递归；任一失败立即返回，避免无意义遍历。
- **复杂度**：最坏时间 `O(m+n)`；完全相等时每个对应节点只比较一次。辅助空间是递归深度 `O(h)`；平衡树约 `O(log n)`，退化树最坏 `O(n)`。
- **可验证性**：固定边界覆盖双空、单空、单节点、值不同、结构不同、重复值和倾斜树；再用 5000 组确定性随机树，把递归实现与独立的 BFS 成对比较 oracle 对照，并比较前后序列化结果确认无修改。

## 原理机制

```java
public static boolean sameTree(Node a, Node b) {
    if (a == null || b == null) {
        return a == b;
    }
    if (a.value != b.value) {
        return false;
    }
    return sameTree(a.left, b.left)
        && sameTree(a.right, b.right);
}
```

用于差分验证的 BFS oracle 使用不同控制流：维护两个同步队列；每次同时取出一个对应位置，比较空状态和值，再把左右孩子按同样顺序入队。测试只把它作为 oracle，不把它当作题源规定的实现方式。

固定用例和 5000 组随机树的预检输出为：

```text
PASS fixed=8 randomized=5000 oracle=bfs-paired-tree-equality mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有生产项目上下文，因此不编造项目经历。工程里如果树深度可能非常大，递归版本要考虑调用栈风险，可以改成显式栈或队列；但无论实现形式如何，先固定“相等”的契约比直接写代码更重要。

## 常见追问

- **两个空树算相等吗？** 当前候选契约里算相等，因为每个对应位置都一致；这是显式 API 选择。
- **为什么不能只比较前序遍历结果？** 如果不编码空节点位置，不同结构可能得到相同值序列；结构比较会丢失。
- **为什么不能直接写 `a == b`？** 那是对象身份比较；两个独立对象可以拥有完全相同的结构和值。
- **如果节点值允许重复会怎样？** 算法不受影响，因为比较的是对应位置，而不是按值寻找节点；测试包含重复值。
- **递归会不会栈溢出？** 极度倾斜树的递归深度可到 `O(n)`；若输入可能很深，可用显式栈/队列实现同一成对比较逻辑。

## 易错点

- 先读 `value` 再判断空节点，直接触发空指针异常。
- 只比较根值和节点数，没有比较左右对应结构。
- 用引用相等替代内容相等。
- 只比较一个方向的子树，遗漏右子树或左子树。
- 声称原题指定了 Java、`int`、某个在线题库签名或对象身份语义，而仓库来源并没有这些信息。
