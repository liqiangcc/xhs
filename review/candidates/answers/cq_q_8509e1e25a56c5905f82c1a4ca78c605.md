# 判断一棵树是否为平衡二叉树

## 核心结论

来源只保留“算法：判断一棵树是否为平衡二叉树”，没有进一步定义“平衡”的口径。下面采用面试中最常见的**高度平衡二叉树**契约：对树中每个节点，其左、右子树高度差的绝对值都不超过 1；这里只判断高度平衡，不额外要求 BST 有序性。

最直接的线性做法是后序 DFS：递归函数返回当前子树高度；一旦发现任意子树已经不平衡，就返回一个特殊值 `-1` 向上传播。这样每个节点只计算一次高度，避免“每个节点再单独求左右高度”造成退化树上的 `O(n^2)` 重复遍历。

## 1 分钟版

- 先定义递归返回值：非负数表示“这棵子树平衡，并且高度是多少”；`-1` 表示“这棵子树已经不平衡”。
- 空树高度记为 0，因此空树自然是平衡的。
- 后序先拿到左、右子树高度；如果任一边已经返回 `-1`，当前节点直接返回 `-1`。
- 若 `abs(leftHeight - rightHeight) > 1`，当前节点不平衡，返回 `-1`。
- 否则当前高度是 `max(leftHeight, rightHeight) + 1`。
- 根节点最终返回 `-1` 就是不平衡，否则平衡。
- 每个节点最多处理一次，时间 `O(n)`；递归栈空间是 `O(h)`，`h` 为树高，退化树最坏 `O(n)`。

## 3 分钟版

```java
public final class BalancedBinaryTree {
    static final class TreeNode {
        final int value;
        TreeNode left;
        TreeNode right;

        TreeNode(int value) {
            this.value = value;
        }
    }

    public static boolean isBalanced(TreeNode root) {
        return heightIfBalanced(root) >= 0;
    }

    private static int heightIfBalanced(TreeNode node) {
        if (node == null) {
            return 0;
        }

        int leftHeight = heightIfBalanced(node.left);
        if (leftHeight < 0) {
            return -1;
        }

        int rightHeight = heightIfBalanced(node.right);
        if (rightHeight < 0) {
            return -1;
        }

        if (Math.abs(leftHeight - rightHeight) > 1) {
            return -1;
        }

        return Math.max(leftHeight, rightHeight) + 1;
    }
}
```

例如根节点左子树高度 2、右子树高度 1，则当前节点满足平衡条件并返回高度 3；如果某个更深节点已经发现左右高度差为 2，它会返回 `-1`，祖先节点无需继续重复计算那棵子树的真实高度，可以直接把“不平衡”向上传播。

## 关键细节

- **平衡条件是“每个节点”都满足**：只比较根节点左右高度不够；根的高度差可能小于等于 1，但某个内部子树已经严重倾斜。
- **为什么使用后序**：父节点判断是否平衡，需要先知道左右子树的高度和状态，所以天然是“左子树 → 右子树 → 当前节点”。
- **哨兵值不会和合法高度冲突**：合法高度从 0 开始非负，因此 `-1` 可以安全表示失败状态。
- **可以提前失败**：左子树已经不平衡时，不必继续遍历右子树；对于明显不平衡的树，这能减少实际访问节点数，但最坏复杂度仍是 `O(n)`。
- **不是 BST 判断**：高度平衡只约束树形结构；若面试官问的是“AVL 树是否合法”，还必须同时验证二叉搜索树有序性以及具体 AVL 定义。
- **递归深度边界**：极深退化树可能导致语言调用栈压力。若输入规模可能非常大且树高度不可控，可以用显式栈模拟后序遍历。

## 原理机制

朴素写法常见的问题是：在每个节点调用一次 `height(left)`、`height(right)`，再递归判断左右子树是否平衡。这样同一节点的高度会被祖先反复计算；在链式退化树中，总工作量接近 `n + (n-1) + ... + 1 = O(n^2)`。

后序方案把两个需求合并成一次递归：子问题同时返回“高度”与“是否失败”。非负高度携带正常结果，`-1` 携带失败状态。于是每条父子边只在递归过程中经过常数次，每个节点只做常数次比较和取最大值，总时间就是 `O(n)`。

## 常见追问

- 问：为什么只看根节点高度差不行？答：平衡要求所有节点都满足条件，内部某个节点可能已经不平衡，而它上方的左右总高度仍恰好接近。
- 问：为什么这个写法是 `O(n)`？答：每个节点只在一次后序 DFS 中计算一次高度；没有从多个祖先重复启动高度遍历。
- 问：空树算平衡吗？答：本候选按标准高度平衡定义把空树高度记为 0，因此返回 true；这是实现契约的一部分，来源原文没有单独说明空树。
- 问：`-1` 为什么可以当哨兵？答：合法子树高度是非负整数，所以 `-1` 不会和正常高度混淆。
- 问：如果面试官要求不用递归呢？答：可以用显式栈做后序遍历，并用 Map 或节点状态保存已经计算出的左右高度；核心仍是“子树高度只计算一次，并在父节点组合”。
- 问：这和判断 AVL 树是不是同一题吗？答：不完全是。当前只验证高度平衡；AVL 通常还要求二叉搜索树的有序性质，若题意明确为 AVL 合法性，需要增加 BST 约束验证。
- 问：怎样做独立验证？答：可以写一个较慢但直观的 oracle：对每个节点单独求左右高度并递归检查所有节点，再把大量随机小树的结果与线性哨兵算法比较。

## 易错点

- 只检查根节点左右高度差，漏掉内部不平衡节点。
- 在每个节点重复调用完整 `height`，导致退化树上 `O(n^2)`。
- 递归函数返回高度却没有把“不平衡”状态向上传递，导致祖先继续无意义计算。
- 把“平衡二叉树”自动解释成“合法 AVL/BST”，加入来源没有要求的有序性约束。
- 忘记说明空树、极深递归等边界语义。
