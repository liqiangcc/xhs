# 最长公共前缀（Longest Common Prefix）

## 核心结论

原始面经只保留了“最长公共前缀，暴力做的”，没有保存具体语言、输入规模、`null` 语义或空数组规则。面试现场可以先确认这些边界，再给一个直接的纵向扫描：拿第一个字符串作为长度上界，逐列比较所有字符串；某一列第一次出现越界或字符不同，就返回此前已经确认的前缀。

下面给一个可执行的 Java 参考契约：输入数组与数组元素都非 `null`；空数组返回空字符串；允许空字符串。这个边界是本文实现选择，不是原始面经额外保存下来的要求。

## 1 分钟版

- 公共前缀必须从每个字符串的下标 `0` 开始连续相同，不是公共子串。
- 以第一个字符串为基准，从左到右检查第 `i` 个字符；对其余字符串，只要 `i` 已越界或字符不同，答案就是 `first.substring(0, i)`。
- 如果所有列都通过，答案就是整个第一个字符串。
- 时间复杂度可写成 O(S)，`S` 是实际比较到的字符总量，上界是 O(n·m)，其中 `m` 是最短相关扫描长度；额外空间 O(1)（不计返回字符串）。
- 原始面经写了“暴力做的”，因此没有必要为了这道题强行引入 Trie；除非后续问题变成大量动态字符串上的重复前缀查询。

## 3 分钟版

```java
class Solution {
    public String longestCommonPrefix(String[] strs) {
        if (strs == null) throw new IllegalArgumentException("strs must not be null");
        if (strs.length == 0) return "";
        for (String s : strs) {
            if (s == null) throw new IllegalArgumentException("element must not be null");
        }

        String first = strs[0];
        for (int i = 0; i < first.length(); i++) {
            char expected = first.charAt(i);
            for (int j = 1; j < strs.length; j++) {
                if (i >= strs[j].length() || strs[j].charAt(i) != expected) {
                    return first.substring(0, i);
                }
            }
        }
        return first;
    }
}
```

循环不变量是：进入外层第 `i` 轮时，区间 `[0, i)` 已经被证明是所有字符串的公共前缀。当前列如果任何一个字符串缺少该位置，或者字符不同，就无法把公共前缀再延长；如果所有字符串都通过，则不变量扩展到 `[0, i+1)`。因此第一次失败的位置正好给出最长公共前缀长度。

## 关键细节

- **先处理越界再取字符**：短字符串可能先结束，必须先判断 `i >= strs[j].length()`，否则会数组/字符串越界。
- **第一个字符串可以直接当扫描上界**：如果它比其它字符串长，短字符串会触发越界并提前返回；如果它最短，全部字符通过后它本身就是最长可能前缀。
- **空字符串**：只要数组中有空字符串，公共前缀必然为空；当前实现会自然在第一个需要比较的位置返回 `""`，若首元素本身为空则直接结束外层循环。
- **Unicode 语义**：代码按 Java UTF-16 `char` 单元比较。普通面试字母字符串通常足够；如果题目要求按 Unicode code point 比较，需要改用 code point 迭代。来源没有保存这类要求。
- **复杂度**：最坏情况下所有字符串共享很长前缀，需要逐列检查；算法不会额外复制中间前缀，只在最终返回时构造结果。

## 原理机制

最长公共前缀可以看成一个单调判定：如果长度为 `k` 的前缀不是所有字符串共有的，那么任何更长前缀也不可能共有。纵向扫描从 `k=1` 逐步扩张，一旦第一处失败就可以立刻停止。这里不需要回溯，也不需要额外状态结构。

另一种常见写法是“横向收缩”：先把第一个字符串当候选前缀，再与第二、第三个字符串逐步缩短。两种方法都正确；纵向扫描更容易直接说明“第一次不同的位置就是答案长度”。Trie 更适合大量字符串插入后反复查询前缀，不是这道一次性题目的必要复杂度。

## 常见追问

- 问：为什么这是 O(n·m) 而不是 O(m)？答：每一列最多要检查 `n` 个字符串；若共同前缀长度接近 `m`，比较次数是两者乘积量级。也可以用所有被访问字符数 `S` 表达得更精确。
- 问：如果第一个字符串不是最短的会不会错？答：不会。其它字符串先结束时，越界判断会立即返回，因而扫描不可能超过真正的公共前缀边界。
- 问：为什么不用排序？答：排序后比较字典序首尾字符串也能求公共前缀，但排序引入 O(n log n) 比较成本；一次性求解没有必要。
- 问：什么时候适合 Trie？答：当字符串集合长期维护、需要反复做前缀查询或统计时才可能值得；单次求所有字符串公共前缀时，线性扫描更直接。
- 问：空数组和 `null` 怎么处理？答：原始面经没有保存规则；本文参考实现选择空数组返回空串、`null` 输入显式拒绝，实际面试按题目契约调整。

## 易错点

- 把“公共前缀”写成任意位置的公共子串。
- 先访问 `strs[j].charAt(i)` 再检查短字符串越界。
- 每轮都创建新的前缀字符串，制造没有必要的中间对象。
- 没有区分原始题干和自己补充的 `null`/空数组语义。
- 为一次性简单题过度设计 Trie，却没有先给清楚可验证的基础解法。
