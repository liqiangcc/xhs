# 算法：求递增数组中相加等于 10 的元素对

## 核心结论

仓库原始来源只保留“求递增数组中相加等于10的元素对”，没有规定是否只找一对、是否返回下标、是否允许重复值、整数范围或函数签名。这里显式采用候选契约：输入是按非递减顺序排列的 `int[]`，目标值默认为题源中的 `10`；返回所有**不重复的值对** `(a,b)`，满足 `a + b = 10` 且 `a <= b`。如果面试官只要求任意一对，第一次命中时即可直接返回。

有序性使双指针成为线性解法：左指针指向当前最小候选，右指针指向当前最大候选。两数和小于目标时，只能增大左值；大于目标时，只能减小右值；等于目标时记录该值对并跨过左右重复值。每个指针只单向移动，因此时间复杂度 `O(n)`，除返回结果外辅助空间 `O(1)`。

## 1 分钟版

我会先确认“递增”是否允许重复、要一对还是所有对、返回值还是下标。这里按“有序数组 + 返回所有不重复值对”回答。

设 `left = 0`、`right = n - 1`：

1. 用 `long` 计算 `sorted[left] + sorted[right]`，避免两个 `int` 相加溢出。
2. 和小于 `10`：`left++`。因为右端已经是当前可选最大值，当前左值与任何更小右值相加都不会达到目标。
3. 和大于 `10`：`right--`。因为左端已经是当前可选最小值，当前右值与任何更大左值相加都只会更大。
4. 和等于 `10`：记录这一对，并跳过与当前左右值相同的元素，避免重复输出。

两个指针最多各走一遍数组，所以时间 `O(n)`；若把输出本身记为 `k` 对，总空间是 `O(k)`，算法额外空间是 `O(1)`。

## 3 分钟版

这道题真正利用的是“数组已经有序”。如果不用这个条件，哈希表可以做到平均 `O(n)`，但需要 `O(n)` 额外空间；有序数组用双指针能同时做到线性时间和常数辅助空间。

正确性可以用排除法说明。当前看 `(left,right)`：

- 若 `a[left] + a[right] < target`，`right` 已经是剩余范围的最大值，所以固定这个 `left` 再配任何 `j < right`，和只会更小或相等；当前左值不可能再参与一个目标对，可以安全右移 `left`。
- 若和大于目标，`left` 已经是剩余范围的最小值，所以固定这个 `right` 再配任何 `i > left`，和只会更大或相等；当前右值不可能再参与一个目标对，可以安全左移 `right`。
- 若和等于目标，就找到了一个合法值对。要返回所有不重复值对时，记录后跳过两端重复值，不会漏掉新的不同值对，因为同一个左值或右值只会产生同一个目标补数。

算法不会回退指针，所以总移动次数是 `O(n)`。实现里用 `long sum = (long) a[left] + a[right]`，避免类似 `Integer.MAX_VALUE + Integer.MAX_VALUE` 在 `int` 中溢出后破坏比较。

如果题目明确说“严格递增”，跳重逻辑只是冗余但不影响正确性；如果题目只要一对，则命中后立刻返回即可；如果要求原始下标且数组并非已经有序，就不能先排序后丢失下标信息，需要改用哈希表或保留 `(value,index)`。

## 关键细节

- **题源边界**：来源只支持“递增数组”“元素对”“和为 10”；返回一对还是全部、值还是下标、严格递增还是允许重复、API 和数值范围都没有保存，必须显式说明假设。
- **为什么能移动左指针**：当前和偏小时，当前左值连剩余最大右值都达不到目标，因此它不可能和剩余任何元素组成目标对。
- **为什么能移动右指针**：当前和偏大时，当前右值连剩余最小左值都超过目标，因此它不可能和剩余任何元素组成目标对。
- **重复值**：候选实现返回不重复的值对；命中后同时跳过左右重复值。若业务要求所有下标组合，则不能这样去重。
- **整数溢出**：比较和时提升到 `long`，否则 `int` 溢出可能把“大于目标”错误变成负数。
- **输入前提**：线性双指针依赖数组已按非递减顺序排列；若这个前提不成立，应先排序（`O(n log n)`）或使用哈希表。
- **复杂度**：时间 `O(n)`；除输出外辅助空间 `O(1)`，返回 `k` 个值对时结果存储占 `O(k)`。
- **可验证性**：固定用例覆盖空数组、单元素、无解、一解、多解、重复值、负数和 `int` 极值；再用 5000 组确定性随机有序数组与 `O(n²)` 暴力去重 oracle 比较结果。

## 原理机制

```java
import java.util.ArrayList;
import java.util.List;

public final class SortedPairSum {
    private SortedPairSum() {}

    public static List<int[]> uniqueValuePairs(int[] sorted, int target) {
        List<int[]> result = new ArrayList<>();
        if (sorted == null || sorted.length < 2) {
            return result;
        }

        int left = 0;
        int right = sorted.length - 1;
        while (left < right) {
            int leftValue = sorted[left];
            int rightValue = sorted[right];
            long sum = (long) leftValue + rightValue;

            if (sum < target) {
                left++;
            } else if (sum > target) {
                right--;
            } else {
                result.add(new int[] {leftValue, rightValue});
                while (left < right && sorted[left] == leftValue) {
                    left++;
                }
                while (left < right && sorted[right] == rightValue) {
                    right--;
                }
            }
        }
        return result;
    }
}
```

对题源目标值调用 `uniqueValuePairs(sorted, 10)` 即可。仓库内的确定性测试使用不同控制流的二重循环作为 oracle，不复用双指针逻辑。

固定边界与 5000 组随机数组的预检输出为：

```text
PASS fixed=9 randomized=5000 oracle=quadratic-unique-pairs target=10 mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有生产项目上下文，因此不编造项目经历。工程代码里更重要的是先把输出语义定死：是任意一对、所有值对、所有下标组合，还是只计数。不同语义会直接影响去重方式和结果规模，但不应把这些未保存的条件冒充成原题要求。

## 常见追问

- 问：为什么和小于目标时可以直接移动左指针，不会漏解？答：因为右指针已经指向剩余最大值；当前左值与它相加仍偏小，与任何更小右值相加只会更小，所以当前左值不可能参与目标对。
- 问：如果数组里有多个 `5`，要不要输出很多 `(5,5)`？答：当前候选契约返回不重复值对，所以只输出一次；如果要求所有下标组合，就要保留每个重复位置并改变输出逻辑。
- 问：为什么不用哈希表？答：哈希表对无序数组很好，但这里已经有序；双指针同样是 `O(n)` 时间，同时把额外空间降到 `O(1)`。
- 问：如果要求返回原始下标呢？答：若输入本身就是题目给定的有序数组，可以返回当前指针下标；若为了双指针先对无序输入排序，则必须保留原始下标映射，或改用哈希表。
- 问：两个 `int` 相加为什么要转 `long`？答：否则大整数相加可能溢出并改变符号，导致指针向错误方向移动。

## 易错点

- 忽略“有序”条件，写出不必要的 `O(n)` 哈希额外空间。
- 和偏小时移动右指针，或和偏大时移动左指针，把单调性方向写反。
- 要求不重复值对时，命中后没有跳过重复值。
- 直接用 `int` 求和，在极值输入下溢出。
- 没说明“元素对”究竟返回值还是下标、一个还是全部，却把自己的 API 选择说成题源原话。
