# 算法手撕：每日温度（Daily Temperatures）

## 核心结论

这题用“存下标的单调栈”在线确定每一天第一次遇到的更高温度。仓库来源保留了题名 `Daily Temperatures`，另一条同源近邻只保留“温度（单调栈）”；来源没有保存完整函数签名、数值范围或空输入约束。因此下面把可执行练习合同明确写成假设，而不冒充原题原文：输入温度数组 `temperatures`，返回同长度数组 `answer`；`answer[i]` 表示从第 `i` 天起还要等多少天才会首次遇到严格更高的温度，后面不存在则为 `0`。

## 1 分钟版

- 从左到右扫描，栈里只放“还没有找到下一次更高温度”的下标。
- 保持栈对应的温度从栈底到栈顶单调不增；当前温度 `temperatures[i]` 严格大于栈顶温度时，说明 `i` 就是那个栈顶下标第一次遇到的更暖日期。
- 每弹出一个下标 `j`，写 `answer[j] = i - j`；一直弹到当前温度不再更高，再把 `i` 入栈。
- 相等温度不能弹，因为题意是“更高”而不是“大于等于”。扫描结束仍留在栈里的位置没有未来更高温度，默认答案就是 `0`。
- 每个下标最多入栈一次、出栈一次，所以时间 `O(n)`，额外空间 `O(n)`。

## 3 分钟版

这里采用的可执行合同是：`temperatures` 为一个温度序列，结果 `answer` 与它等长；`answer[i]` 是右侧第一个满足 `temperatures[j] > temperatures[i]` 的位置距离 `j - i`，如果不存在则为 `0`。仓库题面没有保留完整 API 和数据范围，所以这些接口细节是为了复习与测试显式采用的合同。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public final class DailyTemperatures {
    public static int[] daysUntilWarmer(int[] temperatures) {
        int n = temperatures.length;
        int[] answer = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty()
                    && temperatures[i] > temperatures[stack.peek()]) {
                int j = stack.pop();
                answer[j] = i - j;
            }
            stack.push(i);
        }
        return answer;
    }
}
```

栈的不变量是：栈中所有下标都还没有在已扫描区间内找到更高温度，并且按入栈时间看，对应温度保持单调不增。对栈顶 `j` 来说，如果之前某一天已经严格更热，`j` 早就应该被弹出；因此第一次出现 `temperatures[i] > temperatures[j]` 时，当前 `i` 一定就是 `j` 的最近更暖日期。一次当前温度可能连续解决多个更低温度的等待天数。

## 关键细节

- **必须存下标**：答案要的是天数差，只有温度值不够计算 `i - j`，重复温度也需要区分不同日期。
- **比较必须是严格 `>`**：例如 `[70, 70, 71]` 中第 0 天应等待 2 天，第 1 天等待 1 天；如果用 `>=`，第 0 天会错误地把相同温度当成答案。
- **栈为何单调不增**：更低的栈顶会被当前更高温度持续弹出；停止后栈顶温度一定大于等于当前温度，再压入当前下标即可保持不增关系。
- **未弹出的元素**：扫描结束后没有更暖日期，`int[]` 初始值正好是 `0`，无需二次回填。
- **复杂度**：虽然有嵌套 `while`，但一个下标只会被 `push` 一次、`pop` 一次，摊还总操作数是线性的，因此时间 `O(n)`；最坏严格递减时所有下标都留在栈中，空间 `O(n)`。
- **空/单元素边界**：仓库来源没有保存空输入约束；本实现对空数组自然返回空数组，单元素返回 `[0]`。`null` 不在本候选采用的输入合同内。

## 原理机制

暴力做法会对每一天向右扫描直到找到第一天更暖温度，最坏需要 `O(n^2)`。单调栈把“尚未解决的左侧位置”保存起来，并利用当前温度批量关闭它们。

当扫描到 `i` 时，栈顶是最近一个尚未解决的位置。若当前温度不够高，它不能解决栈顶，更不可能越过这个栈顶直接证明某个更高或相同温度的旧位置已经找到答案，于是把 `i` 也作为待解决位置压栈。若当前温度更高，则对栈顶 `j` 来说，区间 `(j, i)` 里的所有位置都已经扫描过但都没有让 `j` 出栈，所以 `i` 就是第一天严格更暖的日期；写入距离后继续检查新的栈顶。这个“第一次满足条件即出栈”的机制同时保证了正确性和线性复杂度。

## 项目经验版

来源没有真实项目背景，不能虚构生产使用经历。项目映射时可以把它看成“为一批尚未满足阈值的事件寻找右侧第一个严格更大值”的 next-greater-element 模式；真正落地前要先确认比较关系是 `>` 还是 `>=`、输出要距离还是目标位置、是否允许流式处理，以及是否需要保留全部历史数据。若需求不同，栈中保存的数据和出栈条件也会改变。

## 常见追问

- 问：为什么栈里保存下标而不是温度？答：结果是等待天数，需要计算 `i - j`；保存下标还能在存在重复温度时准确回填每个位置。
- 问：为什么相等温度不能弹栈？答：当前合同要求“严格更高”。相等温度不能结束等待；如果问题改成“下一次大于等于”，才把比较条件改成 `>=`。
- 问：`while` 在 `for` 里面，为什么不是 `O(n^2)`？答：每个下标最多入栈一次、出栈一次，所有 `while` 迭代加起来最多 `n` 次弹栈，因此总时间 `O(n)`。
- 问：能不能从右往左做？答：可以。右到左时可以维护候选的更暖下标，并弹掉不可能成为答案的较冷或相等候选；但需要重新清楚定义栈不变量。左到右版本更直接地在第一次遇到更高温度时回填等待距离。
- 问：如果题目要求下一次“大于等于”当前温度呢？答：核心框架不变，但出栈比较从 `>` 改成 `>=`；重复值用例必须重新验证，因为它正是两个合同的分界。
- 问：如果要求循环数组，最后一天还能从开头继续找呢？答：那已经是不同合同，通常需要把索引扫描扩展到两轮或等价处理，并限制只给每个原始下标赋值一次；不能把当前非循环答案直接复用成结论。

## 易错点

- 用 `>=` 代替 `>`，把相同温度误认为“更暖”。
- 栈只存温度值，导致无法计算距离并难以处理重复值。
- 看到双层循环就直接判断 `O(n^2)`，忽略每个下标只弹一次的摊还分析。
- 把栈的方向说反：本实现按扫描时间看，栈中温度保持单调不增。
- 给仍在栈里的位置填 `-1` 或其它值，却没有先确认输出合同；本候选明确采用不存在时返回 `0`。
- 把仓库没有保存的函数名、温度范围、`null` 行为或循环语义说成原题已给条件。
