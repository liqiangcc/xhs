# 在有序数组中查找目标值的第一个和最后一个位置——把“命中”改成两个边界搜索

## 核心结论

仓库恢复出的面试题写的是“在排序数组中查找元素的第一个和最后一个位置（Find First and Last Position of Element in Sorted Array）”。这句话明确了**有序数组、目标值、首尾位置**，但本地题干没有展开“目标不存在时返回什么”或复杂度要求。它命名的标准 LeetCode 34 题面进一步规定：数组按非递减顺序排列；目标不存在时返回 `[-1, -1]`；算法必须达到 `O(log n)`。

因此不能“先普通二分找到一个 target，再向左右线性扫描”，因为大量重复值时会退化到 `O(n)`。稳妥做法是把问题拆成两个单调边界：

1. `lowerBound(target)`：第一个 `>= target` 的下标；
2. `lowerBound(target + 1)` 不能安全用于 `Integer.MAX_VALUE`，所以直接做 `upperBound(target)`：第一个 `> target` 的下标。

若 `left == n` 或 `nums[left] != target`，目标不存在，返回 `[-1, -1]`；否则右边界是 `upperBound(target) - 1`。两个二分各 `O(log n)`，额外空间 `O(1)`。

## 1 分钟版

我不会先“找到任意一个 target 再左右扫”，因为重复元素可能让扫描变成线性。

我直接找两个边界：

- 左边界：找第一个 `nums[i] >= target` 的位置；
- 右边界的后一位：找第一个 `nums[i] > target` 的位置。

二分都使用半开区间 `[lo, hi)`。以左边界为例，始终维护：

- `[0, lo)` 全部 `< target`；
- `[hi, n)` 全部 `>= target`。

每次取 `mid`，若 `nums[mid] < target`，说明答案一定在右边，令 `lo = mid + 1`；否则 `hi = mid`。结束时 `lo == hi`，就是第一个 `>= target` 的位置。

如果这个位置越界或值不等于 target，就返回 `[-1,-1]`；否则再找第一个 `> target` 的位置，减一得到最后一次出现的下标。

## 3 分钟版

关键不是“二分查找 target”，而是把**相等区间的两端**转换为两个布尔条件发生变化的位置。

对非递减数组：

- 条件 `nums[i] >= target` 从某个位置开始由 false 变 true，这个转折点就是 first occurrence 的候选；
- 条件 `nums[i] > target` 也只会从 false 变 true，它的转折点减一就是 last occurrence 的候选。

这种写法对“全是 target”“target 只出现一次”“target 小于所有元素”“target 大于所有元素”“空数组”都使用同一个半开区间模板，不需要在命中后维护额外 `answer` 状态。

为什么不写 `lowerBound(target + 1) - 1`？如果元素类型是 Java `int`，当 `target == Integer.MAX_VALUE` 时 `target + 1` 会溢出。直接实现“第一个 `> target`”的 upper bound，可以完整覆盖整数边界。

为什么普通二分命中后继续向左/右也能做？可以，但要明确维护答案并继续收缩搜索区间。用 lower/upper bound 的好处是两个函数都有清晰的单调谓词和半开区间不变量，证明、复用和边界测试都更直接。

复杂度是两次二分，`O(log n)` 时间、`O(1)` 额外空间。

## 关键细节

- 本地恢复题干只明确“排序数组 + 首尾位置”；`[-1,-1]` 与 `O(log n)` 来自它命名的标准 LeetCode 34 题面，不能反过来伪装成本地笔记逐字给出的条件。
- 数组必须是非递减；若输入未排序，二分边界不成立。
- 空数组时两个边界函数都返回 `0`，随后不存在性检查返回 `[-1,-1]`。
- `lowerBound` 找第一个 `>= target`；`upperBound` 找第一个 `> target`，两者只差一个比较符号。
- 使用 `[lo, hi)` 可令初始 `hi = nums.length`，自然表达“边界可能在数组末尾之后”。
- `mid = lo + (hi - lo) / 2` 避免 `lo + hi` 的整数加法溢出习惯性风险。
- 不要用 `target + 1` 构造 upper bound；`Integer.MAX_VALUE` 会溢出。
- 先检查 `left == n || nums[left] != target`，再计算最终区间。
- 线性向两侧扩张虽然样例能过，但不满足标准题要求的 `O(log n)` 最坏复杂度。

## 原理机制

```java
import java.util.Objects;

public final class SearchRange {
    private SearchRange() {}

    public static int[] searchRange(int[] nums, int target) {
        Objects.requireNonNull(nums, "nums");

        int left = lowerBound(nums, target);
        if (left == nums.length || nums[left] != target) {
            return new int[] {-1, -1};
        }

        int rightExclusive = upperBound(nums, target);
        return new int[] {left, rightExclusive - 1};
    }

    static int lowerBound(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] < target) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }

    static int upperBound(int[] nums, int target) {
        int lo = 0;
        int hi = nums.length;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] <= target) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }
}
```

确定性验证应使用一个**结构不同的线性 oracle**：从左到右扫描排序数组，记录第一次和最后一次等于 target 的位置。固定用例覆盖空数组、单元素、目标不存在、单次出现、多次连续出现、全数组相等、目标位于两端，以及 `Integer.MIN_VALUE/MAX_VALUE`。再生成固定随机种子的非递减数组与 target，比较二分实现和线性 oracle；这样随机验证不会复制二分算法本身。

## 项目经验版

这是算法手撕题，原始面试记录没有生产项目背景，不应虚构线上使用经验。工程迁移点是“把值查找改写成单调边界查找”：例如时间序列里寻找第一个不早于某时间戳的记录、版本区间里找第一个满足阈值的位置，都可以复用 lower-bound 思路；前提仍是数据按对应 key 有序。

## 常见追问

- 问：为什么不能找到一个 target 后向左右扫描？答：若数组里有 `O(n)` 个重复 target，扫描最坏是 `O(n)`，违反标准题的 `O(log n)` 要求。
- 问：`lowerBound` 为什么能得到第一次出现？答：它找第一个 `>= target` 的位置；如果该位置值正好等于 target，那么此前所有位置都 `< target`，所以它必然是第一次出现。
- 问：最后一次出现为什么是 `upperBound - 1`？答：upper bound 是第一个 `> target` 的位置，在非递减数组中它前一位就是最后一个 `<= target` 的元素；已确认 target 存在后，该位置就是最后一个 target。
- 问：为什么不用 `lowerBound(target + 1)`？答：对 Java `int`，`Integer.MAX_VALUE + 1` 会溢出；直接比较 `<= target` 实现 upper bound 更安全。
- 问：如果数组未排序呢？答：两个谓词不再单调，边界二分的前提失效；需要先排序（会改变下标语义）或改用线性扫描。
- 问：如何证明不是只过题目样例？答：用线性首尾扫描作为不同结构的 oracle，对固定边界用例和大量固定种子非递减数组做逐例比较。

## 易错点

- 命中后左右线性扫描，复杂度退化为 `O(n)`。
- 左右边界都使用同一个比较条件，导致重复值区间一侧错一位。
- `hi = n - 1` 却套用 `[lo, hi)` 模板，混淆闭区间和半开区间。
- `nums.length == 0` 时直接访问 `nums[left]`。
- 未命中时忘记返回 `[-1,-1]`。
- 用 `target + 1` 找右边界，忽略整数溢出。
- 把“输入有序”当成实现细节而不是二分正确性的前置条件。
