# 一个数字出现奇数次、其他数字出现偶数次：怎样 O(n)/O(1) 找出来？

## 核心结论

把数组所有元素做按位异或即可。因为 `x ^ x = 0`、`x ^ 0 = x`，并且异或满足交换律和结合律，所以所有出现偶数次的数字最终两两抵消为 0；唯一出现奇数次的数字会剩下一份，最终异或结果就是它。

来源已经明确给出关键前提：“有一个数字出现奇数次，其他数字均出现偶数次”。它没有固定语言、整数位宽、空输入行为或是否需要校验前提。下面选择 Java `int[]`；`null`/空数组抛 `IllegalArgumentException`。算法本身不额外用 HashMap 验证频次，因为那会把额外空间从 O(1) 提升到 O(k)。

## 1 分钟版

- 初始化 `ans = 0`，依次做 `ans ^= x`。
- 偶数次出现的值会完全抵消：两次是 0，四次等价于两组 0。
- 奇数次出现的目标值抵消掉偶数份之后还剩一份，所以最后 `ans` 就是目标值。
- 数组顺序不重要，因为异或满足交换律/结合律。
- 时间 O(n)，额外空间 O(1)。
- 如果“不止一个奇数次值”或题目前提不成立，单个总异或值就不再保证等于某个目标元素；要先重新确认问题模型。

## 3 分钟版

```java
public static int findOddFrequency(int[] a) {
    if (a == null || a.length == 0) {
        throw new IllegalArgumentException("array must be non-empty");
    }
    int ans = 0;
    for (int x : a) {
        ans ^= x;
    }
    return ans;
}
```

设目标数字是 `v`，出现 `2k+1` 次；其它每个数字 `u` 都出现 `2m` 次。由于异或可以任意重排和分组，所有 `u` 都能配成 `u ^ u = 0`，目标 `v` 的前 `2k` 份也能配掉，最后只剩 `0 ^ v = v`。这就是算法正确性的完整不变量，不依赖元素在数组中的位置。

## 关键细节

- 负数也可以按 Java `int` 的位表示直接异或；这里没有算术加法溢出问题。
- 重复次数不要求“偶数值恰好出现两次”，只要是任意偶数次都能完全抵消。
- 目标也不要求只出现一次；3、5、7 等任意奇数次都等价于“若干对 + 剩一份”。
- 不需要排序；排序会把 O(n) 变成通常 O(n log n)，也不是必要条件。
- 若题目改成“有两个数字出现奇数次”，需要使用总异或结果中的某个置位把数字分组，再分别异或；那是不同契约。

## 原理机制

异或把“频次奇偶性”编码进了每一位：相同位模式出现偶数次时成对抵消，出现奇数次时保留一份。因此这道题不是在求次数本身，而是在利用群式的抵消性质，把所有不需要的偶数频次信息压缩掉。相比 HashMap 计数，异或只保留一个累积状态，所以额外空间保持 O(1)。

## 项目经验版

来源没有真实项目场景，不能虚构线上使用经验。工程代码如果输入前提并不可信，通常要用计数或额外校验来发现脏数据；但那是数据校验需求，不能和这道“前提已保证、求目标数字”的算法复杂度混为一谈。

## 常见追问

- 问：目标出现 3 次还能用吗？答：能，`v ^ v ^ v = v`，任意奇数次都只剩一份。
- 问：其他数字出现 4 次呢？答：能，四次可以配成两对，每对异或为 0。
- 问：为什么顺序不影响结果？答：异或满足交换律和结合律，可以把相同值重新分组配对。
- 问：为什么不用 HashMap？答：HashMap 当然能计数，但需要 O(k) 额外空间；题目的奇偶频次结构允许用一个 XOR 累积值做到 O(1)。
- 问：如果有两个奇数次数字？答：总异或会得到两者的 XOR，不再直接是答案；要基于其中一个置位分组后各自异或，这是另一道题。

## 易错点

- 把前提误读成“其他数字都只出现两次”；实际上任意偶数次都可以。
- 为了验证前提而偷偷引入 HashMap，却仍宣称额外空间 O(1)。
- 当前提不成立时仍把总异或结果解释成“唯一目标数字”。
- 把异或 `^` 写成逻辑或/幂运算，或混淆 Java 中 `^` 的位运算语义。
