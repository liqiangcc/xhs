# 数组中是否存在严格大于其他所有数两倍的元素

## 核心结论

题源原话是：**“一个数组中是否能找到一个数大于其他数字的2倍，找到返回它的索引，否则返回-1”**。这里的“**大于**”是严格 `>`，不能因为熟悉某道“dominant index”题就擅自改成“至少两倍 `>=`”。题源也没有给非负数组、唯一解、空数组、单元素或溢出规则，因此候选明确采用以下 API：输入任意 Java `int[]`（允许负数和重复值），返回**最小的满足条件的索引**；null/空数组返回 `-1`，单元素返回 `0`。

对某个位置 `i`，条件是：

`nums[i] > 2 * nums[j]` 对所有 `j != i` 都成立。

因为乘 2 在整数上保持大小关系，只需要比较“除 `i` 外的最大值” `maxOther(i)`：

`nums[i] > 2 * maxOther(i)`。

先一趟找出数组中最大的两个**位置**，第二趟按索引从小到大检查。对全局最大位置，`maxOther` 是第二大位置的值；对其他位置，`maxOther` 就是全局最大值。乘 2 时先转成 `long`，避免 `int` 溢出。整体 `O(n)` 时间、`O(1)` 额外空间，不修改输入。

## 1 分钟版

不要先套“找最大和第二大后只检查最大”这个模板，因为题源没说数组非负。负数下，一个不是全局最大值的数也可能满足“严格大于其他数的两倍”。例如 `[-3,-2]`：

- `-3 > 2*(-2) = -4`，成立；
- `-2 > 2*(-3) = -6`，也成立。

候选定义多个解时返回最小索引，所以这个例子返回 0。

通用做法仍然可以 `O(n)`：先记录最大值位置 `first` 和第二大位置 `second`。然后按索引检查每个 `i`：

- `i == first`：其余元素最大值是 `nums[second]`；
- 否则：其余元素最大值是 `nums[first]`。

只要 `(long) nums[i] > 2L * maxOther` 就返回当前 `i`。检查顺序从 0 开始，自然得到最小满足索引。

## 3 分钟版

目标谓词是一个全称条件：

`P(i) := ∀ j != i, nums[i] > 2*nums[j]`。

固定 `i` 后，右侧 `2*nums[j]` 随 `nums[j]` 单调增大，所以最难满足的那个 `j` 一定是“其余元素中的最大值”。因此：

`P(i) <=> nums[i] > 2 * max_{j != i}(nums[j])`。

这一步对正数、0、负数都成立，只依赖乘以正数 2 的单调性。

于是问题变成怎样在 `O(1)` 辅助空间内快速得到每个位置的 `maxOther`。一趟维护值最大的两个**索引**：

- 新值严格大于第一名：原第一名降为第二名，新位置成为第一名；
- 否则若大于第二名：更新第二名。

这里维护“位置”而不是两个不同值很重要：如果最大值重复，例如 `[5,5,1]`，第一、第二名应分别指向两个 5。检查任意一个 5 时，另一个 5 仍在“其他元素”里。

第二趟中，只有 `first` 位置需要使用 `second`；所有其他位置的“其他元素”都包含 `first`，所以 `maxOther = nums[first]`。每个位置常数工作，故总时间 `O(n)`。比较写成 `(long) nums[i] > 2L * maxOther`，使 `Integer.MAX_VALUE/MIN_VALUE` 的两倍仍落在 `long` 范围内。

候选返回“第一个满足位置”只是为源中未定义的多解情况选一个确定合同；如果面试官补充数组全非负且解唯一，第二趟可以简化为只检查最大值位置，但不能把这个未给出的前提倒灌回题源。

## 关键细节

- **严格比较**：源写的是“大于其他数字的2倍”，候选实现 `>`；`[3,6]` 返回 `-1`，因为 `6 > 6` 为假。
- **不是熟题覆盖源题**：常见题可能使用 `>=` 且限制非负数组，本候选不借这些隐藏条件改写原句。
- **负数允许**：这会让多个位置同时满足条件，甚至非最大值也可能满足；因此候选定义返回最小满足索引。
- **重复值**：维护最大的两个位置而不是两个 distinct value；这样“排除自身后的最大值”正确。
- **null/空数组**：候选返回 `-1`；源没有规定，这是 API 选择。
- **单元素**：没有“其他数字”，全称条件在空集合上为真，因此候选返回 0；如果业务希望单元素无解，应在接口合同里改掉。
- **溢出**：不能写 `nums[i] > 2 * maxOther`，因为 `2 * int` 可能先溢出；使用 `2L * maxOther`。
- **输入不变**：算法只读数组，不排序、不修改。
- **复杂度**：两次线性扫描，`O(n)` 时间；只保存两个索引和局部变量，`O(1)` 空间。

## 原理机制

```java
public final class StrictDoubleDominantIndex {
    private StrictDoubleDominantIndex() {}

    public static int findFirst(int[] nums) {
        if (nums == null || nums.length == 0) {
            return -1;
        }
        if (nums.length == 1) {
            return 0;
        }

        int first = -1;
        int second = -1;
        for (int i = 0; i < nums.length; i++) {
            if (first == -1 || nums[i] > nums[first]) {
                second = first;
                first = i;
            } else if (second == -1 || nums[i] > nums[second]) {
                second = i;
            }
        }

        for (int i = 0; i < nums.length; i++) {
            int maxOther = (i == first) ? nums[second] : nums[first];
            if ((long) nums[i] > 2L * maxOther) {
                return i;
            }
        }
        return -1;
    }
}
```

可执行验证包含严格边界（`6` 对 `3` 不算）、普通正数、0、负数、多解、重复最大值、单元素和 `int` 极值；随后用固定随机种子生成 **20,000 个** 长度 0..24 的任意 `int` 数组，与独立的 `O(n^2)` 定义式 oracle 比较。oracle 对每个候选索引逐个检查所有 `j != i`，没有复用“前两大”优化，因此能发现最大/第二大维护或负数语义错误；同时检查输入数组未被修改。实际夹具预期输出：`PASS fixed=16 randomized=20000 oracle=quadratic-definition input=unmodified`。

## 项目经验版

这是算法题，题源没有生产项目背景，因此不虚构工程经历。若这是实际 API，最需要澄清的是数据域是否保证非负、多个满足元素如何选、空/单元素语义以及返回索引还是元素值。只要补充“非负数组”，满足条件的元素若存在就只能是全局最大值，代码可以进一步简化；但当前候选故意覆盖更宽的 `int` 域，因为题源没有给这个限制。

## 常见追问

- 问：为什么只看“其他元素的最大值”就够？答：因为乘以正数 2 保序；若候选比最大那个的两倍还大，自然也比所有更小元素的两倍大。
- 问：为什么不能只检查全局最大值？答：在非负数组可以，但负数下不成立。`[-3,-2]` 中索引 0 的 -3 不是最大值，却满足 `-3 > -4`。
- 问：为什么要维护两个位置？答：检查全局最大位置时必须把它自己排除，第二大位置就是其余元素最大值；重复最大值也必须作为独立位置保留。
- 问：`[3,6]` 呢？答：返回 `-1`，源要求严格“大于”，`6 > 2*3` 即 `6 > 6` 不成立。
- 问：`[-3,-2]` 为什么返回 0？答：两个位置都满足候选定义；API 约定返回最小满足索引，因此先返回 0。
- 问：单元素为什么返回 0？答：需要对“所有其他元素”成立，而其他元素集合为空；候选采用全称量词的真空真语义。这是明确的接口选择，不是源中给出的条件。
- 问：`int` 溢出怎么处理？答：在乘 2 之前转 `long`，例如 `2L * maxOther`。
- 问：如果面试官确认数组全是非负数？答：那只有最大值可能满足，找最大和第二大后只检查最大即可；严格 `>` 仍要保留，除非面试官也修改比较语义。

## 易错点

- 把源题的 `>` 擅自改成常见版本的 `>=`。
- 默认数组非负，只检查最大值，却没有声明这个未给出的前提。
- “第二大”只记录 distinct value，遇到重复最大值时错误地跳过另一个最大位置。
- 先用 `int` 计算 `2 * maxOther` 再转 long，溢出已经发生。
- 对负数直接套“最大值必须大于等于两倍第二大”的熟题结论。
- 多解、null、空数组和单元素没有给出确定的 API 行为。
