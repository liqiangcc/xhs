# 两个无环单链表的相交节点：双指针换头法

## 核心结论

对两个有限、无环的单链表，如果“相交”指两个链表从某个位置开始共享同一个节点对象，而不是节点值恰好相等，可以让两个指针分别从 A、B 出发：走到 `null` 后切到另一条链表头继续走。两条路径分别变成 A→B 和 B→A，总路程相同，原本的长度差被换头抵消；有相交时两指针会在第一个共享节点相遇，不相交时会同时到 `null`。时间 O(m+n)，额外空间 O(1)，且不修改链表。

## 1 分钟版

- 先明确“相交”比较的是**节点身份**：`p == q`，不是 `p.value == q.value`；无环单链表一旦共享某个节点，之后整个后缀都共享。
- `p` 从 A 走，走到 `null` 就跳到 B 头；`q` 从 B 走，走到 `null` 就跳到 A 头。
- 换头以后，一个指针补上另一条链表较长/较短的那部分前缀，最终两者走过相同的组合路径长度，长度差自然被抵消。
- 循环条件直接写 `while (p != q)`；退出时 `p` 要么是第一个共享节点，要么两个都是 `null`。
- 每个指针最多走过两条链表各一次，时间 O(m+n)、空间 O(1)，不用预先计算长度，也不改 `next`。

## 3 分钟版

```java
public final class LinkedListIntersection {
    public static final class Node {
        public final int value;
        public Node next;

        public Node(int value) {
            this.value = value;
        }
    }

    public static Node firstIntersection(Node headA, Node headB) {
        Node p = headA;
        Node q = headB;
        while (p != q) {
            p = (p == null) ? headB : p.next;
            q = (q == null) ? headA : q.next;
        }
        return p;
    }
}
```

例如 A 的独有前缀长度是 2，B 的独有前缀长度是 3，之后共享同一段尾链。单独从两个头同步走时，较短前缀的一方会更早进入共享段，所以位置一直错开；让 A 指针走完 A 后再走 B，让 B 指针走完 B 后再走 A，相当于双方都补走了对方的长度，前缀差被消掉，随后会在共享段的入口处对齐。如果根本没有共享节点，两条组合路径最终都在 `null` 对齐。

## 关键细节

- **身份而不是值**：两个不同节点即使 `value` 相同也不算链表相交；判断条件必须是同一对象引用。
- **为什么相交后是共享后缀**：单链表每个节点只有一个 `next`。在无环前提下，一旦 A、B 到达同一个节点，后续 `next` 路径就完全相同。
- **换的是另一条链表头**：`p` 走完 A 后跳 B，`q` 走完 B 后跳 A；若又跳回自己的头，就无法抵消长度差。
- **空链表自然覆盖**：一边或两边为空时，同一循环仍会收敛到 `null`，不需要额外分支。
- **同一个头结点**：如果 `headA == headB`，循环一次都不执行，直接返回该头节点，它就是第一个共享节点。
- **不修改输入**：只移动局部指针，不重写任何 `next`，因此不会破坏调用方的链表结构。
- **复杂度**：两个指针各自至多经过 A、B 两条有限链表各一次，所以总时间 O(m+n)，只使用两个指针，额外空间 O(1)。
- **环形边界**：原题没有保存“链表可能有环”的约束。本实现明确只处理有限无环链表；有环时必须先判断两条链的环结构和入环点，不能直接套用这里的终止证明。

## 原理机制

设 A、B 长度分别为 m、n。直接同步移动时，长度差会让两个指针进入潜在共享后缀的时间不同。换头法让 `p` 的完整路线是“A 的节点序列，再接 B 的节点序列”，`q` 则是“B 的节点序列，再接 A 的节点序列”。两条路线的总长度都由 m+n 决定，因此无论哪条原链更长，前缀差都会在第二段被另一方补齐。如果存在共享后缀，两指针会在它的第一个节点以相同引用对齐；如果不存在，则最终都变成 `null`。这个证明依赖链表有限且无环，否则“走到 null 再换头”的路径模型不成立。

## 项目经验版

来源没有提供真实项目中共享链表节点的案例，不能虚构生产经历。工程里若出现持久化不可变结构或结构共享，应该先确认“共享”是否真的按对象身份定义、数据结构是否可能成环，以及遍历期间是否会并发修改；只有满足当前无环且结构稳定的前提，才能直接复用这个 O(1) 空间解法。

## 常见追问

- 问：为什么不能比较节点值？答：值相同只说明数据相等，不说明两个链表指向同一个节点对象；例如两条各自独立的 `1 -> 2 -> 3` 值完全相同，但没有任何共享节点。
- 问：换头为什么能消掉长度差？答：一个指针走 A→B，另一个走 B→A，双方最终覆盖相同的总长度；较长链多出来的前缀会由另一指针在切换链表后补走。
- 问：两个链表不相交会不会死循环？答：在有限无环前提下不会；两条组合路径都走完后，`p` 和 `q` 会同时为 `null`，循环结束并返回 `null`。
- 问：还有别的方法吗？答：可以先分别计算长度，让较长链先走长度差，再同步前进；复杂度同样是 O(m+n)/O(1)，但需要显式的长度统计步骤。
- 问：如果链表有环怎么办？答：不能直接沿用本实现。要先判断各自是否有环、环入口是否相同或环是否连通，再按不同结构讨论交点；这是另一个问题边界。

## 易错点

- 用节点值相等代替节点引用相同，产生假交点。
- 指针走到末尾后跳回自己的头，而不是另一条链表头。
- 写成 `while (p.next != q.next)` 一类条件，导致空指针或漏掉头节点/尾节点交点。
- 为了做标记而修改 `next` 或节点内容，破坏输入结构。
- 没有声明无环前提，却声称这个循环对任意链表都一定终止。
