# 无重复字符的最长子串：输出子串本身

## 核心结论

这是一个滑动窗口问题。维护左边界 `left` 和“某个字符上一次出现的位置”；右指针每读到一个字符，如果它在当前窗口内出现过，就把 `left` 跳到该字符上次位置的下一位。每一步窗口都保持“内部没有重复字符”的不变量，同时记录见过的最长窗口。原题只要求输出最长子串本身，没有规定并列时选哪一个；下面的 Java 参考实现约定：长度并列时返回最先出现的那个。

## 1 分钟版

- 输入是一个字符串，输出是其中**不含重复字符**的最长连续子串；不是子序列，也不只是返回长度。
- 右指针从左到右扫描；`lastSeen[c]` 记录字符 `c` 最近一次出现的位置。
- 如果 `c` 的上次位置 `>= left`，说明重复发生在当前窗口内，于是令 `left = lastSeen[c] + 1`；否则左边界不动。
- 更新 `lastSeen[c]` 后，用当前窗口长度更新最优答案。因为只在“严格更长”时更新，所以并列时自然保留最左边的最长子串。
- 时间复杂度 O(n)，额外空间 O(k)，`k` 是窗口扫描过程中记录过的不同 Unicode code point 数。

## 3 分钟版

原题没有指定编程语言、字符语义、空串处理和并列规则。这里给一个明确的参考契约：输入为非 `null` Java `String`，空串返回空串；按 Unicode code point 判断“字符是否重复”，不把一个 supplementary character 拆成两个 UTF-16 `char`；若存在多个同长最优解，返回最左边的一个。

```java
import java.util.HashMap;
import java.util.Map;

public final class Solution {
    public static String longestUniqueSubstring(String s) {
        if (s == null) {
            throw new IllegalArgumentException("s must not be null");
        }

        int[] codePoints = s.codePoints().toArray();
        Map<Integer, Integer> lastSeen = new HashMap<>();

        int left = 0;
        int bestStart = 0;
        int bestLength = 0;

        for (int right = 0; right < codePoints.length; right++) {
            int cp = codePoints[right];
            Integer prev = lastSeen.get(cp);
            if (prev != null && prev >= left) {
                left = prev + 1;
            }
            lastSeen.put(cp, right);

            int length = right - left + 1;
            if (length > bestLength) {
                bestLength = length;
                bestStart = left;
            }
        }

        return new String(codePoints, bestStart, bestLength);
    }
}
```

例如：

- `"abcabcbb"` → `"abc"`
- `"bbbbb"` → `"b"`
- `"pwwkew"` → `"wke"`
- `""` → `""`

这里最关键的不是 `HashMap` 本身，而是左边界只能单调向右。遇到重复字符时不能简单写成 `left = prev + 1`；必须先确认 `prev >= left`，否则可能把已经移出窗口的旧重复位置重新拉回来，破坏当前窗口。

## 关键细节

- **输入输出**：输入一个 `String`，输出最长的无重复连续子串本身。
- **连续性**：子串必须连续；如果允许跳过字符，那是“子序列”问题，状态定义完全不同。
- **窗口不变量**：任意时刻 `[left, right]` 内不存在重复 code point。
- **并列规则**：原题未指定。本实现只在 `length > bestLength` 时更新，因此返回最左边的最长解；如果要求最右边，可以改成 `>=`。
- **旧重复不能让窗口后退**：只有 `prev >= left` 才移动左边界。
- **Unicode 边界**：实现按 code point 处理，避免 supplementary character 被拆成两个 `char`；但 code point 仍不等于“用户感知字符（grapheme cluster）”。如果题目要求按 grapheme cluster 判重，需要换成更高层的文本分段语义。
- **空串**：返回空串；`null` 不是原题定义的输入，这里显式拒绝。
- **复杂度**：把字符串转成 code point 数组 O(n)，滑动窗口再 O(n)，总时间 O(n)；数组和 `HashMap` 需要 O(n) 最坏额外空间。若明确输入只包含固定小字符集，可用数组替代 `HashMap` 降低常数。

## 原理机制

暴力做法会枚举起点，再向右扩展直到重复，最坏 O(n²)。滑动窗口利用了一个单调性：当右端加入新字符 `c` 后，如果 `c` 与窗口内旧位置 `prev` 冲突，那么任何仍包含 `prev` 和当前 `right` 的窗口都不可能合法；因此合法窗口的最小左边界至少是 `prev + 1`。把 `left` 一次跳到那里，就能一次性丢掉所有必然非法的起点，而不需要逐个尝试。

`lastSeen` 让我们 O(1) 均摊时间定位冲突位置。由于 `left` 和 `right` 都只向右移动，每个位置最多进入和离开窗口一次，所以扫描是线性的。

## 常见追问

- 问：为什么 `left` 不能直接设成 `prev + 1`？答：`prev` 可能已经在当前窗口左边。如果无条件赋值，`left` 会倒退，重新把已排除字符纳入窗口；正确写法是只在 `prev >= left` 时更新。
- 问：为什么不是用 `Set`？答：`Set` 也能做，但发生重复时通常需要从左侧逐个删除。记录 last seen 可以直接跳到冲突位置之后，逻辑更直接。
- 问：如果只要求最长长度怎么改？答：不再保存 `bestStart`，只维护 `bestLength` 即可；窗口逻辑不变。
- 问：多个最长子串长度相同怎么办？答：原题没有指定。本实现选择最左边；如果业务要求最右边或字典序最小，需要把 tie-break 明确写进比较规则。
- 问：为什么不用 `char`？答：Java `char` 是 UTF-16 code unit，一些 Unicode 字符由两个 `char` 表示。这里选择 code point 语义，避免把一个 supplementary character误判成两个字符。

## 易错点

- 只返回最大长度，漏掉原题明确要求的“输出最长子串本身”。
- 把子串写成子序列，允许不连续取字符。
- 重复时让 `left` 后退，导致窗口重新包含已淘汰字符。
- 只记 `Set` 却忘记同步收缩左边界。
- 没有说明并列最长子串的选择规则，却把某一个结果说成唯一答案。
- 在 Java 中直接把 `char` 当成完整 Unicode 字符，同时声称“支持所有 Unicode 字符”。
