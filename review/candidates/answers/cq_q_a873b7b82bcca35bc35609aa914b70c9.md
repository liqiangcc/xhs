# 二叉树：求根节点到叶子节点路径组成数字之和

## 核心结论

仓库原始面经只保留了“求根节点到叶子节点的数字之和”。它没有明确节点值范围、空树返回值、整数溢出策略或函数签名。要形成可执行答案，必须把这些补充项标成实现假设，而不能冒充原题要求。

下面采用最小十进制契约：每个节点值是 `0..9` 的一位数字；从根到某个真实叶子的路径按十进制拼成一个数；答案是所有根到叶路径数字之和；空树返回 `0`。Java 参考实现使用 `long`，并用 `Math.multiplyExact` / `Math.addExact` 显式暴露溢出，而不是静默回绕。

## 1 分钟版

- DFS 从根向下维护当前前缀 `prefix`。
- 到节点 `x` 时，新前缀是 `prefix * 10 + x.val`。
- 只有 `left == null && right == null` 才是真正叶子；到叶子时返回当前完整路径数字。
- 非叶子分别递归左右子树，再把两边结果相加。
- 时间复杂度 `O(n)`，每个节点访问一次；递归额外空间 `O(h)`，`h` 是树高。
- 节点是否一定是十进制单个数字并非来源事实；如果允许多位数或负数，拼接规则会改变，必须先重新定义契约。

## 3 分钟版

```java
final class RootToLeafNumberSum {
    static final class TreeNode {
        final int val;
        TreeNode left;
        TreeNode right;

        TreeNode(int val) {
            this.val = val;
        }
    }

    static long sumRootToLeafNumbers(TreeNode root) {
        if (root == null) return 0L;
        return dfs(root, 0L);
    }

    private static long dfs(TreeNode node, long prefix) {
        if (node.val < 0 || node.val > 9) {
            throw new IllegalArgumentException("node value must be a decimal digit");
        }

        long current = Math.addExact(
            Math.multiplyExact(prefix, 10L),
            node.val
        );

        if (node.left == null && node.right == null) {
            return current;
        }

        long left = node.left == null ? 0L : dfs(node.left, current);
        long right = node.right == null ? 0L : dfs(node.right, current);
        return Math.addExact(left, right);
    }
}
```

例如树 `1` 的左右孩子分别是 `2`、`3`，两条路径形成 `12` 和 `13`，结果为 `25`。前导 `0` 不需要特殊处理：路径 `0 -> 1 -> 3` 的数值自然是 `13`，因为十进制数值本身不会保留“013”的文本格式。

## 关键细节

- **叶子判定**：只有两个孩子都为空才结束路径；不能在“缺一个孩子”时提前结算，否则会把未到叶子的前缀算进去。
- **前缀状态**：每层只需要父路径累积值，不需要构造字符串或保存整条路径。
- **前导零**：按数值语义自然处理；`0 -> 5` 就是 `5`。若题目要求保留字符串表示，则已经是另一种契约。
- **节点值边界**：当前实现主动拒绝 `<0` 或 `>9`，因为多位节点和负数的“拼接”没有被原始来源定义。
- **溢出**：即使节点只有一位数字，树很深或叶子很多也可能超过 `long`。这里 fail-fast；若输入规模允许更大，应改用 `BigInteger` 或明确模数规则。
- **递归深度**：极端退化链可能触发 JVM 栈深度限制；可以用显式栈保存 `(node, prefix)`，算法不变量不变。

## 原理机制

这个问题的核心不变量是：进入 `dfs(node, prefix)` 时，`prefix` 恰好表示“从根到 `node` 的父节点”为止的十进制路径值；计算 `current = prefix * 10 + node.val` 后，`current` 就对应从根到当前节点的路径数字。

如果当前节点是叶子，这条路径已经完整，因此 `current` 就是该叶子的贡献；如果不是叶子，则所有完整路径必然落在左子树或右子树中，所以左右递归贡献之和就是当前子树的答案。这个分解保证每条根到叶路径恰好被计算一次。

## 项目经验版

来源没有真实项目、线上树规模或生产故障数据，不能虚构使用经历。工程中如果路径可能很长，我会先明确数值上界，再决定 `long`、`BigInteger` 或模运算；如果树可能退化得很深，会把递归改成显式栈，并用边界测试覆盖叶子判定、前导零和溢出策略。

## 常见追问

- 问：为什么不是把所有路径先存下来再求和？答：不需要。DFS 用一个前缀值就能在到叶子时得到完整数字，避免为每条路径额外分配字符串或列表。
- 问：只有左孩子或只有右孩子怎么办？答：继续沿存在的孩子走；缺失的一侧贡献 `0`，不能把当前非叶节点当成叶子。
- 问：节点值是 `12` 怎么办？答：原始来源没有定义多位节点的拼接语义。当前参考契约只接受 `0..9`；若允许 `12`，必须先决定它代表两位十进制片段还是一个普通数值节点，然后修改状态转移。
- 问：为什么用 `long` 而不是 `int`？答：路径拼接增长很快，`long` 只是提高可表达范围；它仍然可能溢出，所以代码使用 exact arithmetic 显式报错。
- 问：能否用 BFS？答：可以。队列保存 `(node, prefix)`，到叶子累加；DFS 和 BFS 的关键不变量相同，复杂度也都是 `O(n)`。

## 易错点

- 把“只有一个孩子为空”误判为叶子。
- 每层用字符串拼接再解析，增加无必要分配并把数值边界隐藏起来。
- 默认节点一定 `0..9` 却不说明这是补充假设。
- 用 `int` 或普通 `long` 运算静默溢出，还把错误结果当正确答案。
- 只测满二叉树，不测单节点、非对称树、前导零和深链边界。
