# 算法：两两交换链表中的节点（LeetCode 24）

## 核心结论

用虚拟头节点统一处理头部交换。维护 `prev -> first -> second -> rest`，每轮只重连三条边：`first.next = rest`、`second.next = first`、`prev.next = second`，然后把 `prev` 移到 `first`。这样交换的是**节点本身**而不是节点值，时间复杂度 `O(n)`，额外空间 `O(1)`。

## 1 分钟版

- 题目要求把相邻节点两两交换并返回新头节点，而且不能通过交换 `val` 偷换成“值交换”。
- 虚拟头 `dummy` 指向原头节点，`prev` 始终指向“下一对待交换节点之前的节点”。
- 若 `prev.next` 和 `prev.next.next` 都存在，就令它们为 `first`、`second`，保存 `second.next` 作为后继，再把局部链 `prev -> first -> second -> rest` 改成 `prev -> second -> first -> rest`。
- 一轮结束后 `first` 已经成为这一对的尾部，所以令 `prev = first`，继续处理后面的两个节点。
- 空链表、单节点以及奇数长度最后剩下的一个节点都无需特殊分支；循环条件会自然保留它们。

## 3 分钟版

这题真正的难点不是遍历，而是避免改指针时丢链或形成环。虚拟头节点把“第一对节点交换后头节点变化”与中间位置的交换统一起来，因此循环里不需要为头节点单独写分支。

设当前局部结构为 `prev -> first -> second -> rest`。交换前先拿到这几个引用，然后按安全顺序重连：先让 `first.next = rest`，这样 `first` 不再指向 `second`；再让 `second.next = first`；最后让 `prev.next = second`。局部结构就变成 `prev -> second -> first -> rest`。之后把 `prev` 移到 `first`，因为它是已交换前缀的最后一个节点。

```java
public final class SwapNodesInPairs {
    private SwapNodesInPairs() {}

    public static final class ListNode {
        public final int val;
        public ListNode next;

        public ListNode(int val) {
            this.val = val;
        }
    }

    public static ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode prev = dummy;

        while (prev.next != null && prev.next.next != null) {
            ListNode first = prev.next;
            ListNode second = first.next;
            ListNode rest = second.next;

            first.next = rest;
            second.next = first;
            prev.next = second;

            prev = first;
        }
        return dummy.next;
    }
}
```

例如 `[1,2,3,4]` 经过第一轮变成 `[2,1,3,4]`，第二轮变成 `[2,1,4,3]`；`[]` 和 `[1]` 原样返回，`[1,2,3]` 返回 `[2,1,3]`。测试除了检查值顺序，还应按对象身份确认输出仍由原来的节点组成，才能证明实现没有靠改值伪造交换。

## 关键细节

- **交换节点，不交换值**：节点值保持不变，改变的是 `next` 关系。重复值用例特别适合检查实现是否真的按节点身份重排。
- **虚拟头只用于统一指针操作**：它不会进入最终结果；返回 `dummy.next` 即可。
- **循环不变量**：进入每轮时，`prev` 之前的所有节点已经按两两交换后的最终顺序连接；`prev.next` 是下一段尚未处理链表的头。
- **奇数长度**：若最后只剩一个节点，`prev.next.next == null`，循环结束，这个尾节点保持原位置。
- **不会丢链**：在覆盖任何关键 `next` 之前先保存 `second` 和 `rest`；重连完成后剩余链仍由 `first.next` 接回。
- **不会成环**：关键是先断开 `first -> second`，再建立 `second -> first`；如果顺序写错且没有正确接回 `rest`，很容易出现两节点环或丢失后缀。
- 每个原节点最多被常数次读取和改链，因此时间复杂度是 `O(n)`；只维护固定数量的节点引用，额外空间是 `O(1)`。
- 递归也能写：交换前两个节点后递归处理第三个节点开始的后缀；写法更短，但调用栈需要 `O(n)` 空间，因此面试手写时迭代版本更容易说明空间边界。

## 原理机制

把链表看成若干长度为 2 的局部块。每一轮只改变当前块内部顺序以及它与前驱、后继的连接，不修改其他节点。假设进入某轮前，已处理前缀已经正确且与未处理后缀连通；当前轮把 `first, second` 改成 `second, first`，并让 `prev` 与 `rest` 分别接到交换后的两端，因此前缀长度增加 2，同时保持整条链连通。循环结束时未处理部分最多只剩一个节点，本身无需交换，所以整条链满足题意。

虚拟头节点的作用可以理解为给真实头节点补一个稳定前驱。没有 `dummy` 时，第一对节点交换会改变返回头，通常需要额外记录；有了 `dummy`，第一对和任意中间一对都使用同一套 `prev/first/second` 逻辑，从而减少分支和指针错误。

## 常见追问

- 问：为什么一定要虚拟头节点？答：不是理论上必须，但它给原头补了统一前驱，使第一对交换与中间节点交换使用同一逻辑，并且最终直接返回 `dummy.next`，能减少头节点特判。
- 问：为什么 `prev` 一轮后要移到 `first`？答：交换后局部顺序是 `second -> first`，`first` 成为已处理前缀的尾节点；下一轮的待处理节点正是 `first.next` 开始的后缀。
- 问：如果只交换两个节点的值可以吗？答：不可以。题目明确要求不能修改节点内部值；即使输出值序列相同，也没有满足节点交换的约束。
- 问：递归怎么写、复杂度有什么区别？答：令 `first=head`、`second=head.next`，先递归交换 `second.next` 后的链，再接成 `second -> first -> swappedRest`；时间仍为 `O(n)`，但递归栈是 `O(n)`，迭代额外空间为 `O(1)`。
- 问：怎样测试没有丢节点或产生环？答：除了比较输出值序列，还可记录输入节点的对象身份集合，遍历输出时用 identity set 检查无重复访问、节点数不变、身份集合完全相同，并验证期望的成对身份顺序。

## 易错点

- 只交换 `val`，没有真正交换节点。
- 不使用虚拟头却忘记更新第一对交换后的新头节点。
- 先写 `second.next = first` 却没有保存或正确接回后缀，造成丢链或成环。
- 交换完后把 `prev` 移到 `second`，导致下一轮从错误位置开始。
- 循环只判断一个节点存在，访问 `prev.next.next` 时空指针。
- 忘记奇数长度最后一个节点应保持原样。
- 只用 `[1,2,3,4]` 一个样例验证，没有覆盖空链表、单节点、奇数长度、重复值和节点身份不变性。
