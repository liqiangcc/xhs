# 算法：重排链表（LeetCode 143）

## 核心结论

把链表 `L0 → L1 → … → Ln` 原地重排成 `L0 → Ln → L1 → Ln-1 → …`，最稳妥的做法分三步：**快慢指针找到前半段尾部 → 反转后半段 → 两段交替合并**。整个过程只修改 `next` 指针，不修改节点值；时间复杂度 `O(n)`，除少量指针变量外额外空间 `O(1)`。

## 1 分钟版

- 先用快慢指针找中点：`slow` 最终停在前半段尾部，把 `second = slow.next` 保存下来后执行 `slow.next = null`，明确切成两条链。
- 原地反转后半段。反转后，第二段节点顺序从“靠近中点到尾部”变成“原尾部到中点”。
- 用两个指针交替合并：每轮先保存 `first.next` 与 `second.next`，再接成 `first -> second -> 原 first.next`，避免丢失剩余链表。
- 偶数长度时两段等长；奇数长度时前半段多一个中间节点。循环只以 `second != null` 为条件，中间节点会自然保留在末尾。

## 3 分钟版

题目要求保持节点本身，只改变链接顺序，所以不能用“交换节点值”规避指针操作。目标序列的特点是头、尾、次头、次尾不断交替；如果直接从单链表尾部反复找节点，会退化为 `O(n^2)`。因此先把“从尾往前取”转化为一次后半段反转，就能让后续每次都从两个链表头部 `O(1)` 取节点。

第一步找切分点。下面的循环让 `slow` 每次走一步、`fast` 每次走两步：

```text
while (fast.next != null && fast.next.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
```

对于 `1→2→3→4`，`slow` 停在 `2`，切成 `1→2` 与 `3→4`；对于 `1→2→3→4→5`，`slow` 停在 `3`，切成 `1→2→3` 与 `4→5`。前半段长度因此总是不小于后半段。切分时必须把 `slow.next` 断开，否则反转和交替连接过程中很容易把旧链接重新接回，形成环。

第二步原地反转第二段，例如 `3→4` 变成 `4→3`、`4→5` 变成 `5→4`。第三步交替合并。每一轮都先保存两边的后继，再改 `next`：

```text
ListNode nextFirst = first.next;
ListNode nextSecond = second.next;
first.next = second;
second.next = nextFirst;
first = nextFirst;
second = nextSecond;
```

完整 Java：

```java
public final class ReorderList {
    private ReorderList() {}

    public static final class ListNode {
        public final int val;
        public ListNode next;

        public ListNode(int val) {
            this.val = val;
        }
    }

    public static void reorderList(ListNode head) {
        if (head == null || head.next == null || head.next.next == null) {
            return;
        }

        ListNode slow = head;
        ListNode fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        ListNode second = slow.next;
        slow.next = null;
        second = reverse(second);

        ListNode first = head;
        while (second != null) {
            ListNode nextFirst = first.next;
            ListNode nextSecond = second.next;
            first.next = second;
            second.next = nextFirst;
            first = nextFirst;
            second = nextSecond;
        }
    }

    private static ListNode reverse(ListNode head) {
        ListNode previous = null;
        ListNode current = head;
        while (current != null) {
            ListNode next = current.next;
            current.next = previous;
            previous = current;
            current = next;
        }
        return previous;
    }
}
```

官方示例中，`[1,2,3,4]` 变成 `[1,4,2,3]`，`[1,2,3,4,5]` 变成 `[1,5,2,4,3]`。官方约束要求节点数至少为 1，且明确要求不能修改节点值，只能修改节点本身的链接。仓库内 writer-round 自检另外覆盖了长度 `1..64` 的顺序链表，并用独立数组 oracle 生成期望顺序；每个用例同时检查无环、节点数量不变、节点 identity 集合不变、节点值不变，全部通过。

## 关键细节

- **切分不变量**：进入反转前，两段必须互不相连；`slow.next = null` 是显式边界，不是可省略的清理步骤。
- **反转不变量**：`previous` 始终是已经反转好的前缀头，`current` 指向尚未处理的剩余后缀；改 `current.next` 前必须先保存原后继。
- **合并不变量**：每轮结束后，已合并前缀已经符合 `L0, Ln, L1, Ln-1, ...` 的目标顺序，而 `first`、`second` 分别指向两段尚未消费的头节点。
- **奇偶长度**：偶数长度切成等长两段；奇数长度前半段多一个中间节点，因此只需要循环到第二段耗尽。
- **节点而非值**：题意要求重排节点。即使所有值互不相同，也不应通过交换 `val` 来模拟结果；重复值场景更能暴露这种错误。
- **复杂度**：找中点、反转、合并各自至多线性扫描一次，总时间 `O(n)`；没有数组、栈或递归调用栈，额外空间 `O(1)`。
- 独立实现对 `null` 也安全返回，但正式题目约束本身保证链表至少有一个节点。

## 原理机制

目标顺序同时需要“从头向后取”和“从尾向前取”。单链表天然只支持从当前节点向后访问，因此真正的难点是怎样高效得到 `Ln, Ln-1, ...`。把后半段反转后，这一序列就变成第二条链表从头到尾的自然遍历顺序，于是问题从“反复找尾节点”转换成“两条链表的线性交替归并”。

切分点选择保证第一段长度不小于第二段，所以合并时不会出现“第二段还有节点，但第一段已经没有插入位置”的情况。显式断链则把原链表的历史结构消掉，使后续的反转与合并只需要维护当前两段的局部不变量。三步各自职责单一，也便于分别验证：切分验证长度关系，反转验证顺序，合并验证最终节点排列。

## 常见追问

- 问：为什么快慢指针要让 `slow` 停在前半段尾部？答：这样奇数长度时中间节点留在前半段，保证第一段长度始终不小于第二段；合并循环只处理第二段即可自然结束。
- 问：为什么切分后一定要执行 `slow.next = null`？答：不先断开旧边界，第二段反转或重新穿插时仍可能通过原链接指回第一段，增加形成环或重复节点的风险；先断链能让两个阶段的结构边界明确。
- 问：交替合并时为什么先保存两个 `next`？答：一旦执行 `first.next = second` 或 `second.next = nextFirst`，原后继关系就被覆盖；不先保存会丢失尚未处理的链表尾部。
- 问：能否用数组或栈保存节点后再双端取？答：可以把所有节点存起来后按首尾交替连接，时间仍是 `O(n)`，但需要 `O(n)` 额外空间；反转后半段能把额外空间降到 `O(1)`。
- 问：为什么不能只交换节点值？答：题目明确要求不修改节点值；而且“重排链表”考查的是节点链接关系，值交换不能证明节点 identity 的顺序真的发生了变化。

## 易错点

- 找到中点后忘记断开 `slow.next`，后续重连导致环或重复链接。
- 反转链表时先改 `next`、后保存原后继，导致剩余节点丢失。
- 合并时只保存一侧后继，第二次改链后无法继续遍历。
- 奇数长度把中间节点误放入两段都处理，造成重复节点。
- 用交换 `val` 代替节点重排，违反题目约束。
- 每次从头扫描寻找当前尾节点，虽然结果可能正确，但整体退化到 `O(n^2)`。
