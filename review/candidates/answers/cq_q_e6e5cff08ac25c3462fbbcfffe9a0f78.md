# 算法：不同的二叉搜索树

## 核心结论

仓库来源只保留“算法：不同的二叉搜索树”，并标注了 BST 与动态规划；它没有保存完整函数签名、输入范围，也没有明确是“计数”还是“生成所有树”。因此本候选先定义一个可执行、可追问的计数契约：给定 `n >= 0`，使用互不相同的有序键 `1..n`，返回能形成的**结构不同**二叉搜索树数量；`n=0` 返回 1，表示空树这一种空结构；负数输入抛 `IllegalArgumentException`。为了不依赖来源里不存在的 `int` 上限，返回 `BigInteger`。

动态规划的关键是枚举根节点。若一棵树共有 `nodes` 个键，选定第 `root` 个键为根后，左子树有 `root-1` 个键，右子树有 `nodes-root` 个键；左右子树结构可以独立组合，所以该根贡献 `dp[left] * dp[right]` 种。把所有根的贡献相加即可。

## 1 分钟版

- 先明确当前回答解决“计数不同 BST”而不是“生成全部 BST”；来源没有保存这两个语义中的哪一个。
- 定义 `dp[k]` 为使用 `k` 个连续有序键能形成的不同 BST 数量，`dp[0]=1`。
- 对 `nodes=1..n`，枚举左子树节点数 `left=0..nodes-1`，右侧就是 `right=nodes-1-left`。
- 根左右两侧的结构独立，因此这一划分贡献 `dp[left] * dp[right]`；对所有 `left` 求和得到 `dp[nodes]`。
- 时间复杂度 O(n²)，额外空间 O(n)。这里用 `BigInteger` 避免把未保存的输入上限偷偷绑定到 `int` 溢出范围。

## 3 分钟版

```java
import java.math.BigInteger;

public final class UniqueBsts {
    private UniqueBsts() {}

    public static BigInteger countUniqueBsts(int n) {
        if (n < 0) {
            throw new IllegalArgumentException("n must be >= 0");
        }

        BigInteger[] dp = new BigInteger[n + 1];
        dp[0] = BigInteger.ONE;

        for (int nodes = 1; nodes <= n; nodes++) {
            BigInteger total = BigInteger.ZERO;
            for (int left = 0; left < nodes; left++) {
                int right = nodes - 1 - left;
                total = total.add(dp[left].multiply(dp[right]));
            }
            dp[nodes] = total;
        }
        return dp[n];
    }
}
```

例如 `n=3` 时：

- 根取第 1 个键：左侧 0 个、右侧 2 个，贡献 `dp[0] * dp[2]`；
- 根取第 2 个键：左右各 1 个，贡献 `dp[1] * dp[1]`；
- 根取第 3 个键：左侧 2 个、右侧 0 个，贡献 `dp[2] * dp[0]`。

因此只需要“左右各有多少个键”，不需要真的把键值写进状态。BST 的有序性已经决定：根左边那些较小键只能进入左子树，根右边那些较大键只能进入右子树；决定结构数量的是子问题规模。

## 关键细节

- **题意边界**：来源标题不足以证明是在问计数。如果面试官实际要求“生成所有不同 BST”，则输出规模本身就是答案数量，需要返回树列表并真正构造节点，不能只返回这个 DP 数字。
- **空子树为什么是 1**：组合计数里，某一侧没有节点时应有一种“什么都不放”的选择；若设 `dp[0]=0`，单节点树就会被乘成 0。
- **为什么不用具体键值做状态**：对于连续且互不相同的有序键，只要节点个数相同，结构计数相同；键值的绝对大小不影响可形成的相对 BST 结构。
- **乘法来自独立组合**：固定根后，每一种左结构都可以与每一种右结构配对，因此使用乘法；不同根对应互斥的树集合，因此根之间使用加法。
- **数值范围**：数量增长很快。来源没有给 `n` 上限，所以候选直接使用 `BigInteger`，避免把语言整型溢出当作隐含题目约束。
- **复杂度**：外层计算 `n` 个状态，每个状态枚举 O(nodes) 个左右划分，因此时间 O(n²)；`dp` 保存 `n+1` 个计数，空间 O(n)。这里的复杂度不计 `BigInteger` 随数值增长带来的位运算成本；若严格按 bit complexity 计，还要把大整数加乘成本算进去。

## 原理机制

二叉搜索树的定义把根节点两侧的键集合切成两个不相交区间。对于 `1..n`，一旦选定某个键为根，哪些键属于左侧、哪些属于右侧就已经确定；剩下的不确定性只有“左侧内部怎么长成 BST”和“右侧内部怎么长成 BST”。

因此可以把一个规模为 `nodes` 的问题拆成所有可能的 `(left, right)`，满足 `left + right = nodes - 1`。固定一组规模后，左、右结构做笛卡尔组合；再把所有根对应的结果相加。这个“按根划分 + 左右独立组合”的递推正是动态规划能复用的重叠子问题。

## 项目经验版

来源没有真实项目背景，不能虚构线上使用经历。工程里如果只是需要计数，应优先返回数值而不是构造所有树，因为“生成全部结构”的内存和输出成本至少与结果数量成正比。若真实约束给出了很大的 `n`、只要求取模、或者要求生成具体树结构，则数据类型、状态和算法接口都应该随契约调整。

## 常见追问

- 问：为什么 `dp[0]` 是 1？答：空子树是组合时的一种合法选择。单节点树需要 `dp[0] * dp[0] = 1`。
- 问：为什么左右子树数量要相乘？答：固定根后，每一种左结构都能独立搭配每一种右结构，所以组合数相乘。
- 问：为什么不同根的数量相加？答：根键不同的 BST 不会是同一棵带有这些有序键的树，因此这些情况互斥。
- 问：如果要求输出所有树呢？答：当前 DP 只计数。生成题需要递归构造每个区间的根，并组合左右树列表，还要明确节点对象是否共享。
- 问：为什么返回 `BigInteger`？答：来源没有保存 `n` 上限。使用精确大整数能把“计数逻辑”与某个固定宽度整型的溢出边界分开。
- 问：还能优化到 O(n) 吗？答：如果允许使用这一计数序列的闭式/递推数学公式，可以减少状态枚举；但当前候选优先展示从 BST 根划分直接推导出的 DP，因果链更贴近题意。

## 易错点

- 看到标题就默认完整题面，没说明“计数”与“生成”的歧义。
- 把 `dp[0]` 设成 0，导致所有含空子树的组合被错误消掉。
- 固定根后把左右方案数相加，而不是相乘。
- 用 `int` 返回却不说明输入上限和溢出条件。
- 真正要求生成所有 BST 时仍只给计数 DP。
- 声称 O(n²) 是严格位复杂度，却忽略 `BigInteger` 随 `n` 增长后的大整数运算成本。
