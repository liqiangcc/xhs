# 算法手撕：二叉树任意两点之间的最长距离

## 核心结论

原始贝壳面经只记录了“二叉树两点之间最长距离”，没有说明距离按“边数”还是“路径节点数”计。这个口径必须先说清：下面以**边数**为主；若面试官按节点数计，则非空树的结果是 `diameterEdges + 1`，算法和状态完全不变。

一次后序 DFS 就能完成。对每个节点，递归返回“从该节点向下能走到最深叶子的节点高度”；若左、右子树高度分别为 `L`、`R`，那么经过当前节点的最长路径边数就是 `L + R`。全局取所有节点的 `L + R` 最大值，就是整棵树任意两点之间的最长距离。每个节点只处理一次，时间 `O(n)`；递归辅助空间最坏 `O(h)`，退化树时 `h=n`。

## 1 分钟版

- 先澄清“距离”按边数还是节点数；这里代码返回边数。
- DFS 的返回值不是“子树直径”，而是“当前节点向下的最大节点高度”。
- 设左、右子树高度是 `L,R`，经过当前节点的最长路径由“左边最深点 → 当前节点 → 右边最深点”组成，边数正好是 `L + R`。
- 用全局最大值记录所有节点的 `L + R`；向父节点返回 `1 + max(L,R)`。
- 空树和单节点树的边数直径都为 0；链式树的直径就是首尾之间的边数。
- 时间 `O(n)`，递归栈 `O(h)`；极深退化树要注意栈深度。

## 3 分钟版

最长路径不一定经过根节点，所以只算 `root.leftDepth + root.rightDepth` 会漏掉完全位于某个子树中的答案。正确做法是对**每个节点**都计算一次“经过它的候选最长路径”。

定义：

```text
depth(node) = 从 node 出发向下到最深叶子，包含 node 自身的节点数
depth(null) = 0
```

后序遍历时先得到：

```text
L = depth(node.left)
R = depth(node.right)
```

如果最长路径经过当前节点，那么左半段有 `L` 条从当前节点连接到左侧最深点的边，右半段有 `R` 条边，因此候选直径（按边数）是：

```text
throughNode = L + R
```

把它更新到全局最大值；而父节点只需要知道“从当前节点向下最长能延伸多远”，所以返回：

```text
1 + max(L, R)
```

为什么这能覆盖全局答案？任意两点的简单路径都有一个最低公共祖先 `x`。这条路径要么两端分处 `x` 的左右两侧，要么一端就是 `x`；在 DFS 处理 `x` 时，它一定被某个 `L + R` 候选覆盖。对所有节点取最大值，因此不会漏解。

仓库测试除了空树、单节点、链、平衡树等固定边界，还生成 3000 棵确定性随机二叉树，并把 DFS 结果与“把树转成无向图后，从每个节点 BFS 求最远距离”的结构不同 oracle 对照，全部一致。

## 关键细节

- 原始面经没有规定边数/节点数口径，答案必须显式保留这个边界，不能把常见平台定义冒充原题条件。
- 代码把 `depth(null)=0` 定义成“节点高度”，这样 `L+R` 自然得到经过当前节点的边数。
- 空树按边数返回 0；单节点树没有两条不同端点间的边，返回 0。
- 若业务/题库定义“路径长度=节点数”，非空树返回 `diameterEdges(root)+1`，空树仍为 0。
- 不能只在根节点计算一次，因为最长路径可能完全位于左/右子树内部。
- 不需要为每对节点实际求路径；后序汇总把 `O(n^2)` 的枚举降到 `O(n)`。
- 递归栈空间是 `O(h)`。平衡树约 `O(log n)`，退化链表形态最坏 `O(n)`；如果输入可能极深，可改显式栈做迭代后序。

## 原理机制

不变量有两个：

1. `depth(node)` 返回的值只描述“从 node 向下”的最长单支路径，因此父节点可以安全复用。
2. 在 `depth(node)` 返回之前，`best` 已经包含该节点整棵子树中所有可能最低公共祖先对应的最长路径候选。

处理叶子时左右高度都是 0，候选直径为 0，返回高度 1，两个不变量成立。假设左右子树递归返回时不变量成立，那么它们内部的最长路径已经进入 `best`；再加入当前节点自己的 `L+R`，就覆盖了所有最低公共祖先为当前节点的路径。最后返回 `1+max(L,R)` 给父节点。因此归纳到根节点后，`best` 就是全树直径。

## Java 复习实现

```java
public final class BinaryTreeDiameter {
    public static final class TreeNode {
        public final int value;
        public TreeNode left;
        public TreeNode right;

        public TreeNode(int value) {
            this.value = value;
        }
    }

    private BinaryTreeDiameter() {}

    public static int diameterEdges(TreeNode root) {
        int[] best = {0};
        depthInNodes(root, best);
        return best[0];
    }

    private static int depthInNodes(TreeNode node, int[] best) {
        if (node == null) {
            return 0;
        }
        int leftDepth = depthInNodes(node.left, best);
        int rightDepth = depthInNodes(node.right, best);
        best[0] = Math.max(best[0], leftDepth + rightDepth);
        return 1 + Math.max(leftDepth, rightDepth);
    }
}
```

## 项目经验版

这是纯算法题，不应该硬套生产经历。面试时最有价值的是先把距离口径讲清，再准确区分“递归返回的单支高度”和“全局汇总的双支直径”，最后用链式树和“最长路径不经过根”的例子证明自己没有把状态定义混在一起。

## 常见追问

- 问：为什么最长路径一定能被某个 `L+R` 覆盖？答：任意两点路径都有最低公共祖先；处理那个祖先时，路径的两部分正好由左右向下深度组成，若一端就是祖先，对应一侧深度为 0。
- 问：为什么递归不能直接返回子树直径？答：父节点要拼出“经过自己”的路径，需要的是左右两侧可向下延伸的最长单支长度；子树直径不能用于这个拼接。
- 问：最长路径必须经过根节点吗？答：不必须，所以要在每个节点都更新全局候选，不能只在根算一次。
- 问：按节点数计怎么改？答：非空树的节点数路径长度等于边数直径加 1；状态和 DFS 不用改变。
- 问：递归会有什么工程边界？答：极端退化树的递归深度是 `O(n)`，若节点数可能很大且运行时栈有限，应改用显式栈实现迭代后序。

## 易错点

- 没问清“距离”是边数还是节点数，导致和面试官样例差 1。
- 把 `depth`、`diameter` 两种状态混为一谈，向父节点返回了不可拼接的值。
- 只计算根节点的 `leftDepth + rightDepth`，漏掉子树内部直径。
- 高度定义前后不一致：一会儿按节点数、一会儿按边数，造成 off-by-one。
- 忽略退化树的递归栈风险。
