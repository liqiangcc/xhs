# 数据结构：Java 不使用 PriorityQueue 实现小根堆

## 核心结论

仓库来源只要求“在 Java 中不直接使用 `PriorityQueue` 实现一个小根堆”，没有保存固定 API、容量上限、空堆行为或是否允许重复值。这里定义一个可执行的最小契约：堆保存 `int`，允许重复值，支持 `add`、`peek`、`poll`、`size`；空堆执行 `peek`/`poll` 时抛 `NoSuchElementException`。实现使用动态 `int[]` 表示完全二叉树，不调用 `PriorityQueue`。

数组下标关系是：节点 `i` 的父节点 `(i-1)/2`，左孩子 `2*i+1`，右孩子 `2*i+2`。插入时先放到数组尾部，再不断与父节点比较并上浮；删除堆顶时用最后一个元素补到根，再选择更小的孩子向下交换，直到恢复“父节点不大于孩子”的小根堆不变量。

## 1 分钟版

- 用数组保存完全二叉树，避免显式节点和指针。
- `add(x)`：把 `x` 放在末尾，若比父节点小就持续上浮，时间 O(log n)。
- `peek()`：直接读 `data[0]`，时间 O(1)。
- `poll()`：保存根值，用最后一个元素覆盖根，再持续和更小的孩子交换，时间 O(log n)。
- 重复值是合法元素；比较用 `<`/`<=`，不需要去重。
- 动态扩容只改变底层数组容量，不改变堆的逻辑顺序。

## 3 分钟版

```java
import java.util.Arrays;
import java.util.NoSuchElementException;

public final class MinHeap {
    private int[] data = new int[8];
    private int size;

    public void add(int value) {
        ensureCapacity();
        int i = size++;
        data[i] = value;

        while (i > 0) {
            int parent = (i - 1) / 2;
            if (data[parent] <= data[i]) {
                break;
            }
            swap(parent, i);
            i = parent;
        }
    }

    public int peek() {
        if (size == 0) {
            throw new NoSuchElementException("heap is empty");
        }
        return data[0];
    }

    public int poll() {
        int result = peek();
        int last = data[--size];

        if (size > 0) {
            data[0] = last;
            int i = 0;

            while (true) {
                int left = i * 2 + 1;
                if (left >= size) {
                    break;
                }
                int right = left + 1;
                int smaller = right < size && data[right] < data[left]
                        ? right
                        : left;

                if (data[i] <= data[smaller]) {
                    break;
                }
                swap(i, smaller);
                i = smaller;
            }
        }
        return result;
    }

    public int size() {
        return size;
    }

    public boolean isEmpty() {
        return size == 0;
    }

    private void ensureCapacity() {
        if (size == data.length) {
            data = Arrays.copyOf(data, data.length * 2);
        }
    }

    private void swap(int a, int b) {
        int tmp = data[a];
        data[a] = data[b];
        data[b] = tmp;
    }
}
```

插入和删除都只沿根到叶的一条路径移动，不需要每次重新排序整个数组。`poll()` 中必须选择两个孩子里更小的那个交换；如果只固定选左孩子，可能让根大于右孩子，从而破坏小根堆。

## 关键细节

- **堆不变量**：对每个存在父节点的下标 `i`，都应满足 `data[parent(i)] <= data[i]`。这只保证堆顶是全局最小值，并不保证整个数组有序。
- **完全二叉树表示**：按层连续存储后，父子关系能直接由下标计算，因此数组末尾天然对应下一次插入位置。
- **删除堆顶**：不能把根直接删除后整体左移；那既是 O(n)，也没有利用堆结构。正确做法是“尾元素补根 + 下沉”。
- **下沉选更小孩子**：父节点若需要下沉，必须先和较小的孩子比较/交换，才能同时满足左右两侧的堆序。
- **重复值**：本契约允许重复值。相等时无需继续交换，仍然满足 `parent <= child`。
- **空堆行为**：来源没有规定，这里显式选择抛 `NoSuchElementException`，而不是返回某个可能与合法数据冲突的哨兵值。
- **复杂度**：`peek` O(1)；`add`/`poll` 最多移动树高 O(log n) 层；存储 n 个元素需要 O(n) 空间。偶发数组扩容是 O(n)，按连续插入的摊还成本仍为 O(1)，不会改变上浮的 O(log n) 主路径。
- **整数边界**：比较直接比较 `int`，没有做减法，因此 `Integer.MIN_VALUE` / `Integer.MAX_VALUE` 不会因为比较差值溢出而反转顺序。

## 原理机制

堆利用了两个性质。第一，形状固定为完全二叉树，所以可以紧凑地映射到数组；第二，只要求局部的父子有序，而不是全局有序。局部不变量足以推出根是最小值：从任意节点一路向上，每一步父节点都不大于子节点，因此根不大于所有可达节点。

插入只可能在新叶子到根的路径上制造一个违例，所以执行上浮即可；删除根后，只有新根到某个叶子的路径可能违例，所以执行下沉即可。每次修复只触碰一条高度为 O(log n) 的路径，这就是堆能同时提供 O(1) 取最小值和 O(log n) 更新的原因。

## 项目经验版

来源没有真实项目背景，不能虚构线上经验。工程中如果只是需要标准优先队列，应优先使用 JDK 已验证的 `PriorityQueue`；手写堆更适合面试、教学，或需要自定义索引更新、原地结构、特定内存布局等标准容器不能直接满足的场景。真实使用前还应根据并发模型、容量上限和对象类型补齐契约与测试。

## 常见追问

- 问：为什么数组可以表示完全二叉树？答：按层连续编号后，父子下标存在固定算术关系，不需要额外指针。
- 问：为什么 `poll` 要和较小的孩子交换？答：若父节点比孩子大，要恢复 `parent <= both children`，优先换到较小孩子的位置才能保证换上来的值不大于另一个孩子。
- 问：为什么不用每次插入后排序？答：全排序至少会做远超一条树高路径的工作；堆只维护足够支持最小值访问的局部顺序。
- 问：重复元素怎么办？答：本契约把每次插入都视为一个元素，重复值保留；相等父子无需交换。
- 问：能支持泛型吗？答：可以把 `int[]` 换成对象数组，并通过 `Comparator<? super T>` 定义顺序；但来源没有要求泛型，这里先保持最小实现。
- 问：如何 O(n) 建堆？答：如果一次拿到完整数组，可以从最后一个非叶子节点开始依次下沉，整体是 O(n)，比逐个 `add` 的 O(n log n) 更合适。
- 问：线程安全吗？答：当前契约没有并发要求，实例不是线程安全的；若共享访问，需要在更高层定义同步策略，而不是默认加锁改变 API 语义。

## 易错点

- 下沉时总选左孩子，没有比较右孩子是否更小。
- `poll` 后忘记减少 `size`，或把已删除尾元素仍算在有效区间内。
- 用 `a-b` 的正负判断整数大小，在极值下发生溢出。
- 误以为堆数组整体有序；堆只保证父子局部顺序和根的极值性质。
- 空堆时返回 `0` 等哨兵值，却没有说明它可能也是合法元素。
- 为了“不能用 PriorityQueue”转而调用其他已经实现堆语义的库结构，实际上没有展示核心上浮/下沉机制。
