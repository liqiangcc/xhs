# 数组分组：把“按什么分”作为函数参数传入

## 核心结论

仓库里的原始面试记录能恢复出的要求是：**对一个数组做分组，既要能按性别分，也要能按年龄分，并且“分组逻辑通过函数传入”以便写得更通用。** 原记录提到“图2的数组”，但仓库没有恢复出那张图里的具体样例数据，因此答案不能伪造原数组。

最直接的抽象是把“如何从元素得到分组键”提成 `keySelector`：

```javascript
const bySex = groupBy(people, person => person.sex);
const byAge = groupBy(people, person => person.age);
```

这里实现返回 `Map<key, item[]>`。选择 `Map` 是实现决策，不是题目原文要求；它能保留数字键与字符串键的区别，也不会被 `__proto__`、`constructor` 这类对象属性名影响。如果面试官明确要求普通对象或 JSON，再在边界层转换即可。

## 1 分钟版

不要分别写 `groupBySex`、`groupByAge` 两套循环，而是把变化点提成函数参数：遍历数组，对每个元素调用 `keySelector(item, index, items)` 得到 key；第一次遇到 key 就创建桶，之后继续 `push` 到对应桶。

```javascript
function groupBy(items, keySelector) {
  const groups = new Map();
  for (let index = 0; index < items.length; index += 1) {
    const item = items[index];
    const key = keySelector(item, index, items);
    const bucket = groups.get(key);
    if (bucket === undefined) groups.set(key, [item]);
    else bucket.push(item);
  }
  return groups;
}
```

时间复杂度平均是 `O(n)`，额外桶结构和结果引用是 `O(n)`。同一组内保持输入顺序；函数不会重排或修改输入数组，但桶里仍保存原元素引用，不做深拷贝。

## 3 分钟版

这题真正考察的是把“稳定流程”和“变化规则”分开。稳定流程只有一次：遍历输入、计算分组键、找到桶、追加元素。变化规则是“按什么分”，所以通过 `keySelector` 注入。

原始记录只明确了“按性别”“按年龄”和“分组逻辑通过函数传入”，没有恢复输入对象字段的完整结构、输出格式、空值规则或图2样例。因此实现把这些未知点保持在边界上：

1. 输入必须是数组，分组器必须是函数；否则显式抛 `TypeError`。
2. `keySelector` 可以返回字符串、数字、布尔值、对象等任意 `Map` key。
3. 首次出现某个 key 时创建新数组，因此 key 的迭代顺序是首次出现顺序。
4. 每个桶只按遍历顺序追加，所以组内顺序稳定。
5. 不修改输入数组，也不修改元素；但输出桶持有原元素引用，所以这不是深拷贝。

如果面试官要求输出普通对象，可以在确认 key 一定能安全字符串化之后改用 `Object.create(null)`，或者最后把 `Map` 转换成对象。不要在题干没说明时默认把所有 key 强制 `String(key)`，否则数字 `1` 和字符串 `"1"` 会被无声合并。

## 关键细节

- **来源边界**：原始笔记写的是“数组分组，图2的数组如何按性别分组？如何按年龄分组？怎么写更优雅（分组逻辑通过函数传入）”。图2中的具体数组没有被仓库成功恢复，所以测试数据只能是明确标注的验证样例，不能冒充原题样例。
- **抽象点**：把 `item -> key` 作为函数参数，循环本身只负责分桶。
- **返回类型**：本实现选 `Map`，这是为避免字符串键碰撞和类型丢失而做的工程选择，不是源题硬约束。
- **顺序**：`Map` 保持 key 的首次插入顺序；每个桶保持元素在输入中的相对顺序。
- **引用语义**：新建的是桶数组，不深拷贝元素。修改桶数组不会改变输入数组结构，但修改桶里的对象仍会影响同一个对象。
- **复杂度**：假设 `Map#get/set` 平均常数时间，单次遍历为 `O(n)`；结果本身需要保存 `n` 个元素引用，因此空间为 `O(n)`。
- **`reduce` 不是必需条件**：结构化元数据提到 `Array.prototype.reduce`，但原始笔记真正要求的是“分组逻辑通过函数传入”。用 `for`、`for...of` 或 `reduce` 都能实现，清晰性优先。

## 原理机制

```javascript
'use strict';

function groupBy(items, keySelector) {
  if (!Array.isArray(items)) {
    throw new TypeError('items must be an array');
  }
  if (typeof keySelector !== 'function') {
    throw new TypeError('keySelector must be a function');
  }

  const groups = new Map();
  for (let index = 0; index < items.length; index += 1) {
    const item = items[index];
    const key = keySelector(item, index, items);
    const bucket = groups.get(key);
    if (bucket === undefined) {
      groups.set(key, [item]);
    } else {
      bucket.push(item);
    }
  }
  return groups;
}

module.exports = { groupBy };
```

循环不变量是：处理完前 `k` 个元素后，`groups` 中每个桶恰好包含这 `k` 个元素里 selector 结果等于该 key 的元素，并且顺序与输入一致。处理第 `k+1` 个元素时，只把它追加到对应桶，因此不变量继续成立；遍历结束时就覆盖全部输入。

仓库测试不用另一份 `Map` 实现做 oracle，而是用一个故意较慢的“键-桶二元组线性扫描”实现作为结构不同的对照。固定用例覆盖空数组、按性别、按年龄、按索引、特殊字符串 key、数字/字符串 key 区分、非法参数和输入顺序不变；另外固定随机种子生成 1000 轮数组，对性别、年龄、年龄取模和布尔条件四种 selector 与独立 oracle 做逐组比较。

## 项目经验版

这是手撕题，原始面试记录没有提供生产项目背景，因此不编造业务规模或线上收益。工程里这个抽象可以用于前端列表按状态、日期、负责人等维度聚合，但真实项目还要明确：key 是否可序列化、结果是否需要 JSON、是否允许空 key、元素是否需要拷贝，以及大数组是否要流式处理。

## 常见追问

- 问：为什么把分组规则做成函数，而不是传字符串字段名？答：函数既能覆盖 `item.sex`、`item.age`，也能表达年龄段、组合键等计算逻辑；主循环不需要随规则变化。
- 问：为什么这里返回 `Map` 而不是 `{}`？答：原题没规定输出形态；`Map` 能保留 key 类型并避开对象原型属性名冲突。若接口要求 JSON，再在确认键编码规则后转换。
- 问：用 `reduce` 会不会更优雅？答：可以，但并不会改变核心抽象或复杂度；题目的关键是 selector 注入，而不是必须使用某个数组 API。
- 问：同一组里的顺序能保证吗？答：能。算法从左到右遍历，只对桶做尾部 `push`，所以同组元素保持原输入相对顺序。
- 问：这个实现会复制对象吗？答：只新建分组桶数组，不深拷贝元素；桶和输入数组中的对象引用指向同一对象，这个引用语义要明确。

## 易错点

- 为“按性别”和“按年龄”各复制一套循环，没有抽出变化规则。
- 把 selector 限死为字段名，导致年龄段、组合条件等计算分组又要改主流程。
- 直接用普通对象并忽略 `__proto__` / `constructor` 等特殊键，或把数字 key 和字符串 key 无声合并。
- 声称测试中的人员数组就是“图2原数组”；仓库没有恢复该图片数据，这属于伪造来源。
- 只说 `O(n)`，却不说明结果桶本身需要 `O(n)` 引用空间和元素不是深拷贝。
