# 二维字母表中的单词路径：DFS + 回溯

## 核心结论

仓库图片转写把原题补充为“单词路径（二维字母表，是否存在给定字符串的路径）”，但没有继续保存邻接方向、能否重复使用格子等完整函数契约。这里采用经典单词搜索的最小可执行约定：从任意格子开始，每一步只能上下左右移动到相邻格子，同一个格子在一条路径里最多使用一次；判断是否能按顺序拼出给定字符串。做法是从每个可能起点 DFS，进入格子时标记 `visited`，分支失败后回溯清除。

## 1 分钟版

- 枚举每个格子作为起点；只有当前字符等于 `word[index]` 才继续。
- DFS 状态是 `(row, col, index)`，同时用 `visited` 表示当前路径已经占用的格子。
- 当前字符匹配且 `index == word.length()-1` 时成功。
- 否则尝试上、下、左、右四个邻居；越界、已访问、字符不匹配都直接剪枝。
- 返回上一层前必须撤销 `visited[row][col]`，否则不同搜索分支会互相污染。
- 最坏时间可写为 O(R×C×4^L) 的上界，实际因为不能立即复用格子会更小；额外空间 O(R×C + L)。

## 3 分钟版

```java
public final class WordPath {
    private static final int[][] DIRS = {
        {1, 0}, {-1, 0}, {0, 1}, {0, -1}
    };

    public static boolean exists(char[][] board, String word) {
        if (word == null || board == null) {
            return false;
        }
        if (word.isEmpty()) {
            return true;
        }
        if (board.length == 0 || board[0].length == 0) {
            return false;
        }

        int cols = board[0].length;
        for (char[] row : board) {
            if (row == null || row.length != cols) {
                throw new IllegalArgumentException("board must be rectangular");
            }
        }

        boolean[][] visited = new boolean[board.length][cols];
        for (int r = 0; r < board.length; r++) {
            for (int c = 0; c < cols; c++) {
                if (dfs(board, word, r, c, 0, visited)) {
                    return true;
                }
            }
        }
        return false;
    }

    private static boolean dfs(
            char[][] board,
            String word,
            int r,
            int c,
            int index,
            boolean[][] visited) {
        if (r < 0 || r >= board.length
                || c < 0 || c >= board[0].length
                || visited[r][c]
                || board[r][c] != word.charAt(index)) {
            return false;
        }
        if (index == word.length() - 1) {
            return true;
        }

        visited[r][c] = true;
        for (int[] d : DIRS) {
            if (dfs(board, word, r + d[0], c + d[1], index + 1, visited)) {
                visited[r][c] = false;
                return true;
            }
        }
        visited[r][c] = false;
        return false;
    }
}
```

例如经典字母表 `A B C E / S F C S / A D E E` 中，`ABCCED` 和 `SEE` 可以由相邻格子连接得到，而 `ABCB` 需要重复使用已经走过的 `B`，在“不重复使用格子”的契约下返回 false。

## 关键细节

- **起点不固定**：必须扫描整个二维表，因为路径可以从任意匹配首字符的位置开始。
- **路径级 visited**：标记只对当前 DFS 路径有效；回溯时撤销，别的起点和别的分支才能再次使用该格子。
- **成功分支也恢复**：即使已经找到答案，本实现返回前也撤销当前 `visited`，保持调用结束时辅助状态干净。
- **不修改输入**：也可以临时把 `board[r][c]` 改成哨兵字符来省 `visited` 数组，但要保证恢复；本候选选择独立布尔数组，避免修改调用方棋盘。
- **矩形检查**：来源没有 ragged array 语义；本候选要求 Java 二维数组每行等长，非法形状显式拒绝。
- **空字符串**：来源未规定。本候选把空字符串视为可由空路径匹配，因此返回 true；若面试平台保证 word 非空，这个分支不会触发。
- **复杂度**：每个格子都可能成为起点，每一步最多尝试四个方向，因此可给 O(R×C×4^L) 的简单上界；`visited` 和递归深度分别为 O(R×C) 与 O(L)。

## 原理机制

DFS 负责枚举“下一步走哪个相邻格子”，回溯负责撤销这个选择。核心不变量是：进入 `dfs(..., index, visited)` 时，`visited` 精确表示当前前缀路径已经使用的格子；当前格子匹配后才把它加入路径，离开本层时再恢复。

字符不匹配、越界和重复使用都是不可能产生合法后缀的状态，因此可以立即剪枝。正是这些局部约束，把暴力枚举所有坐标序列缩小成只搜索相邻且不重复的候选路径。

## 项目经验版

来源没有真实项目场景，不能虚构。类似回溯模型可以映射到网格搜索、拼图或约束路径问题，但真实系统还要关注输入规模、递归深度和是否需要返回具体路径；本题只要求存在性判断，不需要把所有路径保存下来。

## 常见追问

- 问：为什么不能只用一个全局 visited，不回溯？答：同一个格子不能在“一条路径”里重复，但可以出现在另一条候选路径里；全局永久标记会错误剪掉合法答案。
- 问：能不能原地修改 board 标记访问？答：可以，把当前字符临时替换成不可能出现的哨兵并在返回前恢复，可省去 O(R×C) visited；但会短暂修改输入，本候选选择不修改。
- 问：如果允许斜着走怎么办？答：把方向集合从 4 个扩展到 8 个，DFS/回溯框架不变，但搜索分支数和复杂度上界会改变。
- 问：如果同一个格子允许重复使用呢？答：去掉路径级 visited 约束，但要重新考虑循环和最大路径长度；当前 word 长度仍能限制递归深度。
- 问：如果要返回具体路径而不是 boolean？答：额外维护坐标列表，在选择时 append、回溯时 remove，成功时复制或返回该路径。

## 易错点

- 匹配成功后忘记回溯 visited，后续调用或分支状态被污染。
- 把“当前路径不可重复”写成“整个搜索过程中格子永远不可再用”。
- 只从左上角或第一个首字符开始搜，漏掉其他起点。
- 越界检查晚于数组访问，导致异常。
- 来源没有明确斜向移动、重复使用或空字符串语义，却把自己的实现约定冒充成原题条件。
