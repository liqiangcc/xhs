# 二叉树中序遍历

## 核心结论

仓库原始来源只保留了“二叉树中序遍历”，没有规定节点类型、递归/迭代方式、返回 API、空树行为或实现语言。这里显式采用候选契约：节点值为 `int`；Java API 返回 `List<Integer>`；空树返回空列表；遍历顺序是左子树 → 当前节点 → 右子树；不修改输入树。

递归写法直接把定义翻译成代码；迭代写法用显式栈保存“左链上尚未访问自身和右子树”的节点：不断向左压栈，左边走到底后弹栈访问当前节点，再转向它的右子树。两种实现都访问每个节点一次，时间复杂度 `O(n)`；除输出外，递归调用栈或显式栈最坏都为 `O(h)`，其中 `h` 是树高。

## 1 分钟版

中序遍历的顺序就是“左—根—右”。

递归实现很直接：先递归左子树，再记录当前值，再递归右子树。迭代实现用一个栈模拟同样的控制流：只要当前节点不为空，就一路把左链压栈；当前为空时，弹出栈顶并输出它，然后把当前指针切到这个节点的右孩子，再重复。

栈里保存的是已经到达、但因为左子树还没处理完，所以暂时不能输出的节点。这个不变量保证弹栈时，它的左侧已经完成，而右侧还没开始，因此输出次序与递归定义一致。

## 3 分钟版

原题只给出“二叉树中序遍历”这个目标，因此不能把“必须递归”“必须非递归”“节点是某个在线题库的固定类”当作来源事实。候选答案把接口收窄为 Java 的 `Node(int value)` 和 `List<Integer>`，并明确空树返回空列表、输入树不被修改。

递归版 `inorderRecursive(node)` 的正确性来自结构定义：对任意节点，先得到它左子树的中序序列，再追加当前值，最后追加右子树的中序序列。叶子和空树自然落到终止条件。

迭代版把递归调用栈显式化。外层循环条件是“当前节点非空或者栈非空”。内层先沿左指针不断压栈；走到空指针后，栈顶就是当前尚未访问节点里左子树已经处理完成、最应该被访问的节点。弹栈输出后转向右子树，再对右子树重复同样过程。

每个节点恰好入栈、出栈和输出一次，所以时间是 `O(n)`；栈大小最多等于一条根到叶路径，即 `O(h)`。输出列表本身需要 `O(n)` 空间，不应混在辅助空间里。

## 关键细节

- **题源边界**：来源只支持“二叉树中序遍历”；`int` 值、Java、返回值列表、空树返回空列表和不修改输入都是显式候选选择。
- **递归不变量**：一个调用完成后，结果中该子树节点的相对次序是“左子树全部节点 → 根 → 右子树全部节点”。
- **迭代栈含义**：栈中节点已经被发现，但仍在等待其左子树完成；弹出节点时才能访问自身。
- **循环条件**：必须是 `current != null || !stack.isEmpty()`；只检查当前指针会在走到最左端时提前结束。
- **访问时机**：节点应在弹栈后、进入右子树前输出；压栈时输出会变成先序风格。
- **复杂度**：两种实现都为 `O(n)` 时间；辅助空间最坏 `O(h)`，极度倾斜树时 `h = n`。
- **可验证性**：固定边界用例覆盖空树、单节点、平衡树、左右倾斜树和重复值；再生成 5000 棵确定性随机树，让迭代实现与独立递归 oracle 完全一致，并比较遍历前后结构序列确认无修改。

## 原理机制

```java
public static List<Integer> inorderIterative(Node root) {
    List<Integer> result = new ArrayList<>();
    Deque<Node> stack = new ArrayDeque<>();
    Node current = root;

    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            stack.push(current);
            current = current.left;
        }
        Node node = stack.pop();
        result.add(node.value);
        current = node.right;
    }
    return result;
}
```

用于差分验证的递归 oracle 采用不同的控制流：

```java
private static void inorderRecursive(Node node, List<Integer> out) {
    if (node == null) {
        return;
    }
    inorderRecursive(node.left, out);
    out.add(node.value);
    inorderRecursive(node.right, out);
}
```

固定用例和 5000 棵随机树的预检输出为：

```text
PASS fixed=6 randomized=5000 oracle=recursive-inorder mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有生产项目上下文，因此不编造项目经历。工程代码里选择递归还是迭代，主要取决于树高是否可能很深、调用栈风险以及代码可读性；无论选择哪一种，都应先固定遍历契约和是否允许修改节点。

## 常见追问

- **中序遍历为什么是左—根—右？** 这是中序遍历的定义；对每个子树都递归应用同一顺序。
- **迭代版的栈为什么能替代递归？** 递归调用本来就需要保存“当前节点处理到哪一步”的上下文；显式栈保存了等待左子树完成后再访问的祖先节点。
- **什么时候弹栈？** 当前指针一路向左走到空时弹栈，此时栈顶节点的左子树已经全部完成。
- **空树返回什么？** 当前候选约定返回空列表；这是 API 选择，不是原始来源明示的要求。
- **空间复杂度为什么是 `O(h)` 而不是 `O(n)`？** 辅助栈最多同时保存一条未完成的祖先链；平衡树约为 `O(log n)`，倾斜树最坏为 `O(n)`。输出列表另占 `O(n)`。

## 易错点

- 把节点压栈时就输出，导致次序变成根优先。
- 弹栈输出后忘记转向右子树。
- 外层循环只写 `current != null`，走到最左端后遗漏栈内祖先。
- 把输出数组计入辅助栈复杂度，混淆输出空间和工作空间。
- 为了遍历临时改写左右指针，却没有在契约中说明会修改输入。
