# 删除排序链表中的重复元素 II：整段跳过重复值

## 核心结论

来源只保留“删除排序链表中的重复元素 II (LeetCode 82)”。本答案按该题的标准语义处理：输入链表按值非递减排序；凡某个值出现超过一次，该值对应的所有节点都删除，只保留原链表中只出现一次的值。Java 的 `ListNode` 结构、是否允许复用原节点以及空链表行为没有在来源中展开，因此这里明确采用答案侧契约：原地重连现有节点、允许 `head == null`、不新建结果节点，只额外使用一个虚拟头节点和常数个指针。

核心做法是利用“已排序”这一条件：相同值一定连续出现。让 `prev` 始终指向当前已经确认保留部分的尾节点，让 `cur` 扫描待处理段。如果 `cur` 后面还有相同值，就把这一整段相同值全部跳过，并令 `prev.next` 指向下一段；如果 `cur` 没有重复，则把它纳入保留部分并前移 `prev`。

## 1 分钟版

- 因为链表有序，重复值必然连续，所以只需要一次线性扫描。
- 加一个 `dummy -> head`，这样“头部就是重复段”的情况和中间重复段可以统一处理。
- `prev` 指向最后一个确定保留的节点，`cur` 指向当前待判断节点。
- 先向后吃完整个与 `cur.val` 相同的连续段；若段长度大于 1，则 `prev.next = cur.next`，整段删除。
- 若当前值只出现一次，就令 `prev = prev.next`，保留该节点。
- 最后 `cur = cur.next` 继续扫描。
- 时间复杂度 `O(n)`，每个节点最多被扫描常数次；额外空间 `O(1)`。

## 3 分钟版

```java
static final class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }

    ListNode(int val, ListNode next) {
        this.val = val;
        this.next = next;
    }
}

static ListNode deleteDuplicates(ListNode head) {
    ListNode dummy = new ListNode(0, head);
    ListNode prev = dummy;
    ListNode cur = head;

    while (cur != null) {
        boolean duplicated = false;

        while (cur.next != null && cur.val == cur.next.val) {
            duplicated = true;
            cur = cur.next;
        }

        if (duplicated) {
            prev.next = cur.next;
        } else {
            prev = prev.next;
        }

        cur = cur.next;
    }

    return dummy.next;
}
```

例如 `1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5`：扫描到 `3` 时发现连续重复，`cur` 会移动到最后一个 `3`，然后 `prev.next` 直接接到第一个 `4`；随后 `4` 也整段跳过，最终得到 `1 -> 2 -> 5`。对于 `1 -> 1 -> 1 -> 2 -> 3`，虚拟头节点可以直接跨过开头整段 `1`，得到 `2 -> 3`。

## 关键细节

- **题目是 II，不是 LeetCode 83**：这里不是“每个重复值保留一个”，而是“只要某个值出现多次，这个值的所有节点都删除”。
- **排序条件是算法成立的关键**：只有在相同值连续时，才能通过扫描一段来判断整个值是否应该删除；未排序链表需要额外计数或其他策略。
- **`prev` 不能在重复段里前移**：它必须停在最后一个确定保留节点，这样才能一次把整段重复节点摘掉。
- **`cur` 要先走到重复段最后一个节点**：否则只跳过一个节点会留下同值节点，退化成另一道题的语义。
- **虚拟头节点统一首部删除**：如果开头就是重复段，不需要单独修改 `head` 的特殊分支。
- **原地重连**：本实现复用原节点，只修改 `next`；如果调用方要求输入结构完全不可变，就需要构造新链表，这是不同契约。
- **整数值本身无特殊限制**：虚拟头的 `0` 只是哨兵值，从不参与与业务节点的相等判断，因此即使链表里存在 `0` 也不影响结果。

## 原理机制

维护不变量：进入每轮外层循环时，`dummy.next ... prev` 这一段已经处理完，并且其中只包含在原输入中确认应保留的唯一值节点；`cur` 是下一个尚未分类的值段起点。

由于输入有序，从 `cur` 开始所有相同值形成一个连续区间。内层循环把 `cur` 推到该区间末尾，因此可以准确知道该区间长度是否大于 1。若重复，`prev.next = cur.next` 直接让已确认前缀跳过整个区间，不变量继续成立；若不重复，把当前唯一节点纳入前缀并前移 `prev`。每轮最后把 `cur` 移到下一值段起点。扫描结束时没有未处理节点，因此 `dummy.next` 恰好由所有只出现一次的值节点组成。

## 项目经验版

来源只有算法题，没有真实项目背景，因此不虚构生产经历。工程里如果有“已按 key 排序的单链式记录流，需要删除所有冲突 key 而不是做去重保留”的场景，可以复用同一个思想：依赖排序保证相同 key 连续，先识别完整 run，再决定整段保留或丢弃。若输入没有排序保证，就不能直接套这个指针算法，应先明确是否允许排序、是否能用哈希计数，以及内存约束。

## 常见追问

- 问：为什么需要 dummy？答：它让头节点参与删除时仍然有一个稳定的前驱节点，首部重复段和中间重复段可以走同一套逻辑。
- 问：和“删除排序链表中的重复元素 I / LeetCode 83”有什么区别？答：83 对重复值保留一个节点；82 要把出现过重复的值全部删除。例如 `1,1,2`，83 得到 `1,2`，82 得到 `2`。
- 问：为什么是 O(n) 而不是内外循环 O(n²)？答：内层循环虽然嵌套在外层中，但 `cur` 只单向前进，每个节点最多被访问常数次，总移动次数与节点数线性相关。
- 问：可以只比较 `cur` 和 `cur.next` 然后逐个删吗？答：可以设计其他正确写法，但必须保证知道整个值是否重复；如果删除到只剩最后一个同值节点再误把它保留，就会违反 II 的语义。
- 问：如果链表未排序怎么办？答：相同值不再连续，当前算法失去“整段就是一个值”的前提；可先统计频次后再重连，通常需要 O(n) 额外空间，或在允许改变顺序时先排序。
- 问：会不会产生环？答：算法只把 `prev.next` 指向当前重复段之后原本就存在的后继节点，且所有指针都沿原链表向前移动，不会反向连接；验证时仍应对输出做无环检查。

## 易错点

- 把题意做成“重复值保留一个”，误答成 LeetCode 83。
- 遇到重复只删除当前节点，没有跳过整个同值连续段。
- 重复段处理后仍然前移 `prev`，导致 `prev` 指向本应删除的节点。
- 没有 dummy，首部连续重复时写出多套容易出错的特殊分支。
- 忽略“排序链表”前提，却宣称算法适用于任意链表。
- 看到两层 `while` 就误判为 `O(n²)`，没有按指针总移动次数分析。
