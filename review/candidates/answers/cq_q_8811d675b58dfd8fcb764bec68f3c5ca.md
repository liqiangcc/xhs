# 删除有序数组中的重复项：O(1) 额外空间原地压缩

## 核心结论

数组已经有序，因此相同值一定连续出现；不需要额外集合就能去重。维护读指针扫描原数组、写指针指向“下一个唯一值应写入的位置”。每当当前值与已保留的最后一个值不同，就把它写到写指针并推进写指针。题目只明确“删除有序数组中的重复项”和 `O(1)` 额外空间，没有给函数签名或尾部语义；这里采用一个明确的回答契约：原地修改 `int[]`，返回唯一元素个数 `k`，`nums[0..k)` 保存升序唯一值，`k` 之后的内容不作保证。

## 1 分钟版

- 有序性是关键：重复元素相邻，所以只需要比较当前读到的值和最后一个已经保留的值。
- 空数组返回 `0`；非空时先保留 `nums[0]`，令 `write=1`，然后 `read` 从 `1` 扫到末尾。
- 若 `nums[read] != nums[write-1]`，说明遇到新的唯一值，执行 `nums[write++] = nums[read]`。
- 循环结束时 `write` 就是唯一元素个数，且前 `write` 个位置是去重后的有序结果。
- 全程只使用常数个变量，因此时间 `O(n)`、额外空间 `O(1)`；尾部旧数据不属于结果。

## 3 分钟版

```java
public final class SortedArrayDeduplicator {
    private SortedArrayDeduplicator() {}

    public static int deduplicate(int[] nums) {
        if (nums == null) {
            throw new IllegalArgumentException("nums must not be null");
        }
        if (nums.length == 0) {
            return 0;
        }

        int write = 1;
        for (int read = 1; read < nums.length; read++) {
            if (nums[read] != nums[write - 1]) {
                nums[write] = nums[read];
                write++;
            }
        }
        return write;
    }
}
```

不变量是：进入每次循环时，`nums[0..write)` 恰好等于已经扫描过的前缀中的所有不同值，并且仍然严格递增；`write` 也是这个唯一前缀的长度。由于输入非递减，若 `nums[read]` 等于 `nums[write-1]`，它只能是当前最后一个唯一值的重复项，跳过不会漏值；若不等，则它一定是新的更大值，写入后不变量继续成立。循环覆盖全部元素后，不变量直接给出结果。

## 关键细节

- **输入前提**：来源明确说“有序数组”；这里按非递减整数数组解释。若输入无序，不能使用“只和最后唯一值比较”来证明正确性。
- **输出契约**：来源没有规定返回形式。这里返回 `k`，只承诺 `nums[0..k)`；不要把 `k` 之后的残留值解释成结果。
- **原地含义**：允许覆盖数组已经扫描过或当前可安全覆盖的位置，但不分配随 `n` 增长的容器；几个整数变量属于 `O(1)` 额外空间。
- **重复很多**：例如 `[1,1,1,1]`，`write` 始终为 `1`，结果前缀只有一个 `1`。
- **没有重复**：每次都写回相同位置或后续位置，最终 `k=n`，内容保持不变。
- **负数与极值**：算法只比较 `int` 是否相等，不做加减运算，因此 `Integer.MIN_VALUE` / `MAX_VALUE` 不引入溢出问题。
- **复杂度**：每个元素最多读一次、每个唯一元素最多写一次，时间 `O(n)`；额外变量数量固定，空间 `O(1)`。

## 原理机制

这其实是“稳定原地压缩”。读指针负责发现新类别，写指针维护已经压缩好的有效前缀。有序性把“这个值之前是否出现过”的全局问题降成了“它是否等于当前最后一个唯一值”的局部判断，因此不需要 `HashSet`。同时始终有 `write <= read + 1`，写入位置不会越过尚未读取的数据，所以原地覆盖是安全的。

## 项目经验版

来源没有提供真实项目场景，不能虚构线上经历。工程里若要处理大块已排序数据，我会先确认“原地修改是否允许、后半段是否必须清零、数据类型是否允许比较、结果是否需要保留原索引”等契约；这些条件会决定能否直接使用这种双指针压缩，不能把本题的最小契约外推成所有去重任务的通用接口。

## 常见追问

- 问：为什么不用 `HashSet`？答：有序性让重复项连续，只比较最后一个保留值就能判断是否重复；`HashSet` 会引入 `O(n)` 级额外空间，不符合题目要求。
- 问：为什么比较 `nums[write-1]`，而不是固定比较 `nums[read-1]`？答：两者在严格有序扫描中都可构造正确写法，但 `nums[write-1]` 直接表达“最后一个已经保留的唯一值”，与有效前缀不变量一致。
- 问：数组尾部需要清零吗？答：来源没有要求；当前契约只保证前 `k` 个位置有效。若调用方要求清零，那是额外的输出契约，可以在得到 `k` 后处理，但不应冒充原题要求。
- 问：输入 `[1,1,2,2,3]` 会怎样？答：依次保留 `1、2、3`，返回 `3`，数组前缀变成 `[1,2,3]`，后面的值不保证。
- 问：如果数组没有排序呢？答：这个不变量失效；若仍要求保持首次出现顺序，通常需要额外集合，或者接受更高时间复杂度，具体取决于可修改性和空间约束。

## 易错点

- 忽略“有序”前提，把相邻比较方法用于任意无序数组。
- 为了去重创建与输入规模相关的 `Set` 或新数组，违反 `O(1)` 额外空间要求。
- 忘记空数组，直接把 `write` 初始化为 `1` 后返回错误长度。
- 返回新长度后仍把整个原数组当成去重结果，误读尾部残留值。
- 在遍历时执行删除/搬移整段数组，导致最坏 `O(n²)`，而双指针只需线性扫描。
