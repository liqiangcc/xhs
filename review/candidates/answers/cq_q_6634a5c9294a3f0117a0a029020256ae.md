# LeetCode 198：打家劫舍（House Robber）

## 核心结论

这是线性动态规划：走到第 `i` 间房时只有两种合法选择——不偷它，最优值仍是前 `i-1` 间的最优值；偷它，则第 `i-1` 间不能偷，收益是前 `i-2` 间的最优值加 `nums[i]`。因此状态转移是 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`。只依赖前两个状态，可以把空间从 O(n) 压到 O(1)，时间仍为 O(n)。

## 1 分钟版

- 状态：`dp[i]` 表示考虑到第 `i` 间房时，满足“不能偷相邻房屋”的最大金额。
- 不偷第 `i` 间：得到 `dp[i-1]`。
- 偷第 `i` 间：第 `i-1` 间必须跳过，得到 `dp[i-2] + nums[i]`。
- 二者取最大值：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`。
- 因为每一步只看前两个状态，用 `prev2`、`prev1` 滚动即可，时间 O(n)、额外空间 O(1)。
- 题源明确给出非负金额和“不进入相邻房屋”的约束；空数组、`null` 等接口行为没有在题源中规定，下面的 Java 示例把空数组定义为 0、把 `null` 明确拒绝，这属于示例接口契约而不是题源事实。

## 3 分钟版

设 `prev2` 是处理到当前位置前两间房的最优值，`prev1` 是处理到前一间房的最优值。遍历当前金额 `money` 时：

```java
final class HouseRobberSolution {
    static long rob(int[] nums) {
        if (nums == null) {
            throw new IllegalArgumentException("nums must not be null");
        }
        long prev2 = 0;
        long prev1 = 0;
        for (int money : nums) {
            long current = Math.max(prev1, prev2 + money);
            prev2 = prev1;
            prev1 = current;
        }
        return prev1;
    }
}
```

为什么这个转移是完整的？对第 `i` 间房，任意合法最优解要么不包含它，要么包含它，不存在第三种情况。不包含它时问题退化为前 `i-1` 间的最优解；包含它时由于相邻限制，必须排除第 `i-1` 间，剩余部分就是前 `i-2` 间的最优解，再加当前金额。两种互斥且穷尽的情况取最大值，就得到前 `i` 间的最优解。

## 关键细节

- **状态含义要一致**：这里的状态是“前缀范围内的最大合法金额”，不是“必须偷第 `i` 间时的最大金额”。
- **更新顺序**：先用旧的 `prev2`、`prev1` 算 `current`，再执行 `prev2 = prev1; prev1 = current;`，否则会混用当前轮状态。
- **边界**：滚动写法天然支持空数组返回 0、单元素返回该元素；这是示例实现明确添加的接口边界。题源本身只保存了非负金额数组的核心契约。
- **数值范围**：示例把累计结果放在 `long`，避免在输入规模未保存时把 `int` 累加安全性当作无条件事实；真实平台若给出更窄约束，可再收紧类型。
- **不需要贪心**：不能只比较相邻两间后选较大者。例如 `[2, 1, 1, 2]` 的最优解是首尾两间，总额 4；局部选择规则不能表达跨位置组合。
- **不修改输入**：实现只读取 `nums`，不需要改写数组。

## 原理机制

这题的关键是最优子结构。把前 `i` 间房的最优解按“是否选择第 `i` 间”分类后，两类都能由更短前缀的最优解构造。由于限制只涉及相邻位置，决定当前位置时不需要记住完整选择历史，只需保留前两个前缀最优值，因此状态可以压缩。

从不变量看，每轮开始时：`prev1` 等于已经处理前缀的最大合法金额，`prev2` 等于再少一间房的最大合法金额。`current = max(prev1, prev2 + money)` 恰好覆盖“不偷当前”和“偷当前”两类合法解。更新后同一个不变量对下一轮继续成立；遍历结束时 `prev1` 就是整个数组的答案。

## 项目经验版

题源没有提供真实项目经历、线上规模或性能数据，不能虚构。若把这个机制映射到工程场景，它适用于“线性资源中相邻项互斥、目标最大化权重和”的抽象模型；是否真的能用于某个业务，必须先验证业务约束是否只有相邻互斥，不能因为形式相似就直接套用。

## 常见追问

- 问：为什么不是 `dp[i-1] + nums[i]`？答：如果偷第 `i` 间，就不能偷第 `i-1` 间，因此要接在 `dp[i-2]` 后面。
- 问：为什么 O(1) 空间就够？答：第 `i` 个状态只依赖 `i-1` 和 `i-2` 两个状态，旧的更早状态不会再被读取。
- 问：能不能贪心地每次挑相邻两间里金额大的？答：不能。`[2,1,1,2]` 的全局最优是 4，局部相邻选择不能保证全局最优。
- 问：如果房屋首尾也相邻呢？答：那是环形版本（通常对应 House Robber II），当前两个题源都只保存线性 House Robber / LeetCode 198 契约，不能把环形约束混进本题；环形版本通常需要拆成“不选首”与“不选尾”两个线性子问题。
- 问：如果金额允许负数呢？答：当前显式题源给的是非负整数数组。若业务允许负数，还要先确认“可以一间都不选吗”等契约；不能直接把未给出的负数语义算进原题。
- 问：怎么证明转移没漏解？答：所有合法解按是否包含当前房屋分成两类；两类互斥且覆盖全部合法解，各自都由更短前缀的最优解给出，因此取最大值就是当前前缀最优解。

## 易错点

- 把“不能偷相邻房屋”误写成“连续两间只能选金额更大的那间”，从 DP 偷换成不成立的局部贪心。
- 滚动变量更新顺序错误，导致 `prev2` 已经变成当前轮值后再参与计算。
- 状态定义含糊，一会儿表示“前缀最优”，一会儿表示“必须选择当前”，最终得到错误转移。
- 把 House Robber II 的首尾相邻条件混入 LeetCode 198。
- 题源没有规定 `null`、异常或具体语言，却把示例接口行为描述成原题要求。
