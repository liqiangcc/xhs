# 二叉树路径和

## 核心结论

仓库原始来源只保留了“二叉树路径和”这个题名，没有保留目标值、路径方向、返回“是否存在/数量/具体路径”、节点类型、语言或函数签名。因此这里不把任何常见在线题契约冒充原题，而是明确采用一个候选契约：给定一棵节点值为 `int` 的二叉树和一个 `long target`，判断是否存在一条**从根到叶子**的路径，使路径节点值之和等于 `target`；空树返回 `false`；不修改输入树。

在这个契约下，递归只需要维护“剩余目标值”。访问节点 `node` 时令 `remaining = target - node.value`：如果它是叶子，就检查 `remaining == 0`；否则把同一个子问题递归交给左右孩子，只要任一分支成立就返回 `true`。

## 1 分钟版

这道题的关键不是先背某个题号，而是先把“路径和”契约说清楚。这里选择“根到叶路径是否存在”这一版本。

递归函数 `hasPathSum(node, target)` 做三件事：

1. `node == null`：没有路径，返回 `false`。
2. 计算 `remaining = target - node.value`；如果当前节点是叶子，只有 `remaining == 0` 才成功。
3. 非叶子继续检查左子树或右子树是否存在满足剩余目标值的根到叶路径。

最坏情况下每个节点访问一次，时间 `O(n)`；递归辅助空间等于树高 `O(h)`，平衡树约 `O(log n)`，退化树最坏 `O(n)`。

## 3 分钟版

来源只写了“二叉树路径和”，所以“目标值”“从根到叶”“返回布尔值”都必须显式声明为候选实现选择。这里选布尔存在性，是为了形成一个完整、可运行、可验证且不声称恢复了缺失题干的答案。

递归不变量是：`hasPathSum(node, t)` 表示“从当前 `node` 出发，是否存在一条到某个叶子的向下路径，其节点和恰好为 `t`”。进入当前节点后先减去 `node.value`。如果当前节点已经是叶子，就没有后续节点可以补偿，因此剩余值必须正好为 0；如果不是叶子，则问题被分成左右两个规模更小、语义完全相同的子问题。

为什么必须检查“叶子”而不能在任意中间节点 `remaining == 0` 就返回成功？因为当前候选契约要求路径走到叶子。比如根到某个内部节点的前缀和刚好等于目标，但下面仍有孩子，这条前缀不能被当作完整根到叶路径。

实现使用 `long` 保存目标和剩余值，避免两个 `int` 节点值相加时把路径和限制在 `int` 范围。节点值本身仍选择 `int`。这同样是候选 API 选择，不是题源事实。

## 关键细节

- **题源边界**：来源只支持题名“二叉树路径和”；根到叶、存在性、目标值、Java、`int` 节点与 `long target` 都是明确候选选择。
- **叶子条件不能省略**：在当前契约下，只有完整根到叶路径才算答案；内部节点前缀和命中不能提前成功。
- **允许负数和 0**：算法不依赖单调性，不做“剩余值小于 0 就剪枝”这类只适用于非负节点的假设。
- **不修改输入**：递归只读取节点和值。
- **复杂度**：最坏访问全部 `n` 个节点，时间 `O(n)`；辅助空间是递归深度 `O(h)`。
- **可验证性**：固定用例覆盖空树、单节点、多个命中路径、仅内部前缀命中、负数、0 和整数边界；再用 5000 组确定性随机树与独立迭代枚举 oracle 对照，并在调用前后序列化树验证无修改。

## 原理机制

```java
public final class BinaryTreePathSum {
    public static final class Node {
        public final int value;
        public Node left;
        public Node right;

        public Node(int value) {
            this.value = value;
        }
    }

    private BinaryTreePathSum() {}

    public static boolean hasPathSum(Node root, long target) {
        if (root == null) {
            return false;
        }
        long remaining = target - root.value;
        if (root.left == null && root.right == null) {
            return remaining == 0L;
        }
        return hasPathSum(root.left, remaining)
            || hasPathSum(root.right, remaining);
    }
}
```

独立验证 oracle 不使用“剩余目标”递归，而是用显式栈枚举所有根到叶路径并累计路径和。固定测试和 5000 组随机树的预检输出为：

```text
PASS fixed=10 randomized=5000 oracle=iterative-root-to-leaf-enumeration mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有生产项目上下文，因此不编造项目经历。工程中若树可能极深，递归实现要考虑调用栈上限，可改成显式栈；如果真实题目要求“路径数量”“输出所有路径”或“任意起终点路径”，状态和返回值都需要相应改变，不能直接把当前候选答案当成这些变体。

## 常见追问

- 问：为什么一定要到叶子？答：这是当前候选契约的显式选择，不是从题源恢复出的隐藏条件；因此代码必须在叶子处判断完成。
- 问：节点有负数还能做吗？答：可以。当前实现没有使用剩余值单调递减的剪枝，所以负数不会破坏正确性。
- 问：为什么目标用 `long`？答：这是为了让多个 `int` 节点之和不因 `int` 加法溢出而改变语义，是候选 API 的安全选择。
- 问：如果题目改成返回所有满足的路径呢？答：需要维护当前路径列表，并在叶子命中时复制结果；复杂度还要计入输出规模。
- 问：如果题目是任意节点之间的路径和呢？答：当前“从根向下”的递归不变量不再适用，需要重新定义路径方向和状态，不能只改函数名。

## 易错点

- 把内部节点的前缀和命中误当成根到叶路径完成。
- 默认节点全为非负数并做错误剪枝。
- 用 `int` 累计长路径和而未考虑溢出。
- 修改节点值来保存剩余目标，污染输入树。
- 声称原题就是某个在线题号、要求根到叶存在性或指定 Java，而仓库来源并没有这些信息。
