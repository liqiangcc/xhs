# 用 XOR 找出出现奇数次的数字

## 核心结论

题源只说明“多数数字出现偶数次、少数数字出现奇数次”，没有保存“奇数次数字到底有几个”的约束，因此不能把某一个经典题型冒充成唯一原题。位运算的核心事实是：相同整数异或偶数次会抵消为 0，0 与 x 异或仍是 x。于是：若恰好一个值出现奇数次，全部异或即可得到它；若恰好两个值出现奇数次，可先得到 `a ^ b`，再用其中一个为 1 的位把数组分组，分别异或恢复 a、b；若奇数次值的数量不固定且可能大于 2，仅靠一个总 XOR 不足以恢复全部值，需要额外约束或频次表。

## 1 分钟版

- `x ^ x = 0`，偶数次出现的值两两抵消；异或满足交换律和结合律，所以输入顺序不影响结果。
- **恰好一个奇数次值**：扫描一次，`xor ^= x`，最终 `xor` 就是答案，时间 O(n)、额外空间 O(1)。
- **恰好两个奇数次值**：总 XOR 为 `a ^ b` 且非 0；取 `lowbit = xor & -xor`，a、b 在这一位必然不同。按该位是否为 0 分组，每组内部偶数次元素仍成对抵消，最终得到 a 和 b。
- **任意多个奇数次值**：题源若没有数量上界，不能声称上述 O(1) 状态能找全。通用办法是用哈希表统计频次，再筛选奇数频次。
- Java `int` 的 XOR 对正负数都按位工作；`xor & -xor` 在二进制补码下也能提取最低位的 1，包括最高位为唯一 1 的情况。

## 3 分钟版

```java
final class OddFrequencyNumbers {
    static int findOneOdd(int[] nums) {
        if (nums == null) throw new IllegalArgumentException("nums must not be null");
        int xor = 0;
        for (int x : nums) xor ^= x;
        return xor;
    }

    static int[] findTwoOdd(int[] nums) {
        if (nums == null) throw new IllegalArgumentException("nums must not be null");
        int xor = 0;
        for (int x : nums) xor ^= x;
        if (xor == 0) {
            throw new IllegalArgumentException("contract requires exactly two distinct odd-frequency values");
        }
        int lowbit = xor & -xor;
        int a = 0;
        int b = 0;
        for (int x : nums) {
            if ((x & lowbit) == 0) a ^= x;
            else b ^= x;
        }
        return new int[]{a, b};
    }
}
```

对“一个奇数次值”，循环不变量是：处理前 k 个元素后，`xor` 等于这 k 个元素按频次奇偶性保留下来的异或结果；扫描结束时所有偶数频次值都抵消，只剩唯一奇数频次值。

对“两个奇数次值”，先得到 `a ^ b`。因为 a != b，`a ^ b != 0`，必有某一位为 1；选最低这样的位后，a、b 会进入不同组。任何偶数频次值的所有副本拥有相同位值，会完整落在同一组，仍然能成对抵消，因此两个组的最终异或分别是 a、b。

## 关键细节

- **先问数量约束**：一个、两个、还是任意多个奇数次值，决定了是否能用 O(1) 额外空间完成。
- **为什么不能随便挑分组位**：必须从 `a ^ b` 的置 1 位中选，因为只有这些位能保证两个目标值被分开。
- **`xor == 0` 的含义**：在“恰好两个不同奇数次值”的契约下不可能出现；若出现，说明输入不满足契约，而不是应该继续计算一个任意答案。
- **顺序无关**：异或的交换律和结合律允许把相同值在数学上重新配对抵消，不要求它们在数组中相邻。
- **负数不需要特殊分支**：这里处理的是 `int` 位模式，不是十进制字符串；负数同样满足 `x ^ x = 0`。
- **任意多个奇数次值**：总 XOR 只保留这些值的整体异或，信息量不足以唯一反推每个成员；不要把“两数分组技巧”无条件递归成一个没有证明的通用算法。

## 原理机制

XOR 可以看成对每一个二进制位分别做模 2 加法。一个值重复偶数次时，它在每个位上的 1 都出现偶数次，因此对总 XOR 的贡献为 0；重复奇数次时，最终贡献等价于出现一次。

当只有两个奇数频次值 a、b 时，总 XOR 把问题压缩成 `a ^ b`。任取其中一个置 1 位，相当于找到一个能区分 a、b 的二进制特征；按该特征分桶后，每个偶数频次值的副本不会被拆散，所以桶内仍能利用 XOR 抵消。这一步的本质是“用已知差异位构造一个保持偶数配对、不拆散重复值的分区”。

## 项目经验版

题源没有真实项目场景、输入规模或生产数据，不能虚构。工程实现前要先确认数据契约：奇数频次值数量是否固定、输入是否允许空数组、是否需要返回稳定顺序、是否可能违反前提。如果数据来自不可信外部输入，建议增加契约校验或在测试中覆盖违约样例，而不是依赖面试题的隐含前提。

## 常见追问

- 问：为什么一个奇数次值可以直接全异或？答：所有偶数频次值的贡献都抵消为 0，唯一剩余的奇数频次值贡献等价于一次。
- 问：两个奇数次值为什么不能直接从 `a ^ b` 还原？答：`a ^ b` 只给出两者哪些位不同，不唯一确定 a、b；需要再利用一个差异位把原数组分成两组，借助原始频次信息分别恢复。
- 问：为什么 `lowbit = xor & -xor`？答：二进制补码的 `-xor` 会让最低置 1 位与原值共同保留，其更低位为 0，因此按位与得到只含最低置 1 位的掩码。
- 问：如果有三个或更多奇数次值呢？答：仅有总 XOR 时信息不足。若题目没有额外结构，使用哈希表统计每个值的频次是直接可靠的通用方案。
- 问：能处理负数吗？答：可以，XOR 基于 `int` 位模式；只要同一个负数的位模式相同，偶数次仍然抵消。

## 易错点

- 没确认奇数频次值的数量，就直接套“一个数”或“两个数”的经典解法。
- 两数场景随便选择一个分组位，不能保证两个目标值被分开。
- `xor == 0` 时继续计算 `lowbit` 并返回伪结果，而不是识别输入违约。
- 为了处理任意多个奇数次值，机械递归两数分组技巧，却没有信息充分性证明。
- 把 XOR 位运算和十进制数值正负语义混为一谈，给负数增加不必要的特殊规则。
