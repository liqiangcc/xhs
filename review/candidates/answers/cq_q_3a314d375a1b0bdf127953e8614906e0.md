# 两条相交的单向链表：求第一个公共节点

## 核心结论

来源只保留“两条相交的单向链表，如何求第一个公共节点”，没有规定语言、节点类型、是否允许环或“不相交”时的返回方式。这里明确一个答案侧契约：Java、两条**无环**单向链表，以“同一个节点对象”定义公共节点；如果不相交返回 `null`。用两个指针分别从 `headA`、`headB` 出发，走到各自链尾后切换到另一条链表的头部。两个指针最终会在第一个共享节点相遇；若没有共享节点，则会同时到达 `null`。

## 1 分钟版

- 相交指的是节点 identity 相同，不是节点里的 `value` 相等；一旦两个无环单链表共享某个节点，后面的整段后缀都会共享。
- 指针 `a` 走 `A`，到尾后改走 `B`；指针 `b` 走 `B`，到尾后改走 `A`。
- 两个指针都最多走 `len(A)+len(B)` 条路径，因此自动抵消两条链表不同的前缀长度。
- 第一次满足 `a == b` 时，就是第一个公共节点；不相交时两者最终都为 `null`。
- 时间 `O(m+n)`，额外空间 `O(1)`。

## 3 分钟版

```java
public final class LinkedListIntersection {
    private LinkedListIntersection() {}

    public static final class Node {
        public final int value;
        public Node next;

        public Node(int value) {
            this.value = value;
        }
    }

    public static Node firstCommon(Node headA, Node headB) {
        Node a = headA;
        Node b = headB;
        while (a != b) {
            a = (a == null) ? headB : a.next;
            b = (b == null) ? headA : b.next;
        }
        return a;
    }
}
```

设 A 的独有前缀长度为 `x`，B 的独有前缀长度为 `y`，公共后缀长度为 `c`。切换头结点后，两个指针在相遇前分别走过 `x+c+y` 和 `y+c+x`，总路程相同，所以不同前缀造成的长度差被抵消。若存在公共后缀，它们会在该后缀的起点相遇；如果不存在，则在各走完 A+B 后同时变成 `null`。

## 关键细节

- **公共的含义**：必须比较节点引用 `a == b`。两个不同节点即使 `value` 一样，也不是链表的公共节点。
- **为什么相交后不会再分叉**：单向链表节点只有一个 `next`。同一个节点之后的 `next` 链唯一，因此一旦共享一个节点，后续后缀全部共享。
- **边界**：任一头结点为 `null` 时算法仍然成立；两条链表头就是同一对象时立即返回该头；不相交时返回 `null`。
- **无环前提**：当前证明和终止性基于两条链表无环。若输入可能带环，要先定义“第一个公共节点”的路径语义并结合环入口分类处理，不能直接套用这段循环。
- **复杂度**：每个指针最多完整经过 A 和 B 各一次，时间 `O(m+n)`；只用两个节点引用，空间 `O(1)`。
- **替代方法**：也可以先计算两条链表长度，让长链先走长度差再同步前进；同样是 `O(m+n)` / `O(1)`。双指针切头只是把对齐过程隐式完成。

## 原理机制

把每条链表分成“独有前缀 + 公共后缀”。如果 A 是 `A-prefix -> C`，B 是 `B-prefix -> C`，两个前缀可能长短不同，直接同步从头走会错位。让 A 指针走完 A 后接着走 B，让 B 指针走完 B 后接着走 A，相当于让两边都经历同样的总前缀长度 `x+y`。进入共享后缀时，它们已经处于同一个相对位置，因此在 `C` 的第一个节点相遇。

这个机制也解释了“不相交”场景：没有 C 时，两边各走完 A+B 后都到达空指针；`null == null` 结束循环并返回 `null`，不需要额外分支。

## 项目经验版

来源没有真实项目经历，不能虚构“线上用过这道算法”。工程里如果节点来自持久化记录或反序列化对象，需要先确认“公共”到底是对象 identity、稳定 ID 还是业务 key；这道题的标准链表语义是共享同一个节点对象。若实际数据结构允许环、并发修改或多版本节点，必须先重新定义遍历和一致性契约。

## 常见追问

- 问：为什么不能比较节点值？答：值相等只说明数据相同，两个节点仍可能是不同对象；相交要求两条链真正指向同一个节点。
- 问：为什么切换头结点后一定能对齐？答：A 指针走 `A+B`，B 指针走 `B+A`，两边都补上了对方独有前缀的长度差，所以进入公共后缀时位置一致。
- 问：不相交会死循环吗？答：无环前提下不会；最多走完两条链表各一次后，两指针同时为 `null`。
- 问：先算长度可以吗？答：可以。先让长链走 `|m-n|` 步，再同步比较 identity，也能得到 `O(m+n)` 时间和 `O(1)` 空间。
- 问：链表有环怎么办？答：需要先求各自环入口，再按无环/有环组合和环入口是否相同分类；当前来源没有给带环条件，本实现明确限定无环。

## 易错点

- 用 `value` 相等代替节点 identity 相等。
- 切头时写成 `a = headB` 但忘记只有 `a == null` 时才切换，导致跳过正常后继。
- 用哈希集合却仍宣称额外空间 `O(1)`。
- 忽略不相交、空链表、同头结点等边界。
- 在可能有环的链表上直接使用当前循环，却没有重新证明终止性。
- 把 Java、无环前提、`null` 返回策略说成题源明确规定。
