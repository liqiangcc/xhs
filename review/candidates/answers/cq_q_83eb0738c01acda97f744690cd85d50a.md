# 最长回文子串（LeetCode 5）

## 核心结论

回文串关于中心对称，所以不必枚举所有 `O(n^2)` 个子串再逐个做 `O(n)` 回文检查。对长度为 `n` 的字符串，回文中心只有 `2n-1` 种：`n` 个字符中心处理奇数长度回文，`n-1` 个字符间隙处理偶数长度回文。对每个中心向两侧扩展到字符不等为止，记录最长区间即可。

下面采用中心扩展法：时间复杂度最坏 `O(n^2)`，额外空间 `O(1)`（返回子串本身除外）。如果出现多个等长最长答案，本实现固定返回**起始位置最靠前**的那个；这是为了让实现和测试确定，不把它冒充成题目额外要求。

## 1 分钟版

- 回文的关键性质是左右对称，因此枚举“中心”比枚举“子串”更直接。
- 对每个 `i` 分别扩展 `(i,i)` 和 `(i,i+1)`，覆盖奇数、偶数两类回文。
- 扩展条件是 `left >= 0 && right < n && s.charAt(left) == s.charAt(right)`。
- 扩展结束后真实回文区间是 `[left+1, right-1]`，长度为 `right-left-1`。
- 如果新长度更长就更新答案；若等长，本实现只在起点更靠前时更新，保证结果确定。
- 空串返回空串，单字符直接得到自身。
- 中心数量 `O(n)`，单中心最坏扩展 `O(n)`，所以最坏 `O(n^2)`；只保存几个下标，额外空间 `O(1)`。

## 3 分钟版

```java
public final class LongestPalindromicSubstring {
    static String longestPalindrome(String s) {
        if (s == null || s.length() < 2) return s == null ? "" : s;

        int bestStart = 0;
        int bestLen = 1;

        for (int center = 0; center < s.length(); center++) {
            int[] odd = expand(s, center, center);
            int[] even = expand(s, center, center + 1);

            if (better(odd[0], odd[1], bestStart, bestLen)) {
                bestStart = odd[0];
                bestLen = odd[1];
            }
            if (better(even[0], even[1], bestStart, bestLen)) {
                bestStart = even[0];
                bestLen = even[1];
            }
        }
        return s.substring(bestStart, bestStart + bestLen);
    }

    private static int[] expand(String s, int left, int right) {
        while (left >= 0 && right < s.length()
                && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        int start = left + 1;
        int len = right - left - 1;
        return new int[]{start, len};
    }

    private static boolean better(
            int start,
            int len,
            int bestStart,
            int bestLen) {
        return len > bestLen || (len == bestLen && start < bestStart);
    }
}
```

例如 `babad` 有两个长度为 3 的最长回文 `bab` 和 `aba`。题目通常允许任意一个最长答案；本实现按“同长度取最早起点”的确定性规则返回 `bab`。`cbbd` 的最长答案是偶数长度的 `bb`，因此必须同时检查字符间隙中心。

## 关键细节

- **子串不是子序列**：回文字符必须连续，不能跳过中间字符。
- **奇偶中心都要覆盖**：只做 `(i,i)` 会漏掉 `bb`、`abba`；只做 `(i,i+1)` 又会漏掉 `aba`。
- **扩展后的下标**：循环退出时左右指针已经各越过一格，实际区间从 `left+1` 到 `right-1`。
- **等长答案**：最长回文可能不唯一。实现可以返回任意最长答案；这里固定最早起点，只为确定性。
- **空值边界**：LeetCode 原题通常给非空字符串约束，但仓库来源只保留“LeetCode 第5题”。本实现额外对 `null`/空串做安全处理，不把这个扩展契约声称为原题要求。
- **Unicode 边界**：`charAt` 按 UTF-16 code unit 比较。若业务要求按 Unicode code point 或用户感知字符（grapheme cluster）定义回文，需要先改变字符模型；普通 LeetCode 字符串题不需要擅自扩张到该语义。

## 原理机制

任何非空回文都存在唯一的几何中心：奇数长度回文中心落在某个字符上，偶数长度回文中心落在两个字符之间。从一个固定中心开始，只要左右字符相等，就能把当前回文向外扩一层；第一次不等时，以这个中心为中心的更长字符串也不可能是回文，所以该中心的最长答案已经确定。

因此遍历全部 `2n-1` 个中心不会漏解。最坏情况如 `aaaa...a`，很多中心都会扩展接近整个字符串，总比较次数为二次量级；但算法只维护当前左右边界和全局最佳区间，不需要 `O(n^2)` DP 表。

## 项目经验版

来源是算法题，没有真实项目上下文，因此不虚构线上经验。工程上如果只处理普通短字符串，中心扩展实现简单且空间小；如果字符串很长且必须追求线性最坏时间，可以讨论 Manacher 算法，但其半径数组、哨兵变换和实现复杂度更高，是否值得采用取决于真实规模与性能目标。

## 常见追问

- 问：为什么普通滑动窗口不合适？答：回文性质不是随着窗口单调扩大/缩小而保持的约束；窗口加一个字符后是否仍为回文不能只靠一个简单计数状态决定。中心对称性才是直接结构。
- 问：动态规划怎么做？答：可定义 `dp[l][r]` 表示 `s[l..r]` 是否回文，转移为两端字符相等且内部长度小于等于 1 或 `dp[l+1][r-1]` 为真；时间 `O(n^2)`、空间 `O(n^2)`。
- 问：中心扩展为什么不会漏掉最长回文？答：每个回文都有一个字符中心或字符间隙中心，而算法枚举了全部这两类中心并扩展到极限。
- 问：`babad` 应返回 `bab` 还是 `aba`？答：两者长度相同，若题目允许任意最长回文都正确；本实现为了结果确定，选择起点更早的 `bab`。
- 问：能做到 `O(n)` 吗？答：可以用 Manacher 算法在线性时间求每个中心的最大回文半径，但实现复杂度高于中心扩展。
- 问：为什么不能先反转字符串再求最长公共子串？答：公共子串的位置映射必须满足原串中的镜像位置约束；只求原串和反串的最长公共子串可能得到位置不对应的伪回文，不能直接等价替代。

## 易错点

- 把最长回文**子串**写成最长回文子序列。
- 只处理奇数中心，漏掉偶数长度回文。
- 扩展退出后使用错误的 `left/right` 边界，产生 off-by-one。
- 把某个样例的唯一返回值当成题目要求，忽略等长最长答案可能有多个。
- 用 `O(n^3)` 的“枚举所有子串 + 每次重新检查回文”作为最终方案却没有说明复杂度。
- 声称中心扩展是线性时间；`aaaa...a` 会触发最坏 `O(n^2)` 扩展。
