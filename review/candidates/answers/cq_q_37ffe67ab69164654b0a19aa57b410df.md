# 算法：拓扑排序

## 核心结论

来源只保留“手撕拓扑排序”，没有给语言、图的输入格式、顶点编号、是否要求字典序或遇到环时的返回方式。这里明确一个可执行的答案侧契约：Java，顶点编号为 `0..vertexCount-1`，`edges[i] = {from, to}` 表示有向边 `from -> to`；返回任意一个合法拓扑序。如果图里存在有向环，抛出 `IllegalArgumentException`。实现使用 Kahn 算法：先统计每个点的入度，把所有入度为 0 的点入队；每弹出一个点，就删除它的出边并减少邻点入度，新变成 0 的点继续入队。最终输出数量等于顶点数时成功，否则说明至少还有一部分点被环锁住。

## 1 分钟版

- 拓扑排序只对有向无环图有完整排序结果；核心不变量是“入队的点当前入度一定为 0”。
- 先建邻接表并统计 `indegree[to]++`，再把所有入度为 0 的顶点放入队列。
- 每次取出一个点加入答案，遍历它的出边，把对应邻点入度减 1；减到 0 就入队。
- 如果最后处理了全部 `V` 个点，得到合法拓扑序；若只处理了少于 `V` 个点，剩余子图中存在有向环。
- 建图和每条边只处理常数次，所以时间 `O(V + E)`，邻接表、入度、队列和结果总空间 `O(V + E)`。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;

public final class TopologicalSort {
    private TopologicalSort() {}

    public static int[] sort(int vertexCount, int[][] edges) {
        if (vertexCount < 0) {
            throw new IllegalArgumentException("vertexCount must be >= 0");
        }
        if (edges == null) {
            throw new NullPointerException("edges");
        }

        List<List<Integer>> graph = new ArrayList<>(vertexCount);
        for (int i = 0; i < vertexCount; i++) {
            graph.add(new ArrayList<>());
        }
        int[] indegree = new int[vertexCount];

        for (int[] edge : edges) {
            if (edge == null || edge.length != 2) {
                throw new IllegalArgumentException("each edge must contain from and to");
            }
            int from = edge[0];
            int to = edge[1];
            if (from < 0 || from >= vertexCount || to < 0 || to >= vertexCount) {
                throw new IllegalArgumentException("edge endpoint out of range");
            }
            graph.get(from).add(to);
            indegree[to]++;
        }

        ArrayDeque<Integer> queue = new ArrayDeque<>();
        for (int v = 0; v < vertexCount; v++) {
            if (indegree[v] == 0) {
                queue.addLast(v);
            }
        }

        int[] order = new int[vertexCount];
        int size = 0;
        while (!queue.isEmpty()) {
            int v = queue.removeFirst();
            order[size++] = v;
            for (int next : graph.get(v)) {
                if (--indegree[next] == 0) {
                    queue.addLast(next);
                }
            }
        }

        if (size != vertexCount) {
            throw new IllegalArgumentException("graph contains a directed cycle");
        }
        return order;
    }
}
```

例如边 `0→2, 1→2, 2→3` 中，最初 `0、1` 的入度都是 0，可以先后以任意顺序处理；只有两者都被移除后，`2` 的入度才会降到 0，之后才能处理 `3`。因此合法答案不一定唯一，验证时应该检查所有边都满足 `position[from] < position[to]`，而不是把某一个固定数组当成唯一标准答案。

## 关键细节

- **来源边界**：题源只要求“手撕拓扑排序”。Java、`int[][] edges`、顶点从 0 编号、Kahn/BFS 和“有环抛异常”都是答案侧选择，不冒充原题要求。
- **为什么入度为 0 才能取**：当前还没有任何未处理前驱指向它，因此把它放到当前答案位置不会违反依赖顺序。
- **怎么判环**：如果队列提前空了但仍有顶点没输出，剩余顶点都至少有一个来自剩余子图的前驱；沿前驱持续追溯必然重复某个点，因此剩余部分含有向环。
- **答案可能不唯一**：同时有多个入度 0 顶点时，选择顺序可以不同。若题目额外要求字典序最小，应把普通队列换成优先队列；当前来源没有这个要求。
- **重复边**：本契约允许重复 `from -> to` 记录。建图时每条都让入度加 1，删除 `from` 时也逐条减 1，因此仍然自洽；如果业务语义要求去重，应在输入契约中单独说明。
- **自环**：`v -> v` 会让 `v` 永远无法降到 0，最终按有向环处理。
- **空图**：`vertexCount == 0` 且空边集合时返回空数组。
- **复杂度**：每个顶点入队出队至多一次，每条边建图和删除各访问一次，因此时间 `O(V + E)`；邻接表占 `O(V + E)`，其他结构 `O(V)`。

## 原理机制

Kahn 算法可以理解为不断删除 DAG 的“源点”。DAG 一定至少存在一个入度为 0 的顶点；否则从任意点不断沿前驱往回走，在有限顶点集合中必然遇到重复点，从而形成环，和 DAG 假设矛盾。删除一个源点及其所有出边后，剩下的图仍然是 DAG，所以可以重复这个过程。每次删除的源点都追加到结果中，保证它出现在所有尚未删除后继之前。

反过来，如果处理过程中已经没有入度为 0 的点，但图里还有顶点，说明剩余子图不存在源点，因此必然含环。于是“输出了多少个点”同时给出了排序成功和环检测的判据。

## 项目经验版

来源没有真实项目经历，不能虚构“线上用拓扑排序解决过某个依赖系统”。工程映射时常见的是任务依赖、构建依赖或配置依赖；真正落地前需要确认图是否可能动态变化、是否允许重复边、是否要稳定/字典序输出，以及发现环后要返回哪条环路。当前代码只回答静态图的一次性拓扑排序；若要诊断具体环，需要额外保存父指针或再做一次 DFS 提取环路径。

## 常见追问

- 问：为什么拓扑序可能不唯一？答：同一时刻可能有多个入度为 0 的点，它们之间当前没有必须先后的依赖；选择顺序不同会得到不同但都合法的拓扑序。
- 问：怎么判断返回结果正确？答：结果必须包含每个顶点恰好一次，并且对每条 `u -> v` 都满足 `u` 在 `v` 前面；不能只和一个固定期望数组做相等比较。
- 问：如果有环怎么办？答：Kahn 算法最终处理数量会小于 `V`；当前 API 明确抛异常。若题目要求返回空数组或布尔值，只需调整接口语义，核心判环条件不变。
- 问：DFS 也能做吗？答：可以。DFS 用三色状态发现回边，并在退出节点时逆序记录；Kahn 用入度和队列。两者都是 `O(V+E)`，这里选 Kahn 只是答案侧实现选择。
- 问：如果要求字典序最小拓扑序呢？答：把当前保存零入度顶点的 FIFO 队列换成最小堆，每次取编号最小的可选点，时间会多出堆操作成本。

## 易错点

- 把拓扑排序当普通数值排序，完全没有建有向图和依赖关系。
- 入度统计错方向，把 `from` 而不是 `to` 的入度加 1。
- 输出部分顶点后直接返回，没有用 `processed == V` 检测环。
- 认为拓扑序只有一个，测试代码写死一个固定答案。
- 使用邻接矩阵后仍声称无条件 `O(V+E)`，没有按实际数据结构重新核算复杂度。
- 把 Java、BFS/Kahn、编号方式或异常行为说成题源已经明确规定。
