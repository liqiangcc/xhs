# 双向链表的插入

## 核心结论

双向链表插入的核心不是背四行代码，而是保持局部不变量：把新节点 `x` 插到相邻节点 `left` 和 `right` 之间后，必须同时满足 `left.next == x`、`x.prev == left`、`x.next == right`、`right.prev == x`。原题没有指定“按位置、按节点、头插还是尾插”的 API；下面明确采用“已知锚点节点，插到它后面”的 O(1) 契约，并用头尾哨兵统一空表、头部和尾部边界。

## 1 分钟版

- 先明确契约：已知当前链表中的 `anchor`，把新节点插到 `anchor` 后面；若只给下标，先定位节点会额外 O(n)。
- 找到插入缝隙：`left = anchor`，`right = anchor.next`。
- 先让新节点连接两侧：`x.prev = left`、`x.next = right`。
- 再让两侧回指新节点：`left.next = x`、`right.prev = x`；四个关系缺一个都会破坏前后遍历一致性。
- 使用 head/tail 哨兵后，空链表、首部、尾部都走同一个 `insertBetween(left,right,x)`，已知位置插入时间 O(1)、额外空间 O(1)。

## 3 分钟版

原题只说“双向链表的插入”，没有给节点定义和插入位置语义。因此先约定一个可测试 API：链表带 `head` / `tail` 两个哨兵；`insertAfter(anchor, value)` 要求 `anchor` 属于当前链表且不是 tail，返回新节点。真正的状态变化只发生在 `anchor` 与原来的 `anchor.next` 之间。

```java
import java.util.ArrayList;
import java.util.List;

public final class DoublyLinkedList {
    public static final class Node {
        private final int value;
        private Node prev;
        private Node next;
        private DoublyLinkedList owner;

        private Node(int value, DoublyLinkedList owner) {
            this.value = value;
            this.owner = owner;
        }

        public int value() { return value; }
    }

    private final Node head = new Node(0, this);
    private final Node tail = new Node(0, this);
    private int size;

    public DoublyLinkedList() {
        head.next = tail;
        tail.prev = head;
    }

    public Node addFirst(int value) {
        return insertBetween(head, head.next, value);
    }

    public Node addLast(int value) {
        return insertBetween(tail.prev, tail, value);
    }

    public Node insertAfter(Node anchor, int value) {
        if (anchor == null || anchor.owner != this || anchor == tail) {
            throw new IllegalArgumentException("anchor must be a non-tail node of this list");
        }
        return insertBetween(anchor, anchor.next, value);
    }

    private Node insertBetween(Node left, Node right, int value) {
        if (left.next != right || right.prev != left) {
            throw new IllegalStateException("broken insertion boundary");
        }
        Node x = new Node(value, this);
        x.prev = left;
        x.next = right;
        left.next = x;
        right.prev = x;
        size++;
        return x;
    }

    public int size() { return size; }

    public List<Integer> valuesForward() {
        List<Integer> out = new ArrayList<>();
        for (Node p = head.next; p != tail; p = p.next) out.add(p.value);
        return out;
    }

    public List<Integer> valuesBackward() {
        List<Integer> out = new ArrayList<>();
        for (Node p = tail.prev; p != head; p = p.prev) out.add(p.value);
        return out;
    }
}
```

这里先接 `x.prev/x.next` 再改两侧指针，是为了让四个关系的意图清晰；在单线程普通链表里只要最终四个赋值都正确即可。若 API 改成“按下标插入”，插入动作本身仍是 O(1)，但寻找第 i 个节点需要 O(n)；若改成“插到某节点前”，只需把缝隙改为 `left = anchor.prev, right = anchor`。

## 关键细节

- **四个指针关系**：双向链表比单链表多一条反向边，插入后既要保证 `next` 链，也要保证 `prev` 链；只维护一边会造成正向可走、反向断链的隐蔽错误。
- **哨兵节点**：head/tail 不承载业务值，只提供永久边界，使空表首插等价于“插在 head 与 tail 之间”，尾插等价于“插在 tail.prev 与 tail 之间”。
- **锚点归属**：示例显式记录 `owner`，拒绝把另一个链表的节点当锚点，否则会把两个对象图意外拼接。
- **尾哨兵不可作为 insertAfter 锚点**：tail 没有业务上的后继插入缝隙；尾插通过 `addLast` 或在最后一个业务节点后插入完成。
- **复杂度**：已知相邻节点或 anchor 时插入 O(1) 时间、O(1) 额外空间；按值/下标先搜索则总成本通常 O(n)。
- **并发边界**：这份实现是单线程数据结构契约。并发写入时四个指针更新不是原子事务，需要额外同步/锁或改用专门并发结构，不能直接宣称线程安全。

## 原理机制

可以把双向链表看成一组局部互逆关系：对任意相邻业务/哨兵节点 `a`、`b`，若 `a.next == b`，就应有 `b.prev == a`。插入节点不是“修改一个 next”，而是把原来的一条双向邻接 `left <-> right` 替换为两条双向邻接 `left <-> x <-> right`。

所以最可靠的推导方式是先冻结旧边界 `left/right`，再建立 `x` 到两侧的连接，最后让两侧指向 `x`。测试也不应只看 size 或正向结果，而要同时从 head 正向、从 tail 反向遍历，验证顺序互为反转；这样才能捕捉漏写 `prev` 的错误。

## 常见追问

- 问：为什么双向链表插入是 O(1)？答：前提是插入位置或 anchor 已知，只需要常数次指针修改；如果先按下标或值找节点，搜索本身仍是 O(n)。
- 问：四个赋值最容易漏哪个？答：常见错误是只写 `left.next = x` 和 `x.next = right`，漏掉 `x.prev = left` 或 `right.prev = x`，导致反向遍历错误。
- 问：为什么用哨兵？答：把空表、头插、尾插的空指针分支转换为相同的“在两个非 null 边界节点之间插入”，减少边界分支。
- 问：如果要 insertBefore 呢？答：把 `right` 设为 anchor、`left` 设为 `anchor.prev`，仍复用同一个 `insertBetween` 不变量。
- 问：为什么要检查 owner？答：这是本候选 API 的防御性选择，用来避免跨链表锚点破坏两个链表；原题没有规定，面试官若追求最简实现可以省略并把“anchor 属于本表”作为调用前置条件。

## 易错点

- 只更新 next 链，忘记 prev 链，导致单向测试通过但双向结构已损坏。
- 不保存原后继就覆盖 `anchor.next`，之后失去 `right` 引用，无法正确回接。
- 没说明“已知节点”前提却直接说所有插入都是 O(1)，忽略按下标/值定位的 O(n)。
- 空表、首部、尾部各写一套分支，增加漏改指针概率；哨兵可以统一这些边界。
- 把单线程四次普通字段写入误说成线程安全的原子操作。
