# 双向链表插入：同时维护前驱和后继指针

## 核心结论

来源只保留“算法：双向链表的插入”，没有给节点结构、插入位置或函数签名。这里采用一个覆盖头部、中间、尾部和空链表的最小可执行契约：实现 `DoublyLinkedList.insert(index, value)`，`index` 是 0 基插入位置，合法范围 `[0,size]`，新节点插入后成为该 index 上的元素。关键不是只改一条 `next`，而是同时维护 `prev/next` 两个方向以及 `head/tail/size` 不变量。

## 1 分钟版

- 双向链表每个节点有 `prev` 和 `next`，插入时必须同时维护四条可能受影响的引用。
- 中间插入到 `prev` 和 `next` 之间时：`node.prev=prev`、`node.next=next`、`prev.next=node`、`next.prev=node`。
- 头部没有 `prev`，要更新 `head`；尾部没有 `next`，要更新 `tail`。
- 空链表第一次插入后 `head == tail == node`。
- 查找位置需要 O(min(index,size-index))；找到位置后的指针重连是 O(1)。

## 3 分钟版

```java
public final class DoublyLinkedList {
    private static final class Node {
        final int value;
        Node prev;
        Node next;

        Node(int value) {
            this.value = value;
        }
    }

    private Node head;
    private Node tail;
    private int size;

    public void insert(int index, int value) {
        if (index < 0 || index > size) {
            throw new IndexOutOfBoundsException("index=" + index + ", size=" + size);
        }

        if (index == size) {
            linkLast(value);
            return;
        }

        Node next = nodeAt(index);
        Node prev = next.prev;
        Node node = new Node(value);

        node.prev = prev;
        node.next = next;
        next.prev = node;

        if (prev == null) {
            head = node;
        } else {
            prev.next = node;
        }
        size++;
    }

    private void linkLast(int value) {
        Node node = new Node(value);
        Node prev = tail;
        node.prev = prev;
        tail = node;

        if (prev == null) {
            head = node;
        } else {
            prev.next = node;
        }
        size++;
    }

    private Node nodeAt(int index) {
        if (index < (size >>> 1)) {
            Node p = head;
            for (int i = 0; i < index; i++) {
                p = p.next;
            }
            return p;
        }

        Node p = tail;
        for (int i = size - 1; i > index; i--) {
            p = p.prev;
        }
        return p;
    }
}
```

这里把 `index == size` 单独作为尾插处理；其他位置先找到当前 index 上的 `next` 节点，再把新节点插到 `next.prev` 与 `next` 之间。这样 `index=0` 时自然落到头插分支，而中间插入不需要额外特殊逻辑。

## 关键细节

- **指针更新顺序**：先保存旧的 `prev/next`，再连接新节点，避免覆盖后丢失原链路。
- **头插**：当 `next.prev == null` 时，说明 `next` 原本是头节点；新节点的 `prev` 保持 `null`，并把 `head` 改为新节点。
- **尾插**：旧 `tail` 成为新节点的 `prev`，旧尾节点的 `next` 指向新节点，再更新 `tail`。
- **空链表**：旧 `tail == null`，尾插函数同时设置 `head` 和 `tail`。
- **双向不变量**：对任意相邻节点 `a -> b`，都应满足 `a.next == b` 且 `b.prev == a`；头节点 `prev == null`，尾节点 `next == null`。
- **索引边界**：允许 `index == size` 表示追加，不允许负数或大于 size 的位置。
- **复杂度**：定位节点从更近的一端遍历，时间 O(min(index,size-index))；重连 O(1)，新增节点 O(1) 空间。

## 原理机制

双向链表可以看成一串相邻节点关系。插入的本质是把原来的边 `prev <-> next` 拆成两组边：`prev <-> node` 和 `node <-> next`。头尾只是其中一侧不存在的边界情况，因此需要额外维护 `head/tail`。

最容易出错的是只完成一个方向。例如设置 `prev.next=node` 和 `node.next=next`，却忘记 `next.prev=node`，从前往后遍历看似正常，但从后往前已经断链。测试应同时验证正向序列、反向序列和 head/tail 边界，而不是只看一个方向。

## 项目经验版

来源没有真实项目或内核/容器实现背景，不能虚构。实际工程中若手写侵入式双向链表，还要明确节点生命周期、并发保护、删除期间是否允许遍历、哨兵节点策略等；面试中的单线程插入只证明局部指针不变量，不代表已经解决并发与内存管理问题。

## 常见追问

- 问：为什么双向链表插入是 O(1) 还是 O(n)？答：如果已经拿到相邻节点引用，重连是 O(1)；本候选按 index 插入，需要先查找位置，所以总时间包含遍历成本。
- 问：能不能用哨兵节点减少分支？答：可以。头尾哨兵能统一空链表和边界插入，但会增加两个固定节点；本候选显式维护 `head/tail`。
- 问：为什么 `index == size` 合法？答：本候选把 index 定义为“插入后的元素位置”，因此 size 表示追加；这是明确的 API 选择，不是来源已经给出的约束。
- 问：怎样验证没有断链？答：同时从 head 正向遍历和从 tail 反向遍历，并逐对检查 `next.prev` 与 `prev.next`。
- 问：并发插入怎么办？答：需要额外的锁、CAS 或更复杂的数据结构协议；当前单线程链表代码没有并发安全保证。

## 易错点

- 只更新 `next` 不更新 `prev`，导致反向遍历断链。
- 头插后忘记更新 `head`，或尾插后忘记更新 `tail`。
- 空链表首插只设置一端，造成 `head` 与 `tail` 不一致。
- 覆盖旧指针后才尝试寻找相邻节点，导致链路丢失。
- 把“已知节点后的 O(1) 插入”和“按 index 查找后插入”的复杂度混为一谈。
