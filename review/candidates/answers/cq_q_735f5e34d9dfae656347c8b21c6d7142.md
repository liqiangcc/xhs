# 对称字符映射：判断一个字符串能否整体替换成另一个字符串

## 核心结论

原始记录明确补充：如果字符 `x` 要变成 `y`，那么 `y` 也要变成 `x`。因此本答案把操作解释为**一次全局的对称字符映射**：每个字符要么保持自己不变，要么只和另一个字符成对交换，满足 `f(f(c)) = c`。逐位置看 `source[i]=x`、`target[i]=y`，就必须同时约束 `x -> y` 和 `y -> x`；同一个字符一旦被要求拥有两个不同伙伴，就不存在合法映射。

来源例子 `aabba -> eeffe` 可以取 `a <-> e`、`b <-> f`，所以为 `true`。`asdf -> asag` 则要求 `a -> a`，同时后面又要求 `d -> a`；由于 `a` 已经是固定点，不可能再和 `d` 配对，所以为 `false`。

来源没有说明可以连续执行任意多轮不同交换。本答案只验证“一次全局对称映射”；若面试官允许任意交换序列，多个 transposition 的复合可以形成更一般的置换，那是另一份契约。

## 1 分钟版

- 先按 Unicode code point 比较长度；不同长度直接 `false`。
- 用一个 `Map<Integer,Integer> partner` 记录字符的唯一伙伴。
- 对每个位置 `(x,y)`：若 `x` 已绑定且伙伴不是 `y`，失败；若 `y` 已绑定且伙伴不是 `x`，也失败。
- 没冲突就同时写 `partner[x]=y`、`partner[y]=x`。当 `x==y` 时记录的是固定点。
- 扫描完没有冲突，就能构造出满足全部位置的对称映射。
- `n` 为 code point 数、`u` 为涉及的不同字符数：时间 `O(n)`，额外空间 `O(u)`。

## 3 分钟版

```java
import java.util.HashMap;
import java.util.Map;
import java.util.Objects;

public final class SymmetricCharMapping {
    public static boolean canTransform(String source, String target) {
        Objects.requireNonNull(source, "source");
        Objects.requireNonNull(target, "target");

        int[] a = source.codePoints().toArray();
        int[] b = target.codePoints().toArray();
        if (a.length != b.length) return false;

        Map<Integer, Integer> partner = new HashMap<>();
        for (int i = 0; i < a.length; i++) {
            int x = a[i], y = b[i];
            Integer px = partner.get(x);
            Integer py = partner.get(y);
            if (px != null && px != y) return false;
            if (py != null && py != x) return false;
            partner.put(x, y);
            partner.put(y, x);
        }
        return true;
    }
}
```

只验证单向 `x -> y` 不够。例如前面已经得到 `a -> e`，后面又出现 `b -> e`，单向函数对 `a` 和 `b` 都可能各自稳定，但来源的对称规则要求 `e` 只能回到 `a`，所以目标端也必须检查。

## 关键细节

- **不变量**：处理完前 `i` 个位置后，若 `partner[x]=y`，就一定有 `partner[y]=x`，并且这组配对满足前 `i` 个位置的全部转换要求。
- **固定点要真正记入约束**：`x -> x` 不是“什么都没发生所以跳过”，它意味着 `x` 已经只能和自己配对；否则会错误接受来源中的 `asdf -> asag` 一类冲突。
- **比普通同构字符串更强**：普通 isomorphic string 只要求一致双射；本题还要求映射等于自己的逆，因此不能出现 `a->b, b->c, c->a` 的 3-cycle。
- **Unicode**：用 `codePoints()` 而不是逐个 UTF-16 `char`，避免把非 BMP 字符拆成两个代理项。
- **空串**：两个空串在本接口下返回 `true`，因为空映射满足所有零个约束；这是答案侧定义。
- **null**：直接拒绝，不把 `null` 当空串。
- **多轮交换边界**：如果允许任意次不同的 pair swap，就必须重写问题模型；不能把“一次对称映射”的算法静默扩张过去。

## 原理机制

每个位置 `(x,y)` 实际产生两条等式：`f(x)=y`、`f(y)=x`。把字符看成图节点，合法关系的每个节点只能有一个伙伴：要么是自己形成固定点，要么与另一个节点形成 2-cycle。逐位置加入约束时，只要某个节点出现第二个不同邻居，就证明不存在这样的映射。

哈希表保存的正是这个“唯一伙伴”关系，所以每一步只需要常数期望时间的两次查找和两次写入。若始终无冲突，最终表本身就是一个满足所有已出现字符的构造性证明；未出现字符如何映射并不影响两个输入串的转换。

## 项目经验版

这是算法题，来源没有真实项目背景，因此不虚构线上案例。工程里若真有字符 rename，我会先明确是 simultaneous rename 还是多轮操作、是否允许固定点、字符单位是 byte/UTF-16/code point，以及未出现字符是否受约束；这些契约会直接决定算法。

## 常见追问

- 问：为什么目标字符也要查伙伴？答：因为来源要求 `x<->y`。只保证 source 端是函数仍可能让两个不同 source 字符指向同一个 target，违反对称关系。
- 问：为什么 `asdf -> asag` 不行？答：首位已经约束 `a->a`，后面的 `d->a` 又要求 `a->d`，同一个 `a` 出现两个伙伴，冲突。
- 问：允许 `x->x` 吗？答：来源未禁止，并且示例中的相同位置自然产生固定点；本答案允许。
- 问：和同构字符串有什么区别？答：同构允许一般置换，本题的对称规则只允许固定点和两两交换。
- 问：长度不同时为什么直接失败？答：当前契约只有字符替换，没有插入删除，因此 code point 数不会变化。
- 问：如果允许连续交换很多轮？答：那需要新的操作定义；任意 transposition 序列的复合不必满足 `f(f(c))=c`。

## 易错点

- 只检查 `source -> target` 的函数性，漏掉反向伙伴冲突。
- 遇到 `x==y` 就跳过，导致固定点没有锁定。
- 把来源的对称替换误写成普通 isomorphic string。
- 把“任意交换序列”偷换成“一次对称映射”或反过来。
- 用 `char` 实现却宣称对所有 Unicode 字符正确。
