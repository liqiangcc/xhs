# 镜像二叉树：递归与显式栈两种原地实现

## 核心结论

仓库原始面经保留的问题只有：**“镜像二叉树（递归和非递归）”**。原文没有规定节点类型、是否原地修改、是否需要复制新树、空树行为等 API 细节。

下面把候选实现契约明确为：节点保存 `int` 值和可变的 `left/right` 引用；**原地**把整棵树变成镜像树并返回原根节点；空树返回 `null`。这些是候选 API 选择，不冒充原题已经给出的条件。

镜像的结构定义很直接：对每个节点，把原来的右子树变成新的左子树，把原来的左子树变成新的右子树。递归版直接按这个定义做；非递归版用显式栈遍历每个节点，并在访问节点时交换左右孩子。两种实现都访问每个节点一次，所以时间复杂度是 `O(n)`；额外空间由树高决定，递归版是调用栈 `O(h)`，显式 DFS 栈也是 `O(h)`，极端退化树时 `h = n`。

## 1 分钟版

递归函数的语义可以定义成：`mirror(node)` 把以 `node` 为根的子树原地镜像，并返回这个根。

- `node == null` 时直接返回；
- 先把原右子树镜像，作为新的左子树；
- 再把原左子树镜像，作为新的右子树；
- 返回 `node`。

非递归版不改变这个定义，只是把系统调用栈换成显式 `Deque`：弹出一个节点，交换它的 `left/right`，再把非空孩子压栈，直到栈为空。

## 3 分钟版

递归版可以用结构归纳证明正确：

1. 空树显然已经是自己的镜像；
2. 假设左右子树都能被正确镜像；
3. 当前节点把“原右子树的镜像”挂到左边，把“原左子树的镜像”挂到右边，于是当前整棵子树满足镜像定义。

非递归版维护的遍历不变量是：已经从栈中弹出的节点都完成了一次左右孩子交换；尚未处理的可达非空孩子都在栈中或会由栈中的祖先加入。每个节点只会被加入和弹出一次，因此结束时所有节点都完成交换。

镜像还是一个**对合（involution）**：对同一棵树连续镜像两次会恢复原结构和值。这个性质很适合做回归测试，但它不能单独替代“第一次结果是否正确”的 oracle，所以测试同时比较一个独立的结构镜像序列化结果。

## 关键细节

- **原地还是复制**：原题未说明。当前候选选择原地修改；如果调用方要求保留原树，应改成创建新节点的纯函数版本。
- **节点值不变**：镜像只交换结构引用，不修改节点值。
- **递归顺序**：保存原左右引用，或者像实现中一样先计算两个镜像子树后再赋值，避免覆盖后丢失原子树。
- **空树与单节点**：都应自然成立；单节点镜像后还是自己。
- **退化树**：递归深度最坏是 `O(n)`，可能触发栈溢出；显式栈版本更适合非常深的树，但它仍然需要 `O(h)` 显式内存。
- **复杂度**：每个节点交换一次，`O(n)` 时间；递归/显式 DFS 的辅助空间是 `O(h)`。
- **验证**：除固定非对称树外，还应验证镜像两次恢复原树、递归与迭代结果一致，以及随机树对独立结构 oracle 的一致性。

## 原理机制

```java
import java.util.ArrayDeque;
import java.util.Deque;

public final class MirrorBinaryTree {
    private MirrorBinaryTree() {}

    public static final class Node {
        public final int value;
        public Node left;
        public Node right;

        public Node(int value) {
            this.value = value;
        }

        public Node(int value, Node left, Node right) {
            this.value = value;
            this.left = left;
            this.right = right;
        }
    }

    public static Node mirrorRecursive(Node root) {
        if (root == null) {
            return null;
        }
        Node mirroredLeft = mirrorRecursive(root.right);
        Node mirroredRight = mirrorRecursive(root.left);
        root.left = mirroredLeft;
        root.right = mirroredRight;
        return root;
    }

    public static Node mirrorIterative(Node root) {
        if (root == null) {
            return null;
        }
        Deque<Node> stack = new ArrayDeque<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            Node node = stack.pop();
            Node tmp = node.left;
            node.left = node.right;
            node.right = tmp;

            if (node.left != null) {
                stack.push(node.left);
            }
            if (node.right != null) {
                stack.push(node.right);
            }
        }
        return root;
    }
}
```

仓库的候选验证包含：空树、单节点、非对称树的精确结构结果、递归/迭代原地语义、镜像两次恢复原树、4000 棵固定随机种子的随机树（共 8000 次递归/迭代断言）对独立结构镜像 oracle 的比较，以及 20000 层左偏树的迭代镜像检查。

## 项目经验版

这是算法题，原始面经没有生产项目背景，因此不应该编造“线上曾经这样处理树”的经历。工程上真正需要澄清的是：是否允许修改原对象、树可能有多深、节点是否共享或形成环、是否要求线程安全。当前候选只处理普通无环二叉树；如果输入不是树而是带共享节点/环的图，就需要额外的访问集和不同的契约。

## 常见追问

- 问：递归版为什么是正确的？答：对树做结构归纳；左右子树正确镜像后再交换挂接，就得到当前节点的镜像。
- 问：非递归一定要 BFS 吗？答：不需要。栈做 DFS、队列做 BFS 都可以，只要每个节点恰好交换一次；当前实现用栈，辅助空间与树高相关。
- 问：为什么递归版可能有风险？答：退化树的递归深度可达 `n`，JVM 调用栈可能不足；显式栈把这个资源消耗变成可控的堆对象。
- 问：如何证明两种实现等价？答：对同一输入分别执行后比较完整结构；仓库测试还用独立的“按原树右、左顺序序列化” oracle 验证，而不是让一个实现给另一个实现当唯一 oracle。
- 问：镜像两次恢复原树能证明实现一定正确吗？答：不能。某些错误变换也可能是对合，所以还必须检查已知样例和独立结构 oracle。
- 问：如果不能修改原树怎么办？答：创建新节点，递归构造 `new Node(root.value, mirrorCopy(root.right), mirrorCopy(root.left))`，空间会包含新树本身。

## 易错点

- 交换 `left/right` 时覆盖了其中一边，又继续使用被覆盖后的引用。
- 只交换根节点，没有继续处理所有子树。
- 把“镜像二叉树”和“判断两棵树是否镜像对称”混成同一个问题。
- 忽略原题没有说明“原地/复制”，却把某一种 API 选择写成原始条件。
- 只用“镜像两次恢复”做测试，没有独立检查第一次镜像结构是否正确。
