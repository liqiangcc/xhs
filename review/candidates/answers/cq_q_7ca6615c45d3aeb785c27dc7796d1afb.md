# 最大版本号：基于 LeetCode 165 比较多个版本字符串

## 核心结论

仓库更强来源明确写了“最大版本号（165. 比较版本号）”，并补充“面试的时候是输入多个版本号进行比较”。所以先实现 LeetCode 165 的两版本比较语义：按 `.` 分隔的 revision 从左到右比较、忽略前导零、缺失 revision 当 0；再对多个版本做一次线性扫描保留最大值。来源没有保存 ACM 的具体输入行格式，也没有规定语义相等的不同字符串表示返回哪一个；下面显式约定输入为非空 `List<String>`，相等时保留首次出现的原字符串。

## 1 分钟版

- 版本号不能当浮点数；`1.10 > 1.2`，因为第二个 revision 是 10 和 2。
- 两个版本同步取下一段；去掉段内前导零后，先比较有效数字长度，长度相同再逐字符比较，等价于比较非负整数且无需转整型 API。
- 一边 revision 用完时按 0 处理，所以 `1.0 = 1.0.0`。
- 多版本求最大：从第一个开始，只有 `compareVersion(current,best)>0` 才替换；语义相等保留第一个原字符串。
- 单次 `compareVersion(a,b)` 时间是 O(|a|+|b|)、额外空间 O(1)。对 n 个版本直接反复与当前 `best` 比较时，若 M 是最长版本字符串长度，简单归约的清晰最坏上界是 O(nM)；不能只按“所有输入字符只读一次”宣称 O(L)，因为当前 best 可能被重复扫描。

## 3 分钟版

```java
import java.util.List;

public final class MaxVersion {
    public static String maxVersion(List<String> versions) {
        if (versions == null || versions.isEmpty()) {
            throw new IllegalArgumentException("versions must not be empty");
        }
        String best = requireValid(versions.get(0));
        for (int i = 1; i < versions.size(); i++) {
            String current = requireValid(versions.get(i));
            if (compareVersion(current, best) > 0) {
                best = current;
            }
        }
        return best;
    }

    public static int compareVersion(String a, String b) {
        requireValid(a);
        requireValid(b);
        int i = 0, j = 0;
        while (i < a.length() || j < b.length()) {
            int aEnd = nextDot(a, i);
            int bEnd = nextDot(b, j);
            int cmp = compareRevision(a, i, aEnd, b, j, bEnd);
            if (cmp != 0) return cmp;
            i = aEnd < a.length() ? aEnd + 1 : a.length();
            j = bEnd < b.length() ? bEnd + 1 : b.length();
        }
        return 0;
    }

    private static int nextDot(String s, int start) {
        if (start >= s.length()) return s.length();
        int p = start;
        while (p < s.length() && s.charAt(p) != '.') p++;
        return p;
    }

    private static int compareRevision(
            String a, int aStart, int aEnd,
            String b, int bStart, int bEnd) {
        while (aStart < aEnd && a.charAt(aStart) == '0') aStart++;
        while (bStart < bEnd && b.charAt(bStart) == '0') bStart++;
        int aLen = aEnd - aStart;
        int bLen = bEnd - bStart;
        if (aLen != bLen) return Integer.compare(aLen, bLen);
        for (int k = 0; k < aLen; k++) {
            char x = a.charAt(aStart + k), y = b.charAt(bStart + k);
            if (x != y) return Character.compare(x, y);
        }
        return 0;
    }

    private static String requireValid(String s) {
        if (s == null || s.isEmpty() || s.charAt(0) == '.' || s.charAt(s.length() - 1) == '.') {
            throw new IllegalArgumentException("invalid version");
        }
        boolean needDigit = true;
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (ch == '.') {
                if (needDigit) throw new IllegalArgumentException("invalid version");
                needDigit = true;
            } else if (ch >= '0' && ch <= '9') {
                needDigit = false;
            } else {
                throw new IllegalArgumentException("invalid version");
            }
        }
        if (needDigit) throw new IllegalArgumentException("invalid version");
        return s;
    }
}
```

例如输入 `['1.0.9','1.01.0','1.0.10','1.0.10.0']`。`1.01.0` 的 revisions 是 `[1,1,0]`，它大于 `1.0.10` 的 `[1,0,10]`，所以最大值是 `1.01.0`。另一个 tie 例子 `['2.0','2.0.0']` 在 LeetCode 165 语义下相等，因此按本答案适配约定返回首次出现的 `2.0`。

## 关键细节

- **前导零**：`1.01` 与 `1.001` 的第二段都代表 1，应相等。
- **缺失段为 0**：`1.0`、`1.0.0`、`1.0.0.0` 语义相等。
- **不能用浮点数**：版本是 revision 序列，不是十进制小数。
- **避免整数解析依赖**：官方 165 当前约束允许 revision 放进 32 位整数，但去零后按长度+字典序比较同样符合其非负整数语义，并能避免扩展输入的解析溢出。
- **多版本适配**：官方 165 是二元比较；“输入多个版本号”由仓库截图明确保存，因此用同一 comparator 线性归约。
- **相等代表**：题源没有说明语义相等时返回哪个原始表示；“保留第一个”是答案侧适配契约。
- **ACM 格式**：截图只保存“ACM 不熟”，未保存 stdin/stdout 格式，所以不虚构 `n`、空格或换行布局。
- **复杂度边界**：pairwise comparator 线性于两个参与字符串；多版本直接 fold 会重复读取当前最大版本。如果需要严格按总输入字符量一次性处理，可先把每个版本解析/规范化后再比较，但会引入与解析结果相关的额外空间。

## 原理机制

单个 revision 去掉前导零后，位数更多的非负十进制整数一定更大；位数相同时逐字符字典序与数值顺序一致。因此无需构造整数也能实现 LeetCode 165 的 revision 比较。整个版本按 revision 序列从左到右比较，第一个不同段决定结果；尾部缺失段补 0。多个版本求最大就是在这个比较器上做 fold：维护 `best`，新值严格更大才替换，因此结束时 `best` 不小于所有已扫描版本。

## 项目经验版

来源没有真实版本治理系统或线上事故数据，不能虚构项目经历。工程里还要区分这种纯数字点分版本与 SemVer；SemVer 有 prerelease、build metadata 等不同规则，不能直接复用 LeetCode 165 comparator，应按真实规范选择解析器并做规范样例测试。

## 常见追问

- 问：为什么 `1.10 > 1.2`？答：第二个 revision 是整数 10 与 2，不是小数位。
- 问：`1.01` 与 `1.001` 呢？答：忽略前导零，两个 revision 都是 1，所以相等。
- 问：`1.0` 与 `1.0.0` 呢？答：缺失 revision 按 0 处理，因此相等。
- 问：为什么不用 `Integer.parseInt`？答：官方约束下可以；这里用长度+字典序直接比较非负整数段，少依赖一个转换 API，也避免扩展输入溢出。
- 问：多个版本怎么求最大？答：用同一个 pairwise comparator 线性扫描，严格更大才更新当前最大。

## 易错点

- 把版本号当 `double`。
- 直接按原字符串字典序比较。
- 忽略前导零或缺失 revision 视为 0。
- 为了“多个输入”虚构没有保存的 ACM 输入格式。
- 把 LeetCode 165 规则误当成完整 SemVer 规则。
