# 螺旋矩阵 II（LeetCode 59）：按边界逐层填充 1 到 n²

## 核心结论

仓库原题明确写的是 **LeetCode 59：Spiral Matrix II**。按这一显式题号映射，目标是：给定正整数 `n`，生成一个 `n x n` 矩阵，把 `1..n²` 按顺时针螺旋顺序填入。最直接的实现是维护 `top / bottom / left / right` 四条未填边界，每轮依次填写上边、右边、下边、左边，然后四条边界向内收缩。

关键不变量是：循环开始时，边界之外的格子已经全部且只被写入一次，边界矩形内部仍未写入；下一轮只写当前最外层。因此每个格子恰好访问一次，时间复杂度 `O(n²)`，除返回矩阵外额外空间 `O(1)`。

## 1 分钟版

- 初始化 `top=0, bottom=n-1, left=0, right=n-1, value=1`。
- 先从左到右填 `top` 行，再 `top++`。
- 再从上到下填 `right` 列，再 `right--`。
- 如果还有剩余行，从右到左填 `bottom` 行，再 `bottom--`。
- 如果还有剩余列，从下到上填 `left` 列，再 `left++`。
- 四条边界交叉后结束。

两个 `if` 不是装饰：矩形缩到单行或单列时，如果继续无条件写下边或左边，会重复覆盖中心层。虽然本题始终是方阵，奇数阶矩阵最终也会收缩到一个中心格，所以仍要保持边界检查。

## 3 分钟版

这题可以把未填区域看成一个不断缩小的闭区间矩形 `[top..bottom] x [left..right]`。每一轮完成这个矩形的最外圈：

1. `top` 行：`left -> right`；
2. `right` 列：`top -> bottom`；
3. 如果 `top <= bottom`，`bottom` 行：`right -> left`；
4. 如果 `left <= right`，`left` 列：`bottom -> top`。

每写完一条边就立即收缩对应边界，保证后面的边不会再次碰到已经写过的角。`value` 每写一个格子加一，从 1 连续增长到 `n²`；因为每个合法坐标只在其所属的最外层被访问一次，所以最终既不会漏格，也不会重复值。

仓库来源只保留了 LeetCode 59 的题号，没有保存实现语言、必须使用的算法、越界输入策略等细节。因此这些实现选择要明确标成答案侧约定，不能反推成原题事实。正式题域是正整数 `n`；下面的本地 helper 对 `n <= 0` 显式抛错，只用于可执行验证，不属于来源要求。

## 关键细节

- **输入输出**：输入是正整数 `n`，输出新建的 `n x n` 整数矩阵；本题没有输入矩阵可原地修改。
- **顺序**：从左上角写 `1`，先向右，再向下、向左、向上，整体是顺时针。
- **角点处理**：上边写完就 `top++`，右边写完就 `right--`，因此右上角不会被重复写；其余角同理。
- **中心层**：奇数 `n` 最后只剩一个格子，边界检查保证它只被填写一次。
- **复杂度**：恰好写 `n²` 个位置，时间 `O(n²)`；边界变量只占常数空间，若不计输出矩阵额外空间是 `O(1)`。
- **失败边界**：来源没有定义非正数输入；本地 helper 的异常策略只是防御式 API 约定。
- **验证方式**：不用另一份四边界循环做 oracle，而用“方向向量 + visited + 碰壁转向”的不同状态机逐项对照。

## 原理机制

```java
public final class SpiralMatrixII {
    private SpiralMatrixII() {}

    public static int[][] generateMatrix(int n) {
        if (n <= 0) {
            throw new IllegalArgumentException("n must be positive");
        }

        int[][] matrix = new int[n][n];
        int top = 0;
        int bottom = n - 1;
        int left = 0;
        int right = n - 1;
        int value = 1;

        while (top <= bottom && left <= right) {
            for (int col = left; col <= right; col++) {
                matrix[top][col] = value++;
            }
            top++;

            for (int row = top; row <= bottom; row++) {
                matrix[row][right] = value++;
            }
            right--;

            if (top <= bottom) {
                for (int col = right; col >= left; col--) {
                    matrix[bottom][col] = value++;
                }
                bottom--;
            }

            if (left <= right) {
                for (int row = bottom; row >= top; row--) {
                    matrix[row][left] = value++;
                }
                left++;
            }
        }
        return matrix;
    }
}
```

这个实现使用“收缩边界”来定义下一步坐标。仓库测试的 oracle 不复制这个机制，而是维护当前位置、方向向量和 `visited` 矩阵：如果下一步越界或已经访问，就顺时针转向。两种状态机对 `n=1..20` 逐项比较，并额外固定断言 `n=1/2/3` 的已知矩阵；同时检查结果恰好是 `1..n²` 的一个排列。

## 项目经验版

这是纯算法题，仓库来源没有真实项目场景、性能指标或生产故障材料，因此不编造“线上使用螺旋矩阵”的经验。可迁移的工程习惯是：对二维状态机先定义坐标边界和“不重复访问”不变量，再选择边界收缩或方向转向实现；验证时最好用结构不同的 oracle，而不是把同一套循环复制成测试。

## 常见追问

- 问：为什么第三、第四段要再判断边界？答：当剩余区域已经缩成单行或单列时，前两段可能已经把这一层全部填完；继续写会重复覆盖。
- 问：能不能用方向数组做？答：可以。方向数组 + visited 的实现更统一，但需要额外 `O(n²)` visited 状态；边界收缩在本题上只需常数额外状态。
- 问：为什么复杂度不是 `O(n)`，明明只有四个 for？答：四个循环会在不同层覆盖全部 `n²` 个格子，总迭代次数是 `n²`，不是四倍 `n`。
- 问：如何证明没有漏格？答：每轮完整写当前未填矩形的外圈，随后边界各向内一格；归纳到边界交叉时，所有层都已写完。
- 问：为什么不需要 visited？答：边界本身编码了“哪些区域还没写”，只要每条边写完立即收缩，就不会重新进入已完成区域。
- 问：如果题目改成读取任意 `m x n` 矩阵的螺旋顺序呢？答：同样可以用四边界，但输出语义从“生成连续整数矩阵”变成“按顺序读取现有矩阵”，属于 Spiral Matrix I 的不同契约。

## 易错点

- 写完上边后没有先收缩 `top`，导致右上角被重复写。
- 单行/单列中心层没有条件判断，重复覆盖已经写过的格子。
- 把 `O(n²)` 输出规模误报成 `O(n)`。
- 用 visited 实现却声称额外空间 `O(1)`。
- 把本地 helper 的 `n <= 0` 异常策略说成 LeetCode 59 的来源要求。
- 把 Spiral Matrix I 的“读取矩阵”与 Spiral Matrix II 的“生成矩阵”混为一题。
