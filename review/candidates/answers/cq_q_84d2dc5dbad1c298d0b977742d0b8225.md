# 手写实现全排列算法

## 核心结论

全排列可以直接用回溯生成：当前位置依次尝试所有“尚未使用”的元素，选择后递归到下一层，返回时撤销选择。来源只保留“手写实现全排列算法”，没有给语言、输入类型、重复元素语义或输出顺序。下面明确采用一个最小可执行契约：输入是 **互不相同的 `int` 值**，返回所有排列；空数组返回一个空排列 `[[]]`；`null` 视为非法输入。若输入允许重复值并要求结果去重，需要额外定义并实现同层去重规则，不能把那套语义偷偷混进原题。

## 1 分钟版

- 把长度为 `n` 的排列看成一棵深度为 `n` 的搜索树。
- `path` 表示当前已经选出的前缀，`used[i]` 表示原数组第 `i` 个元素是否已经出现在当前路径里。
- 每一层遍历所有 `used[i] == false` 的位置：选中 → 标记 → 递归 → 撤销标记和路径。
- 当 `path.size() == n` 时得到一个完整排列，要复制当前 `path` 放入结果，不能直接保存同一个可变列表引用。
- 对 `n` 个不同元素，结果数量就是 `n!`；生成并复制每个长度 `n` 的结果，因此输出主导的时间复杂度是 `O(n · n!)`，递归栈和当前路径是 `O(n)`，若把结果也算空间则是 `O(n · n!)`。
- 如果题目追问“有重复元素怎么去重”，可以先排序，再在同一搜索层跳过“前一个相同值且前一个位置本层未被使用”的选择。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.List;

public final class Permutations {
    public static List<List<Integer>> permute(int[] nums) {
        if (nums == null) {
            throw new IllegalArgumentException("nums must not be null");
        }

        List<List<Integer>> result = new ArrayList<>();
        boolean[] used = new boolean[nums.length];
        backtrack(nums, used, new ArrayList<>(), result);
        return result;
    }

    private static void backtrack(
            int[] nums,
            boolean[] used,
            List<Integer> path,
            List<List<Integer>> result) {
        if (path.size() == nums.length) {
            result.add(new ArrayList<>(path));
            return;
        }

        for (int i = 0; i < nums.length; i++) {
            if (used[i]) {
                continue;
            }

            used[i] = true;
            path.add(nums[i]);

            backtrack(nums, used, path, result);

            path.remove(path.size() - 1);
            used[i] = false;
        }
    }
}
```

例如输入 `[1,2,3]`。第一层先选 `1`，第二层只能从 `2,3` 中选；得到 `[1,2,3]` 后回退到 `[1]`，再走 `[1,3,2]`。随后第一层撤销 `1`，继续从 `2`、`3` 开头的分支。最终正好遍历 6 个叶子，也就是 3! 个排列。

## 关键细节

- **状态含义要明确**：`used[i]` 表示“位置 i 是否已进入当前路径”，不是“这个值是否在全局出现过”。
- **撤销必须和选择对称**：递归前执行 `used[i]=true` 和 `path.add`，递归后必须恢复 `path` 和 `used[i]`，否则后续兄弟分支会继承错误状态。
- **保存结果时要复制**：`path` 会被不断修改；如果 `result.add(path)`，最终结果里的多项会指向同一个列表对象。
- **空数组语义**：组合数学上空集合有一个排列——空排列，因此这里返回 `[[]]`。这是本候选的显式 API 契约，来源本身没有规定。
- **重复值不是当前主契约**：如果输入 `[1,1,2]`，按“位置互异”搜索会产生值序列重复。若题目要求唯一排列，应先明确这个要求，再采用排序 + 同层去重。
- **不要用 `contains` 代替位置状态**：`path.contains(nums[i])` 对不同值输入虽然能工作，但每次检查是线性的，会额外增加开销；并且一旦允许重复值，值级 contains 无法表达“哪个位置已使用”。
- **输出本身有阶乘规模**：任何真正枚举全部排列的算法都无法把总运行时间降到多项式级；优化重点是避免无意义重复扫描、错误复制和不必要的额外状态。

## 原理机制

回溯的核心不变量是：进入深度 `d` 时，`path` 恰好包含 `d` 个互不重复的位置，且 `used` 与 `path` 一一对应。当前层把任意一个未使用位置接到末尾，因此每条根到叶子的路径都会形成一个合法排列；反过来，任意一个排列都对应唯一的“第 1 位选哪个位置、第 2 位选哪个位置……”的选择序列，所以不会漏解。

对不同元素，深度 0 有 `n` 个选择，深度 1 有 `n-1` 个选择，直到最后只剩 1 个，因此叶子数量是 `n!`。每到一个叶子还要复制长度为 `n` 的结果，所以完整枚举的时间至少包含 `Θ(n · n!)` 的输出成本。

## 项目经验版

来源是算法手写题，没有真实项目背景，因此不虚构线上使用经历。工程里真正遇到排列搜索时，首先要判断是否真的需要“枚举全部结果”；如果只需要计数、字典序第 k 个排列、满足约束的一个解，通常应利用问题结构避免物化全部 `n!` 个结果。全排列回溯更适合作为搜索状态、递归恢复和复杂度意识的基础题。

## 常见追问

- 问：为什么一定要 `new ArrayList<>(path)`？答：因为 `path` 是整棵搜索树复用的可变工作区；保存引用而不是快照，后续回溯会修改已经放进结果的内容。
- 问：时间复杂度为什么不是简单的 `O(n!)`？答：有 `n!` 个结果，每个结果长度为 `n`，仅把结果复制出来就需要 `Θ(n · n!)` 的元素写入。
- 问：空数组返回什么？答：本契约返回一个空排列 `[[]]`，这样递归的“深度等于 n 就产生一个排列”在 `n=0` 时也自然成立；来源没有规定这一边界，所以需要显式声明。
- 问：有重复元素怎么办？答：先确认是否要求去重。若要求唯一值排列，通常先排序，然后在同一层使用 `i>0 && nums[i]==nums[i-1] && !used[i-1]` 跳过重复分支，同时仍用 `used` 区分位置。
- 问：能不能原地交换数组来做？答：可以。固定位置 `first`，把后面的每个元素交换到 `first`，递归后再交换回来；对不同元素同样正确，能省掉 `used[]`，但要特别注意恢复输入数组。
- 问：递归深度是多少？答：恰好是 `n`。如果 `n` 大到递归栈成为问题，阶乘级输出通常更早成为主要瓶颈；若只做懒生成，也可以用迭代的 next-permutation 等方案。
- 问：如何验证没有漏解或重复？答：对小 n 可以和独立的字典序 next-permutation 枚举器比较结果集合，同时验证结果数是 `n!`、每一项长度为 n、元素多重集合与输入一致。

## 易错点

- 递归回来后忘记 `used[i]=false` 或忘记删除 `path` 最后一个元素。
- 直接 `result.add(path)`，导致结果共享同一可变对象。
- 把“元素值是否出现过”和“输入位置是否使用过”混为一谈。
- 来源没有说重复元素，却在答案里默认“必须去重”或反过来默认“重复结果就是正确语义”。
- 把阶乘级枚举说成低阶多项式复杂度，忽略输出规模本身。
- 为了避免重复使用 `path.contains`，既降低性能又让重复值语义变得含混。
