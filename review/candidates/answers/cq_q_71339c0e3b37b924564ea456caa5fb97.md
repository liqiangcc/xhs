# 超过半数的数字：Boyer-Moore（摩尔）投票法

## 核心结论

如果一个数组里确实存在出现次数 **严格大于 `n/2`** 的元素，Boyer-Moore Majority Vote 可以用 `O(n)` 时间、`O(1)` 额外空间找出它的候选值：维护 `candidate` 和 `count`，相同元素给候选“加一票”，不同元素“抵消一票”，当 `count == 0` 时用当前元素重建候选。

原题只说“超过半数的数字（摩尔投票法）”，没有明确说输入是否保证一定存在多数元素。为了不把保证条件凭空补进题目，下面给一个更稳健的接口：第一遍找候选，第二遍验证候选出现次数确实 `> n/2`；不存在时返回 `OptionalInt.empty()`。如果面试官明确保证多数元素一定存在，则第二遍验证可以省掉。

## 1 分钟版

- `count == 0` 时把当前值设成候选，并把计数置 1。
- 后续值等于候选就 `count++`，不同就 `count--`。
- 可以把 `count--` 理解成“一个候选值和一个非候选值成对删除”。
- 真正超过半数的元素不可能被这种一对一删除全部消掉，所以若多数元素存在，第一遍最后的候选一定是它。
- 若题目没有保证多数元素存在，第一遍只能得到“候选”，必须第二遍计数验证 `occurrences > n / 2`。
- 两遍都是线性扫描，总时间仍为 `O(n)`，只用常数个变量，额外空间 `O(1)`。

## 3 分钟版

```java
import java.util.OptionalInt;

public final class MajorityVote {
    public static OptionalInt majorityElement(int[] nums) {
        if (nums == null || nums.length == 0) {
            return OptionalInt.empty();
        }

        int candidate = 0;
        int count = 0;
        for (int value : nums) {
            if (count == 0) {
                candidate = value;
                count = 1;
            } else if (value == candidate) {
                count++;
            } else {
                count--;
            }
        }

        int occurrences = 0;
        for (int value : nums) {
            if (value == candidate) occurrences++;
        }
        return occurrences > nums.length / 2
                ? OptionalInt.of(candidate)
                : OptionalInt.empty();
    }
}
```

若输入 `[2,2,1,1,1,2,2]`，不同值不断与当前候选抵消，最后留下候选 `2`；第二遍确认它出现 4 次，而 `4 > 7/2`，因此返回 2。若输入 `[1,2,3]`，第一遍同样会留下某个候选，但第二遍发现它没有超过半数，就返回 empty。

## 关键细节

- **“超过半数”是严格大于**：长度 4 的数组中出现 2 次只是恰好一半，不是多数元素。
- **第一遍不是通用存在性证明**：Boyer-Moore 在没有多数元素时仍会产生候选；只有题目保证多数存在，才能直接返回第一遍候选。
- **抵消不要求相邻**：算法只是用计数器等价表示成对删除，不需要真的修改数组。
- **负数和任意 int 都可以**：候选值不需要特殊哨兵，关键由 `count == 0` 决定候选是否有效。
- **空输入契约**：原题没有给 API；本答案选择空数组/`null` 返回 `OptionalInt.empty()`，这是答案侧接口定义。
- **复杂度**：找候选一遍 `O(n)`，验证一遍 `O(n)`，合起来仍为 `O(n)`；只保存候选、计数和验证计数，额外空间 `O(1)`。

## 原理机制

假设真正的多数元素是 `M`。每当算法遇到与当前候选不同的值并执行一次减计数，都可以等价看成从尚未抵消的元素中删除一对不同值。任何一次这样的删除最多删除一个 `M`，同时也必须删除一个非 `M`。因为 `M` 最初数量严格大于所有非 `M` 的总数，所以无论怎样成对删除不同值，都不可能把所有 `M` 删除干净。于是当确实存在多数元素时，最终剩下的候选只能是 `M`。

这个证明同时解释了为什么“没有多数元素时要二次验证”：如果没有哪个值占超过一半，成对抵消结束后仍可能留下某个值，但它只是抵消过程的剩余者，并不自动满足多数条件。

## 项目经验版

来源是纯算法题，没有真实项目背景，因此不虚构生产经历。实际写库函数时，我会先明确接口是否承诺“多数必存在”：若承诺存在，可以返回 `int` 并只跑一遍；若不承诺，就像这里一样返回可空结果并做第二遍验证。这个差异是 API 契约问题，不是算法本身的隐藏条件。

## 常见追问

- 问：为什么不同元素可以直接抵消？答：目标元素超过总数一半，每删除一个多数元素都必须搭配删除一个非多数元素，而非多数总数更少，所以真正多数不可能全部被抵消。
- 问：为什么 `count == 0` 可以换候选？答：此前维护的未抵消候选票已经被不同值一一抵完，对最终多数判断不再提供净优势，可以从当前位置重新开始计票。
- 问：如果题目保证一定有多数元素，第二遍还需要吗？答：不需要；保证条件本身就补足了存在性证明，第一遍候选可直接返回。
- 问：如果不保证存在，为什么第二遍足够？答：第一遍只会给一个候选；第二遍直接数它的真实出现次数并检查 `> n/2`，就能决定是否存在满足条件的结果。
- 问：能找超过 `n/3` 的元素吗？答：单候选 Boyer-Moore 不够；可推广为最多维护两个候选，再二次验证，因为超过 `n/3` 的元素最多有两个。
- 问：复杂度为什么还是 O(n)？答：常数次完整扫描是 `O(n)`，不是 `O(2n)` 这种新的渐进复杂度。

## 易错点

- 把“第一遍最后候选”无条件当作多数元素，即使题目没有保证多数一定存在。
- 用 `>= n/2` 验证，把恰好一半误判成“超过半数”。
- `count == 0` 时只换候选却忘记把当前元素计为 1 票。
- 为了实现“抵消”真的删除数组元素，把 `O(1)` 空间和线性扫描优势破坏掉。
- 把 `candidate` 的初始值当成特殊值；候选是否合法由计数状态决定，与数值本身无关。
