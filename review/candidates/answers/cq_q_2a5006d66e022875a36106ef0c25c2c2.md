# 最长连续序列长度

## 核心结论

仓库原始来源只保留了“最长连续序列长度”这个题名，没有保留“连续”是按输入下标连续还是按数值相邻、输入类型、重复值语义、复杂度目标、语言或函数签名。因此这里显式采用候选契约：输入一个 `int[]`，忽略原始顺序，寻找由**不同整数值按 `+1` 连续**组成的最长序列，并返回其长度；重复值不增加长度；`null` 或空数组返回 `0`；不修改输入。

在这个契约下，可把所有值放入集合。只从“没有前驱 `x-1`”的值开始向后扩展 `x, x+1, ...`；这样每段连续区间只从真正起点扫描一次，避免从区间中间重复计数。

## 1 分钟版

我先把“连续”定义清楚：这里不是数组下标连续，而是数值连续，例如 `[100,4,200,1,3,2]` 的最长连续值序列是 `1,2,3,4`，长度 4。

做法是：

1. 把所有整数放进集合，自动去重。
2. 遍历集合里的每个 `x`；如果集合里存在 `x-1`，说明 `x` 不是一段序列的起点，跳过。
3. 只有起点才不断检查 `x+1、x+2...`，更新最大长度。

在 HashSet 平均常数时间假设下，期望时间 `O(n)`，额外空间 `O(n)`。当前实现把集合元素提升成 `long`，避免在 `Integer.MIN_VALUE - 1` 或 `Integer.MAX_VALUE + 1` 处发生整数溢出。

## 3 分钟版

来源没有说明“连续”的定义，因此候选答案必须先承认这个缺口。这里选择常见的“按整数值相邻，输入顺序无关”的契约；HashSet 和平均 `O(n)` 也只是实现选择，不冒充原题复杂度要求。

集合有两个作用：第一是去重，所以重复的 `2` 不会把 `1,2,3` 误算成长度 4；第二是支持快速判断某个数的前驱和后继是否存在。

最重要的优化是只从序列起点扩展。若 `x-1` 已存在，那么从 `x` 开始扫描一定会重复覆盖一段已经应该由更小值负责的连续区间。只有当 `x-1` 不存在时，`x` 才是该区间的最小值；从这里向 `x+1` 扩展即可得到整段长度。

为了让边界行为确定，集合使用 `Long` 保存由 `int` 提升后的值。这样检查 `value - 1` 和 `current + 1` 不会在 `Integer.MIN_VALUE`/`MAX_VALUE` 上回绕。这个实现不排序、不修改输入数组。

## 关键细节

- **题源边界**：来源只支持题名“最长连续序列长度”；按数值 `+1` 连续、忽略输入顺序、Java `int[]`、HashSet、重复值与复杂度都是显式候选选择。
- **去重**：重复值属于同一个整数点，不应增加连续区间长度。
- **只从起点扫描**：有 `x-1` 时跳过 `x`，避免同一连续区间从多个位置重复扩展。
- **整数边界**：使用 `long` 集合承载 `int` 值，防止 predecessor/successor 检查溢出。
- **不修改输入**：实现不排序原数组；验证用的排序 oracle 只操作副本。
- **复杂度**：在 HashSet 平均 `O(1)` 查找假设下，构建集合和扫描的期望时间为 `O(n)`，额外空间 `O(n)`；最坏哈希退化不宣称严格线性。
- **可验证性**：固定用例覆盖空输入、乱序、重复值、负数、全重复以及 int 两端边界；再用 5000 组确定性随机数组与独立“排序—去重—扫描” oracle 对照，并验证输入数组未修改。

## 原理机制

```java
import java.util.HashSet;
import java.util.Set;

public final class LongestConsecutiveSequence {
    private LongestConsecutiveSequence() {}

    public static int longestConsecutive(int[] values) {
        if (values == null || values.length == 0) {
            return 0;
        }

        Set<Long> set = new HashSet<>();
        for (int value : values) {
            set.add((long) value);
        }

        int best = 0;
        for (long value : set) {
            if (set.contains(value - 1L)) {
                continue;
            }
            int length = 1;
            long current = value;
            while (set.contains(current + 1L)) {
                current++;
                length++;
            }
            best = Math.max(best, length);
        }
        return best;
    }
}
```

独立验证 oracle 使用完全不同的控制流：复制数组、排序、跳过重复值，再扫描相邻不同值是否相差 1。固定测试和 5000 组随机数组的预检输出为：

```text
PASS fixed=10 randomized=5000 oracle=sort-deduplicate-scan mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有生产项目上下文，因此不编造项目经历。如果真实题目中的“连续”指**原数组中的连续子数组**，本答案的集合方法就不适用；应该改成滑动窗口、动态规划或按具体约束重新建模。先确认“连续”的语义是这道题最重要的边界。

## 常见追问

- 问：为什么不直接排序？答：排序副本可以得到更简单的 `O(n log n)` 解法；当前候选选择集合，是为了在平均哈希假设下做到期望 `O(n)`，但这不是题源要求。
- 问：重复值怎么处理？答：集合会去重，重复值不增加连续区间长度，例如 `[1,2,2,3]` 返回 3。
- 问：为什么只从没有 `x-1` 的值开始？答：因为它才是该连续区间的最小值；从中间值扫描会重复工作。
- 问：为什么用 `long` 集合？答：为了安全检查 `int` 边界的前驱/后继，避免溢出回绕。
- 问：如果“连续”是下标连续怎么办？答：那是另一道契约，必须基于子数组而不是数值集合重新设计算法。

## 易错点

- 没先定义“连续”就直接套用某个在线题模板。
- 从集合里的每个值都向后扫描，导致重复工作。
- 忘记去重，让重复值错误增加长度。
- 在 `Integer.MIN_VALUE/MAX_VALUE` 上直接用 `int` 做 `-1/+1` 导致溢出。
- 为了排序直接修改输入数组却没有声明副作用。
- 声称 HashSet、`O(n)` 或某个在线题号是原题要求，而仓库来源并没有这些信息。
