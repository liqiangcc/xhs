# SQL：查找所有张姓学生及其最高成绩

## 核心结论

来源只给出一张包含“学生名、科目名、成绩”的表，并要求查找所有张姓学生的名字及对应最高成绩；没有给真实表名、列名、学生 ID、排序规则或同名学生区分方式。这里采用最小可执行契约：表名为 `student_scores(student_name, subject_name, score)`，一行表示某个姓名在一个科目上的一条成绩记录；先用 `student_name LIKE '张%'` 过滤张姓，再按姓名分组，用 `MAX(score)` 取该姓名对应的最高成绩。

## 1 分钟版

- 先按姓名前缀筛选：`WHERE student_name LIKE '张%'`。
- 输出粒度是一名“按姓名识别的学生”一行，所以按 `student_name` 分组。
- 每组用 `MAX(score)` 取最高成绩；并列最高分不会影响最终数值。
- 来源没有学生 ID，因此同名不同人无法可靠区分；如果真实表有 `student_id`，应按 ID + 姓名分组。
- 来源没有要求排序，正式 SQL 不把 `ORDER BY` 当成必需条件。

## 3 分钟版

```sql
SELECT
    student_name,
    MAX(score) AS max_score
FROM student_scores
WHERE student_name LIKE '张%'
GROUP BY student_name;
```

这个 SQL 先把非张姓记录过滤掉，再按姓名聚合。假设 `张三` 有语文 88、数学 95、英语 95 三条记录，聚合结果仍只有一行 `张三, 95`；如果 `李四` 有 100 分，因为不满足 `张%`，不会进入聚合。

## 关键细节

- **姓名前缀**：这里把“张姓”解释为姓名字符串以“张”开头。若真实数据有独立姓氏列，应优先按结构化字段过滤。
- **同名学生**：来源只保存学生名，没有学生 ID。按姓名分组会把同名不同人合并；这是源数据契约不足，不应伪造一个 ID 解决。
- **空值**：标准 SQL 的 `MAX(score)` 会忽略 `NULL`；如果某个姓名的全部成绩都是 `NULL`，结果为 `NULL`。是否允许空成绩需要真实 schema 决定。
- **重复记录**：重复成绩行不会改变 `MAX` 的数值；但它们可能代表数据质量问题，不能因为结果一样就默认忽略上游重复。
- **排序**：来源没要求结果顺序。如果需要按姓名或最高分排序，再明确增加 `ORDER BY`。
- **复杂度**：逻辑上需要扫描满足条件的行并按姓名聚合；具体代价取决于数据库、索引、数据量和执行计划，不能脱离真实引擎给固定复杂度结论。

## 原理机制

`WHERE` 在聚合前缩小参与计算的行集合；`GROUP BY student_name` 把剩余行划分成按姓名的分组；`MAX(score)` 在每个分组内计算最大值。因此最终结果粒度从“每个科目一条成绩记录”收缩为“每个张姓姓名一条最高成绩记录”。

如果真实表同时有 `student_id`，更稳妥的分组粒度应是 `(student_id, student_name)`，因为姓名不是可靠主键。这不是 SQL 语法问题，而是数据模型决定结果语义的问题。

## 项目经验版

来源没有真实项目表结构、数据库类型、索引和数据规模，不能虚构生产经验。实际落地时应先核对姓名字段是否规范化、是否存在独立姓氏或学生 ID、`score` 是否允许 `NULL`，再用目标数据库的执行计划验证过滤和聚合成本。

## 常见追问

- 问：为什么不用 `HAVING` 筛选张姓？答：张姓是行级条件，应在聚合前用 `WHERE` 过滤；`HAVING` 更适合对聚合结果做条件判断。
- 问：如果要同时返回最高分对应的科目怎么办？答：仅 `MAX(score)` 不够；需要窗口函数、子查询或连接，并定义并列最高分时返回一科还是多科。
- 问：同名学生怎么办？答：来源没有学生 ID，当前最小契约只能按姓名聚合；真实表若有 ID，应把 ID 纳入分组。
- 问：如果要按最高分从高到低排序？答：在聚合后增加 `ORDER BY max_score DESC`，但这属于新增输出要求。
- 问：为什么不写 `DISTINCT student_name, MAX(score)`？答：`GROUP BY` 已经定义了聚合粒度，额外 `DISTINCT` 没有必要。

## 易错点

- 忘记 `GROUP BY`，导致姓名和聚合值的关系不明确或 SQL 直接报错。
- 先按所有学生聚合再错误地用与姓名无关的条件筛选。
- 把姓名当可靠唯一键，却不说明同名学生会被合并。
- 为了返回最高分对应科目，只写 `MAX(score)` 却同时随意选择一个 `subject_name`。
- 来源没有排序、ID、空值规则，却把实现偏好写成原题约束。
