# 子数组和至少为 target：一般整数输入的最短长度

## 核心结论

仓库原始面经只保留了：**“给一个数组，一个 int 型 target，求使得子数组和大于等于 target 时，最小的子数组长度。”** 原文没有说明数组元素一定为正数，因此不能把“全为正数时可用的双指针滑动窗口”当成题目已给条件。

候选实现选择更一般的契约：输入为任意 `int[]`，元素允许正数、零和负数；返回满足“连续、非空、元素和 `>= target`”的最短长度；不存在时返回 `0`；`null` 输入显式抛出 `NullPointerException`。这些 API/异常选择是候选约定，不冒充原题条件。

一般整数下使用**前缀和 + 单调递增下标队列**。设 `P[i]` 是前 `i` 个元素之和，则区间 `[j, i)` 的和是 `P[i] - P[j]`。扫描每个 `i` 时，只保留那些未来仍可能成为更优左端点的 `j`。整个过程中每个前缀下标最多入队一次、出队一次，因此时间 `O(n)`，空间 `O(n)`；前缀和使用 `long`，避免多个 `int` 相加溢出。

## 1 分钟版

先把数组变成前缀和 `P`。问题变成：对每个右端点 `i`，找最大的可用左端点 `j < i`，使 `P[i] - P[j] >= target`，这样长度 `i-j` 最短。

队列中的下标按前缀和值严格递增维护：

- 如果当前 `P[i] - P[队首] >= target`，队首已经形成可行区间；先更新最短长度，再弹出队首继续尝试更靠右的左端点。
- 如果当前 `P[i] <= P[队尾]`，旧队尾永远不如当前 `i`：当前前缀和更小或相等，而且位置更靠右，未来拿它做左端点只会得到更大的区间和、同时区间更短，因此弹掉旧队尾。
- 最后把 `i` 入队。

这和正数数组的滑动窗口不同：有负数时，右端扩张后窗口和可能下降，移动左端后窗口和也不再单调，所以普通双指针不成立。

## 3 分钟版

定义 `P[0]=0`，`P[i+1]=P[i]+nums[i]`。任意连续子数组 `[j,i)` 的和正好是 `P[i]-P[j]`。

队列保存“尚有可能成为未来最优左端点”的前缀下标，并保持两个性质：下标递增、对应的前缀和值严格递增。

为什么可以从队首弹可行项？当 `P[i]-P[j] >= target` 时，`j` 已经得到一个以 `i` 为右端点的可行区间。若队列里还有更靠右的下标，也应该继续检查，因为它会给出更短长度；而已经弹出的 `j` 对任何未来更大的右端点都不可能产生比当前更短的区间，所以更新答案后永久删除是安全的。

为什么可以从队尾删除更大的前缀和？若有 `j < i` 且 `P[j] >= P[i]`，对任何未来 `k > i`：

- `P[k]-P[i] >= P[k]-P[j]`，所以用 `i` 不会更难达到 target；
- `k-i < k-j`，所以用 `i` 还会得到更短区间。

因此 `j` 被 `i` 完全支配，可以删除。

两个 while 分别只会把每个下标弹出一次，所以虽然嵌套在主循环里，总操作数仍是线性的。

## 关键细节

- **正数前提不能偷加**：原题没有说元素为正。若面试官补充“所有元素均为正”，可把实现简化成 `O(1)` 额外空间的滑动窗口；当前候选默认支持负数。
- **连续且非空**：长度由前缀下标差 `i-j` 给出，只在 `j < i` 时产生非空子数组。
- **无解返回值**：原题没定义，候选约定返回 `0`。
- **空数组**：没有非空子数组，因此返回 `0`。
- **null**：原题没定义，候选选择显式失败，而不是静默把它当空数组。
- **溢出**：元素和可能超过 `int`，所以前缀和使用 `long`；`target` 仍保持原题的 `int`。
- **target 可为负数**：算法不依赖 target 为正；只要存在单元素或更短区间达到条件，就会返回最短长度。
- **复杂度**：`O(n)` 时间、`O(n)` 额外空间。

## 原理机制

```java
import java.util.Objects;

public final class ShortestSubarrayAtLeastTarget {
    private ShortestSubarrayAtLeastTarget() {}

    /**
     * Returns the minimum length of a contiguous subarray whose sum is at least target.
     * Returns 0 when no such non-empty subarray exists.
     */
    public static int minLength(int[] nums, int target) {
        Objects.requireNonNull(nums, "nums");
        int n = nums.length;
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }

        int[] deque = new int[n + 1];
        int head = 0;
        int tail = 0;
        int best = n + 1;

        for (int i = 0; i <= n; i++) {
            while (head < tail && prefix[i] - prefix[deque[head]] >= target) {
                best = Math.min(best, i - deque[head]);
                head++;
            }
            while (head < tail && prefix[i] <= prefix[deque[tail - 1]]) {
                tail--;
            }
            deque[tail++] = i;
        }

        return best == n + 1 ? 0 : best;
    }
}
```

仓库验证使用固定边界样例和固定随机种子的差分测试：5000 组长度不超过 24、同时含正负数的数组，与独立 `O(n^2)` 穷举 oracle 比较；另外覆盖无解、空数组、单元素、负 target、负数破坏普通滑窗、以及两个 `Integer.MAX_VALUE` 相加的前缀和溢出风险。

## 项目经验版

这是算法题，原始面经没有生产项目背景，因此不编造项目经历。工程实现时真正要确认的是：数组规模、是否允许负数、无解如何编码、输入是否可为空、是否需要返回具体区间而不只是长度。如果题目明确元素全为正，可以改用滑动窗口把额外空间降到 `O(1)`；若允许任意整数，则必须保留能处理非单调区间和的方法。

## 常见追问

- 问：为什么普通滑动窗口在含负数时不可靠？答：加入一个负数可能让窗口和下降，移除一个负数反而可能让窗口和上升，“右移右端只增、右移左端只减”的单调关系不存在，不能据此安全丢弃状态。
- 问：队尾为什么可以被当前前缀永久淘汰？答：若旧前缀和值更大或相等且位置更左，那么当前前缀对任何未来右端点都能提供不少于它的区间和，同时区间更短，旧状态被完全支配。
- 问：队首为什么达到 target 后可以弹出？答：当前右端已经是这个左端能遇到的最早可行右端；未来右端只会更靠右、长度更长，因此该左端不可能再改善答案。
- 问：如果面试官确认所有元素都为正呢？答：使用左右指针；右端扩张累加，`sum >= target` 时不断右移左端并更新最短长度，可做到 `O(n)` 时间、`O(1)` 额外空间。
- 问：为什么前缀和要用 `long`？答：即使每个元素和 target 都是 `int`，多个元素累加仍可能超过 32 位范围；使用 `long` 避免比较条件被整数溢出破坏。
- 问：如果还要返回区间端点呢？答：在更新 `best` 时同时保存当前 `deque[head]` 和 `i-1` 即可；若有多个同长答案，还要额外约定 tie-break。

## 易错点

- 默认题目是经典“正整数最短子数组”而直接套普通滑动窗口。
- 前缀和仍使用 `int`，大输入下溢出后单调关系和差值判断都错误。
- 只维护前缀和递增，却忘了先从队首反复收缩所有当前可行左端点，错过更短答案。
- 用 `prefix[i] < prefix[tail]` 而不是 `<=`，把相等但更靠右、显然更优的前缀位置保留不彻底。
- 把“无解返回 0”写成原题条件；它只是候选 API 约定。
