# DFS 求单源最短路径：先把“特殊条件”和图模型说清

## 核心结论

来源只保留“给定一个图，使用 DFS 求单源最短路径（带特殊条件处理）”，没有保留图是否带权、方向、输入 API，也没有说明“特殊条件”到底是什么，因此不能把某一种条件补写成原题。这里给出一个可执行参考契约：**有向无权图**，边的代价统一为 1；额外传入 `blocked[v]` 作为“不可经过节点”的示例特殊条件；源点不能被屏蔽；不可达或被屏蔽节点返回 `-1`。为了尊重题干中的 DFS，本实现不是“一次 visited 就结束”，而是在 DFS 中做距离松弛：只有发现更短 hop 数时才更新并继续向外传播。

## 1 分钟版

- 如果无权图只要求最短 hop 数，工程上优先 BFS，复杂度 `O(V+E)`，语义也最直接。
- 题干明确要求 DFS 时，不能用普通 `visited`：第一次 DFS 到达某点的路径不保证最短，后面更短路径必须允许重新更新。
- 参考实现维护 `dist[v]`；从 `u` 走到 `v` 的候选是 `dist[u]+1`，只有候选更小时才写入并递归 `v`。
- `blocked[]` 只是对“特殊条件”的一个显式参考定义，不声称来源就是这个条件；被屏蔽节点完全不参与路径。
- 由于节点距离只会严格下降有限次，算法会终止；但同一顶点可能多次被重新扫描，最坏可到 `O(VE)`，明显不如 BFS。

## 3 分钟版

```java
import java.util.*;

public final class Solution {
    private Solution() {}

    public static int[] shortestHopsDfs(List<List<Integer>> graph, int source, boolean[] blocked) {
        Objects.requireNonNull(graph, "graph");
        int n = graph.size();
        if (blocked == null || blocked.length != n) throw new IllegalArgumentException("bad blocked array");
        if (source < 0 || source >= n) throw new IllegalArgumentException("bad source");
        if (blocked[source]) throw new IllegalArgumentException("source is blocked");

        int[] dist = new int[n];
        Arrays.fill(dist, -1);
        dist[source] = 0;
        relaxDfs(graph, source, blocked, dist);
        return dist;
    }

    private static void relaxDfs(List<List<Integer>> graph, int u, boolean[] blocked, int[] dist) {
        List<Integer> nexts = graph.get(u);
        if (nexts == null) throw new IllegalArgumentException("null adjacency");
        int candidate = dist[u] + 1;
        for (Integer boxed : nexts) {
            if (boxed == null) throw new IllegalArgumentException("null endpoint");
            int v = boxed;
            if (v < 0 || v >= graph.size()) throw new IllegalArgumentException("bad endpoint");
            if (blocked[v]) continue;
            if (dist[v] == -1 || candidate < dist[v]) {
                dist[v] = candidate;
                relaxDfs(graph, v, blocked, dist);
            }
        }
    }
}
```

例如边 `0→1, 0→2, 1→3, 2→4, 4→3`，从 0 出发时 3 的最短 hop 数是 2。DFS 的遍历顺序可以先走长路径，但只要后续发现更小的 `candidate`，3 会被再次更新并继续传播；这也是为什么不能把“第一次访问”当成最短路已经确定。

## 关键细节

- **为什么普通 DFS visited 不对**：DFS 的第一次到达顺序由邻接表排列决定，并不按路径长度分层；第一次到达可能是长路径。
- **终止性**：所有边代价为 1，任何成功松弛都会让某个 `dist[v]` 从未知变成有限值，或把有限值严格减小；有限图中这种下降次数有限。
- **复杂度**：一个顶点可能因更短距离被多次重新递归。有限最短 hop 数不超过 `V-1`，因此每个顶点成功改善次数是 `O(V)`，总边扫描可达 `O(VE)`；递归栈最深 `O(V)`。
- **特殊条件边界**：这里选择“屏蔽节点”只是为了让参考实现可执行。若真实条件是“必须经过某点”“最多经过 K 条边”“某类边不可用”等，状态定义和算法都要相应变化。
- **带权图**：若边权不是统一 1，就不能把 hop 数当距离。非负权通常考虑 Dijkstra；负权还要重新确认负环和算法契约。
- **为什么仍推荐 BFS**：在同一个无权 + blocked 契约下，BFS 第一次入队即可确定最短层数，时间 `O(V+E)`；DFS 松弛法主要用于回答“题目强制要求 DFS 时怎么保证正确”。

## 原理机制

这个 DFS 版本本质上执行重复的松弛传播。`dist[u]` 表示当前已知的 source→u 最少边数上界；每条可用边 `u→v` 都产生候选 `dist[u]+1`。一旦候选更小，就更新 `dist[v]`，并用 DFS 立即把这次改善继续传播到后继。最终没有任何边还能继续改善时，所有可达节点都满足最短路的 Bellman 最优性条件。它和 BFS 的区别在于调度顺序：BFS 按距离层调度，一次就能确定无权图最短距离；这里按调用栈深度调度，所以可能反复修正。

## 项目经验版

来源没有真实图规模、特殊条件定义或线上数据，不能虚构实际项目效果。落地时我会先把“特殊条件”改写成明确状态约束，再用一个独立 BFS/最短路实现做随机差分测试；如果没有“必须使用 DFS”的外部限制，无权图生产实现会直接选 BFS，避免 `O(VE)` 的重复扫描和深递归栈风险。

## 常见追问

- 问：为什么不能 DFS 第一次访问后就 `visited=true`？答：第一次到达不保证路径最短，后面可能从另一个分支得到更短距离；永久 visited 会把这次改善挡掉。
- 问：这个 DFS 为什么不会在有环图里无限递归？答：只有距离严格改善才递归；正 hop 代价的环不可能不断产生更短距离，所以改善次数有限。
- 问：特殊条件如果是“最多走 K 条边”怎么办？答：状态必须扩成 `(vertex, usedEdges)`，不能只保存每个顶点一个 dist；这已经是不同契约。
- 问：为什么 BFS 更适合无权最短路？答：BFS 按 hop 数分层，第一次到达节点就是最少边数，因此每个顶点和边只需线性处理。
- 问：如果图有非负权重还能这样 `+1` 吗？答：不能，候选必须用真实权重；此时应重新选适合权重模型的算法，通常是 Dijkstra，而不是把 hop 数冒充距离。

## 易错点

- 把来源没有说明的“特殊条件”直接当成 blocked、必经点或步数限制中的某一种，并声称是原题。
- 用普通 DFS + 永久 visited 就认为得到了最短路径。
- 图有权却仍然用 `dist[u]+1`。
- 忽略环、不可达、屏蔽源点和非法端点。
- 明明是无权图通用实现，却忽略 BFS 更简单且复杂度更好的事实。
