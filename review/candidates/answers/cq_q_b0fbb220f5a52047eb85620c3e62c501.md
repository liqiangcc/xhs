# DFS 求单源最短路径：先说明适用边界，再给可验证参考实现

## 核心结论

来源只保留“给定一个图，使用 DFS 求单源最短路径（带特殊条件处理）”，没有保留图是否有向、边权、特殊条件、输出是单目标还是全点距离，也没有给数据规模。因此不能把某一种图模型冒充成原题。下面采用一个明确的参考契约：**有向图、非负 `long` 边权、给定源点，返回源点到全部顶点的最短距离；不可达返回 `Long.MAX_VALUE`；负权边拒绝；距离加法溢出显式失败。** 实现使用 DFS 式松弛：只有当某条路径把顶点距离变短时才继续从该顶点递归扩展。

## 1 分钟版

- `dist[source]=0`，其他点先设为无穷大。
- DFS 到边 `u -> v (w)` 时计算候选距离 `dist[u]+w`；只有候选值更小才更新 `dist[v]` 并继续从 `v` 深搜。
- 当前递归路径用 `onPath` 防止沿环立即递归回去；非负权图的最短路一定可以取简单路径，因此跳过当前路径上的重复顶点不会损失最优解。
- 这不是一般图最短路的首选算法：无权图优先 BFS，非负加权图通常用 Dijkstra。这里坚持 DFS 是为了忠于来源中明确保留下来的“使用 DFS”。
- 如果真实“特殊条件”包含负权、DAG、只能经过某类节点等，算法和证明都要按真实条件重新定义。

## 3 分钟版

```java
import java.util.*;

public final class Solution {
    private Solution() {}

    public record Edge(int to, long weight) {}

    public static long[] shortestPaths(List<List<Edge>> graph, int source) {
        Objects.requireNonNull(graph, "graph");
        int n = graph.size();
        if (source < 0 || source >= n) throw new IllegalArgumentException("invalid source");
        for (int u = 0; u < n; u++) {
            List<Edge> edges = Objects.requireNonNull(graph.get(u), "null adjacency list");
            for (Edge e : edges) {
                Objects.requireNonNull(e, "null edge");
                if (e.to() < 0 || e.to() >= n) throw new IllegalArgumentException("invalid endpoint");
                if (e.weight() < 0) throw new IllegalArgumentException("negative weight");
            }
        }

        long[] dist = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[source] = 0L;
        boolean[] onPath = new boolean[n];
        onPath[source] = true;
        relaxDfs(graph, source, dist, onPath);
        return dist;
    }

    private static void relaxDfs(List<List<Edge>> graph, int u, long[] dist, boolean[] onPath) {
        for (Edge e : graph.get(u)) {
            long next = Math.addExact(dist[u], e.weight());
            int v = e.to();
            if (next >= dist[v]) continue;
            dist[v] = next;
            if (onPath[v]) continue;
            onPath[v] = true;
            try {
                relaxDfs(graph, v, dist, onPath);
            } finally {
                onPath[v] = false;
            }
        }
    }
}
```

例如 `0->1(5), 0->2(1), 2->1(1)`：第一次从 `0` 到 `1` 得到 5；随后 DFS 走 `0->2->1` 把 `1` 改成 2，并再次从 `1` 扩展。关键不是“访问过就不再访问”，而是“距离真正变短才继续传播”。

## 关键细节

- **为什么普通 visited 不行**：一个顶点第一次被 DFS 到达时不一定就是最短距离；若永久标记 visited，后续更短路径无法继续传播。
- **为什么 `onPath` 可以**：它只阻止当前递归链中的环，不阻止顶点以后因更短距离再次进入 DFS。非负权下，最短路可去掉环得到简单路径。
- **为什么要求非负权**：来源没有保留负权语义。负权会让“已有距离不会被绕环持续改善”的证明失效；有负环时最短路甚至没有有限答案。
- **复杂度**：这个 DFS 式松弛可能让同一顶点多次重新扩展，最坏情况明显劣于 Dijkstra，不能把它宣传成通用高效 SSSP。面试时应主动说明这是受“DFS”约束的参考实现。
- **溢出**：`Math.addExact` 让不可表示的路径长度直接失败，而不是 long 回绕成负数后污染最短距离。
- **不可达点**：保留 `Long.MAX_VALUE` 作为无穷大哨兵；如果业务要求 `-1` 或 Optional，需要在接口层转换。

## 原理机制

这个实现维护一个单调不变量：`dist[v]` 只会变小，而且每次变小时都会尝试把改进继续传播到后继。对任意一条源点出发的简单路径，只要其前缀距离被发现，DFS 就会尝试下一条边；因此所有能产生更短值的简单路径都会触发松弛。非负权图存在不含环的最短路径，所以阻止当前递归链重复顶点不会排除最优解。算法最终稳定时，不再存在一条边能让后继距离变小。

## 项目经验版

来源没有真实图规模、边权模型或线上约束，不能虚构项目数据。真实工程里若是无权最短路会直接选 BFS；非负权大图通常选 Dijkstra 或相应堆优化；若是 DAG 则按拓扑序做线性松弛。只有当题目明确要求 DFS 或图规模很小、特殊约束适合回溯时，才会考虑这里这种 DFS 传播方式。

## 常见追问

- 问：DFS 为什么能做，为什么又说不推荐？答：在这里的非负权参考契约下，反复“变短才传播”的 DFS 松弛最终能覆盖所有改进；但顶点可能被重复展开很多次，复杂度没有 Dijkstra 稳定。
- 问：能不能用一个全局 visited？答：不能。第一次到达一个点的路径可能更长，全局 visited 会阻断后来的更短路径。
- 问：如果是无权图呢？答：应优先 BFS，因为按层扩展天然保证第一次到达就是最短边数。
- 问：如果有负权边呢？答：本候选显式拒绝。真实题目若允许负权，应重新确认是否有负环并考虑 Bellman-Ford、DAG 松弛等算法。
- 问：特殊条件如果是“某些点不能经过”怎么办？答：把条件放到边/节点扩展前做过滤即可，但必须先冻结真实条件；不能凭空补题。

## 易错点

- 把 DFS 的第一次到达当成最短路径。
- 用永久 visited，导致更短路径无法继续向后传播。
- 没说明边权与负权边界，却把实现说成通用最短路。
- long 距离相加不检查溢出。
- 明知 BFS/Dijkstra 更自然，却不解释为什么题目要求 DFS 时仍这样实现。
