# Linux：统计文件中每个 URL 出现次数（awk / sort / uniq）

## 核心结论

题目只明确要求用 Linux 指令统计“文件中每个 URL 的出现次数”，并点名 `awk`、`sort`、`uniq`，但没有保留真实日志格式，也没有说明 URL 在第几列。因此不能把 `$1`、`$7` 等字段位置当成题目事实。最小可执行契约先按“每个非空行就是一个 URL”处理：先用 `awk` 提取 URL，再 `sort` 把相同 URL 排到一起，最后 `uniq -c` 计数；若真实文件是访问日志，只需要把 `awk` 的提取表达式替换成实际 URL 字段。

## 1 分钟版

- `uniq -c` 只能统计相邻重复行，所以前面必须先 `sort`。
- 如果一行就是一个 URL：`awk 'NF {print $0}' file | sort | uniq -c`。
- 如果是结构化日志，先确认 URL 在哪个字段；题目没有给字段位置，不能默认 `$1` 或 `$7`。
- 想按出现次数从高到低展示，可在最后再加 `sort -nr`；这属于输出排序增强，不是计数本身的必要条件。
- URL 默认按完整字符串精确比较；是否忽略 query、大小写、协议或尾斜杠必须另行定义。

## 3 分钟版

如果 `urls.txt` 每个非空行就是一个完整 URL：

```bash
LC_ALL=C awk 'NF {print $0}' urls.txt \
  | sort \
  | uniq -c \
  | sort -nr
```

例如输入三次 `https://a.example/x`、两次 `https://b.example/y`、一次 `https://c.example/z`，结果就是 `3/2/1`。如果真实文件是访问日志，经过确认 URL 恰好在第 7 列，则只替换提取步骤为 `awk 'NF >= 7 {print $7}' access.log`；“第 7 列”只是示例，不是来源事实。

## 关键细节

- **先 sort**：`uniq` 只合并连续相同行；不排序时，同一个 URL 分散在文件不同位置会被分成多组。
- **awk 的职责**：从原始记录提取 URL。日志 schema 不同，字段选择表达式也不同。
- **空行处理**：`NF` 过滤空白行，避免把空字符串统计成 URL。
- **匹配语义**：`https://a/x?a=1` 与 `https://a/x?a=2` 默认是两个字符串；若要按 path 聚合，必须先定义归一化口径。
- **locale**：`LC_ALL=C` 让排序采用稳定字节序，便于复现；不是计数正确性的必要前提。
- **复杂度**：`awk` 和 `uniq` 线性扫描，传统 `sort` 主导，约 O(n log n)；大文件可能使用外部排序和临时磁盘。
- **替代方案**：若不要求 `sort/uniq`，可以用 `awk` 关联数组直接计数，用内存保存唯一 URL 集合；题目点名这些命令时应先答标准流水线。

## 原理机制

这是典型 Unix pipeline：`awk` 把原始记录投影成 URL 流；`sort` 按 URL key 把相同记录聚集成连续区间；`uniq -c` 对每个连续区间计数；最后的 `sort -nr` 再按计数排序。每一步职责单一，所以可以独立替换 URL 提取规则并做 fixture 验证。

## 项目经验版

来源没有真实生产日志格式、文件规模或线上事故数据，不能虚构项目经历。真实落地时先取样确认字段、编码和 URL 归一化口径，再用已知计数的小 fixture 回归；文件很大时再关注 `sort` 的临时目录、磁盘和 locale。

## 常见追问

- 问：为什么直接 `uniq -c file` 不行？答：因为 `uniq` 只统计相邻重复记录，同一 URL 若不连续会被拆成多组，所以通常必须先排序。
- 问：URL 在 nginx access log 里怎么取？答：先确认具体 `log_format`，只有字段位置确定后才能写 `$N`，不能根据常见格式猜。
- 问：如何按次数降序？答：在 `uniq -c` 后加 `sort -nr`；次数相同时若还要求固定 URL 次序，再定义次级排序。
- 问：query 参数不同算同一个 URL 吗？答：默认完整字符串不同就算不同；若要忽略 query，先定义归一化规则再计数。
- 问：文件特别大怎么办？答：`sort` 可能做外部排序并使用临时磁盘；可调临时目录/内存，或在允许时改用 `awk` 哈希计数，但后者把唯一 URL 集合留在内存。

## 易错点

- 没有 `sort` 就直接 `uniq -c`。
- 来源没有日志 schema 却写死 `$1`、`$7`。
- 忘记过滤空行。
- 未定义 URL 归一化却擅自去 query、改大小写或删尾斜杠。
- 只看连续重复样例，没有验证非相邻重复。
