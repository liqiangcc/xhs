# 两个无环单链表的第一个公共节点：双指针、哈希、长度对齐

## 核心结论

这题要先把“公共节点”定义清楚：比较的是**同一个节点对象/地址**，不是节点值相等。原题明确要求三种思路，因此我会都给出；在两个链表都是无环单链表的标准前提下，首选双指针换头法，时间复杂度 `O(m+n)`、额外空间 `O(1)`，长度对齐法复杂度相同，哈希法则用 `O(m)` 额外空间换直观实现。

如果链表可能有环，三种标准写法都不能直接当作完整答案，需要先处理环入口以及两条链表的环关系；原题没有给出这个条件，所以这里不擅自扩展成环链表问题。

## 1 分钟版

- 公共节点按引用/地址相同判断；值相同不代表相交。
- 双指针：`p` 走完 A 后切到 B，`q` 走完 B 后切到 A。两者都走过 `m+n` 的总路程，若有公共尾部就会在第一个公共节点相遇；不相交时最终同时到 `null`。
- 哈希：把 A 的节点引用放进集合，扫描 B，第一个命中的节点就是答案。
- 长度对齐：先算两条链长度，让长链先走长度差，再同步前进，第一次引用相同的位置就是答案。
- 标准无环前提下：双指针 `O(m+n)` / `O(1)`；哈希 `O(m+n)` / `O(m)`；长度对齐 `O(m+n)` / `O(1)`。

## 3 分钟版

设 A 的独有前缀长度为 `a`，B 的独有前缀长度为 `b`，公共尾部长度为 `c`。双指针换头法中，A 指针依次走 `a+c+b`，B 指针依次走 `b+c+a`。两条路径长度相等，所以如果存在公共尾部，两者会在进入公共尾部的起点对齐；如果不存在公共尾部，两者都会在走完 `m+n` 后变成 `null`。

这个方法成立还有一个重要结构前提：两个**无环**单链表一旦共享某个节点，此后 `next` 链就完全相同，因此公共部分必然是一段共同尾部。正因为公共部分不能再分叉，“第一次引用相同”才就是第一个公共节点。

哈希法更直接：集合记录 A 出现过的节点身份，扫描 B 时第一次命中就是 B 从头到尾遇到的第一个公共节点。长度对齐法则先消掉两个独有前缀的长度差，再让两个指针保持相同的“距尾距离”，从而在公共尾部起点相遇。

## 关键细节

- 判断条件必须是 `p == q`，不是 `p.value == q.value`。
- 双指针切换时用 `p = (p == null) ? headB : p.next`，两个指针最多各走 `m+n` 步，不需要长度计数。
- 空链表、两个头节点就是同一个对象、只在尾节点相交、完全不相交都应覆盖。
- 算法不修改任何 `next`，因此不会破坏输入链表。
- 哈希集合应按节点身份判断；Java 中本实现的 `Node` 没有覆盖 `equals/hashCode`，`HashSet<Node>` 因而使用对象身份语义。若业务节点类覆盖了值相等语义，应改用身份集合，例如基于 `IdentityHashMap`。
- 长度对齐法先计算长度，再把长链推进 `abs(m-n)` 步；之后同步移动并按引用比较。
- 如果输入可能包含环，需要先检测环并分类讨论；标准无环算法不能直接声称覆盖这种输入。

## 原理机制

下面给出三种完整 Java 实现。`firstBySwitching` 是首选；另外两个方法用于展示原题要求的哈希与长度对齐思路。

```java
import java.util.HashSet;
import java.util.Set;

public final class LinkedListFirstCommonNode {
    public static final class Node {
        public final int value;
        public Node next;

        public Node(int value) {
            this.value = value;
        }
    }

    public static Node firstBySwitching(Node headA, Node headB) {
        Node p = headA;
        Node q = headB;
        while (p != q) {
            p = (p == null) ? headB : p.next;
            q = (q == null) ? headA : q.next;
        }
        return p;
    }

    public static Node firstByHash(Node headA, Node headB) {
        Set<Node> seen = new HashSet<>();
        for (Node p = headA; p != null; p = p.next) {
            seen.add(p);
        }
        for (Node q = headB; q != null; q = q.next) {
            if (seen.contains(q)) {
                return q;
            }
        }
        return null;
    }

    public static Node firstByAlignedLength(Node headA, Node headB) {
        int lenA = length(headA);
        int lenB = length(headB);
        Node p = headA;
        Node q = headB;

        for (int i = lenA - lenB; i > 0; i--) {
            p = p.next;
        }
        for (int i = lenB - lenA; i > 0; i--) {
            q = q.next;
        }

        while (p != q) {
            p = p.next;
            q = q.next;
        }
        return p;
    }

    private static int length(Node head) {
        int length = 0;
        for (Node p = head; p != null; p = p.next) {
            length++;
        }
        return length;
    }
}
```

正确性可以从三个不变量看：

1. 双指针法每个指针恰好把“两条链的总长度差”通过换头抵消；第二段路径开始后，两者距尾部的剩余长度一致。
2. 哈希法的集合精确表示“所有 A 中已存在的节点身份”，所以 B 从头扫描时第一个命中就是 B 上最早的公共节点。
3. 长度对齐法推进长度差后，两指针距各自尾部的距离相同；公共尾部长度相同，因此若有交点，第一次引用相同恰好是公共尾部起点。

仓库的确定性 Java 测试对这三份实现使用相同输入进行交叉检查，覆盖两个空链、单边为空、同一头节点、只共享尾节点、不同长度前缀、相同值但不同节点的“不相交”反例，以及 3000 组固定随机种子的“独有前缀 + 可选公共尾部”结构。测试直接持有构造时的预期公共节点引用，因此不会把某一种实现本身当作另一种实现的真值来源。

## 项目经验版

这是一道算法题，原始材料没有提供生产项目经历，不应该编造“在线上用双指针优化了多少内存”。工程上真正值得补充的是对象身份语义：如果领域对象重写了 `equals/hashCode`，哈希法不能默认等同于“同一节点”，这时要明确使用身份比较；而双指针和长度对齐法天然通过引用相等判断，不受值相等实现影响。

## 常见追问

- 问：为什么双指针换头后一定能对齐？答：两人分别走 `a+c+b` 与 `b+c+a`，总长度相同；换头消掉独有前缀长度差，所以会在公共尾部起点相遇，或同时走到 `null`。
- 问：两个节点值相同算公共节点吗？答：不算。公共节点是同一个节点对象/地址；两个独立节点即使值完全相同也不是相交。
- 问：为什么两个无环单链表相交后不会再分开？答：单链节点只有一个 `next`。一旦两个指针指向同一个节点，后续沿着同一个 `next` 链前进，所以公共部分必然是共同尾部。
- 问：如果链表可能有环怎么办？答：先检测两条链的环入口，再区分都无环、一个有环一个无环、同环入口和不同环入口；不能直接套标准换头法并宣称完整正确。
- 问：三种方法怎么选？答：无环且只求一次交点时优先双指针，`O(1)` 空间且无需先算长度；需要复用 A 的节点集合做多次查询时哈希可能更合适；长度对齐法在希望显式解释长度差时最直观。

## 易错点

- 用节点值比较，导致“值相同但对象不同”的假阳性。
- 双指针只让一个指针换头，或在切换顺序上提前退出，破坏等路程性质。
- 长度对齐时长度差方向写反，或者没有先推进长链。
- 把哈希法的 `equals/hashCode` 值语义误当成节点身份语义。
- 忽略“无环”前提，把标准答案直接扩展到环链表。
