# 找到最大连续子数组的和

## 核心结论

这是经典的最大连续子数组问题。来源只保存“找到最大连续子数组的和”，没有规定空数组语义、整数位宽、是否返回区间或具体语言。下面采用一个可执行参考契约：输入是**非空** Java `int[]`，返回至少包含一个元素的连续子数组最大和，返回类型用 `long`。核心状态 `ending` 表示“必须以当前位置结尾的最大连续子数组和”，每到一个元素 `x`，只有两种选择：从 `x` 重新开始，或把 `x` 接到前一个最优结尾后面，因此 `ending = max(x, ending + x)`；全局答案 `best` 取遍历过程中最大的 `ending`。这就是 Kadane 算法，时间 O(n)，额外空间 O(1)。

## 1 分钟版

- 状态不是“前 i 个数的最大和”，而是“**必须以 i 结尾**的最大和”；这样下一步只依赖一个值。
- 对当前 `x`：如果前面的 `ending` 是负贡献，就从 `x` 重启；否则继续接上，所以 `ending = max(x, ending + x)`。
- `best = max(best, ending)` 保存所有结尾位置里见过的最好答案。
- 必须用第一个元素初始化 `ending` 和 `best`，不能初始化为 0，否则全负数组会错误返回 0。
- 本参考 API 用 `int[]` 输入、`long` 累加；空数组在来源中没有定义，这里显式拒绝。

## 3 分钟版

例如 `[-2,1,-3,4,-1,2,1,-5,4]`。扫描到 `4` 时，之前以 `-3` 结尾的最优和是负数，所以重新从 `4` 开始；随后接上 `-1,2,1` 得到 6。再接 `-5` 只剩 1，因此全局最佳仍是 6，对应连续子数组 `[4,-1,2,1]`。

```java
public final class Solution {
    private Solution() {}

    public static long maxSubarraySum(int[] nums) {
        if (nums == null) {
            throw new NullPointerException("nums");
        }
        if (nums.length == 0) {
            throw new IllegalArgumentException("reference contract requires a non-empty array");
        }

        long ending = nums[0];
        long best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            long x = nums[i];
            ending = Math.max(x, ending + x);
            best = Math.max(best, ending);
        }
        return best;
    }
}
```

为什么这个局部状态足够？任何以位置 `i` 结尾的连续子数组，要么只包含 `nums[i]`，要么等于“某个以 `i-1` 结尾的连续子数组 + nums[i]”。若选择后者，显然应该接在以 `i-1` 结尾的最大和后面，因此不需要保存更早的完整区间集合。

## 关键细节

- **连续**：不能跳元素。若题目问的是“子序列最大和”，模型不同。
- **全负数组**：例如 `[-5,-2,-7]` 的答案是 `-2`，不是 0；所以必须以首元素初始化。
- **空数组**：来源没有定义。参考实现选择抛 `IllegalArgumentException`，不把 0、负无穷或 Optional 等某一种语义冒充原题要求。
- **返回类型**：来源没给数据范围。参考实现输入 `int[]`、返回 `long`；Java 数组长度受 `int` 下标约束，因此即使所有元素都是 `Integer.MAX_VALUE`，任一可实际表示数组的数学总和仍可放进 `long`。
- **不修改输入**：算法只读数组。
- **复杂度**：每个元素访问一次，时间 O(n)；只维护 `ending/best` 两个状态，额外空间 O(1)。
- **如果还要返回区间**：再维护当前候选起点、最佳左右端点即可，状态转移不变；但来源只要求“和”，本答案不擅自扩大输出。

## 原理机制

Kadane 算法是一个被压缩到常数空间的动态规划。定义 `dp[i]` 为“必须以 i 结尾的最大连续子数组和”，转移是 `dp[i] = max(nums[i], dp[i-1] + nums[i])`。最终答案是 `max(dp[i])`，因为全局最优连续子数组一定有一个右端点。

`dp[i]` 只依赖 `dp[i-1]`，所以数组可以压成变量 `ending`。这个状态同时解释了“为什么负前缀要丢掉”：若 `ending < 0`，对任何当前值 `x`，`ending + x < x`，保留这个前缀只会让以当前位置结尾的候选更差。

## 常见追问

- 问：为什么不能把 `best` 初始化成 0？答：因为参考契约要求子数组非空；全负数组的最大和仍是某个负元素，初始化 0 会凭空允许空子数组。
- 问：为什么负的 `ending` 可以直接丢掉？答：它加到任何后继元素都会让和更小，不可能帮助构成更优的“以当前结尾”候选。
- 问：时间复杂度为什么是 O(n)？答：每个元素只参与一次常数时间状态更新，没有嵌套枚举区间。
- 问：如果要返回最大区间本身呢？答：在选择“从当前元素重启”时记录新起点，在 `best` 更新时冻结左右端点即可。
- 问：如果允许空子数组呢？答：契约会改变；通常可以把 0 纳入候选，使全负输入返回 0，但这不是当前来源已经说明的语义。
- 问：为什么用 `long` 返回？答：这是参考实现为 Java `int[]` 做的防溢出选择；来源没有给数值范围，所以必须把它标成实现契约而不是题目事实。

## 易错点

- 把“连续子数组”写成可以跳元素的子序列。
- `best=0` 导致全负数组错误。
- 只更新 `ending`，最后直接返回它，漏掉更早出现的全局最优。
- 题目只要和，却未经说明改变为空数组返回 0 或额外输出区间。
- 用 `int` 累加而没有数据范围，可能发生溢出。
