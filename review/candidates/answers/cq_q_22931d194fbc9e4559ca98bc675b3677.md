# 奇偶位置分别有序的链表：O(n) 时间、O(1) 额外空间归并成整体升序

## 核心结论

仓库原始面经把约束和解题方向都保留下来了：链表**奇数位置节点正序、偶数位置节点逆序**，两组之间没有大小关系，要求 `O(n)` 时间、`O(1)` 额外空间变成整体有序；原文还明确记录“拆分奇偶链表 → 反转偶数链表 → 合并两个有序链表”。因此这里不需要猜题型，也不应改写成普通链表排序。

候选实现采用以下显式 API 约定：节点保存 `int`；“正序/逆序”解释为非递减/非递增，因此允许重复值；直接复用原节点并修改 `next`，返回新的头节点；空链表和单节点原样返回。重复值来自两条子链时，合并阶段优先取原奇数位置链上的节点只是确定性的 tie policy，不是原题要求的稳定性语义。

算法分三步：按**位置奇偶**原地拆成两条链；反转偶数位置链，使它也非递减；最后像归并排序那样原地合并两条非递减链。每个节点只被有限次访问，时间 `O(n)`；实现只保存常数个节点引用，额外空间 `O(1)`。

## 1 分钟版

不能对整条链表重新做 `O(n log n)` 排序，因为题目已经给了更强结构：奇数位置是一条升序链，偶数位置是一条降序链。

1. 扫一遍原链表，按 1-based 位置把节点拆到 `odd` 和 `even` 两条链，过程中只改 `next`，不新建数据节点。
2. `even` 当前是非递增，原地反转后变成非递减。
3. `odd` 和反转后的 `even` 都是非递减，用两个指针做标准有序链表合并。

拆分 `O(n)`、反转 `O(n)`、合并 `O(n)`，总时间仍是 `O(n)`；只有固定数量指针，所以额外空间 `O(1)`。

## 3 分钟版

关键不是“会不会链表排序”，而是识别两个已经有序的子序列。

原链位置为 `1,2,3,4,...`。把 `1,3,5,...` 接到 odd 链，`2,4,6,...` 接到 even 链。源约束保证 odd 值非递减，even 值非递增。拆分时先保存当前节点的原后继，再把当前节点 `next=null` 后接到对应尾部，这样不会丢链也不会把两条子链意外串回去。

随后反转 even。因为原 even 是 `e1 >= e2 >= ... >= ek`，反转节点顺序后就是 `ek <= ... <= e2 <= e1`，所以得到第二条非递减链。

最后合并两条非递减链。每次比较两个表头，把较小节点接到结果尾部并前进对应指针；若相等，候选实现先取 odd，仅作为确定性选择。合并结束后把剩余后缀直接接上。

正确性可以按三个不变量看：拆分后两条链分别恰好包含原奇/偶位置节点且各自相对顺序保留；反转后 even 从非递增变成非递减；归并过程中输出前缀始终有序且其中每个节点都不大于两条未消费链的当前最小候选。三步合起来得到包含全部原节点的一条非递减链。

## 关键细节

- **奇偶指的是位置，不是节点值的奇偶性**：第 1、3、5… 个节点进入 odd，第 2、4、6… 个节点进入 even。
- **顺序允许相等**：候选把“正序/逆序”解释为非递减/非递增，能覆盖重复值；若面试官要求严格单调，只是更窄的输入子集。
- **原地语义**：不复制值到数组再排序，也不为结果创建第二套节点；只改原节点的 `next`。
- **拆分先保存后继**：`next = current.next` 后再断开 `current.next`，否则容易丢失未处理后缀。
- **反转的是偶数位置子链**：不是反转原链的偶数值，也不是反转整个链表。
- **重复值 tie policy**：合并时 `odd.value <= even.value` 选择 odd；原题没有跨子链稳定性要求，因此这只是候选 API 选择。
- **空/单节点**：无需拆分，直接返回。
- **复杂度**：三次线性过程，总时间 `O(n)`；常数个引用，额外空间 `O(1)`。

## 原理机制

```java
public final class OddEvenMonotonicListSort {
    public static final class Node {
        public final int value;
        public Node next;
        public Node(int value) { this.value = value; }
    }

    public static Node sort(Node head) {
        if (head == null || head.next == null) return head;

        Node oddHead = null, oddTail = null;
        Node evenHead = null, evenTail = null;
        Node current = head;
        boolean oddPosition = true;

        while (current != null) {
            Node next = current.next;
            current.next = null;
            if (oddPosition) {
                if (oddHead == null) oddHead = current;
                else oddTail.next = current;
                oddTail = current;
            } else {
                if (evenHead == null) evenHead = current;
                else evenTail.next = current;
                evenTail = current;
            }
            oddPosition = !oddPosition;
            current = next;
        }

        return mergeAscending(oddHead, reverse(evenHead));
    }

    private static Node reverse(Node head) {
        Node previous = null;
        while (head != null) {
            Node next = head.next;
            head.next = previous;
            previous = head;
            head = next;
        }
        return previous;
    }

    private static Node mergeAscending(Node a, Node b) {
        if (a == null) return b;
        if (b == null) return a;

        Node head;
        if (a.value <= b.value) {
            head = a;
            a = a.next;
        } else {
            head = b;
            b = b.next;
        }
        Node tail = head;

        while (a != null && b != null) {
            if (a.value <= b.value) {
                tail.next = a;
                a = a.next;
            } else {
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b;
        return head;
    }
}
```

仓库候选验证不是只跑一个示例：固定覆盖空链、单节点、两节点、重复值、负数和整数极值；再用固定随机种子生成 5000 条满足“odd 非递减、even 非递增”的输入，与独立的“收集全部原值后完整排序” oracle 比较结果。同时保存排序前全部节点 identity，验证输出节点集合完全相同、节点数不变且无环，从可观察行为上约束“原地复用节点”。

## 项目经验版

这是算法题，原始面经没有生产项目背景，因此不编造项目经历。工程化时应确认的接口问题包括：节点是否可变、是否允许重复值、是否需要保持相等元素的稳定顺序、输入是否保证满足两条单调子序列、以及输入违约时是拒绝还是按未定义行为处理。若题目不再保证奇偶位置各自单调，就不能继续声称线性算法能完成一般比较排序。

## 常见追问

- 问：为什么能做到 `O(n)`，一般链表排序不是 `O(n log n)` 吗？答：这里不是一般输入；题目已经把节点按位置拆成两条单调链，只需线性拆分、一次线性反转和一次线性归并。
- 问：为什么偶数链反转后一定升序？答：偶数位置原顺序满足 `e1 >= e2 >= ... >= ek`，反向后顺序就是 `ek <= ... <= e2 <= e1`。
- 问：怎么保证 `O(1)` 额外空间？答：实现只持有 current/next、两条链的头尾以及归并指针；没有递归栈、数组、堆或新结果节点。
- 问：拆分时最容易错在哪里？答：直接改 `current.next` 后忘记保存原后继，会丢掉剩余链；或者没断开节点，导致 odd/even 子链仍互相串联甚至形成环。
- 问：有重复值怎么办？答：非递减/非递增允许重复；合并时相等先取 odd 是候选的确定性 tie policy，结果仍整体非递减。
- 问：能不能先把所有值放数组里排序再写回？答：那会用 `O(n)` 额外空间并失去题目给出的结构优势，不满足当前 `O(1)` 空间要求。
- 问：如果输入不满足奇数升序、偶数降序呢？答：当前算法的线性正确性依赖该前置条件；若需要防御性接口，应先验证并定义违约行为，而不能把任意输入也宣传成 `O(n)` 可排序。

## 易错点

- 把“奇数节点/偶数节点”误解为节点值为奇数/偶数，而不是链表位置。
- 拆分时忘记保存原 `next` 或忘记断链，导致节点丢失、交叉链接或环。
- 反转错对象：把 odd 反转，或对原链直接做局部翻转而破坏位置分组。
- 合并时没有移动 tail，或者余下后缀没有接回。
- 为了写得简单把节点值复制到数组排序，违反 `O(1)` 额外空间。
- 把“相等时 odd 优先”写成原题稳定性要求；原始材料并未规定这一点。
