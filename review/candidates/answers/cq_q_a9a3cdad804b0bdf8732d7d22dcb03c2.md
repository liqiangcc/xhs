# 自实现堆结构并完成从大到小堆排序

## 核心结论

原始面经明确保留了两个要求：**堆排序结果从大到小**，并且**不能只调用现成容器，需自己补全堆结构**。最直接的做法是原地维护一个最小堆：先 O(n) 建堆；随后每轮把堆顶最小值交换到当前未排序区间的最右端，再对缩小后的堆做 `siftDown`。因为最小值依次被放到数组尾部，最终整个数组就是降序。

下面给一个可执行 Java 参考契约：输入为可修改的 `int[]`；`null` 直接拒绝；空数组和单元素数组原样返回。这个 `null` 约定是本文实现选择，不是原始面经额外保存的要求。

## 1 分钟版

- 目标是降序，所以可以用**最小堆**把当前最小值不断放到数组尾部。
- 建堆从最后一个非叶子节点 `n/2 - 1` 开始向前 `siftDown`，整体 O(n)。
- 排序阶段令 `end` 从 `n-1` 递减：交换 `a[0]` 与 `a[end]`，再在 `[0, end)` 上恢复最小堆。
- 循环不变量：`[0, end]` 是最小堆控制的未排序区；`(end, n)` 已经按降序要求放好了最小的一批元素。
- 总时间 O(n log n)，额外空间 O(1)，不稳定。
- 原始面经要求“自实现堆”，所以不能用 `PriorityQueue` 或 `Arrays.sort` 代替核心算法。

## 3 分钟版

```java
final class Solution {
    static void sortDescending(int[] a) {
        if (a == null) throw new IllegalArgumentException("array must not be null");
        int n = a.length;

        for (int i = n / 2 - 1; i >= 0; i--) {
            siftDown(a, i, n);
        }

        for (int end = n - 1; end > 0; end--) {
            swap(a, 0, end);
            siftDown(a, 0, end);
        }
    }

    private static void siftDown(int[] a, int root, int size) {
        while (true) {
            int left = root * 2 + 1;
            if (left >= size) return;

            int right = left + 1;
            int smaller = left;
            if (right < size && a[right] < a[left]) {
                smaller = right;
            }

            if (a[root] <= a[smaller]) return;
            swap(a, root, smaller);
            root = smaller;
        }
    }

    private static void swap(int[] a, int i, int j) {
        int t = a[i];
        a[i] = a[j];
        a[j] = t;
    }
}
```

为什么这样会得到降序：建好最小堆后，`a[0]` 一定是当前未排序区间的最小值。把它交换到 `a[end]` 后，这个位置以后不再进入堆，所以数组尾部依次固定为“当前最小、次小、……”；从左到右看，这些固定元素自然形成降序尾部。未排序区间每轮缩小 1，并通过 `siftDown` 恢复最小堆。

## 关键细节

- **`size` 是左闭右开的堆边界**：`siftDown(a, 0, end)` 只允许访问 `[0, end)`，刚交换到 `end` 的已排序元素不能再被动。
- **建堆从 `n/2 - 1` 开始**：后半部分都是叶子，不需要下沉；自底向上建堆的总成本是 O(n)，不是把每个节点都按 O(log n) 粗暴相加成 O(n log n)。
- **重复元素**：比较使用 `<` / `<=` 即可；相同值的相对次序不保证，因此堆排序不是稳定排序。
- **负数和极值**：算法只比较和交换 `int`，不做加减乘除，因此不会因数值大小产生算术溢出。
- **为什么不用最大堆直接原地交换？** 标准最大堆每轮把最大值放到尾部会得到升序。要直接得到降序，使用最小堆最省一步；也可以最大堆排成升序后再反转，但多一次 O(n) 扫描。
- **递归还是迭代**：这里 `siftDown` 用迭代实现，额外空间 O(1)，也避免递归栈。

## 原理机制

数组下标可以隐式表示完全二叉树：节点 `i` 的左孩子是 `2i+1`，右孩子是 `2i+2`。最小堆不变量是父节点不大于孩子。`siftDown` 每次只需要和两个孩子里更小的那个比较：如果父节点已经不大于更小孩子，那么它也不大于另一个孩子；否则交换后继续向下，直到叶子或不变量恢复。

排序阶段把“选择当前极值”和“缩小问题规模”结合起来。堆让每次取当前最小值是 O(1)，交换后恢复堆是 O(log n)，共做 n 次，所以排序阶段 O(n log n)。

## 项目经验版

来源是现场算法题，没有真实业务规模、线上指标或项目经历，不能虚构。工程上真正需要先确认的是是否要求稳定排序、是否允许修改输入、数据是否能全部放内存以及比较器语义；这些条件可能让堆排序不再是合适选择。

## 常见追问

- 问：为什么建堆是 O(n)？答：越靠近叶子的节点越多、但下沉高度越小；把各层“节点数 × 最大下沉高度”求和是线性级，而不是 n 个节点都走满 log n。
- 问：为什么最小堆能得到降序？答：每轮把未排序区最小值放到最右端并冻结，所以右侧固定区从右往左是递增，等价于从左往右整体降序。
- 问：用最大堆会怎样？答：最大值每轮放到尾部会直接得到升序；若必须降序，可最后反转，或者像本文一样改用最小堆。
- 问：堆排序稳定吗？答：不稳定。远距离交换可能改变相等元素原有相对顺序。
- 问：和快速排序相比怎么选？答：堆排序最坏 O(n log n)、额外空间 O(1)，但局部性通常不如快排；是否需要最坏界、稳定性和实际常数要结合场景决定。

## 易错点

- 题目要求自实现堆，却直接调用 `PriorityQueue` / `Arrays.sort`。
- `siftDown` 仍把已经交换到尾部的已排序元素算在堆里。
- 用最大堆原地交换后声称结果是降序，实际得到升序。
- 只会写“插入式建堆”却把复杂度误写成 O(n)；从空堆逐个插入通常是 O(n log n)。
- 忘记空数组、单元素、重复值和负数等边界。
