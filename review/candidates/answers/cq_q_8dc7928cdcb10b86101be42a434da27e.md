# LC490 - The Maze（迷宫问题）

## 核心结论

LC490 的关键不是“每次走一格”，而是 **球会沿一个方向持续滚动，直到撞墙前才停下**；只有停下以后才能选择下一方向。因此应把“可停留位置”当作搜索状态：从一个停止点向四个方向滚到下一个停止点，再用 BFS 或 DFS 判断能否到达并停在 `destination`。下面给出不修改 `maze` 的 Java BFS 实现；题目只问可达性，所以 BFS 与 DFS 都可以，BFS 并不是为了求最短路。

## 1 分钟版

- 状态不是相邻格子，而是“球真正停下来的格子”；从当前停止点向四个方向一直滚到墙前一格。
- 每得到一个新的停止点，如果没访问过就标记并入队；每个停止点最多展开一次。
- 只有 `destination` 能作为停止点被搜索到才算成功；球只是从目标格经过但停不下来，答案仍是 `false`。
- 直接滚动扫描的最坏时间上界是 O(mn(m+n))，访问集合和队列是 O(mn)；若预计算每格四个方向的停止点，可把重复滚动扫描进一步收敛。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.Queue;

public final class Solution {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public boolean hasPath(int[][] maze, int[] start, int[] destination) {
        int rows = maze.length;
        int cols = maze[0].length;
        boolean[][] visited = new boolean[rows][cols];
        Queue<int[]> queue = new ArrayDeque<>();
        queue.offer(new int[] {start[0], start[1]});
        visited[start[0]][start[1]] = true;

        while (!queue.isEmpty()) {
            int[] cur = queue.poll();
            if (cur[0] == destination[0] && cur[1] == destination[1]) {
                return true;
            }

            for (int[] dir : DIRS) {
                int r = cur[0];
                int c = cur[1];
                while (inBounds(r + dir[0], c + dir[1], rows, cols)
                        && maze[r + dir[0]][c + dir[1]] == 0) {
                    r += dir[0];
                    c += dir[1];
                }
                if (!visited[r][c]) {
                    visited[r][c] = true;
                    queue.offer(new int[] {r, c});
                }
            }
        }
        return false;
    }

    private boolean inBounds(int r, int c, int rows, int cols) {
        return r >= 0 && r < rows && c >= 0 && c < cols;
    }
}
```

搜索不需要在滚动经过的中间格子上分叉；只有撞墙前的停止点才产生下一轮决策。把停止点标记为 `visited` 后，同一个状态无需重复展开，因此环形通道也不会无限搜索。

## 关键细节

- **目标必须能停下**：这是 LC490 最容易写错的语义。经过 `destination` 不等于到达；只有一次滚动恰好停在那里，或 `start` 本身就是目标，才成功。
- **`visited` 标记停止点**：中间经过的格子不是本题的决策状态，不应该按普通迷宫“一格一步”的方式搜索。
- **BFS/DFS 都正确**：题目只问是否存在路径，不比较路径长度；若换成 Maze II 的最短滚动距离，才需要按距离建模并使用不同的最短路策略。
- **不修改输入**：实现单独维护 `visited`，避免把访问状态写回 `maze`，便于重复调用和测试。
- **复杂度上界**：最多有 O(mn) 个停止状态；每个状态最多向四个方向滚动，每次滚动最多扫描 O(m+n) 个格子，因此直接实现可给出 O(mn(m+n)) 的保守上界，空间 O(mn)。
- **空滚动不会重复入队**：某方向一开始就是墙时，停止点仍是当前格；因为当前格已经访问过，不会重新入队。

## 原理机制

可以把迷宫隐式转换成一个“停止点图”：节点是球能够停住的空格；从节点 `(r,c)` 选择一个方向后，沿该方向越过若干空格，直到下一步会撞墙，此时最后一个合法格子就是一条边的终点。原题于是变成这个隐式图上的可达性问题。BFS 的不变量是：队列里只包含已经确认可作为停止状态、但尚未展开的节点；每次展开都完整生成四个方向的下一个停止点。`visited` 保证每个停止状态最多展开一次，所以搜索最终会终止。

## 项目经验版

来源没有真实项目经历，不能虚构线上迷宫或路径规划案例。工程上可以把这类题映射为“动作具有持续效果、只能在离散边界重新决策”的状态搜索，例如批处理推进到检查点后才能切换策略；真正落地仍要根据业务定义状态、动作终止条件和代价模型。这里仅作算法建模映射，不把它说成个人生产经验。

## 常见追问

- 问：为什么不能对四个相邻空格做普通 BFS？答：因为球不能在任意相邻格停下并转向；一次动作必须一直滚到墙前，所以普通格点 BFS 会引入原题不存在的转向能力。
- 问：为什么球经过终点还可能返回 `false`？答：终点要求“停在”该位置；如果前方没有墙，球会继续滚过去，那个中间位置不是可达停止状态。
- 问：这题为什么 DFS 也可以？答：目标只是判断隐式停止点图里是否可达，不要求最少步数；DFS 和 BFS 都能完整遍历可达状态。
- 问：最坏时间为什么不是简单 O(mn)？答：虽然停止状态最多 O(mn)，但每次展开一个方向都可能沿行或列扫描很多格子；不预计算转移时会有重复走廊扫描，因此给出 O(mn(m+n)) 的保守上界更准确。
- 问：怎么优化重复滚动？答：可以预计算每个空格向四个方向最终会停在哪里，或按行列墙位置建立跳转信息；之后搜索每条状态转移可做到 O(1)，代价是额外预处理和存储。

## 易错点

- 把题目写成普通四邻接迷宫，允许在滚动中的任意格子转向。
- 只要滚动路径经过 `destination` 就立即返回 `true`。
- 用 `visited` 标记经过的每个中间格，混淆“经过位置”和“停止状态”。
- 忘记在入队时标记停止点，导致同一状态被重复加入队列。
- 把 BFS 的理由说成“求最短路”，但本题只要求布尔可达性。
