# 股票问题 III：最多两笔交易的最大利润

## 核心结论

仓库原题只保留“算法：股票问题 III”这一识别性标题；按力扣 123《买卖股票的最佳时机 III》的官方题意恢复完整契约：给定每日股价，最多完成两笔交易，且同一时间不能持有多笔交易。可以把每天压缩成四个核心状态：第一次买入、第一次卖出、第二次买入、第二次卖出后的最大现金；每个状态只依赖前一天，因此一次扫描即可得到最大利润，时间 O(n)、额外空间 O(1)。

## 1 分钟版

- `buy1`：完成第一次买入后最大现金；`sell1`：最多完成第一笔交易后最大现金。
- `buy2`：完成第二次买入后最大现金；`sell2`：最多完成两笔交易后最大现金。
- 每天价格为 `p` 时，四个状态分别比较“今天什么也不做”和“今天执行对应买/卖动作”。
- 第二次买入只能从 `sell1` 转移，因此天然满足“先卖出上一笔，再开始下一笔”。
- 最终返回 `sell2`；“最多两笔”包含 0 笔、1 笔和 2 笔，单调下跌时结果自然是 0。

## 3 分钟版

```java
public final class Solution {
    public int maxProfit(int[] prices) {
        long buy1 = Long.MIN_VALUE / 4;
        long sell1 = 0;
        long buy2 = Long.MIN_VALUE / 4;
        long sell2 = 0;

        for (int price : prices) {
            long nextBuy1 = Math.max(buy1, -1L * price);
            long nextSell1 = Math.max(sell1, buy1 + price);
            long nextBuy2 = Math.max(buy2, sell1 - price);
            long nextSell2 = Math.max(sell2, buy2 + price);
            buy1 = nextBuy1;
            sell1 = nextSell1;
            buy2 = nextBuy2;
            sell2 = nextSell2;
        }
        return (int) sell2;
    }
}
```

这里显式使用 `next*` 保存“今天”的状态，所有转移都读取“昨天”的状态，避免把更新顺序混进正确性证明。以 `[3,3,5,0,0,3,1,4]` 为例，最优利润是 6：可以完成两笔互不重叠的盈利交易。

## 关键细节

- **交易定义**：一笔交易由一次买入和随后一次卖出组成；第二次买入只能发生在第一笔已经卖出之后。
- **最多两笔，不是必须两笔**：`sell1`、`sell2` 从 0 开始，亏损交易不会被强制选择。
- **状态转移**：`buy1=max(buy1,-p)`；`sell1=max(sell1,buy1+p)`；`buy2=max(buy2,sell1-p)`；`sell2=max(sell2,buy2+p)`，本文代码用前一天快照实现同一组方程。
- **空/短输入**：官方约束至少一个价格；即使只有一天，也不可能完成盈利卖出，返回 0。
- **数值范围**：官方约束中单日价格不超过 `10^5`，最多两笔利润远低于 Java `int` 上限；内部仍用 `long` 让负无穷初始化和加减更稳健。
- **复杂度**：每个价格只做常数次状态更新，时间 O(n)，除输入外只保存四个状态，额外空间 O(1)。

## 原理机制

四个变量实际上是交易次数受限的状态机 DP。`buy1` 表示已经进入“第一笔持仓”状态，`sell1` 表示离开第一笔持仓；`buy2` 只能从 `sell1` 进入，所以不会出现两笔持仓重叠；`sell2` 再从 `buy2` 离开。每一步都保留当前状态的历史最优值，因此不需要枚举具体买卖日期组合。

更一般地，可以用 `dp[day][transactions][holding]` 表示状态；当交易上限固定为 2 时，把交易维和天数维压成四个变量只是空间优化，不改变状态语义。

## 项目经验版

来源是算法题，没有真实生产项目背景，不能虚构交易系统经历。工程上可迁移的是“把互斥动作和次数上限编码进状态”，再用独立小规模穷举验证状态压缩前后等价；这比只记四个公式更容易发现转移来源或更新顺序错误。

## 常见追问

- 问：为什么第二次买入用 `sell1 - price`？答：第二次买入前必须已经结束第一笔交易，`sell1` 正是这一前置状态的最大现金。
- 问：为什么最后只返回 `sell2`，会不会漏掉只交易一次？答：`sell2` 初始化为 0，并始终保留旧值；第二笔不划算时它不会强制交易。也可以把最终语义理解为“最多两笔且当前不持仓”的最优现金。
- 问：四个状态能否当天连续更新？答：在无手续费、无冷冻期且允许卖出后再买入的题意下，合理更新顺序可以等价；本文用前一天快照消除这种顺序依赖，让证明更直接。
- 问：如果允许最多 k 笔怎么办？答：把四个固定状态推广成 `transactions × holding` 的 DP；固定 k=2 才适合展开为四个变量。
- 问：如果交易次数不限呢？答：状态可以缩成“持仓/不持仓”两个；若没有手续费和冷冻期，还可进一步使用相邻上涨差值的贪心结论。

## 易错点

- 把“最多两笔”误写成“必须两笔”，导致下降行情出现负利润。
- 第二次买入直接从 0 或第一次买入状态转移，破坏交易顺序约束。
- 原地更新四个变量却没有说明同日状态是否允许复用，导致证明和实现不一致。
- 用两层买卖日期暴力枚举后误判复杂度，或只验证官方样例而没有与独立穷举对照。
- 把“股票问题 III”标题之外的约束说成仓库原题原文；完整契约应明确来自对应官方题面。
