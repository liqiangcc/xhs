# 无重复字符字符串的全排列：回溯交换生成所有排列

## 核心结论

来源只要求“给出一个无重复字符的字符串，生成所有排列”，没有限定语言、输出顺序、空串语义或 Unicode 表示。这里明确采用 Java 契约：输入按 Unicode code point 处理；输入字符必须互不重复，若违反前提就抛出 `IllegalArgumentException`；空串返回唯一的空排列 `[""]`；结果顺序不作为 API 保证。

实现用 **回溯 + 原地交换**。递归层 `first` 表示 `[0, first)` 已经固定；把区间 `[first, n)` 中的每个字符依次交换到 `first`，递归生成剩余位置，返回后再交换回来恢复现场。因为输入无重复字符，每一条“位置选择序列”都对应唯一排列，不需要额外去重集合。

## 1 分钟版

- 把字符串转成 code point 数组，避免把一个非 BMP 字符拆成两个 UTF-16 `char`。
- `first` 之前的位置已经确定；当前层从 `first..n-1` 逐个选择一个字符放到 `first`。
- 选择后递归处理 `first + 1`，递归返回时交换回来，保证下一次选择看到的是原来的状态。
- 当 `first == n` 时得到一个完整排列，复制成字符串加入结果。
- 输入字符互不重复，所以每个叶子天然唯一；如果题目允许重复字符，就必须增加去重策略，不能直接沿用“无重复”的结论。
- 一共有 `n!` 个结果，每个结果构造长度为 `n`，因此时间下界和本实现都是 `O(n · n!)`；递归栈 `O(n)`，若把输出也计入则空间为 `O(n · n!)`。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Objects;
import java.util.Set;

public final class StringPermutations {
    public static List<String> permutations(String input) {
        Objects.requireNonNull(input, "input");

        int[] codePoints = input.codePoints().toArray();
        Set<Integer> seen = new HashSet<>();
        for (int cp : codePoints) {
            if (!seen.add(cp)) {
                throw new IllegalArgumentException(
                    "input must contain distinct characters");
            }
        }

        List<String> out = new ArrayList<>();
        backtrack(codePoints, 0, out);
        return out;
    }

    private static void backtrack(int[] a, int first, List<String> out) {
        if (first == a.length) {
            out.add(new String(a, 0, a.length));
            return;
        }
        for (int i = first; i < a.length; i++) {
            swap(a, first, i);
            backtrack(a, first + 1, out);
            swap(a, first, i);
        }
    }

    private static void swap(int[] a, int i, int j) {
        int t = a[i];
        a[i] = a[j];
        a[j] = t;
    }
}
```

例如输入 `"abc"`：第一层先分别固定 `a`、`b`、`c`；固定 `a` 后，第二层在剩余 `b/c` 中继续选择，于是得到 `abc`、`acb`。其它分支同理，最终正好得到 6 个排列。

## 关键细节

- **回溯不变量**：进入 `backtrack(a, first, out)` 时，`[0, first)` 已经是当前分支固定的前缀；`[first, n)` 是尚未选择的位置集合。
- **为什么必须交换回来**：当前递归分支会修改共享数组。如果返回后不恢复，下一次循环就不是从同一父状态出发，会漏解或产生错误排列。
- **为什么不需要 `used`/去重集合**：这里用“位置交换”枚举，而且来源明确说输入无重复字符，因此不同位置选择必然产生不同最终字符串。若输入可以重复，当前实现会重复输出，必须在每层跳过相同字符或改用计数表。
- **输出顺序**：这个 DFS 顺序由输入初始顺序和交换顺序决定，不等于“保证字典序”。来源没有字典序要求，所以答案不把排序扩张成原题契约。
- **空串**：这里采用组合意义上的约定——空集合有一个排列，即空排列，所以返回 `[""]`。如果调用方要求空输入返回空列表，应把它作为不同 API 契约显式修改。
- **Unicode**：Java 的 `char` 是 UTF-16 code unit。实现用 `String.codePoints()`，所以像 `🙂` 这样的非 BMP 字符在排列时作为一个 code point，而不是两个 `char`。
- **规模边界**：排列数阶乘增长。`10! = 3,628,800`，即使算法本身正确，完整物化所有结果也可能带来很高内存成本；更大的输入应考虑迭代器/回调式逐个消费，而不是一次性保存在列表中。

## 原理机制

全排列可以看成一棵决策树：第 0 层决定第 0 个位置放哪个字符，第 1 层决定第 1 个位置放剩余哪个字符，以此类推。第 `k` 层有 `n-k` 个选择，所以叶子数是：

`n × (n-1) × ... × 1 = n!`。

原地交换的作用，是用数组本身同时表示“已固定前缀”和“剩余候选”，不需要每层新建剩余字符集合。回溯时恢复交换，则保证兄弟分支之间互不污染。这类题真正要守住的是状态不变量，而不是只记住“DFS 模板”。

## 项目经验版

来源是纯算法题，没有真实项目经历可还原，因此不虚构线上案例。工程中如果只是消费排列流，我不会默认返回完整 `List<String>`：结果规模是阶乘级，通常应改成 `Consumer<String>`、迭代器或按需搜索，并尽早用业务约束剪枝。这里保留 `List` 只是为了让面试题契约和验证最直接。

## 常见追问

- 问：为什么复杂度不是 `O(n!)`？答：如果只数递归叶子是 `n!`，但每个叶子要构造一个长度 `n` 的字符串，所以完整输出的时间是 `O(n · n!)`，而输出本身也有同样数量级。
- 问：如果输入是 `aab` 怎么办？答：这已经违反当前来源“无重复字符”的前提。若要支持，应在每一层对本层已经尝试过的字符去重，或者先做频次表并按计数回溯。
- 问：能不能保证字典序？答：当前代码不承诺。若要求字典序，可以先排序后按有序选择回溯，或者不断求 next permutation；那是额外契约。
- 问：为什么用 code point 而不是 `char[]`？答：`char[]` 会把部分 Unicode 字符拆成代理项。按 code point 处理更接近“字符”的直觉语义；如果题目明确只允许 ASCII，`char[]` 会更简单。
- 问：能不能不用递归？答：可以，例如用 next permutation 枚举全部排列；但需要先定义初始排序和输出顺序。当前回溯方案更直接表达“每个位置选择一个剩余字符”的状态机。
- 问：如何避免一次性占用大量内存？答：把叶子处的 `out.add(...)` 换成回调/迭代输出，空间可以只保留当前状态和递归栈，但总输出时间仍然无法低于结果规模。

## 易错点

- 递归返回后忘记把交换恢复，导致兄弟分支状态污染。
- 明明来源限定“无重复”，却在答案里混入针对重复字符的复杂去重逻辑，反而模糊主算法。
- 把当前 DFS 顺序说成“字典序保证”。
- 只写 `O(n!)`，忽略每个结果字符串长度为 `n` 的输出成本。
- 用 `char[]` 却声称支持任意 Unicode 字符。
- 对阶乘级结果仍无条件完整物化，却不说明规模边界。
