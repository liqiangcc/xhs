# 二叉树右视图：每层取从右侧可见的第一个节点

## 核心结论

仓库原始来源只保留了“二叉树右视图”，没有给节点类型、空树规则、返回值形式、递归/迭代要求或语言 API。因此这里采用一个显式候选接口：节点值为 `int`，`null` 表示空树，返回从根到最深层的右视图值列表，不修改输入树。

一种直接且容易证明的实现是**右子树优先 DFS**：按 `root -> right -> left` 遍历，并记录深度；第一次到达某个深度时遇到的节点就是从右侧能看到的节点，因此只在 `depth == result.size()` 时加入结果。若树有 `n` 个节点、高度为 `h`，时间复杂度 `O(n)`，递归栈 `O(h)`，结果本身最多 `O(h)`。

## 1 分钟版

这题的关键不是“每层最右孩子”，而是“从右侧看过去，每一层最后挡住视线的节点”。

我会用右优先 DFS：先访问当前节点，再递归右子树，最后递归左子树。因为同一深度的右侧节点一定先被访问，所以某个深度第一次出现时就把这个节点值记下来。判断条件就是 `depth == result.size()`。

这样每个节点只访问一次，时间 `O(n)`；递归额外空间是树高 `O(h)`。如果担心极深退化树导致递归栈过深，可以改成 BFS，每层取最后一个节点，语义相同。

## 3 分钟版

来源只说明“二叉树右视图”，所以返回节点值还是节点对象、空树如何处理、是否必须迭代都不是源事实。当前候选选择常见且可验证的“返回每层可见节点值”接口：空树返回空列表，树结构只读。

右优先 DFS 的不变量是：在访问深度 `d` 的任意节点之前，所有更靠右、且能在同一深度先被右优先路径触达的节点都会更早被访问。因此当 `depth == result.size()` 时，说明这是遍历过程中第一次到达该深度；这个节点就是该层从右侧最先遇到的节点。之后即使左子树还有同深度节点，也不能覆盖已有结果。

例如根节点 `1`，右子树在深度 2 没有节点，但左子树在深度 2 有节点 `5`，右视图仍然可以是 `[1, 3, 5]`。所以不能把答案简化成“沿着 right 指针一直走”；必须按层或按深度处理整棵树。

## 关键细节

- **题源边界**：原始来源只有“二叉树右视图”；`int` 值、返回 `List<Integer>`、空树返回空列表、Java 21 和只读输入都是候选 API 选择。
- **DFS 顺序**：必须先右后左；第一次到达某个深度才记录。
- **不是一直走右指针**：右子树缺失时，左子树更深的节点仍可能出现在右视图。
- **重复值**：右视图按位置/层决定，节点值可以重复；结果中重复值合法。
- **空树**：`null` 返回空列表。
- **不修改输入**：算法不重连、不交换左右子树。
- **复杂度**：访问每个节点一次，`O(n)` 时间；递归栈 `O(h)`，结果最多 `O(h)`。
- **极深树边界**：退化树会让递归深度达到 `O(n)`；若运行环境对栈敏感，改用 BFS 队列可避免递归栈风险。
- **可验证性**：8 组固定树形加 5000 棵确定性随机树，与独立的 BFS“每层最后一个节点”oracle 完全比较，并序列化前后树结构确认无修改。

## 原理机制

```java
public static List<Integer> rightSideView(Node root) {
    List<Integer> result = new ArrayList<>();
    collectRightFirst(root, 0, result);
    return List.copyOf(result);
}

private static void collectRightFirst(Node node, int depth, List<Integer> result) {
    if (node == null) {
        return;
    }
    if (depth == result.size()) {
        result.add(node.value);
    }
    collectRightFirst(node.right, depth + 1, result);
    collectRightFirst(node.left, depth + 1, result);
}
```

验证夹具使用 BFS 作为独立 oracle：对每一层从左到右出队，记录该层最后一个节点值。固定用例覆盖空树、单节点、满二叉树、纯右链、纯左链、右侧有缺口时左子树补位、重复值和负数/不对称树；随后生成 5000 棵最多 60 个节点的随机树，逐棵比较 DFS 与 BFS 结果，并比较执行前后的完整序列化结果确认输入未被修改。预检输出：

```text
PASS fixed=8 randomized=5000 oracle=bfs-last-per-level order=top-down mutation=none
```

## 项目经验版

这是算法面试题，仓库来源没有生产项目背景，因此不编造项目经验。工程里如果树深可能非常大，我会优先用 BFS 或显式栈，避免递归栈不可控；如果只需要流式输出每层结果，也可以在层序遍历时直接消费而不保留整棵层级状态。

## 常见追问

- **为什么右优先 DFS 第一次到达某层就是答案？** 因为遍历顺序保证同层更靠右的可达节点先于左侧节点被访问，第一次到达该层时还没有任何更右节点遗漏在后面。
- **BFS 怎么写？** 层序遍历，每层处理 `levelSize` 个节点，把这一层最后出队的节点值加入结果。
- **能不能只沿 `right` 指针？** 不能。某层右子树可能缺失，但左子树仍有从右侧可见的节点。
- **DFS 和 BFS 怎么选？** 两者都是 `O(n)`；DFS 代码短但递归栈是 `O(h)`，BFS 队列峰值是树宽 `O(w)`，极深窄树更适合 BFS，极宽浅树可能 DFS 更省辅助空间。
- **重复值会有问题吗？** 不会。右视图由节点位置和深度决定，不是按值去重。

## 易错点

- 把“右视图”误解成不断访问 `node.right`。
- DFS 先左后右，却仍把“第一次到达某层”当答案。
- 每层记录第一个 BFS 节点但队列又是左到右入队，得到的是左视图。
- 忽略空树或退化树的递归深度风险。
- 为了得到视图而修改左右子树，破坏输入结构。
