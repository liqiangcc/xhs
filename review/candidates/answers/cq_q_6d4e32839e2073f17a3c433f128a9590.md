# 删除链表中重复元素：先冻结“有序”和“删除”语义

## 核心结论

仓库原题只保留“删除链表中重复元素”，**没有保留链表是否有序，也没有说明重复值是“保留一个”还是“整组全部删除”**。这两个条件会直接改变算法，所以不能把某一道 LeetCode 的隐藏前提冒充成原题。面试现场第一句应该确认：①链表有序吗？②重复值最后保留一个，还是出现过重复的值一个都不留？

常见合同可以分成四格：有序+保留一个时相邻去重即可，O(n) 时间/O(1) 额外空间；有序+整组删除时用 dummy + 前驱指针跳过整段重复值，也是 O(n)/O(1)；无序+保留第一次出现时通常用 HashSet，期望 O(n) 时间/O(n) 空间；无序+整组删除时先统计频次再保留频次为 1 的节点，期望 O(n)/O(n)。下面把四种合同都明确实现，避免在来源缺失时猜错题。

## 1 分钟版

- 先问“**有序吗**”和“**重复值怎么定义删除结果**”。来源没有这两个约束。
- 有序链表的相同值连续，因此可以一次扫描、常数额外空间处理；无序链表不存在这个性质。
- “保留一个”只需识别当前值是否已经出现；“整组删除”必须知道某个值是否重复过，不能把两种输出混为一谈。
- 有序+保留一个：若 `cur.val == cur.next.val` 就 `cur.next = cur.next.next`，否则推进 `cur`。
- 有序+整组删除：dummy 指向头；发现一段重复值后，让 `prev.next` 一次跳到该段之后。
- 无序版本若追求线性期望时间，需要集合/频次表；若额外空间必须 O(1)，通常要接受 O(n²) 的重复扫描，除非还有别的可利用约束。

## 3 分钟版

```java
import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

final class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

// 合同 A：输入按 val 非递减；每个值最终保留一个节点。
static ListNode keepOneSorted(ListNode head) {
    for (ListNode cur = head; cur != null && cur.next != null; ) {
        if (cur.val == cur.next.val) cur.next = cur.next.next;
        else cur = cur.next;
    }
    return head;
}

// 合同 B：输入按 val 非递减；只保留原链表中出现恰好一次的值。
static ListNode removeAllDuplicatesSorted(ListNode head) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode prev = dummy, cur = head;
    while (cur != null) {
        if (cur.next != null && cur.val == cur.next.val) {
            int duplicate = cur.val;
            while (cur != null && cur.val == duplicate) cur = cur.next;
            prev.next = cur;
        } else {
            prev = cur;
            cur = cur.next;
        }
    }
    return dummy.next;
}

// 合同 C：输入可无序；按原顺序保留每个值第一次出现的节点。
static ListNode keepFirstUnsorted(ListNode head) {
    Set<Integer> seen = new HashSet<>();
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode prev = dummy, cur = head;
    while (cur != null) {
        if (!seen.add(cur.val)) prev.next = cur.next;
        else prev = cur;
        cur = cur.next;
    }
    return dummy.next;
}

// 合同 D：输入可无序；只保留原链表中出现恰好一次的值。
static ListNode keepOnlyGloballyUniqueUnsorted(ListNode head) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (ListNode cur = head; cur != null; cur = cur.next) {
        freq.merge(cur.val, 1, Integer::sum);
    }
    ListNode dummy = new ListNode(0), tail = dummy;
    for (ListNode cur = head; cur != null; ) {
        ListNode next = cur.next;
        if (freq.get(cur.val) == 1) {
            tail.next = cur;
            tail = cur;
        }
        cur = next;
    }
    tail.next = null;
    return dummy.next;
}
```

如果面试官补充“链表有序且重复元素保留一个”，只回答合同 A；若他说“重复过的值全部删除”，切到合同 B。不要把四段代码全背出来，关键是先把缺失合同问清楚，再选择最小正确实现。

## 关键细节

- **有序性为什么关键**：有序意味着一个值的所有节点必然连续，所以扫描离开这一段后不用再记住该值；这正是 O(1) 额外空间的来源。
- **保留一个 vs 整组删除**：对 `1→1→2→3→3`，合同 A 输出 `1→2→3`，合同 B 输出 `2`。题面只有“删除重复元素”时，这两个结果都不能被擅自认定为唯一正确答案。
- **dummy 的作用**：合同 B 中头节点本身可能属于重复段。dummy 提供一个永远存在的前驱，使“删除头部重复段”和删除中间段使用同一套指针逻辑。
- **无序 keep-first**：HashSet 保存已经出现的值，重复节点直接从链上摘掉；期望 O(n) 依赖哈希操作的通常期望常数时间。
- **无序整组删除**：单次从左到右无法在第一次看到值时知道后面是否还会重复。两遍法先统计频次，再保留 `freq==1` 的节点，逻辑更直接。
- **原地修改**：示例复用原节点并修改 `next`。来源没有规定是否允许修改输入；如果要求纯函数或保留原链表，需要创建新节点，空间合同会改变。
- **节点身份**：这里用整数 `val` 作为“重复”的等价标准只是可执行示例合同；真实节点若按业务 key 去重，应把比较键替换成题目给出的身份定义。

## 原理机制

链表去重本质上不是“会不会改 next”，而是先确定**等价关系、输入结构不变量和输出保留规则**。有序性把“所有同值节点”压成连续区间，于是局部相邻比较就足以代表全局；无序时局部相邻比较不再能证明某个值是否已经或将再次出现，因此需要额外记忆，或者付出重复扫描成本。

对整组删除，有序版本维护不变量：`prev.next` 始终指向尚未判定区间的起点；如果 `cur` 开头是一段长度至少 2 的同值区间，就找到区间末端并让 `prev.next` 跨过去；否则当前值唯一，推进 `prev`。这样不会因为删除头部节点而需要特殊分支。

## 项目经验版

来源没有真实项目中的链表结构或去重业务，不能虚构。真实系统里我会先定义“重复”的 key、稳定顺序是否重要、是否允许修改输入、内存上限和数据规模；如果数据量大到不能把 key 全放进内存，还可能需要排序、分区或外部状态，这已经超出当前面试题来源。

## 常见追问

- 问：为什么不能看到 `cur.val == cur.next.val` 就统一删除？答：这只在有序链表里能发现所有重复；而且“删当前一个”仍没有回答整组是否保留一个的问题。
- 问：为什么合同 B 要 dummy？答：第一段就可能重复，例如 `1→1→2`；没有 dummy 时删除头部需要额外改 head，dummy 让所有删除都表现为 `prev.next = ...`。
- 问：无序链表能不能 O(1) 空间、O(n) 时间？答：在没有额外值域/结构约束时，线性时间通常需要记住已见值或频次；若禁止额外空间，常见退化方案是对每个节点再扫描后续链表，时间 O(n²)。
- 问：`HashSet` 版本为什么保留第一次出现而不是最后一次？答：这是合同 C 明确选择的稳定规则；来源没规定，面试官若要求保留最后一次，算法要相应调整。
- 问：如果链表节点值相同但对象不同，算重复吗？答：当前示例按 `val` 判定；真实题意若按节点 identity 或复合 key，应以题目给出的等价关系为准。

## 易错点

- 来源没说有序，就直接套“相邻值相等”的 O(1) 空间算法。
- 没确认“保留一个/全部删除”就给出唯一输出。
- 整组删除时处理不好头部重复段，遗漏 dummy 或 head 更新。
- 删除节点后仍无条件推进 `prev`，把前驱移进尚未确认的重复区间。
- 无序链表只比较相邻节点，漏掉非连续重复值。
- 使用 HashSet/HashMap 却声称 O(1) 额外空间。
