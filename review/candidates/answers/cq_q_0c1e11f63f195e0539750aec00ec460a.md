# 代码输出：普通函数和箭头函数的 this——先锁定浏览器经典脚本边界

## 核心结论

仓库 OCR 恢复出的原题代码是一个浏览器脚本片段：先执行 `window.value = "v"`，再分别通过 `objA.fn()`、`objB.fn()`、`objC.fn()` 调用普通函数或箭头函数。按题面原样、以**浏览器 classic script 且未开启 strict mode**执行，三次输出依次是：

```text
A
B
v
```

原因不是“箭头函数永远指向 window”，而是两条规则叠加：普通函数的 `this` 由调用方式决定；箭头函数没有自己的 `this`，会解析到创建它时外层函数环境中的 `this`。因此 `objB.fn()` 里创建的箭头函数继承 `fnB` 的 `this === objB`；而 `objC` 初始化阶段通过裸调用 `fnC()` 创建箭头函数，在非严格 classic script 中该普通函数的 `this` 被绑定为全局对象，箭头函数随后一直保留这个外层 `this`，即使以后以 `objC.fn()` 的形式调用也不会重新绑定。

## 1 分钟版

逐行看三个调用：

1. `objA.fn()`：`fnA` 是普通函数，通过对象属性调用，所以 `this === objA`，输出 `A`。
2. `objB.fn()`：先以方法形式调用普通函数 `fnB`，所以 `fnB` 内 `this === objB`；`arrowFn` 在这个调用环境里创建，箭头函数使用外层 `this`，输出 `B`。
3. `objC` 创建时就执行 `fnC()`。这是裸调用普通函数；题面没有 strict mode，按 classic script 规则，`fnC` 的 `this` 变成全局对象。返回的箭头函数捕获这个外层 `this`。后来 `objC.fn()` 虽然看起来是“对象方法调用”，但箭头函数不会因为调用点变成 `objC`，所以读取的是 `window.value`，输出 `v`。

最终：`A、B、v`。

## 3 分钟版

这道题最容易错在把“函数定义在哪里”和“普通函数在哪里被调用”混成一件事。

`fnA`、`fnB`、`fnC` 都是普通函数。对普通函数，调用时会建立 `this` 绑定。`objA.fn()` 和 `objB.fn()` 的调用引用都带有对象基值，所以传入的 `this` 分别是 `objA`、`objB`。因此 `fnA` 直接读到 `objA.value`；`fnB` 则在 `this === objB` 的环境里创建一个箭头函数。

箭头函数的关键不同是 `[[ThisMode]]` 为 lexical：调用箭头函数时不会执行普通函数那套重新绑定 `this` 的流程。它内部的 `this` 解析到词法外层的 `this` 绑定。所以 `fnB` 里的箭头函数得到 `objB`，输出 `B`。

`fnC` 的差别发生在**创建箭头函数的时刻**：对象字面量执行 `fn: fnC()`，因此 `fnC` 是裸调用。题面是 classic script、没有 `"use strict"`；规范的普通函数 `this` 绑定规则会把 `undefined/null` 的调用 `thisArgument` 替换为当前 Realm 的 global object。于是 `fnC` 的 `this` 是浏览器全局对象，返回的箭头函数保存的也是这个外层 `this`。随后 `objC.fn()` 不能把箭头函数的 `this` 改成 `objC`，所以最终读 `window.value === "v"`。

环境边界必须说清：如果把整段改成 strict mode，那么 `fnC()` 的 `this` 保持 `undefined`；创建箭头函数本身仍可完成，但以后执行 `objC.fn()` 时访问 `this.value` 会抛 `TypeError`。如果直接拿到 Node.js CommonJS 环境运行，题面的 `window` 本身也不存在，不能把浏览器题目的输出无条件外推到 Node。

## 关键细节

- 题目实际代码来自仓库 `note_img_txt/681cc49c000000002101b340.txt`，不是只根据“普通函数和箭头函数 this”标题猜题。
- `objA.fn()`：普通函数按调用引用获得 `this=objA`。
- `objB.fn()`：普通函数先获得 `this=objB`，内部箭头函数再词法继承这个 `this`。
- `fnC()`：在非严格 classic script 中是裸调用，普通函数把缺省的 `thisArgument` 转成 global object。
- `objC.fn()` 调用的是箭头函数；箭头函数没有自己的动态 `this`，所以不会改绑成 `objC`。
- “箭头函数的 this 指向定义时所在对象”也不够准确；更准确的是：箭头函数中的 `this` 按词法环境向外解析到已有 `this` 绑定。
- 题面依赖 `window`，因此浏览器 classic script 是回答 `v` 的必要环境前提。

## 原理机制

题面代码可还原为：

```javascript
window.value = "v";

function fnA() {
  console.log(this.value);
}

function fnB() {
  const arrowFn = () => {
    console.log(this.value);
  };
  arrowFn();
}

function fnC() {
  const arrowFn = () => {
    console.log(this.value);
  };
  return arrowFn;
}

const objA = { value: "A", fn: fnA };
const objB = { value: "B", fn: fnB };
const objC = { value: "C", fn: fnC() };

objA.fn();
objB.fn();
objC.fn();
```

从规范模型看，可以把三次行为压缩成：

- 普通函数调用：计算调用引用携带的 `thisArgument`，再由普通函数的 `OrdinaryCallBindThis` 建立本次调用的 `this`。
- 箭头函数：其函数对象使用 lexical this mode，调用时跳过普通函数的 `this` 绑定；`this` 表达式继续向外层环境解析。
- 非严格普通函数：当传入的 `thisArgument` 是 `undefined` 或 `null` 时，`OrdinaryCallBindThis` 使用当前 Realm 的 global this value。

仓库中的确定性验证使用 Node `vm` 创建 classic-script 风格的独立全局上下文，把 `window` 指向该全局对象并执行恢复出的完整代码，捕获三次 `console.log`，结果必须严格等于 `['A', 'B', 'v']`。同一 fixture 再给源码前加 `"use strict"`，验证第三次调用在访问 `this.value` 时抛 `TypeError`，用于防止把 `v` 错写成与 strictness 无关的永真结论。

## 常见追问

- 问：为什么 `objB.fn()` 输出 `B`？答：`fnB` 是普通函数，方法调用先让 `this=objB`；内部箭头函数没有自己的 `this`，所以使用 `fnB` 这次调用的 `this`。
- 问：为什么 `objC.fn()` 不输出 `C`？答：`objC.fn` 保存的是 `fnC()` 已经返回的箭头函数；箭头函数不会因为之后以对象属性形式调用就重新绑定 `this`。
- 问：为什么第三个是 `v` 而不是 `undefined`？答：只在题面这个非严格浏览器 classic script 边界下成立：裸调用 `fnC()` 时普通函数把缺省 `thisArgument` 绑定为 global object，而题面先设置了 `window.value='v'`。
- 问：加上 `"use strict"` 会怎样？答：`fnC()` 的 `this` 保持 `undefined`；箭头函数继承它，随后执行 `this.value` 时抛 `TypeError`。
- 问：`call/apply/bind` 能改箭头函数的 `this` 吗？答：不能通过调用协议重绑箭头函数的词法 `this`；这些操作仍可传参数，但不会替换它从外层环境解析到的 `this`。
- 问：怎样验证不是背答案？答：保留同一代码，只改变 `objB.fn()` 的接收者、把 `fnC()` 改成 `fnC.call(objC)`、或开启 strict mode，先预测输出/异常再运行对照。

## 易错点

- 把箭头函数简化成“this 永远是 window”。
- 看到 `objC.fn()` 的点号就断言 `this=objC`，忽略 `fn` 实际保存的是箭头函数。
- 忽略 `fnC()` 在对象初始化阶段已经执行，它创建箭头函数时的外层 `this` 已经确定。
- 不说明 classic script / strict mode / Node.js 环境差异，给出无条件的 `A B v`。
- 把“词法 this”误说成“箭头函数定义时固定为某个对象”；真正解析的是外层词法环境中的 `this` 绑定。
