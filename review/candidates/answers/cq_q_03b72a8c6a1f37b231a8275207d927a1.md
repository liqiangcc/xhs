# SQL 手撕：按学生汇总成绩总和

## 核心结论

原始快手面经给出的表只有“学生名、科目名、成绩”三个字段，并要求“查找学生名字和成绩总和”。在这个最小契约下，一行结果应代表一个学生名，因此直接按 `student_name` 分组，对 `score` 做 `SUM()`：

```sql
SELECT student_name,
       SUM(score) AS total_score
FROM student_scores
GROUP BY student_name
ORDER BY student_name;
```

表名和列名只是示例映射，实际面试时替换成题目给出的标识符。MySQL 的聚合函数对每个 `GROUP BY` 子集计算聚合值；`SUM()` 默认忽略 `NULL`。如果真实数据存在“同名不同学生”，只有姓名字段无法可靠区分人，正确建模应增加 `student_id` 并按 `student_id, student_name` 分组。

## 1 分钟版

- 先确定结果粒度：题目要“每个学生一行”。
- 原始表是一科一行，所以需要把同一个学生的多科记录聚成一组。
- `GROUP BY student_name` 建立学生分组，`SUM(score)` 求组内成绩总和。
- 选择列表中的非聚合列 `student_name` 同时出现在 `GROUP BY` 中，兼容 MySQL `ONLY_FULL_GROUP_BY` 的严格用法。
- `SUM(score)` 会忽略单个 `NULL` 成绩；若某学生所有成绩都是 `NULL`，结果也是 `NULL`。业务若要求当成 0，需要显式定义 `COALESCE` 语义。
- 真实系统应优先按稳定主键 `student_id` 分组，而不是把姓名当唯一键。

## 3 分钟版

假设题目给出的表逻辑结构是：

```text
student_scores(student_name, subject_name, score)
```

每一行表示某个学生某个科目的成绩。目标结果则是一行一个学生，所以这是典型的“明细行 → 分组聚合”问题：

```sql
SELECT student_name,
       SUM(score) AS total_score
FROM student_scores
GROUP BY student_name
ORDER BY student_name;
```

`GROUP BY student_name` 把同名行形成一个集合，`SUM(score)` 对集合中的成绩求和。`ORDER BY` 不是求和所必需，只是让输出在测试和展示时稳定。

仓库执行夹具插入 8 行数据，覆盖多科成绩、单个 `NULL`、全 `NULL`、多行相同分数四种情况。查询得到 `Alice=170`、`Bob=70`、`Carol=NULL`、`Dave=180`，与独立预期完全一致。夹具使用 SQLite 执行这条标准分组聚合 SQL；MySQL 8.4 官方文档用于核对 `SUM()` / `GROUP BY` 和 `NULL` 语义。

## 关键细节

- 原始面经没有给实际表名，因此答案用 `student_scores` 作为示例，不应把它冒充原题字段。
- 如果姓名不是唯一身份标识，`GROUP BY student_name` 会把同名学生合并；题目只给姓名时这是无法消除的信息缺失，生产设计应有 `student_id`。
- 若表中一名学生同一科可能有多次考试，当前查询会把所有记录都计入总和。若题意其实是“每科最终成绩”，必须先定义取最新、最高或某次考试，再聚合。
- `SUM()` 忽略 `NULL`；全组都是 `NULL` 时结果为 `NULL`。不要在没有业务要求时擅自把缺考/未知成绩改成 0。
- `ORDER BY student_name` 只负责结果展示顺序，不参与分组正确性。
- 如果题目明确要求保留“学生表中没有任何成绩记录的人”，就需要从学生主表 `LEFT JOIN` 成绩表；当前单表契约没有这个要求。

## 原理机制

逻辑上，数据库先从 `student_scores` 读取满足条件的行；由于本题没有 `WHERE`，所有明细行进入聚合阶段。`GROUP BY student_name` 根据分组键形成若干组，每一组由一个学生名对应的全部明细行构成。`SUM(score)` 再把每组中非 `NULL` 的 `score` 累加，最终每组产生一行结果。

这个答案的核心不变量是“每个输出行只对应一个分组键”。因此所有非聚合输出字段都应该由分组键决定；在这里只选择 `student_name` 和聚合值，避免依赖宽松 SQL 模式随机挑选组内某行的非聚合列。

## 项目经验版

这是 SQL 基础题，不应编造生产经历。更可靠的回答方式是先写出最小查询，再主动指出两个真实数据边界：姓名是否唯一、`NULL`/多次考试如何计入。若面试官继续问性能，再结合真实行数、索引和执行计划讨论，而不是脱离数据量泛称“给 `student_name` 加索引一定更快”。

## 常见追问

- 问：为什么用 `GROUP BY`？答：输入是一科一行，输出要求一名学生一行，必须把相同学生的多条明细归为一个集合后再求和。
- 问：`SUM()` 遇到 `NULL` 怎么办？答：MySQL 聚合函数通常忽略 `NULL`；如果一组没有任何非 `NULL` 值，`SUM()` 返回 `NULL`。是否用 `COALESCE(...,0)` 要看业务语义。
- 问：如果两个学生同名呢？答：仅有姓名字段无法区分，查询会合并。真实模型应增加唯一 `student_id`，按 ID（以及需要展示的姓名）分组。
- 问：为什么不写 `SELECT *` 再 `GROUP BY student_name`？答：其他非聚合列在一个学生组里可能有多个值；在严格分组语义下它们不是合法输出，也会掩盖结果粒度错误。
- 问：如果要找总分大于 240 的学生？答：聚合后过滤用 `HAVING SUM(score) > 240`，而不是把聚合条件放进 `WHERE`。

## 易错点

- 忘记 `GROUP BY`，得到全表一个总分而不是每名学生一个总分。
- 把 `subject_name` 也放进 `GROUP BY`，结果仍是一科一行，没有完成“按学生汇总”。
- 在只按姓名分组时选择不确定的非聚合列，依赖关闭 `ONLY_FULL_GROUP_BY` 后的宽松行为。
- 默认把 `NULL` 当 0，却没有说明缺失成绩的业务含义。
- 忽略同名学生，错误地把姓名当天然主键。
