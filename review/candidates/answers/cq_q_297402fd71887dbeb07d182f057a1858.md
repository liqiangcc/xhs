# 大数相乘：显式采用十进制非负数字符串 API 的竖式乘法

## 核心结论

仓库原始面经只保留了“算法：大数相乘”。来源没有说明输入类型、进制、符号、前导零、是否禁用大整数库或具体语言，因此这里不把熟悉的在线判题题面当作原题。候选明确选择一个可验证的接口：输入两个只含十进制数字的非空字符串，允许前导零，返回规范化的非负十进制乘积字符串；`null`、空串、负号、小数点或其他非数字字符拒绝。

实现模拟竖式乘法，不在被测实现中使用任意精度乘法。长度分别为 `m`、`n` 的输入最多产生 `m+n` 个十进制位；把每一对数字位的乘积累加到对应权位，再从低位向高位统一进位。时间复杂度 `O(m*n)`，额外空间 `O(m+n)`。

## 1 分钟版

设结果数组长度为 `m+n`。从高位开始编号时，`left[i] * right[j]` 的低位贡献落在 `digits[i+j+1]`。先把所有位积累加进去，再从数组末尾向前做：

```text
digits[k-1] += digits[k] / 10
digits[k] %= 10
```

这个进位过程不改变数组代表的十进制数值。最后跳过前导零；若乘积为零，则返回单个 `"0"`。每个输入位对只处理一次，所以主成本是 `O(m*n)`。

## 3 分钟版

第一层不变量是**位权守恒**。每个输入数字位对的乘积被放到与它十进制权重一致的槽位，因此虽然槽位暂时可能大于 9，整个数组代表的总数值已经等于数学乘积。

第二层不变量是**进位等值变换**。一个槽位若是 `10*q+r`，把当前槽改成 `r`、左边槽增加 `q`，只是把同一个十进制数换成规范表示，不改变总数值。按从右到左的顺序处理后，每一位都落在 `0..9`，得到规范十进制结果。

输入中的前导零不需要预处理；输出时统一去掉即可。被测实现使用 `long[]` 存中间累加值，接口层先验证所有字符都是十进制数字。这里的十进制、非负、字符串返回值都是候选 API 选择，而不是来源已经证明的事实。

## 关键细节

- **题源边界**：原始材料只有“大数相乘”；十进制字符串、非负、输出字符串和异常策略均是显式候选接口。
- **输入契约**：两个输入必须非 `null`、非空，且每个字符都在 `0..9`；否则抛 `IllegalArgumentException`。
- **前导零**：允许输入有前导零；输出去除前导零，全零结果返回 `"0"`。
- **实现边界**：生产实现不调用 `BigInteger`；`BigInteger` 只在测试中作为独立 oracle。
- **复杂度**：双层循环处理 `m*n` 个位对，进位与输出是 `O(m+n)`，总时间 `O(m*n)`、额外空间 `O(m+n)`。
- **可验证性**：固定用例与 4000 组确定性随机输入都经过独立 oracle 差分验证，并对每组随机输入检查交换律。
- **来源没有的内容不补写**：不声称原题给了 LeetCode 名称、数据范围、符号规则或禁用标准库条件。

## 原理机制

```java
public final class MultiplyDecimalStrings {
    private MultiplyDecimalStrings() {}

    public static String multiply(String left, String right) {
        requireDigits(left, "left");
        requireDigits(right, "right");

        int m = left.length();
        int n = right.length();
        long[] digits = new long[m + n];

        for (int i = 0; i < m; i++) {
            int a = left.charAt(i) - '0';
            for (int j = 0; j < n; j++) {
                int b = right.charAt(j) - '0';
                digits[i + j + 1] += (long) a * b;
            }
        }

        for (int k = digits.length - 1; k > 0; k--) {
            digits[k - 1] += digits[k] / 10;
            digits[k] %= 10;
        }

        int first = 0;
        while (first < digits.length - 1 && digits[first] == 0) {
            first++;
        }
        StringBuilder out = new StringBuilder(digits.length - first);
        for (int i = first; i < digits.length; i++) {
            out.append((char) ('0' + digits[i]));
        }
        return out.toString();
    }

    private static void requireDigits(String value, String name) {
        if (value == null || value.isEmpty()) {
            throw new IllegalArgumentException(name + " must be a non-empty decimal string");
        }
        for (int i = 0; i < value.length(); i++) {
            char c = value.charAt(i);
            if (c < '0' || c > '9') {
                throw new IllegalArgumentException(name + " must contain only decimal digits");
            }
        }
    }
}
```

仓库中的确定性夹具实际验证：零和前导零、单位元、单数字乘法、普通乘法、连续进位、已知九位数乘积，以及 `null`、空串、负号、小数点和字母等非法输入；随后生成 4000 对 1～80 位十进制字符串，与 `java.math.BigInteger` 的乘积结果逐一比较，并检查交换律。已记录输出为：

```text
PASS fixed=14 randomized=4000 oracle=BigInteger commutative=true
```

## 常见追问

- **为什么数组长度是 `m+n`？** 两个 `m` 位和 `n` 位非负十进制整数的乘积最多 `m+n` 位，例如 `99*99=9801`。
- **为什么可以先累加再统一进位？** 因为每个槽位代表固定十进制权重；`10*q+r` 拆成左侧增加 `q`、当前位保留 `r` 是等值变换。
- **为什么测试可以用 `BigInteger`？** 限制只针对被演示实现；测试使用算法独立的标准库 oracle，能降低测试与实现复制同一 bug 的风险。
- **负数怎么办？** 来源没有符号契约；当前候选明确拒绝负号。若要支持，应在接口层解析符号，再复用无符号核心。
- **为什么不用 `long` 直接解析整个输入？** 固定宽度整数会重新引入上限，无法覆盖“大数”目标。

## 易错点

- 把某个熟悉在线题的完整题面、限制和 API 冒充成仓库来源。
- 把位积写到错误权位，混淆 `i+j+1` 和进位位置。
- 忘记全零结果的规范化，返回空串或多个零。
- 被测实现和测试 oracle 使用同一套手写竖式逻辑，导致同源 bug 无法被差分测试发现。
- 用固定宽度整数解析整个输入，使超出 `long` 的大数失效。
