# 一个数组同时找最大值和最小值：怎样减少比较次数？

## 核心结论

如果分别扫一遍求最小值和最大值，需要 `2(n-1)` 次元素比较。可以把元素两两成对：每对先比较一次决定较小/较大，再让较小者只和当前 `min` 比、较大者只和当前 `max` 比，因此每两个新元素只用 3 次比较。偶数长度总比较次数是 `3n/2 - 2`；奇数长度先用第一个元素同时初始化 `min/max`，总比较次数是 `3(n-1)/2`。

来源只要求“找最大值和最小值，并优化比较次数”，没有固定语言、API、空数组策略或元素类型。下面选择 Java `int[]`；`null` 或空数组抛出 `IllegalArgumentException`，返回 `[min, max]`。这些是答案侧明确声明的契约，不冒充原题条件。

## 1 分钟版

- 朴素方法中，每个新元素通常既跟 `min` 比、又跟 `max` 比，约 2 次比较。
- 两两分组后，一对元素先内部比较 1 次，确定谁更可能刷新最小值、谁更可能刷新最大值。
- 然后小的只比较 `min`，大的只比较 `max`，所以一对共 3 次，而不是 4 次。
- 偶数 `n`：首对初始化花 1 次，其余 `(n-2)/2` 对各 3 次，合计 `1 + 3(n-2)/2 = 3n/2 - 2`。
- 奇数 `n`：首元素直接初始化，不比较；剩余 `(n-1)/2` 对各 3 次，合计 `3(n-1)/2`。
- 时间仍是 O(n)，额外空间 O(1)，优化的是比较次数常数。

## 3 分钟版

```java
public static int[] minMax(int[] a) {
    if (a == null || a.length == 0) {
        throw new IllegalArgumentException("array must be non-empty");
    }

    int min;
    int max;
    int i;
    if ((a.length & 1) == 0) {
        if (a[0] <= a[1]) {
            min = a[0];
            max = a[1];
        } else {
            min = a[1];
            max = a[0];
        }
        i = 2;
    } else {
        min = max = a[0];
        i = 1;
    }

    while (i < a.length) {
        int small;
        int large;
        if (a[i] <= a[i + 1]) {
            small = a[i];
            large = a[i + 1];
        } else {
            small = a[i + 1];
            large = a[i];
        }
        if (small < min) min = small;
        if (large > max) max = large;
        i += 2;
    }
    return new int[]{min, max};
}
```

关键不变量是：一对元素内部比较之后，较小者不可能成为这一对中更值得检查的最大值候选，较大者也不可能成为这一对中更值得检查的最小值候选。因此可以把原来“两个元素各做 min/max 两次比较”的 4 次，压成“对内 1 次 + 对外 2 次”的 3 次。

## 关键细节

- 长度为 1 时 `min == max == a[0]`，比较次数为 0。
- 偶数长度必须先用首对初始化；否则若拿一个哨兵值初始化，可能额外增加比较，破坏精确比较次数公式。
- 相等元素放在哪一侧都不影响正确性；示例统一用 `<=` 把左元素视为 `small`。
- 这是比较模型下的常数优化，渐进时间复杂度仍是 O(n)。
- 如果题目只问代码而不要求精确比较次数，也应能解释“为什么两两分组能从每两元素 4 次降到 3 次”。

## 原理机制

同时求最小值和最大值时，每个元素并不需要同时承担两个方向的竞争。先在局部的一对元素中建立一次大小关系，就得到一条信息：小者无需再参与“这对中的最大候选”竞争，大者无需再参与“这对中的最小候选”竞争。之后每个方向只做一次全局比较。这个方法用一次局部比较复用了信息，因此减少总比较次数，而不是改变遍历数量级。

## 常见追问

- 问：为什么不是 `3n/2`？答：偶数长度首对只需 1 次比较就同时初始化 `min/max`，所以比每对 3 次少 2 次，得到 `3n/2-2`。
- 问：奇数长度怎么算？答：第一个元素无需比较即可同时作为初始最小/最大值，剩下 `(n-1)/2` 对每对 3 次，共 `3(n-1)/2`。
- 问：复杂度是不是从 O(n) 变成 O(n/2)？答：不是，O(n/2) 仍然是 O(n)；优化的是元素比较次数常数。
- 问：有重复值会错吗？答：不会；相等值在对内比较时任选 small/large 方向都保持最小值和最大值不变量。
- 问：能不能排序后取首尾？答：可以得到结果，但比较排序通常要 O(n log n)，为这个目标反而更差。

## 易错点

- 忘记奇偶长度不同的初始化，导致 `i+1` 越界。
- 只说“一对 3 次比较”，却把首对也按 3 次计算，给错精确公式。
- 把 O(n/2) 当作不同于 O(n) 的渐进复杂度。
- 为了统一初始化引入额外比较，却仍宣称达到精确的 `3n/2-2` 上界。
