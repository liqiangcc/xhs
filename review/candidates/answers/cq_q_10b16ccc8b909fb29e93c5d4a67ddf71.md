# 链表大数求和：高位在头、个位在尾时从尾部进位

## 核心结论

仓库原始图片转写 `note_img_txt/694512cd000000001e004d1a.txt` 明确保留了题目：两个链表表示大数，**头节点是最高位、尾节点是个位**，要求输出两数之和的新链表；紧接着还要求说明时间和空间复杂度。

因为单链表的遍历方向与加法进位方向相反，直接从头同时遍历无法在不知道低位进位的情况下确定高位。若不假设可以修改输入，一个清晰稳定的做法是：分别把两个链表的数字压栈，再从栈顶（个位）向高位做逐位加法，并把新节点不断头插到结果链表。

设两条链表长度为 `m`、`n`：遍历入栈 `O(m+n)`，逐位相加仍是 `O(m+n)`；两个栈使用 `O(m+n)` 辅助空间，结果链表本身需要 `O(max(m,n))` 输出空间。

## Source boundary

源材料没有规定：输入是否允许被修改、空链表语义、是否允许前导零。候选实现采用下面的**实现契约**，这些是解法选择，不冒充原题逐字条件：

- 两个输入链表都必须非空；
- 每个节点必须是 `0..9` 的十进制数字；
- 不修改输入链表；
- 不额外规范化前导零，按输入位宽自然计算，最高位只有在最终进位时才新增节点。

若面试官允许原地修改，也可以先反转两条链表再逐位相加，把辅助栈空间降到 `O(1)`（不计输出），但这会改变输入，不能在题目未授权时默认采用。

## 1 分钟版

这题的关键是“高位在头、低位在尾”，而加法必须从个位开始传播 carry，所以单链表遍历方向和运算方向冲突。

我会把两条链表分别压入栈。之后每轮弹出一个最低剩余位：

`sum = digitA + digitB + carry`

新节点保存 `sum % 10`，carry 更新为 `sum / 10`。因为我们是从低位往高位计算，所以每次把新节点插到结果链表头部。两个栈都空以后，如果 carry 还不为 0，再补一个最高位节点。

时间复杂度 `O(m+n)`，额外空间 `O(m+n)`；优点是不修改输入，边界和正确性都比较直观。

## 3 分钟版

用栈以后可以维护一个很清晰的不变量：每轮开始时，两个栈顶分别是各自**尚未处理部分的最低位**，`carry` 是已经处理完的更低位向当前位产生的唯一进位。当前位求和后，把结果数字头插，就能保证 `result` 始终表示“已经计算出的低位后缀”，但链接顺序已经恢复为最高位在头。

长度不一致时，较短链表的栈先空，缺失位按 0 处理即可。最后的 carry 可能新增一位，例如 `999 + 1 = 1000`。

为什么不从头递归？可以通过递归先走到尾部再回溯，但需要先对齐长度，且递归深度是 `O(max(m,n))`。对于很长链表，显式栈避免把问题交给 JVM 调用栈，工程上更可控。

为什么不把链表转成 `long` 再相加？题目叫“大数”，长度可能超过任何固定宽度整数；正确解法应该按位计算而不是依赖机器整数容量。

## 代码

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Objects;

public final class LinkedListBigIntegerAdd {
    public static final class ListNode {
        public final int digit;
        public ListNode next;

        public ListNode(int digit) {
            this(digit, null);
        }

        public ListNode(int digit, ListNode next) {
            if (digit < 0 || digit > 9) {
                throw new IllegalArgumentException("digit must be in [0, 9]");
            }
            this.digit = digit;
            this.next = next;
        }
    }

    public static ListNode add(ListNode left, ListNode right) {
        Objects.requireNonNull(left, "left");
        Objects.requireNonNull(right, "right");

        Deque<Integer> a = digits(left);
        Deque<Integer> b = digits(right);
        ListNode result = null;
        int carry = 0;

        while (!a.isEmpty() || !b.isEmpty() || carry != 0) {
            int sum = carry;
            if (!a.isEmpty()) sum += a.pop();
            if (!b.isEmpty()) sum += b.pop();
            result = new ListNode(sum % 10, result);
            carry = sum / 10;
        }
        return result;
    }

    private static Deque<Integer> digits(ListNode head) {
        Deque<Integer> stack = new ArrayDeque<>();
        for (ListNode node = head; node != null; node = node.next) {
            stack.push(node.digit);
        }
        return stack;
    }
}
```

## 验证策略

固定用例覆盖 `0+0`、不同长度、连续进位、最终新增最高位、一个操作数明显更长等情况。随机验证使用与被测算法结构不同的 oracle：把链表按高位到低位转成十进制字符串，再交给 `java.math.BigInteger` 相加，比较结果字符串；同时在调用前后序列化两条输入链表，确认实现没有修改输入。

随机输入不依赖 `long`，可生成几十位十进制数，从而验证真正的大数场景。实现还显式测试非法 digit 与 null 输入，锁定候选自己声明的 API 边界。

## 常见追问

- **能不能做到更低的辅助空间？** 如果允许破坏或恢复输入链表，可以反转后相加；不允许改输入时，显式栈或递归都需要与链表长度同阶的辅助状态。
- **为什么结果用头插？** 计算顺序是个位到最高位，而最终链表要求最高位在头；头插正好把计算顺序反转回来。
- **超长链表为什么不用递归？** 递归同样是线性辅助空间，而且会占用调用栈；显式栈对深度没有 JVM 调用栈风险。
- **两条链表长度不同怎么办？** 某一栈空后该位按 0 处理，继续消费另一栈和 carry。
- **输入能不能直接转 `BigInteger`？** 测试 oracle 可以这么做来获得独立验证，但正式算法若直接转换就绕过了题目考察的链表逐位进位机制。
