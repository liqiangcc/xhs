# 统计满足 a[i] + reverse(a[i]) 相等的下标对

## 核心结论

把每个元素映射成一个可比较的键 `key(x) = x + reverse(x)`，题目就变成“统计键相同的下标对”。遍历数组时，用哈希表记录每个键之前出现了多少次；当前键已经出现 `c` 次，就新增 `c` 个以当前下标为右端点的合法对，然后把计数加一。这样不需要枚举所有 `(i,j)`，时间从 O(n²) 降到 O(n·d)，其中 `d` 是数字位数；若输入是 32 位非负整数，`d <= 10`，可视为 O(n)，额外空间 O(n)。

## 1 分钟版

- 题源只保存了等式，没有保存输入范围、负数语义和 `(i,j)` 是否要求 `i < j`；下面先声明最小可执行契约：输入是非负 `int[]`，统计无序下标对 `i < j`。
- 对每个 `x` 计算十进制反转值 `reverse(x)`，前导零自然消失，例如 `120 -> 21`，`0 -> 0`。
- 定义 `key = (long)x + reverse(x)`；使用 `long`，避免反转值或加和超过 `int`。
- `count[key]` 表示当前下标之前已经有多少元素得到同一个键。当前出现时先把这个计数加入答案，再把 `count[key]` 加一。
- 这等价于每个键出现 `m` 次贡献 `m*(m-1)/2` 对，但单遍写法不需要二次遍历。

## 3 分钟版

```java
static long countPairs(int[] nums) {
    if (nums == null) {
        throw new IllegalArgumentException("nums must not be null");
    }
    Map<Long, Long> seen = new HashMap<>();
    long pairs = 0;
    for (int x : nums) {
        if (x < 0) {
            throw new IllegalArgumentException("this candidate defines reverse only for non-negative ints");
        }
        long key = (long) x + reverseNonNegativeInt(x);
        long previous = seen.getOrDefault(key, 0L);
        pairs += previous;
        seen.put(key, previous + 1);
    }
    return pairs;
}

static long reverseNonNegativeInt(int x) {
    long reversed = 0;
    int value = x;
    while (value > 0) {
        reversed = reversed * 10 + value % 10;
        value /= 10;
    }
    return reversed;
}
```

不变量是：处理完前 `k` 个元素后，`seen` 精确记录这 `k` 个元素每个 `key` 的频次，`pairs` 精确等于这 `k` 个元素内部所有满足等式且 `i < j` 的下标对数。处理第 `k+1` 个元素时，所有新增合法对只能是“之前某个相同 key 的元素 + 当前元素”，数量正好是 `seen[key]`；更新频次后不变量继续成立。

## 关键细节

- **为什么哈希键有效**：原条件只比较 `a[i] + reverse(a[i])` 与 `a[j] + reverse(a[j])` 是否相等，所以只要把这个表达式的结果作为键，同键即合法、异键即不合法。
- **为什么先加答案再增频次**：这样当前元素只和之前下标配对，天然保证 `i < j`，不会把自己和自己配对，也不会重复计算 `(j,i)`。
- **数值类型**：即使 `x` 是 `int`，十进制反转结果也可能超过 `int`，例如某些 10 位整数反转后大于 2³¹-1；因此反转值、键和答案都使用 `long`。
- **前导零**：十进制整数反转后不保留前导零，`120` 的反转是 `21`。这是示例契约；如果原题把输入当字符串，语义就需要重新确认。
- **负数**：题源没有定义 `reverse(-12)` 是 `-21`、`21` 还是非法。本候选不擅自选择一种隐藏语义，而是显式只接受非负整数；若面试官允许负数，需要先补充契约。
- **答案规模**：若所有元素键都相同，答案是 `n*(n-1)/2`，可能超过 `int`，所以返回 `long`。

## 原理机制

这是“按等价键分组后计数组合数”的典型做法。函数 `f(x)=x+reverse(x)` 把每个元素投影到一个键空间；题目的二元关系恰好是 `f(a[i]) == f(a[j])`。因此数组被划分成若干互不相交的键分组，每组大小为 `m` 时贡献 `C(m,2)` 个合法下标对。

单遍哈希做法把组合计数在线化：一个组中第 1 个元素新增 0 对，第 2 个新增 1 对，第 3 个新增 2 对，直到第 `m` 个新增 `m-1` 对，总和就是 `0+1+...+(m-1)=m(m-1)/2`。哈希表保存的是完成这个增量计算所需的最小状态。

## 项目经验版

题源没有真实项目背景、线上规模或性能数据，不能虚构。工程上如果数据量非常大，除了 O(n) 哈希内存，还要关注键分布、装箱开销和结果是否溢出；若数据已按键排序或可以外部排序，也可以采用排序后按组计数，以 O(n log n) 时间换取不同的内存/流式处理特性。是否值得这样做要由真实数据规模和内存约束决定。

## 常见追问

- 问：为什么不是双重循环？答：因为合法性只由单元素函数 `f(x)=x+reverse(x)` 的结果决定，可以先按 `f(x)` 分组；哈希表让每个元素只处理一次，而不是和所有其他元素比较。
- 问：为什么当前元素新增的对数恰好等于之前同 key 的频次？答：任何新合法对都必须包含当前下标，另一端只能从之前相同 key 的元素中选择；之前有多少个就新增多少对。
- 问：如果所有元素的 key 都相同呢？答：第 k 个元素新增 `k-1` 对，最终得到 `n(n-1)/2`，因此答案应使用 `long`。
- 问：`120` 怎么反转？答：本候选按十进制整数语义得到 `21`；如果题目要求保留字符前导零，那已经是字符串契约，需要改写 `reverse` 定义。
- 问：负数怎么办？答：当前题源没有保存负数语义，所以本候选明确拒绝负数；面试现场应先问清 `reverse` 对符号的定义，再决定实现。
- 问：能不能先把所有 key 排序？答：可以。排序后连续相同 key 的组直接算 `m(m-1)/2`，时间 O(n log n)，额外空间取决于排序实现；哈希方案平均 O(n) 时间但需要 O(n) 频次表。

## 易错点

- 直接 O(n²) 枚举所有 `(i,j)`，没有利用“同一个单元素表达式结果即可判等”的结构。
- 用 `int` 保存十进制反转结果或 `x + reverse(x)`，导致溢出后错误分组。
- 先把当前频次加一再累加答案，误把元素和自己组成一对。
- 同时计算 `(i,j)` 和 `(j,i)`，把无序下标对重复计数。
- 题源没定义负数或字符串前导零，却把某一种解释说成原题硬约束。
