# 打印所有“比前面都小、比后面都大”的数组元素

## 核心结论

对位置 `i`，题意的直接条件是：`a[i]` 严格小于它前面的每个元素，同时严格大于它后面的每个元素。等价地：

`a[i] < min(a[0..i-1]) && a[i] > max(a[i+1..n-1])`。

因此可以先从右向左预计算后缀最大值，再从左向右维护前缀最小值，整体 `O(n)` 时间、`O(n)` 额外空间。来源没有说明首尾元素在“一侧为空”时是否允许，因此下面采用更符合“前面元素”和“后面元素都存在”的最小契约：**只检查 `1..n-2`，首尾不参与**。如果面试官明确采用空集合上的真值语义，再单独调整端点规则。

## 1 分钟版

- “比前面元素都小”不是只和前一个比较，而是 `a[i] < 前缀最小值`。
- “比后面元素都大”不是只和后一个比较，而是 `a[i] > 后缀最大值`。
- 从右向左得到 `suffixMax[i] = max(a[i..n-1])`。
- 从左向右维护 `prefixMin = min(a[0..i-1])`。
- 对每个内部位置 `i` 判断 `a[i] < prefixMin && a[i] > suffixMax[i+1]`，满足就输出。
- 题目使用“都小/都大”的严格比较，所以相等时不满足；不能偷换成 `<=` 或 `>=`。
- 时间复杂度 `O(n)`；后缀数组占 `O(n)`。如果只需打印且愿意换一种预处理，也可以对称地存前缀、从右扫描。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.List;

public final class PrefixMinSuffixMaxFilter {
    static List<Integer> findSpecial(int[] a) {
        List<Integer> result = new ArrayList<>();
        if (a == null || a.length < 3) return result;

        int n = a.length;
        int[] suffixMax = new int[n];
        suffixMax[n - 1] = a[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            suffixMax[i] = Math.max(a[i], suffixMax[i + 1]);
        }

        int prefixMin = a[0];
        for (int i = 1; i <= n - 2; i++) {
            if (a[i] < prefixMin && a[i] > suffixMax[i + 1]) {
                result.add(a[i]);
            }
            prefixMin = Math.min(prefixMin, a[i]);
        }
        return result;
    }

    static void printSpecial(int[] a) {
        for (int value : findSpecial(a)) {
            System.out.println(value);
        }
    }
}
```

例如数组 `[9, 8, 7, 6, 5]`，内部的 `8、7、6` 都满足：每个值都比它左侧所有值小，又比它右侧所有值大，因此都会被打印。

## 关键细节

- **严格比较**：若右侧存在和当前值相同的元素，当前值就不是“比后面元素都大”；例如 `[9,8,8,7]` 中第一个 8 不满足，因为右边还有 8。
- **不能只看相邻元素**：局部满足 `a[i] < a[i-1]`、`a[i] > a[i+1]` 并不能推出它和更远位置的所有元素也满足关系。
- **前缀变量的时序**：检查 `i` 时，`prefixMin` 必须只包含 `0..i-1`；因此要在判断之后再把 `a[i]` 合入。
- **后缀下标**：检查 `i` 时要比较 `suffixMax[i+1]`，不能用包含自身的 `suffixMax[i]`，否则严格 `>` 永远不可能成立。
- **端点语义**：来源没有说明空侧如何处理。本实现要求左右两侧都至少有一个元素，所以长度小于 3 时没有候选；这是明确的实现契约，不冒充原题隐藏条件。
- **输出值还是下标**：来源说“打印数字”，本实现返回/打印值；若面试官要下标，只需把 `result.add(a[i])` 改为记录 `i`。

## 原理机制

条件里有两个全局量：左侧集合的最小值、右侧集合的最大值。把它们缓存后，每个位置的“对所有元素”判断就从 `O(n)` 降成 `O(1)`。

先做一次右向扫描，把每个位置开始的最大值保存为 `suffixMax`。再做左向扫描时，`prefixMin` 是一个滚动状态，不需要完整前缀数组。这样每个元素只参与常数次比较，总时间由朴素 `O(n^2)` 降为 `O(n)`。

## 项目经验版

这是纯算法题，来源没有真实项目上下文，因此不虚构线上经验。可迁移的思路是“把重复区间聚合预计算成前缀/后缀状态”：当很多位置都要询问其左侧或右侧的 min/max 等可结合聚合值时，用线性预处理换掉重复扫描。

## 常见追问

- 问：为什么是前缀最小值，不是前缀最大值？答：要证明当前值“小于左边每一个数”，只要它小于左边最小的那个数，就自然小于其余所有更大的数；因此边界量是最小值。
- 问：为什么右边用最大值？答：要证明当前值“大于右边每一个数”，只需证明它大于右边最大的那个数。
- 问：相等算不算？答：题目写的是“比……小/大”，本答案按严格 `<`、`>`；如果题目明确说“小于等于/大于等于”才改比较符号。
- 问：首元素和尾元素怎么办？答：原题没有定义空侧语义。本实现只检查内部元素；若面试官认为空集合条件自动成立，需要显式定义对应端点规则后再加入。
- 问：能不能做到 O(1) 额外空间？答：如果要求一次在线从左到右直接输出，右侧最大值尚未知；通常至少需要保存一侧的预处理结果，或允许额外遍历/修改输入。当前实现选择清晰的 `O(n)` 后缀数组。
- 问：朴素解法是什么？答：对每个内部位置分别扫描所有左侧和右侧元素，最坏 `O(n^2)`；它适合作为测试 oracle，但不是最优主解。

## 易错点

- 只比较前后相邻两个元素，把全局条件误做成局部峰谷判断。
- 把“比前面都小”错误写成小于前缀最大值。
- 用 `suffixMax[i]` 与 `a[i]` 比较，把当前值自己包含进右侧集合。
- 判断前先更新 `prefixMin`，导致当前值被包含进自己的左侧集合。
- 把严格条件写成 `<=`/`>=`，错误接受重复值。
- 未说明端点语义，却让首尾是否输出取决于实现偶然行为。
