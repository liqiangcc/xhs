# 课程表/上课顺序：用拓扑排序判断依赖并给出合法顺序

## 核心结论

来源只保留“课程表/上课顺序（拓扑排序）”，没有保存具体 LeetCode 题号、API、先修关系二元组方向、是否只判断可完成、还是必须返回一条上课顺序。为了形成可执行合同，这里采用常见的“返回顺序”版本：课程编号为 `0..numCourses-1`，每条 `prerequisites[i] = [course, prerequisite]` 表示学 `course` 前必须先学 `prerequisite`；如果存在环则返回空数组，否则返回任意一条包含全部课程的拓扑序。

核心机制是 Kahn 算法：把先修关系建成 `prerequisite -> course` 的有向边，同时统计每门课的入度。所有入度为 0 的课程都可以立即学习，进入队列；每取出一门课，就“删除”它发出的边并减少后继课程入度，新变成 0 的课程再入队。最终若恰好处理了 `numCourses` 门课，输出顺序就是合法拓扑序；若处理数不足，剩余子图一定存在无法消除的环。

## 1 分钟版

- 建图方向必须和题意一致：`[course, prerequisite]` 转成 `prerequisite -> course`。
- `indegree[x]` 表示课程 `x` 还有多少先修课没有完成。
- 先把所有入度为 0 的课程放入队列，它们没有未满足依赖。
- 每弹出一门课程，把它加入答案，并把所有后继课程入度减 1；减到 0 的后继进入队列。
- 如果最终答案长度等于课程数，就得到一条合法上课顺序；否则说明有环，返回空数组。
- 时间复杂度 `O(V + E)`，空间复杂度 `O(V + E)`，其中 `V=numCourses`，`E=prerequisites.length`。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;

public final class CourseScheduleOrder {
    public static int[] findOrder(int numCourses, int[][] prerequisites) {
        if (numCourses < 0) {
            throw new IllegalArgumentException("numCourses must be non-negative");
        }

        List<List<Integer>> graph = new ArrayList<>(numCourses);
        for (int i = 0; i < numCourses; i++) {
            graph.add(new ArrayList<>());
        }
        int[] indegree = new int[numCourses];

        if (prerequisites != null) {
            for (int[] pair : prerequisites) {
                if (pair == null || pair.length != 2) {
                    throw new IllegalArgumentException("each prerequisite must contain [course, prerequisite]");
                }
                int course = pair[0];
                int prerequisite = pair[1];
                if (course < 0 || course >= numCourses
                        || prerequisite < 0 || prerequisite >= numCourses) {
                    throw new IllegalArgumentException("course id out of range");
                }
                graph.get(prerequisite).add(course);
                indegree[course]++;
            }
        }

        ArrayDeque<Integer> queue = new ArrayDeque<>();
        for (int course = 0; course < numCourses; course++) {
            if (indegree[course] == 0) {
                queue.addLast(course);
            }
        }

        int[] order = new int[numCourses];
        int size = 0;
        while (!queue.isEmpty()) {
            int current = queue.removeFirst();
            order[size++] = current;
            for (int next : graph.get(current)) {
                if (--indegree[next] == 0) {
                    queue.addLast(next);
                }
            }
        }

        if (size != numCourses) {
            return new int[0];
        }
        return order;
    }
}
```

这里的正确性可以用一个不变量理解：进入队列的课程，其所有入边对应的先修课程都已经出现在当前结果前缀中。因此从队列取出的每门课都可以安全追加到拓扑序。反过来，如果队列已经空了但仍有课程没处理，则剩余课程全部至少还有一条指向它的未删除入边；有限有向图中这种状态必然包含环，所以不存在覆盖全部课程的拓扑序。

## 关键细节

- **边方向**：若输入是 `[course, prerequisite]`，必须建 `prerequisite -> course`。方向写反会得到相反依赖语义。
- **返回什么**：来源没有保存是 LeetCode 207 的布尔判断还是 210 的顺序输出。本候选明确选择“返回任意合法顺序”；如果只问能否完成，最终只需要判断处理数量是否等于课程总数。
- **多个合法答案**：多个入度为 0 的课程可以任意先后处理，所以拓扑序通常不唯一；除非题目额外要求字典序最小，否则不需要优先队列。
- **重复边**：本实现会把重复 prerequisite pair 当作两条边，同时入度加两次、遍历时也减两次，仍保持计数一致；若业务要求输入去重，应在合同中明确，而不是静默改变原始边集合。
- **自环**：`[1,1]` 会让课程 1 永远无法入队，最终正确判定为有环。
- **空图**：`numCourses=0` 返回空数组，此时它既是输入中的全部课程，也是一个合法拓扑序；不能仅凭“返回空数组”区分零课程和有环，调用方若需要区分应结合 `numCourses`。
- **输入校验**：来源没有保存异常策略。本实现把负课程数、格式错误和越界课程编号视为非法输入并抛异常；`prerequisites=null` 按“没有依赖”处理。

## 原理机制

拓扑排序只存在于有向无环图。Kahn 算法不断删除当前入度为 0 的节点，相当于逐层剥掉已经没有前置依赖的课程。DAG 至少存在一个入度为 0 的节点，所以这个过程可以一直推进到所有节点都被删除；如果图中有环，环上每个节点始终至少保留来自环内前驱的一条入边，因此它们永远不会变成入度 0。于是“最终处理节点数是否等于 `V`”既是算法终止条件，也是环检测条件。

如果需要的是另一种实现，可以用 DFS 三色标记：未访问、当前递归栈、已完成；遇到“当前递归栈”节点即发现环，后序逆序得到拓扑序。Kahn 更直接地把“剩余依赖数”显式化，也便于解释课程何时变得可学习。

## 项目经验版

来源没有真实项目经历，不能虚构“在线上排课系统使用过拓扑排序”。工程上遇到任务依赖、构建依赖或课程依赖时，我会先确认依赖边方向、是否允许重复边、是否需要稳定/最小字典序输出，以及循环依赖发生时要返回空结果、错误详情还是具体环路径。若需要诊断具体环，单纯的 Kahn 处理数量还不够，应额外做 DFS/父指针追踪或 SCC 分析来输出可解释的循环链路。

## 常见追问

- 问：为什么入度为 0 的课程可以直接学？答：因为按图定义，它当前没有任何尚未完成的先修课；每次删除已完成课程的出边后，新变成 0 的课程也满足同样条件。
- 问：怎么判断存在环？答：队列耗尽后如果处理数量小于课程总数，剩余子图没有入度为 0 的节点；有限有向图在这种情况下必然含环。
- 问：为什么答案可能不唯一？答：同一时刻可能有多门入度为 0 的课程，它们之间没有当前依赖约束，选择不同先后顺序都可能得到合法拓扑序。
- 问：如果要求字典序最小的上课顺序怎么办？答：把 FIFO 队列换成最小堆，每次从所有可选的入度 0 课程中取编号最小者，复杂度变为约 `O((V+E) log V)`。
- 问：DFS 也能做吗？答：可以，用三色状态检测回边，并按 DFS 完成时间逆序得到拓扑序；两者的渐进复杂度都是 `O(V+E)`。
- 问：如果只需要判断是否能修完课程？答：不必保存完整 `order`，只统计 Kahn 算法弹出的节点数，最后比较是否等于 `numCourses` 即可。

## 易错点

- 把 `[course, prerequisite]` 建成 `course -> prerequisite`，导致依赖方向颠倒。
- 只生成一部分顺序就直接返回，没有检查处理数量是否等于课程总数，从而漏掉环。
- 默认拓扑序唯一，拿某个固定数组做唯一正确答案比较。
- 忘记自环也是环，或者用“是否还有边”之外的不可靠条件判断循环依赖。
- 来源没说明 API/异常策略，却把返回布尔值、返回顺序、越界处理等实现选择说成原题条件。
