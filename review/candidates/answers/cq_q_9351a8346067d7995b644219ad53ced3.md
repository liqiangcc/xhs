# 算法：子集问题（不包含空集）

## 核心结论

来源只保留“算法题，子集问题，但不包含空集”，没有给输入类型、元素是否互异、是否要求结果按值去重、输出顺序或规模上限。下面采用一个最小且不偷偷增加来源约束的可执行契约：输入为 `int[] nums`，每个数组位置都可以独立选择一次，输出所有**按位置定义的非空子集**，子集内部保持原数组相对顺序；空数组返回空结果。如果不同位置上的值相同，按位置选择会允许出现值序列相同但来源位置不同的结果；若面试官要求“按值去重”，需要额外确认并改成排序 + 同层去重版本。

## 1 分钟版

- 用回溯维护当前路径 `path` 和下一次可选的起点 `start`。
- 每次选中 `nums[i]` 后，立刻把当前路径复制进结果，再递归到 `i + 1`；因为只在“至少选了一个元素”之后记录结果，所以天然不会产生空集。
- `start` 单调向右，保证同一个数组位置最多使用一次，也不会产生 `[2,1]` 这种打乱原相对顺序的重复排列。
- 回溯返回后删除刚加入的元素，恢复进入这一层前的 `path`，这是核心不变量。
- 一共有 `2^n - 1` 个非空位置子集；考虑复制每个结果的成本，时间复杂度是 `O(n * 2^n)`，递归辅助空间 `O(n)`，输出本身需要 `Theta(n * 2^n)` 级别的元素存储。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.List;

static List<List<Integer>> nonEmptySubsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), result);
    return result;
}

static void backtrack(
        int[] nums,
        int start,
        List<Integer> path,
        List<List<Integer>> result) {
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);
        result.add(new ArrayList<>(path));

        backtrack(nums, i + 1, path, result);

        path.remove(path.size() - 1);
    }
}
```

对 `[1,2,3]`，搜索从空路径开始，但空路径本身不入结果。第一层先选 `1`，记录 `[1]`，再向右继续得到 `[1,2]`、`[1,2,3]`、`[1,3]`；回退后再从 `2` 开始得到 `[2]`、`[2,3]`，最后得到 `[3]`。每个非空位置子集恰好有一个“递增下标序列”，因此不会漏也不会按位置重复。

## 关键细节

- **为什么不会包含空集**：很多标准子集模板会在 DFS 入口先 `add(path)`，那样自然会记录空路径。本题明确排除空集，所以这里改成“做出一次选择后再记录”。
- **为什么递归传 `i + 1`**：子集中的每个位置只能选一次；如果继续传 `start` 或 `i`，会允许同一位置重复使用，变成组合/多重选择的另一类问题。
- **为什么要复制 `path`**：`path` 是一个会持续增删的可变列表；如果直接把同一个引用放进 `result`，后续回溯会把已经记录的答案一起改掉。
- **重复值边界**：来源没有说明 `nums` 是否互异。本答案按“位置子集”定义，因此 `[1,1]` 会得到三个位置子集：第一个 `1`、第二个 `1`、两个 `1`；前两个在值表示上相同。若要求值集合唯一，应先排序，并在同一递归层跳过相同值，而不是直接套当前契约。
- **输出顺序**：来源没有规定顺序。上面的 DFS 顺序只是实现结果，不应把它当成题目要求。
- **空输入**：没有非空子集，所以返回空列表。
- **大输入**：这类问题的输出规模本身就是指数级；当 `n` 很大时，瓶颈不是回溯常数，而是答案数量。若调用方不需要一次性物化所有结果，应改成迭代器/回调式消费。

## 原理机制

把每个非空子集按其被选择的下标从小到大写成唯一序列 `i1 < i2 < ... < ik`。回溯在某一层只枚举 `start...n-1`，选择 `i` 后下一层从 `i+1` 开始，因此生成的每条路径天然对应一个严格递增下标序列；反过来，任意非空递增下标序列都会沿着这些选择被遍历到一次。于是“不会遗漏”和“不会按位置重复”同时成立。

复杂度不能只写 `O(2^n)`。算法确实访问 `2^n - 1` 个非空子集，但每次 `new ArrayList<>(path)` 还要复制当前路径。所有子集长度之和是 `n * 2^(n-1)`，因此把输出实际构造出来的时间和输出空间都达到 `Theta(n * 2^n)` 量级；不计输出时，递归栈与当前路径最多深 `n`，辅助空间为 `O(n)`。

## 项目经验版

来源没有提供真实项目、数据规模或线上使用记录，不能虚构“生产里用过这个回溯”。如果真实系统只是需要遍历组合而不是一次性保存全部结果，我会优先设计流式消费者，在生成一个子集时立即处理，避免把指数级结果全部留在内存；是否可行取决于下游是否需要随机访问、排序或全局聚合。这是工程取舍，不是原题来源事实。

## 常见追问

- 问：为什么不先把空列表放进结果再最后删除？答：可以，但题目明确不要空集，直接在第一次选择后记录更符合契约，也避免额外的“先生成再修正”。
- 问：为什么不会出现 `[2,1]`？答：下一层只允许选择当前下标右侧的位置，下标始终递增，所以只保留原数组相对顺序，不会把一个子集枚举成多个排列。
- 问：输入有重复值怎么办？答：先确认“按位置”还是“按值”定义。当前实现按位置，所以不同位置即使值相同也属于不同选择；如果要求值结果唯一，应排序并做同层去重。
- 问：能不能用位掩码？答：可以。`1...2^n-1` 的每个 mask 都直接表示一个非空位置子集；它更迭代化。回溯的优势是更容易扩展成带约束/剪枝的组合搜索。
- 问：时间复杂度为什么不是单纯 `O(2^n)`？答：如果只统计“访问多少个子集”是指数级，但把每个子集复制进结果还要按其长度付费，所有子集长度之和是 `n * 2^(n-1)`。
- 问：如果只要大小为 `k` 的子集呢？答：把结束条件改成 `path.size() == k` 时记录，并可根据剩余元素数量剪枝；那是组合问题的受限版本。

## 易错点

- 在 DFS 入口无条件记录 `path`，把空集也加入结果。
- 递归时没有把起点推进到 `i + 1`，导致同一位置被重复选取。
- 直接把可变的 `path` 引用加入 `result`，最后所有记录都被回溯修改。
- 来源没说明重复值，却默认套“元素互异”或“按值去重”契约而不声明。
- 只写 `O(2^n)`，忽略实际物化所有子集时的复制成本和指数级输出空间。
