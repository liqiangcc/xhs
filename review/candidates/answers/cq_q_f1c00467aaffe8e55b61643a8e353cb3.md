# 算法手撕：十进制大整数乘法（字符串模拟）

## 核心结论

仓库原始面经只写“最后是手撕，题目是两数相乘”，没有给输入类型、范围或是否允许直接使用整数类型；结构化题目进一步归一化成了“两数相乘（大数乘法）”。因此这里把它明确当作**常见的大整数十进制字符串乘法练习**来准备，而不声称原面试题一定就是 LeetCode 43。按这一契约：两个非负整数用十进制字符串表示，不能把整串直接转成整数或使用 `BigInteger` 完成实现，要求返回乘积字符串。最稳妥的做法是模拟竖式乘法：长度分别为 `m`、`n` 的两个数，乘积最多 `m+n` 位，用长度 `m+n` 的数组累计每一对数字的乘积，再从低位向高位统一进位，时间 `O(mn)`、额外空间 `O(m+n)`。

## 1 分钟版

- 先把题目约束讲清：这里按“两个非负十进制整数字符串相乘”处理，不把整串转成机器整数。
- 若长度是 `m` 和 `n`，十进制乘积最多 `m+n` 位，所以准备长度 `m+n` 的结果数组。
- `num1[i] * num2[j]` 对应竖式中同一权重的位置，累加到 `acc[i+j+1]`。
- 所有位积累加完后，从数组末尾向前做进位：`acc[pos-1] += acc[pos] / 10`，`acc[pos] %= 10`。
- 跳过最高位可能出现的一个前导 `0`，拼成字符串即可。
- 两层循环覆盖所有数字对，时间 `O(mn)`；结果数组长度 `m+n`，空间 `O(m+n)`。

## 3 分钟版

这题不要先想到 `Long.parseLong` 或 `BigInteger`，因为那会绕过“手写大数运算”的核心。把十进制字符串看成数字数组即可。

设 `a` 有 `m` 位、`b` 有 `n` 位。第 `i` 位和第 `j` 位的乘积会贡献到十进制权重 `10^(m-1-i + n-1-j)`，在一个从高位到低位排列、长度为 `m+n` 的数组里，这个贡献先累加到 `i+j+1`。为什么可以先不立即进位？因为加法满足结合律，所有同一权重的贡献可以先集中到一个桶里，最后统一把每个桶的十位及以上向左传播。

下面的实现没有把输入整体转成整数，也没有在实现里使用 `BigInteger`。仓库测试只在**独立 oracle** 中用 `BigInteger` 计算期望值，拿它和当前实现做 5000 组固定随机种子的差分验证。

```java
public final class DecimalStringMultiplier {
    private DecimalStringMultiplier() {}

    public static String multiply(String num1, String num2) {
        String a = normalize(num1, "num1");
        String b = normalize(num2, "num2");
        if (a.equals("0") || b.equals("0")) {
            return "0";
        }

        int m = a.length();
        int n = b.length();
        long[] acc = new long[m + n];

        for (int i = m - 1; i >= 0; i--) {
            int digitA = a.charAt(i) - '0';
            for (int j = n - 1; j >= 0; j--) {
                int digitB = b.charAt(j) - '0';
                acc[i + j + 1] += (long) digitA * digitB;
            }
        }

        for (int pos = acc.length - 1; pos > 0; pos--) {
            acc[pos - 1] += acc[pos] / 10;
            acc[pos] %= 10;
        }

        StringBuilder product = new StringBuilder(acc.length);
        int start = acc[0] == 0 ? 1 : 0;
        for (int i = start; i < acc.length; i++) {
            product.append((char) ('0' + acc[i]));
        }
        return product.length() == 0 ? "0" : product.toString();
    }

    private static String normalize(String value, String name) {
        if (value == null || value.isEmpty()) {
            throw new IllegalArgumentException(name + " must be a non-empty decimal string");
        }
        for (int i = 0; i < value.length(); i++) {
            char ch = value.charAt(i);
            if (ch < '0' || ch > '9') {
                throw new IllegalArgumentException(name + " must contain decimal digits only");
            }
        }
        int firstNonZero = 0;
        while (firstNonZero < value.length() - 1 && value.charAt(firstNonZero) == '0') {
            firstNonZero++;
        }
        return value.substring(firstNonZero);
    }
}
```

官方题型参考 LeetCode 43 的两个典型样例：`"2" * "3" = "6"`，`"123" * "456" = "56088"`。仓库本地验证另外覆盖 `0`、前导零防御性输入、连续进位 `99999 * 99999 = 9999800001`、单边为 `1`、非法字符，并把 5000 组最长 80 位的随机非负整数与 `BigInteger` oracle 对比，全部一致。

## 关键细节

- **来源边界要先讲清**：原始面经正文只写“两数相乘”；“大数乘法”来自后续结构化归一化。把它映射为 LeetCode 43 风格是合理的复习契约，但不是原始面经逐字给出的完整题面。
- 两个十进制数分别有 `m`、`n` 位时，乘积位数至多 `m+n`，因此固定长度数组足够承载结果。
- 单个数字乘积最大是 `9*9=81`；实现用 `long[]` 累计同权重贡献，避免依赖小规模输入下 `int` 累加不会溢出的隐含前提。
- 先累计、后统一进位和逐次“乘一位 + 立即进位”在数学上等价；前者代码更容易证明下标映射。
- 官方 LeetCode 43 契约要求输入本身无前导零（除了 `0`）；这里的 `normalize` 支持前导零只是仓库防御性扩展，不能冒充官方输入要求。
- 如果面试官要求支持负数，应把符号从绝对值乘法中分离：结果符号由两个输入符号异或决定，绝对值部分仍复用本题算法。
- 如果问超大规模优化，学校式乘法仍是 `O(mn)`；Karatsuba/FFT 类算法属于更高阶扩展，面试时只有在规模约束明确需要时再展开。

## 原理机制

核心不变量是：在进位前，`acc[k]` 保存所有应该落在同一十进制权重上的“未归一化系数”。对任意 `i,j`，`a[i] * b[j]` 的权重由两个数字距末尾的位数之和决定，因此所有这一对贡献都可以准确落到 `i+j+1`。

随后从最低位向最高位扫描。对某个位置 `pos`，`acc[pos] % 10` 是这个十进制位最终保留的数字，`acc[pos] / 10` 是必须加到左侧更高一位的进位。因为扫描方向是从右到左，某个位置在被归一化时，所有更低位产生的进位都已经到达它；所以一次反向扫描就能把整个数组归一化成合法十进制数字。

## 项目经验版

这是算法题，不应包装成虚构项目经历。更可靠的口述是：先确认“是否允许 `BigInteger`、是否有符号、输入长度和前导零规则”，再推导位数组；编码后用一个结构不同的 oracle 做差分测试。测试里使用 `BigInteger` 是为了验证手写算法，不是用它替代实现本身。

## 常见追问

- 问：为什么数组长度是 `m+n`？答：两个 `m` 位和 `n` 位非负十进制整数的乘积严格小于 `10^(m+n)`，所以最多 `m+n` 位。
- 问：为什么 `num1[i] * num2[j]` 放到 `i+j+1`？答：这是把两个数字距末尾的位数相加后映射到统一的高位索引；再通过统一进位把系数归一化。
- 问：为什么不边乘边拼字符串？答：同一十进制位会收到多对数字的贡献，必须先合并并处理进位；直接拼接无法维护这个不变量。
- 问：测试里用了 `BigInteger` 会不会违反题意？答：不会。题意限制的是被提交的乘法实现；独立测试 oracle 使用可信现成实现，是为了发现手写算法错误。
- 问：如果有负数怎么办？答：先单独处理符号，对绝对值字符串复用相同乘法；零结果统一返回 `"0"`，避免 `"-0"`。

## 易错点

- 直接用 `long`/`BigInteger` 完成实现，绕过大数乘法核心。
- 下标错一位，把 `i+j`、`i+j+1` 的含义混淆，导致位权错误。
- 忘记从低位向高位传播进位，或者只传播一次局部乘积的进位却遗漏同权重累加。
- 结果为零时返回空串，或保留不必要的前导零。
- 把结构化后的“大数乘法”当成原始面经逐字题面，不记录来源歧义。
