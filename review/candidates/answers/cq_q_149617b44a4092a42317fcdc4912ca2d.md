# 三个有序数组的中位数：三指针扫描到中间位置，O(1) 辅助空间

## 核心结论

仓库原始面经 `note_desc/67de17c200000000001a005fa3.txt` 保留的题目是：**求三个有序数组的中位数，并要求空间复杂度 O(1)**。同一条原始记录还保留了面试者当时的解题方向：把它理解为“三路有序归并”，当已经取出的元素达到总长度一半时记录中间值即可。

因此不需要真正创建合并后的数组。用三个下标分别指向三个数组当前未消费的最小元素，每轮只比较这三个候选并推进其中一个下标，直到走到中间排名。总元素数为 `N` 时，最多扫描到第 `N/2` 个位置，时间复杂度最坏 `O(N)`，额外空间始终只有常数个下标和值，即 `O(1)`。

原始题目没有保留偶数总长度时的中位数约定、元素类型、单个数组是否允许为空、空输入行为等细节。下面的候选实现明确采用：`int[]` 输入；三个数组分别允许为空但总长度必须大于 0；偶数长度按两个中间值的算术平均数返回 `double`；不修改输入。这些是实现契约，不冒充原题逐字条件。

## 1 分钟版

我会做一个“三路归并但不落盘”。三个指针 `i/j/k` 分别指向三个有序数组的当前元素，每次从最多三个候选里取最小值，并只推进对应指针。

如果总长度是 `N`，中位数只依赖排序后下标 `(N-1)/2` 和 `N/2` 这两个位置，所以没有必要把全部元素合并出来。扫描到右中位位置就可以停止：奇数长度两个下标相同，直接返回这个值；偶数长度把两个中间值做平均。

整个过程中只保存三个指针、当前值和两个中间值，所以额外空间是 `O(1)`；最坏扫描线性数量的元素，时间复杂度 `O(N)`。

## 3 分钟版

这题的关键不是“怎么把三个数组合并”，而是意识到**只需要合并到中间位置**。

可以维护这样一个不变量：完成第 `r` 轮选择后，已经跳过的 `r+1` 个元素恰好是三个输入数组并集按非降序排列后的前 `r+1` 小元素；三个指针分别指向各自数组中尚未消费的第一个元素。因为每个输入数组内部已经有序，所以全局下一个最小元素一定就在这最多三个指针指向的元素中。每轮选其中最小者并推进对应指针，不变量继续成立。

总长度为 `N` 时，只需记录排名 `(N-1)/2` 和 `N/2` 的值。循环到 `N/2` 后，中位数所需信息已经完整，后面的元素无须读取。这正好对应原始面经里“相当于合并三个有序链表，已合并的数为总长度一半时记录一下即可”的思路，但实现不创建任何合并容器。

对于偶数总长度，候选实现采用常见统计定义：返回两个中间值的平均。为了避免 `int + int` 在极值处溢出，先提升到 `long` 再除以 `2.0`。三个数组都为空时没有中位数，候选实现直接抛出异常。

## 关键细节

- 原题明确约束的是“三个数组已有序”和“额外空间 O(1)”；并没有要求特定时间复杂度。
- 不要真正构造长度为 `N` 的合并数组，否则辅助空间会变成 `O(N)`，直接违反题目要求。
- 三路扫描只比较当前三个头部候选；某个数组耗尽后忽略该候选即可。
- 相等元素选哪一个数组先推进都不影响中位数，因为它们的值相同。
- 偶数长度需要同时保留左中位和右中位；只记录最后一次值会丢失左中位。
- 平均两个 `int` 中间值时先转成 `long`，否则 `Integer.MAX_VALUE + Integer.MAX_VALUE` 一类输入可能在求和阶段溢出。
- 候选实现不检查“输入是否真的有序”，因为有序性是原始题目的前置条件；若生产 API 需要防御性校验，可以额外线性检查，空间仍为 O(1)。
- 确定性测试使用“复制三数组后整体排序”的不同结构 oracle，只用于测试，不进入正式算法，因此不会污染 O(1) 解法本身。

## 原理机制

```java
import java.util.Objects;

public final class MedianOfThreeSortedArrays {
    public static double median(int[] first, int[] second, int[] third) {
        Objects.requireNonNull(first, "first");
        Objects.requireNonNull(second, "second");
        Objects.requireNonNull(third, "third");

        int total = first.length + second.length + third.length;
        if (total == 0) {
            throw new IllegalArgumentException("at least one value is required");
        }

        int leftTarget = (total - 1) / 2;
        int rightTarget = total / 2;
        int i = 0, j = 0, k = 0;
        int leftValue = 0, rightValue = 0;

        for (int rank = 0; rank <= rightTarget; rank++) {
            int source = -1;
            int value = 0;

            if (i < first.length) {
                source = 0;
                value = first[i];
            }
            if (j < second.length && (source < 0 || second[j] < value)) {
                source = 1;
                value = second[j];
            }
            if (k < third.length && (source < 0 || third[k] < value)) {
                source = 2;
                value = third[k];
            }

            if (source == 0) i++;
            else if (source == 1) j++;
            else k++;

            if (rank == leftTarget) leftValue = value;
            if (rank == rightTarget) rightValue = value;
        }

        return ((long) leftValue + rightValue) / 2.0;
    }
}
```

正确性来自三路归并不变量：每轮开始时，三个指针之前的元素已经全部属于全局最小前缀；每个数组剩余部分的最小值就是当前指针元素，所以全局下一个最小值必然是三个当前元素中的最小者。推进该来源后，全局已消费前缀长度增加 1 且仍保持正确排序排名。循环到 `rightTarget` 时，中位数所需的一个或两个排名值都已得到，因此无需继续扫描。

确定性验证覆盖 10 个固定用例和 5000 个随机用例。随机 oracle 将三个输入复制到测试数组、整体排序后计算常规定义中位数；候选实现逐例与 oracle 精确比较，同时验证输入数组未被修改。固定用例覆盖单元素、偶数总长度、单数组为空、负数、重复值和 `Integer.MIN_VALUE`/`Integer.MAX_VALUE` 的平均溢出边界。

## 项目经验版

这是算法题，源记录没有生产项目上下文，不应虚构线上经历。可迁移的工程思路是：当目标只依赖有序流的某个排名位置时，不必物化完整结果；通过流式消费和提前停止，可以同时减少内存和无用计算。

## 常见追问

- 问：为什么空间复杂度真的是 O(1)？答：正式算法只维护三个数组下标、当前候选和两个中间值；没有随输入规模增长的容器。测试里的合并数组只是 oracle，不属于正式实现。
- 问：为什么每轮只看三个当前位置就能确定全局下一个最小值？答：因为三个输入各自已有序，每个数组所有未消费元素都不小于当前指针元素，所以全局最小未消费值只能出现在三个当前元素中。
- 问：偶数个元素为什么要记录两个位置？答：候选契约把中位数定义为排序后两个中间值的平均，分别对应 `(N-1)/2` 和 `N/2`；只保存一个位置不足以计算结果。
- 问：能不能做到比 O(N) 更快？答：可能存在基于值域或分割思想的其他方案，但原始题只明确 O(1) 空间，而且面经保留的方向就是扫描式三路归并；这个候选不把更强时间复杂度要求伪造成源约束。
- 问：三个数组都为空怎么办？答：原题没有说明；候选 API 把“总长度必须大于 0”作为显式实现契约，空总输入直接抛出异常。

## 易错点

- 为了写起来简单直接合并成新数组，导致空间从 O(1) 退化为 O(N)。
- 偶数总长度只记右中位，忘记左中位。
- 某个数组耗尽后仍继续读它，造成越界。
- 用 `int` 直接相加两个中间值后再除 2，先发生整数溢出。
- 把“数组可以为空”“返回 double”“空输入抛异常”等候选 API 选择误写成原题原文。
- 为了追求更高级算法，反而偏离源材料明确保留的三路扫描方向和 O(1) 空间约束。
