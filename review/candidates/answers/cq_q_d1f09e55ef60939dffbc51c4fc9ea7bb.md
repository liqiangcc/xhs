# 原地删除字符串相邻重复项（LeetCode 1047）：栈与双指针的时空差异

## 核心结论

LeetCode 1047 的正式规则是：每次删除一对**相邻且相等**的字符，持续到不能再删，最终结果唯一；官方当前约束是 `1 <= s.length <= 10^5` 且只含小写英文字母。这个过程天然具有“栈顶消消乐”结构：扫描新字符时，只需要和当前保留序列的最后一个字符比较；相同就弹出，不同就压入。

如果输入本身是可写 `char[]`，可以把“栈”直接复用到原数组前缀：`read` 向右扫描，`write` 既表示当前结果长度，也表示栈顶后一位。这样核心算法仍是 O(n) 时间，但额外工作空间从显式栈的 O(n) 降到 O(1)。不过 Java 的 LeetCode 入口通常拿到的是不可变 `String`；`String` 不能原地改，所以 `String -> char[] -> String` 的包装层仍会产生 O(n) 级内存。面试里说“双指针 O(1) 空间”时，必须明确这是**在已有可写字符缓冲区上的算法辅助空间**，不是 Java `String` 版本的端到端总分配。

## 1 分钟版

- 不变量：`buffer[0..write)` 始终等于“已经扫描前缀完成全部相邻重复消除后的结果”。
- 读到字符 `c` 时，如果 `write > 0 && buffer[write - 1] == c`，说明它和当前结果末尾组成一对，执行 `write--`；否则写到 `buffer[write++]`。
- 每个输入字符只处理一次，所以栈方案和双指针方案都是 O(n) 时间。
- 显式栈要额外保存最多 n 个字符，因此辅助空间 O(n)。
- 双指针复用输入 `char[]` 前缀，不再单独建栈，因此核心辅助空间 O(1)。
- Java `String` 是不可变对象，若入口是 `String`，为了获得可写缓冲区调用 `toCharArray()` 本身就会分配新数组，最后返回 `String` 也需要结果对象；因此不要把“核心 O(1)”偷换成“整个 Java 方法 O(1) 总内存”。

## 3 分钟版

下面把两种方案放在一起。显式栈版本故意使用独立 `char[] stack`；双指针核心则直接覆盖传入的可写数组前缀：

```java
public final class AdjacentDuplicates {
    public static String removeWithStack(String s) {
        char[] stack = new char[s.length()];
        int top = 0;
        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (top > 0 && stack[top - 1] == c) {
                top--;
            } else {
                stack[top++] = c;
            }
        }
        return new String(stack, 0, top);
    }

    public static int removeInPlace(char[] buffer) {
        int write = 0;
        for (int read = 0; read < buffer.length; read++) {
            char c = buffer[read];
            if (write > 0 && buffer[write - 1] == c) {
                write--;
            } else {
                buffer[write++] = c;
            }
        }
        return write;
    }

    public static String removeWithTwoPointers(String s) {
        char[] buffer = s.toCharArray();
        int length = removeInPlace(buffer);
        return new String(buffer, 0, length);
    }
}
```

以 `abbaca` 为例：

1. `a` 入结果：`a`
2. `b` 入结果：`ab`
3. 第二个 `b` 与结果末尾相等，弹出：`a`
4. `a` 又与结果末尾相等，弹出：空
5. `c` 入结果：`c`
6. `a` 入结果：`ca`

最终得到 `ca`。这里关键不是“先找到所有原字符串中的重复对”，而是每次比较**当前归约结果的末尾**；这样前一次删除暴露出的新相邻关系也会自然继续消除。

## 关键细节

- **为什么 `write` 可以当栈顶**：前缀 `buffer[0..write)` 就是栈；压栈是 `buffer[write++] = c`，弹栈是 `write--`。不需要真的创建 `Stack`/`Deque`。
- **为什么删除后会级联**：例如 `abba`，扫描第二个 `b` 后 `bb` 被弹掉，接着最后一个 `a` 会和此前保留的首字符 `a` 比较，再次弹掉，得到空串。
- **结果唯一**：LeetCode 1047 明确说明持续执行合法的相邻重复删除后最终答案唯一，因此单次从左到右的栈归约可以直接产出最终结果，不需要枚举删除顺序。
- **时间复杂度**：两个实现都只线性扫描输入；每个字符最多入一次、出一次，O(n)。没有在中间反复拼接 `String`，避免潜在的 O(n²) 复制。
- **空间复杂度要分层说**：显式栈核心需要 O(n) 辅助空间；对已经可写的 `char[]`，双指针核心只用几个整数和一个临时字符，是 O(1) 辅助空间。若入口是 Java `String`，转换到 `char[]` 和构造返回 `String` 都是线性级存储，因此端到端分配仍是 O(n)。
- **“原地”不能直接作用于 Java String**：Java SE 21 `String` 文档明确说明字符串值创建后不能改变；真正的原地覆盖只能发生在可变缓冲区上。
- **字符边界**：LeetCode 1047 当前题面只允许小写英文字母，所以按 Java `char` 比较没有补充 Unicode grapheme 语义的必要；不要把这个受限题解直接宣称成任意自然语言文本的“字符”消除器。
- **空输入**：官方约束最小长度为 1，因此正式题解无需为 `null` 或空串发明业务语义；测试可以额外验证空数组核心函数的鲁棒性，但不能把它说成题面要求。

## 原理机制

把“删除相邻重复项”看成一个流式归约：已经处理的前缀只需要保留最终未被抵消的后缀状态，而下一字符是否触发变化只取决于这个状态的最后一个字符。于是完整历史不需要回看，状态可以用后进先出的栈表达。

显式栈把状态放在独立存储中；双指针只是观察到“已读区域后面不会再需要原值”，所以把同一栈状态搬回输入数组前缀。`read` 负责消费原输入，`write` 负责维护归约后的有效长度。由于 `write <= read + 1`，每次写入的位置都不会破坏尚未读取的字符。

这也是两种方案时间复杂度相同但辅助空间不同的根本原因：**算法状态相同，存储位置不同**。显式栈另开 O(n) 容器；双指针复用输入缓冲区，因此不再为状态额外付出线性空间。

## 项目经验版

来源没有真实项目背景，不能虚构线上指标。如果真实系统需要做类似流式相邻抵消，我会先确认输入是否允许原地修改、字符语义是 UTF-16 code unit 还是 Unicode code point/grapheme、数据是否分块到达，以及是否需要跨 chunk 保留尾部状态。只有这些边界明确后，才能判断复用输入缓冲区是否安全；验证时会同时覆盖级联删除、最大长度、跨边界重复和内存分配情况，而不是只跑题面样例。

## 常见追问

- 问：为什么不能每找到一对就 `substring` 拼回去？答：删除会级联，反复构造新字符串会重复复制；最坏情况下可能退化到 O(n²)，而栈/双指针单次扫描即可 O(n) 完成。
- 问：双指针为什么还能处理 `abba` 这种删除后才相邻的情况？答：`write` 指向的是当前归约结果末尾；`bb` 弹出后，最后一个 `a` 比较的是此前保留的首个 `a`，所以级联关系自然出现。
- 问：栈和双指针谁更好？答：输入不可修改或更强调表达清晰时，显式栈直观；已有可写数组且需要压低辅助空间时，双指针更合适。两者核心时间都是 O(n)。
- 问：为什么 Java 版本不能简单说 O(1) 空间？答：`String` 不可变；若先 `toCharArray()` 再原地覆盖，这个数组就是 O(n) 分配。O(1) 只适用于“已有可写 `char[]`”的核心算法辅助空间口径。
- 问：能不能直接用 `StringBuilder` 当栈？答：可以，尾部追加和缩短长度能表达 push/pop，但其可变缓冲区最坏仍保存 O(n) 个字符，所以辅助空间仍是 O(n)。
- 问：如果题目改成一次删除 k 个连续相同字符呢？答：需要把栈状态扩展为“字符 + 当前连续计数”；这是 LeetCode 1209 一类变体，不能直接把 1047 的二元抵消条件照搬。

## 易错点

- 把题目理解成“只删除原字符串一开始就相邻的重复对”，漏掉删除后的级联。
- 用字符串中间删除/拼接实现，逻辑能过小样例但复杂度退化。
- 说双指针“总空间 O(1)”却忽略 Java `String` 不可变以及 `toCharArray()`/返回结果的线性分配。
- 双指针弹栈时写成 `write -= 2`；当前新字符还没有写入，正确操作只是把已保留的栈顶弹掉，即 `write--`。
- 忘记 `write > 0` 就访问 `buffer[write - 1]`。
- 把 LeetCode 的小写英文字母约束扩张为对任意 Unicode 用户感知字符都正确。
