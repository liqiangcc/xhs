# 算法：链表怎么定位中间元素（快慢指针）

## 核心结论

对一个有限、无环的单链表，用两个指针同时从头结点出发：`slow` 每次走 1 步，`fast` 每次走 2 步。当 `fast` 走到链表尾部时，`slow` 正好走了约一半距离，因此停在中间位置。本答案明确采用一个常见但并非原题明示的契约：偶数长度链表返回两个中间节点中的后一个；空链表返回 `nullptr`。

## 1 分钟版

- 初始化 `slow = head`、`fast = head`。
- 循环条件是 `fast != nullptr && fast->next != nullptr`。
- 每轮 `slow = slow->next`，`fast = fast->next->next`。
- `fast` 每走两步，`slow` 只走一步，所以 `fast` 到尾部时 `slow` 到达中点。
- 长度为奇数时返回唯一中点；长度为偶数时，这个写法返回后一个中点。
- 时间复杂度 `O(n)`，额外空间 `O(1)`，且不修改链表。

## 3 分钟版

```cpp
struct ListNode {
    int val;
    ListNode* next;
};

ListNode* middleNode(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
    }
    return slow;
}
```

设链表长度为 `n`。每完成一轮，`slow` 前进 1 个节点，`fast` 前进 2 个节点，因此两者走过的边数始终保持约 `1:2`。当循环退出时，`fast` 已经无法再完整前进两步，`slow` 恰好位于下标 `floor(n/2)` 的节点（从 0 开始计数）。所以奇数长度 `n=2k+1` 时返回下标 `k` 的唯一中点；偶数长度 `n=2k` 时返回下标 `k`，也就是后一个中点。

## 关键细节

- **偶数长度语义必须说清楚**：原题只说“中间元素”，没有说明两个中点选哪个。本实现返回后一个中点；若要求前一个中点，需要调整退出条件。
- **空链表**：`head == nullptr` 时两个指针都为空，循环不执行，直接返回 `nullptr`。
- **单节点**：`fast->next == nullptr`，循环不执行，返回头结点本身。
- **不修改结构**：算法只移动局部指针，不写任何 `next`，所以原链表拓扑保持不变。
- **有环链表不在本契约内**：如果存在环，`fast` 不会因为到达尾部而停止；应先定义是否需要判环，而不能把“找线性中点”和“环检测”混成一个未声明的任务。
- **复杂度**：`fast` 最多跨过 `n` 条边，整体是 `O(n)` 时间、`O(1)` 额外空间。

## 原理机制

快慢指针利用的是“速度比”而不是额外计数器。若 `fast` 的速度是 `slow` 的两倍，那么在同一段线性路径上，`fast` 走完整段时，`slow` 走了一半。这个不变量让我们不需要先扫描一次得到长度，再扫描第二次走到 `n/2`；一次遍历就能完成定位。

对偶数长度，退出时 `fast == nullptr`；对奇数长度，退出时 `fast` 指向最后一个节点。两种情况下 `slow` 都处于 `floor(n/2)` 下标，因此行为可以直接由边界样例验证，而不是靠口述记忆。

## 常见追问

- 问：为什么快指针走两步、慢指针走一步就能找到中点？答：两者从同一起点出发，移动距离保持约 `2:1`；快指针覆盖完整链表时，慢指针覆盖一半。
- 问：偶数长度返回哪个中点？答：当前循环条件返回后一个中点。比如 `1->2->3->4` 返回节点 `3`。这是本答案明确选择的契约，不是原题额外给出的条件。
- 问：如何返回前一个中点？答：可以让 `fast` 在还剩至少两条边时才继续，例如根据接口形式改成检查 `fast->next` 与 `fast->next->next`，并单独处理短链表边界。
- 问：为什么不用先求长度再走一半？答：两遍扫描同样是 `O(n)`，但快慢指针一遍即可完成，额外空间仍为 `O(1)`。
- 问：如果链表有环会怎样？答：本算法的终止条件依赖尾部 `nullptr`；有环时不保证终止，所以必须先确认输入契约或先做环检测。

## 易错点

- 没说明偶数长度有两个中点，却把某一种返回结果说成唯一正确答案。
- 写成 `while (fast->next && fast->next->next)` 却没有处理 `fast == nullptr` 或短链表边界。
- 快指针移动两步前没有确认 `fast->next` 存在，导致空指针访问。
- 为了找中点去修改 `next`，引入完全不必要的结构副作用。
- 忽略有环输入会破坏“快指针最终到达 `nullptr`”这一终止前提。
