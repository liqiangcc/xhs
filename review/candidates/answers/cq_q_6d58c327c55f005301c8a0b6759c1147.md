# 根据先序和中序遍历序列得到后序序列

## 核心结论

先序的第一个元素一定是当前子树根；在中序中找到根后，根左边就是左子树、右边就是右子树，由此还能得到左右子树节点数。于是可以不用真的构造树：按“左子树 → 右子树 → 根”的顺序递归，把后序结果直接写入输出数组。

但仓库原题只保留“根据先序和中序遍历序列，给出后序序列”，**没有说明节点值是否唯一、输入是否合法、数据规模和函数签名**。下面给出的 O(n) 实现明确采用“节点值唯一，且两条序列来自同一棵合法二叉树”的常见合同；如果节点值允许重复，仅靠值序列通常不能唯一确定后序结果，必须有节点 identity/额外约束或接受多解。

## 1 分钟版

- 先序 `preorder[preL]` 是当前子树根。
- 用哈希表保存 `value -> inorderIndex`，O(1) 期望时间定位根在中序中的位置。
- `leftSize = rootIndex - inL`，所以左子树对应先序 `[preL+1, preL+leftSize]`，右子树紧随其后。
- 不必建树；递归先处理左区间，再处理右区间，最后把根写入后序数组。
- 每个节点只处理一次，建索引 O(n)，递归 O(n)，总时间 O(n)，索引 O(n)，递归栈最坏 O(n)。
- 若节点值重复，先序+中序按“值”可能有歧义。例如 `pre=[1,1,2]`、`in=[1,1,2]` 可以对应不同后序，因此当前实现 fail-fast 拒绝重复值。

## 3 分钟版

```java
import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

public final class Solution {
    public static int[] toPostorder(int[] preorder, int[] inorder) {
        if (preorder == null || inorder == null || preorder.length != inorder.length) {
            throw new IllegalArgumentException("length mismatch");
        }
        int n = preorder.length;
        Map<Integer, Integer> inIndex = new HashMap<>();
        for (int i = 0; i < n; i++) {
            if (inIndex.put(inorder[i], i) != null) {
                throw new IllegalArgumentException("duplicate node value");
            }
        }
        Set<Integer> seenPre = new HashSet<>();
        for (int value : preorder) {
            if (!seenPre.add(value) || !inIndex.containsKey(value)) {
                throw new IllegalArgumentException("invalid traversal set");
            }
        }

        int[] postorder = new int[n];
        int[] write = {0};
        emit(preorder, 0, 0, n, inIndex, postorder, write);
        return postorder;
    }

    private static void emit(int[] pre, int preL, int inL, int len,
                             Map<Integer, Integer> inIndex,
                             int[] post, int[] write) {
        if (len == 0) return;
        int root = pre[preL];
        Integer rootIndex = inIndex.get(root);
        if (rootIndex == null || rootIndex < inL || rootIndex >= inL + len) {
            throw new IllegalArgumentException("inconsistent traversals");
        }
        int leftSize = rootIndex - inL;
        int rightSize = len - 1 - leftSize;
        emit(pre, preL + 1, inL, leftSize, inIndex, post, write);
        emit(pre, preL + 1 + leftSize, rootIndex + 1, rightSize, inIndex, post, write);
        post[write[0]++] = root;
    }
}
```

例如先序 `[1,2,4,5,3]`、中序 `[4,2,5,1,3]`：根是 `1`，中序左边 `[4,2,5]` 有 3 个节点，所以先序接下来的 `[2,4,5]` 是左子树，剩下 `[3]` 是右子树。递归后得到后序 `[4,5,2,3,1]`。

## 关键细节

- **为什么能切分先序**：先序顺序是“根、完整左子树、完整右子树”。中序定位根后得到 `leftSize`，这个节点数正好决定先序中左子树占多长区间。
- **为什么不需要构树**：题目只要求后序序列。递归区间已经隐式表达子树结构，直接在回溯阶段写根即可，省掉 TreeNode 分配。
- **唯一值合同**：用 `value -> inorderIndex` 的单值映射天然要求值唯一。来源没有说这一点，所以必须把它写成实现假设，而不是冒充原题约束。
- **重复值为什么危险**：相同值在中序里可能对应多个位置；选择不同位置会产生不同子树切分。没有节点 identity 时，遍历序列本身未必唯一确定结构甚至后序结果。
- **输入合法性**：仅检查“值集合相同”还不够；递归时若根索引落在当前中序区间之外，说明两条序列的结构约束彼此矛盾，应 fail-fast。
- **复杂度**：哈希索引使每个根只定位一次，总时间 O(n)。额外空间 O(n) 来自索引和输出；递归调用栈平衡树 O(log n)，退化树 O(n)。如果 n 可能非常大，需要考虑显式栈以避免调用栈溢出。

## 原理机制

两种遍历提供了互补信息：先序告诉我们“谁是根以及子树出现的先后顺序”，中序告诉我们“根左右各有哪些节点”。唯一节点值使这两类信息能在每一层递归中无歧义对齐。递归不变量是：`pre[preL .. preL+len)` 与 `in[inL .. inL+len)` 描述同一棵子树；处理结束后，输出恰好追加这棵子树的后序序列。

对当前子树，先序首元素给出根；中序根位置把节点集合分成左右两部分；`leftSize` 再把先序剩余区间按同样大小切成左右子树。左右递归都完成后追加根，正好满足后序“左、右、根”。

## 常见追问

- 问：为什么不是 O(n²)？答：如果每层都线性扫描中序找根，退化树会 O(n²)；提前建 `value -> inorderIndex` 后每个节点只做 O(1) 期望定位，总计 O(n)。
- 问：必须先重建二叉树吗？答：不必须。只要最终目标是后序序列，递归区间就足够表达结构，左右子问题完成后直接写根即可。
- 问：如果值重复怎么办？答：原题没有说明。仅按值的先序+中序可能多解；要么题目额外保证唯一值，要么提供节点 identity/出现次序等可消歧信息，否则不能承诺唯一后序。
- 问：空树怎么处理？答：两条空序列返回空后序；长度不一致、集合不一致或结构矛盾则视为非法输入。
- 问：递归会不会栈溢出？答：最坏退化树递归深度 n。若规模合同允许非常深的树，应改成显式栈或其它迭代方案；来源没有数据规模，不能假定一定安全。

## 易错点

- 每次递归都 `indexOf`/线性扫描中序，导致最坏 O(n²)。
- 切先序右子树时忘记加上 `leftSize`，区间错位。
- 为了求后序先完整构树，增加不必要的对象分配和代码面。
- 来源没说节点唯一，却直接把“值唯一”写成原题事实。
- 只检查两条序列长度相同，不检查重复、集合或递归区间一致性。
- 只跑一个平衡树样例，没有覆盖空树、单节点、纯左/纯右退化树和非法输入。
