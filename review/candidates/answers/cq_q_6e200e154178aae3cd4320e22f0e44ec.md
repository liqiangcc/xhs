# 二维数组：所有 0 到最近 1 的曼哈顿距离中的最大值

## 核心结论

原题只保留了“二维数组求所有 0 距离最近的 1 的曼哈顿距离的最大值”，没有保存题号、矩阵尺寸、是否保证只有 `0/1`、是否一定同时存在 0 和 1，也没有规定退化输入返回什么。因此不能悄悄套成某一道 LeetCode 的完整契约。

在“非空矩形二值矩阵”这个明确答案侧契约下，核心算法是 **多源 BFS**：把所有值为 `1` 的位置同时作为距离 0 的起点入队，BFS 一层层向四邻域扩散。某个 `0` 第一次被访问时，得到的就是它到所有 `1` 中最短的曼哈顿距离；所有 `0` 的这些最短距离里的最大值，就是答案。时间复杂度 `O(mn)`，额外空间 `O(mn)`。

## 1 分钟版

- 先扫描矩阵，把所有 `1` 同时入队，视为 BFS 第 0 层。
- 从这些源点一起向上、下、左、右扩散，未访问的 `0` 第一次入队时距离就是当前层数。
- 为什么第一次就是最近距离？因为无权网格 BFS 按路径长度非递减顺序扩展，而所有 `1` 同时作为源，相当于求“到源集合的最短路”。
- 每访问一个 `0` 就更新最大距离，队列结束后得到所有可达 `0` 的最近-1距离最大值。
- 来源没有定义退化边界；本文 helper 约定：没有 `0` 返回 `0`，存在 `0` 但没有 `1` 返回 `-1`，并明确这不是原题事实。

## 3 分钟版

设矩阵有 `m` 行、`n` 列。若对每个 `0` 都单独从它 BFS 找最近 `1`，最坏会重复搜索整个矩阵，代价可到 `O((mn)^2)`。更自然的反向思路是：**从所有 1 同时出发**。

初始化时，所有 `1` 的距离都是 0 并进入队列。之后每弹出一个格子，就检查四个相邻格子；只把尚未访问的 `0` 标记并入队。队列按层推进，所以第 1 层是离某个 `1` 曼哈顿距离 1 的格子，第 2 层是最近距离 2 的格子，以此类推。

这里真正的证明点不是“用了 BFS”，而是“所有源同时入队”。单源 BFS 只能求到一个指定 `1` 的距离；多源 BFS 等价于增加一个虚拟超级源，并用 0 代价边连接到所有 `1`，因此第一次到达某个 `0` 时的层数就是 `min_{one} ManhattanDistance(zero, one)`。

为了把来源缺失的边界与算法本体分开，下面可执行 helper 采用：矩阵必须非空、矩形且元素只能是 `0/1`；没有 `0` 返回 `0`；有 `0` 但没有 `1` 返回 `-1`。如果面试官给出别的约定，只改边界返回，不改变多源 BFS 主体。

## 关键细节

- **距离定义**：四邻域每移动一步，曼哈顿距离加 1；不走对角线。
- **多源初始化**：所有 `1` 必须在 BFS 开始前一起入队，不能逐个源完整跑完再覆盖距离。
- **首次访问**：对每个 `0` 只入队一次；首次到达就是最短距离，后续无需松弛。
- **答案含义**：不是求任意 `0-1` 对的最大距离，而是先对每个 `0` 求“最近的 1”，再对这些最近距离取最大值。
- **复杂度**：每个格子最多入队一次，四条方向各检查常数次，所以时间 `O(mn)`；`visited + queue` 最坏 `O(mn)`。
- **可原地优化**：如果允许修改输入，可利用矩阵本身标记访问状态来省掉单独 `visited`，但队列本身仍可能是 `O(mn)`。
- **来源边界**：题干没有题号，也没写 all-zero/all-one 的返回值；答案必须把这些作为显式约定，而不能声称来自原题。

## 原理机制

```java
import java.util.ArrayDeque;

public final class NearestOneMaxDistance {
    private NearestOneMaxDistance() {}

    public static int maxNearestOneDistance(int[][] grid) {
        validate(grid);
        int m = grid.length;
        int n = grid[0].length;
        ArrayDeque<int[]> queue = new ArrayDeque<>();
        boolean[][] seen = new boolean[m][n];
        int zeroCount = 0;

        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (grid[r][c] == 1) {
                    queue.addLast(new int[]{r, c, 0});
                    seen[r][c] = true;
                } else {
                    zeroCount++;
                }
            }
        }
        if (zeroCount == 0) return 0;
        if (queue.isEmpty()) return -1;

        int answer = 0;
        int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
        while (!queue.isEmpty()) {
            int[] cur = queue.removeFirst();
            for (int[] d : dirs) {
                int nr = cur[0] + d[0];
                int nc = cur[1] + d[1];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n || seen[nr][nc]) continue;
                seen[nr][nc] = true;
                int distance = cur[2] + 1;
                answer = Math.max(answer, distance);
                queue.addLast(new int[]{nr, nc, distance});
            }
        }
        return answer;
    }

    private static void validate(int[][] grid) {
        if (grid == null || grid.length == 0 || grid[0] == null || grid[0].length == 0) {
            throw new IllegalArgumentException("grid must be a non-empty rectangle");
        }
        int n = grid[0].length;
        for (int[] row : grid) {
            if (row == null || row.length != n) throw new IllegalArgumentException("grid must be rectangular");
            for (int value : row) {
                if (value != 0 && value != 1) throw new IllegalArgumentException("grid must be binary");
            }
        }
    }
}
```

验证不再写另一份 BFS，而是用朴素 oracle：枚举每个 `0`，扫描所有 `1` 直接计算 `|r1-r2| + |c1-c2|`，对该 `0` 取最小，再对全部 `0` 取最大。它虽然慢，但状态机完全不同，非常适合对小矩阵做穷举/随机对照。

## 项目经验版

来源没有真实项目或生产指标，因此不虚构项目经历。多源 BFS 的可迁移点是“离一组源中最近源的无权最短距离”：例如多个入口、多个故障点、多个资源点同时向外扩散。落地时仍要先确认网格是否真是无权、是否允许四方向、障碍物规则以及退化输入语义。

## 常见追问

- 问：为什么从所有 `1` 出发比每个 `0` 单独 BFS 好？答：多源 BFS 只遍历整个图一次，`O(mn)`；逐个 `0` 搜索会大量重复遍历。
- 问：为什么第一次访问某个 `0` 就是最近距离？答：所有 `1` 同层作为距离 0 起点，BFS 按距离递增扩展，第一次到达即是到源集合的最短路径。
- 问：能用动态规划两遍扫描吗？答：可以在规则四邻域网格上通过正反向扫描传播距离，但多源 BFS 更直接地表达“到任意 1 的无权最短路”，边界也更容易解释。
- 问：全是 1 怎么办？答：来源没规定。本文 helper 约定没有待评价的 `0` 时返回 `0`；如果业务把空集合定义成其他值，应按契约调整。
- 问：全是 0 怎么办？答：没有“最近的 1”，数学对象未定义。本文 helper 返回 `-1` 作为显式 sentinel，不把它冒充成来源规则。
- 问：为什么不是求最远的 1？答：题意有两层聚合：每个 `0` 先取最近的 `1`，最后才在所有 `0` 的最近距离里取最大。

## 易错点

- 把“最大最近距离”误写成任意 `0` 与任意 `1` 的最大距离。
- 只把一个 `1` 入队，算成单源最短路。
- 同一个 `0` 多次入队，既浪费复杂度又让距离语义变乱。
- 允许对角线移动，却仍声称计算的是四邻域曼哈顿距离。
- 没说明全 0、全 1、空矩阵或非矩形输入语义，却把某个返回值说成原题要求。
- 看起来像某个经典题就擅自补题号、约束或样例；当前仓库来源没有保存这些信息。
