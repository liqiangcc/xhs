# 实现子串匹配：KMP 与暴力搜索

## 核心结论

来源允许 KMP 或暴力搜索。这里先明确可执行契约：输入是两个非 `null` 的 Java `String`，返回 pattern 在 text 中**第一次出现**的 UTF-16 `char` 下标；找不到返回 -1；空 pattern 返回 0。暴力法从每个可能起点重新比较，最坏 O(nm)；KMP 预处理 pattern 的最长相等真前后缀数组 `lps`，失配时复用已经匹配的信息，让 text 指针不回退，时间 O(n+m)、额外空间 O(m)。

## 1 分钟版

- `lps[i]` 表示 `pattern[0..i]` 的“最长真前缀 = 后缀”的长度。
- 匹配时 `i` 指向 text、`j` 指向 pattern；字符相等就同时前进。
- 失配且 `j > 0` 时，不把 `i` 退回起点，而令 `j = lps[j-1]`，尝试复用已经匹配后缀对应的前缀。
- 只有 `j == 0` 仍失配时才推进 `i`。
- 当 `j == pattern.length()`，首次匹配起点就是 `i - j`；因为 text 的 `i` 单调向前，所以这是第一次出现位置。

## 3 分钟版

```java
public final class KmpSearch {
    public static int indexOf(String text, String pattern) {
        if (text == null || pattern == null) {
            throw new IllegalArgumentException("text and pattern must be non-null");
        }
        if (pattern.isEmpty()) return 0;

        int[] lps = buildLps(pattern);
        int i = 0;
        int j = 0;
        while (i < text.length()) {
            if (text.charAt(i) == pattern.charAt(j)) {
                i++;
                j++;
                if (j == pattern.length()) return i - j;
            } else if (j > 0) {
                j = lps[j - 1];
            } else {
                i++;
            }
        }
        return -1;
    }

    private static int[] buildLps(String pattern) {
        int[] lps = new int[pattern.length()];
        for (int i = 1, len = 0; i < pattern.length();) {
            if (pattern.charAt(i) == pattern.charAt(len)) {
                lps[i++] = ++len;
            } else if (len > 0) {
                len = lps[len - 1];
            } else {
                lps[i++] = 0;
            }
        }
        return lps;
    }
}
```

例如 `text = "abababca"`、`pattern = "ababca"`。前面已经匹配到较长前缀后发生失配，KMP 不需要把 text 指针重新拉回候选起点；`lps` 告诉我们当前已匹配串的某个后缀本身又是 pattern 的前缀，于是只回退 pattern 指针继续比较。

## 关键细节

- **`lps` 不是“相同字符个数”**：它要求前缀与后缀连续且内容完全相等，并且是真前缀，不能等于整个当前串。
- **为什么是线性**：构造 `lps` 时 `i` 只向前，`len` 回退沿已计算的 lps 链；匹配时 text 的 `i` 从不回退。整体回退次数被前进次数摊销，因此 O(n+m)。
- **空 pattern**：当前答案明确返回 0，与“空串在开头匹配”的常见 `indexOf` 契约一致；这是答案侧 API 约定，不冒充来源额外要求。
- **字符语义**：Java `String.charAt` 按 UTF-16 code unit 比较，所以返回的是 `char` 下标。若题目要求 Unicode code point 或 grapheme cluster，需要改契约与实现。
- **暴力法**：对每个起点 `s`，从 `j=0` 开始比较 `text[s+j]` 与 `pattern[j]`；代码更短、短输入可能足够，但重复前缀场景会反复比较。
- **首次匹配**：本实现一旦 `j == m` 就立即返回，因此不是“返回全部出现位置”的接口。

## 原理机制

假设已经匹配了 pattern 的前 `j` 个字符，却在下一个字符失配。已匹配内容的某个后缀如果同时也是 pattern 的前缀，那么这个后缀不需要和 text 再比较一次；令 `j = lps[j-1]` 就把 pattern 移到仍可能成立的最长位置。若这个位置仍失配，再沿 lps 链继续缩短。KMP 的核心就是把“已知相等关系”编码进 lps，避免 text 回溯。

## 项目经验版

来源没有真实项目、文本规模或延迟指标，不能虚构线上收益。实际选择时先看输入规模、pattern 复用次数和语言库能力：一次很短的查找直接用标准库通常最清晰；如果面试要求手写或需要解释最坏复杂度，再实现 KMP。若同一个 pattern 要匹配大量文本，可以复用已构建的 lps；若需求变成多 pattern 搜索，则应重新评估 Aho-Corasick 等不同问题模型。

## 常见追问

- 问：为什么失配时用 `lps[j-1]`，不是 `lps[j]`？答：当前失败发生在 pattern[j]，真正已经匹配成功的是 `[0,j)`，所以要查询最后一个已匹配字符 `j-1` 对应的最长可复用前后缀。
- 问：KMP 会不会漏掉重叠匹配？答：当前接口只返回第一次匹配，不讨论后续；如果要找全部匹配，命中后可把 `j` 回退到 `lps[j-1]` 继续扫描，从而保留重叠可能。
- 问：暴力法一定很差吗？答：不是。它实现简单、常数小；区别在最坏复杂度保证，重复前缀会让暴力法重复比较，而 KMP 保证 O(n+m)。
- 问：`lps` 怎么自己检查？答：逐位置写出 `pattern[0..i]` 的所有真前缀与后缀，取最长相等长度，再和代码结果对照；像 `aaaa` 会得到 `[0,1,2,3]`。
- 问：为什么返回 UTF-16 下标？答：这是本 Java API 使用 `charAt` 的明确边界；来源没有规定 code point 语义，不能暗中把两种索引混为一谈。

## 易错点

- 构造 `lps` 失配时直接把 `len` 清零，漏掉更短的可复用前后缀。
- 匹配失配且 `j>0` 时同时推进 `i`，从而跳过合法匹配。
- 忘记处理空 pattern，随后访问 `pattern.charAt(0)` 越界。
- 把 Java `char` 下标描述成 Unicode code point 下标。
- 只背 O(n+m)，却解释不出 text 指针为什么不回退以及 lps 回退如何摊销。
