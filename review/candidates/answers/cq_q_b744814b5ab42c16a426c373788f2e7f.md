# 简化 shared_ptr：引用计数、拷贝/移动与最后一次释放

## 核心结论

来源只要求“写一个简化的智能指针（shared_ptr）类的核心逻辑”，没有要求完整复刻 `std::shared_ptr`。因此本答案把范围明确限定为：单对象 `T*` 的共享所有权、强引用计数、拷贝/移动构造与赋值、`reset/get/use_count/operator*/operator->`，最后一个拥有者销毁时释放对象和控制块。它**不实现** `weak_ptr`、线程安全原子计数、自定义 deleter、数组、aliasing constructor、`enable_shared_from_this` 或 `make_shared` 的单次分配优化。

核心不变量只有一个：所有共享同一对象的 `SimpleSharedPtr` 都指向同一个控制块；控制块中的 `strong_count` 等于当前拥有该对象的智能指针数量。拷贝时计数加一，移动时只转移控制块指针而不改计数，析构/reset/覆盖赋值时计数减一；只有从 `1 -> 0` 的那次释放负责 `delete` 对象并销毁控制块。

## 1 分钟版

- 裸指针本身不够，还需要一个**共享控制块**保存对象指针和强引用计数。
- 构造第一个拥有者时计数为 1；拷贝构造/拷贝赋值共享同一控制块并 `++count`。
- 移动构造/移动赋值只是“偷走”控制块指针，把源对象置空，因此引用计数不变。
- 析构或 `reset` 时执行 `release()`：先 `--count`，只有减到 0 才删除对象和控制块。
- 拷贝赋值要处理自赋值；`reset(newPtr)` 可以用临时对象 + `swap`，先建立新所有权再安全释放旧所有权。
- 这个简化版计数不是原子的，所以不同线程并发修改同一控制块不安全；真正的 `std::shared_ptr` 还要处理弱引用控制块生命周期等问题。

## 3 分钟版

```cpp
#include <cstddef>
#include <stdexcept>
#include <utility>

template <class T>
class SimpleSharedPtr {
private:
    struct ControlBlock {
        T* ptr;
        std::size_t strong_count;
        explicit ControlBlock(T* p) : ptr(p), strong_count(1) {}
    };

    ControlBlock* ctrl_ = nullptr;

    void retain() noexcept {
        if (ctrl_ != nullptr) {
            ++ctrl_->strong_count;
        }
    }

    void release() noexcept {
        if (ctrl_ == nullptr) return;
        ControlBlock* old = ctrl_;
        ctrl_ = nullptr;
        if (--old->strong_count == 0) {
            delete old->ptr;
            delete old;
        }
    }

public:
    SimpleSharedPtr() noexcept = default;

    explicit SimpleSharedPtr(T* ptr) {
        if (ptr == nullptr) return;
        try {
            ctrl_ = new ControlBlock(ptr);
        } catch (...) {
            delete ptr;
            throw;
        }
    }

    SimpleSharedPtr(const SimpleSharedPtr& other) noexcept
        : ctrl_(other.ctrl_) {
        retain();
    }

    SimpleSharedPtr(SimpleSharedPtr&& other) noexcept
        : ctrl_(other.ctrl_) {
        other.ctrl_ = nullptr;
    }

    SimpleSharedPtr& operator=(const SimpleSharedPtr& other) noexcept {
        if (this == &other) return *this;
        SimpleSharedPtr temp(other);
        swap(temp);
        return *this;
    }

    SimpleSharedPtr& operator=(SimpleSharedPtr&& other) noexcept {
        if (this == &other) return *this;
        release();
        ctrl_ = other.ctrl_;
        other.ctrl_ = nullptr;
        return *this;
    }

    ~SimpleSharedPtr() {
        release();
    }

    void reset(T* ptr = nullptr) {
        SimpleSharedPtr temp(ptr);
        swap(temp);
    }

    void swap(SimpleSharedPtr& other) noexcept {
        std::swap(ctrl_, other.ctrl_);
    }

    T* get() const noexcept {
        return ctrl_ == nullptr ? nullptr : ctrl_->ptr;
    }

    std::size_t use_count() const noexcept {
        return ctrl_ == nullptr ? 0 : ctrl_->strong_count;
    }

    explicit operator bool() const noexcept {
        return get() != nullptr;
    }

    T& operator*() const {
        if (get() == nullptr) throw std::logic_error("dereference of null SimpleSharedPtr");
        return *get();
    }

    T* operator->() const noexcept {
        return get();
    }
};
```

例如 `a` 首次接管 `new T` 后控制块计数是 1；`b=a` 后 `a` 和 `b` 指向同一控制块，计数变成 2；`c=std::move(b)` 只是把 `b.ctrl_` 转给 `c`，所以计数仍是 2，而 `b.use_count()==0`。当 `a` 先析构时计数变成 1，对象不能删除；直到 `c` 最后析构，计数从 1 变成 0，才执行一次 `delete T` 和一次 `delete ControlBlock`。

## 关键细节

- **控制块必须共享**：如果每个智能指针各有一个独立计数，即使它们保存同一个裸指针，也会各自认为自己是最后一个拥有者，最终 double free。
- **移动不增加引用数**：移动改变“哪个 wrapper 持有这个 ownership token”，没有增加拥有者总数。
- **拷贝赋值用 copy-and-swap**：先构造 `temp(other)` 增加新控制块计数，再交换；临时对象析构时释放旧控制块。这样自赋值易处理，也避免先释放旧对象后再获取新引用造成别名问题。
- **`reset(ptr)` 同样用临时对象**：新控制块创建失败时构造函数会删除传入裸指针并抛异常，当前智能指针仍保持原状态；创建成功后再交换。
- **空指针没有控制块**：本简化版让空对象 `use_count()==0`，避免无意义控制块分配。
- **并发边界**：这里的 `strong_count` 是普通 `size_t`。多个线程同时拷贝/销毁共享同一控制块会数据竞争；完整 `std::shared_ptr` 的控制块引用计数需要线程安全实现。
- **循环引用**：只有强引用计数无法解决 `A -> B -> A` 的环；这正是 `weak_ptr` 存在的重要原因，但本题的“简化核心逻辑”没有扩展到弱引用。
- **不是完整标准库语义**：标准 `shared_ptr` 还涉及 deleter、allocator、aliasing、数组和 `make_shared` 等，本实现故意不冒充完整替代品。

## 原理机制

引用计数把“对象何时可以销毁”转化为一个所有权计数问题。只要 `strong_count > 0`，就至少还有一个 wrapper 承诺拥有对象，对象必须存活；当一次释放使计数从 1 降到 0 时，可以证明已经没有强拥有者，因此该次释放获得唯一的销毁责任。

控制块和对象是两个不同生命周期：在这个没有弱引用的简化版本里，两者可以同时在强计数归零时销毁；真正 `shared_ptr + weak_ptr` 中，即使对象已经在强计数归零时销毁，控制块仍要继续保存弱计数等元数据，直到最后一个 `weak_ptr` 也消失。因此完整实现通常至少要区分 strong/weak count。

## 项目经验版

来源没有提供真实项目经历，不能虚构“自己实现 shared_ptr 用于生产”。工程代码应优先使用标准库 `std::shared_ptr`/`std::make_shared`，而不是维护自制引用计数。手写版本的价值主要是验证所有权模型：控制块为什么共享、Rule of Five 如何维持计数、为什么移动不增计数、为什么最后一次释放必须唯一，以及 `weak_ptr` 为什么需要独立控制块生命周期。

## 常见追问

- 问：为什么计数不能直接存在 `SimpleSharedPtr` 对象里？答：每个 wrapper 都有自己的字段，拷贝后无法天然共享同一个计数；必须让所有副本共同引用一个控制块。
- 问：拷贝赋值为什么不是先 `release()` 再指向 `other`？答：如果两个 wrapper 已经共享控制块或存在别名关系，顺序更容易出错；copy-and-swap 先安全取得新 ownership，再让临时对象统一释放旧 ownership。
- 问：移动构造为什么不 `++count`？答：移动后源 wrapper 被置空，总拥有者数量没有变化，只是 ownership token 换了位置。
- 问：为什么会有循环引用泄漏？答：两个对象互相持有强 `shared_ptr` 时，即使外部引用都消失，双方强计数仍非零，永远无法触发最后一次释放；需要把环上的某些边改成 `weak_ptr`。
- 问：真正的 shared_ptr 为什么线程安全更复杂？答：不同 wrapper 可以跨线程共享同一控制块，所以引用计数更新需要同步；但“被管理对象本身”的业务读写并不会因此自动线程安全。
- 问：`make_shared` 有什么额外价值？答：常见实现可以把控制块和对象放在一次分配中，减少分配次数并改善局部性；这超出当前简化版的核心范围。

## 易错点

- 每个副本各自维护计数，最终发生重复释放。
- 拷贝时忘记加计数，或移动时错误加计数，导致生命周期提前结束或永远不结束。
- `release()` 删除对象后仍保留悬空 `ctrl_`，后续再次析构产生 use-after-free。
- 忽略自赋值和别名场景，赋值时先把唯一引用释放掉。
- 用普通整数计数却宣称和标准 `shared_ptr` 一样支持并发引用管理。
- 把这个教学版说成完整 `std::shared_ptr`，忽略 weak count、deleter、allocator、aliasing 和 `make_shared` 等关键语义。
