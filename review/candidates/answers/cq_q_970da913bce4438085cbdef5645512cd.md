# 矩阵中的最长递增路径

## 核心结论

来源只给出“矩阵中的最长递增路径”，没有补充移动方向、空矩阵、是否允许相等、矩阵是否规则等细节。这里采用经典的四方向严格递增契约：只能向上、下、左、右移动，下一格必须严格大于当前格；路径长度按经过的格子数计算。Java 实现使用 **DFS + 记忆化搜索**：`memo[r][c]` 表示“从 `(r,c)` 出发能得到的最长递增路径长度”，每个格子的状态只真正计算一次，因此时间复杂度 `O(mn)`，额外记忆化空间 `O(mn)`，递归栈最坏可到 `O(mn)`。

本答案把 `null`、0 行或 0 列定义为返回 `0`，要求输入为规则矩阵；锯齿数组直接抛 `IllegalArgumentException`。这些是为了让实现可执行而补充的契约，不是来源原文已经规定的条件。

## 1 分钟版

- 把每个格子当成一个状态，`memo[r][c]` 记录“从这里出发的最长严格递增路径”。
- 从 `(r,c)` 只尝试四个相邻且值更大的格子 `(nr,nc)`，状态转移是 `1 + dfs(nr,nc)`；没有更大邻居时答案就是 `1`。
- 严格递增意味着沿路径数值一直变大，所以不可能回到之前的格子形成环，不需要额外的 `visited` 防环集合。
- 记忆化让同一个格子只展开一次；最终枚举所有起点并取最大值。
- 总时间 `O(mn)`；`memo` 是 `O(mn)`，递归深度最坏也可能达到 `mn`，若担心栈深可以改成按入度分层的拓扑 BFS。

## 3 分钟版

```java
static int longestIncreasingPath(int[][] matrix) {
    if (matrix == null || matrix.length == 0) return 0;
    int cols = matrix[0].length;
    if (cols == 0) return 0;
    for (int[] row : matrix) {
        if (row == null || row.length != cols) {
            throw new IllegalArgumentException("matrix must be rectangular");
        }
    }

    int rows = matrix.length;
    int[][] memo = new int[rows][cols];
    int best = 0;
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            best = Math.max(best, dfs(matrix, r, c, memo));
        }
    }
    return best;
}

private static int dfs(int[][] matrix, int r, int c, int[][] memo) {
    if (memo[r][c] != 0) return memo[r][c];

    int best = 1;
    int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
    for (int[] d : dirs) {
        int nr = r + d[0], nc = c + d[1];
        if (nr < 0 || nr >= matrix.length || nc < 0 || nc >= matrix[0].length) {
            continue;
        }
        if (matrix[nr][nc] <= matrix[r][c]) {
            continue;
        }
        best = Math.max(best, 1 + dfs(matrix, nr, nc, memo));
    }

    memo[r][c] = best;
    return best;
}
```

例如：

```text
9 9 4
6 6 8
2 1 1
```

一条最长路径是 `1 -> 2 -> 6 -> 9`，长度为 `4`。这里真正重要的是状态定义：`dfs(r,c)` 只回答“从当前格子往更大的邻居走，最长能走多远”，所以它不依赖“之前从哪里来”。一旦这个状态被算出，就可以被所有进入该格子的前驱复用。

## 关键细节

- **严格递增消除环**：如果每一步都要求 `next > current`，沿任意合法路径值严格上升，不可能绕一圈回到原格子。因此状态图天然是 DAG；这也是记忆化 DFS 不需要路径级 `visited` 的原因。
- **为什么不能只做普通 DFS**：不同起点会大量重复搜索相同后缀。记忆化把每个 `(r,c)` 的后缀答案缓存下来，后续直接返回。
- **状态含义必须统一**：这里 `memo[r][c]` 是“包含当前格子的最长路径长度”，所以初值从 `1` 开始，转移才是 `1 + child`。
- **相等值不能走**：契约是严格递增，因此比较条件是 `>`；如果题目改成非递减，状态图可能出现相等值之间的环，当前“不需要 visited”的推理就失效。
- **方向边界**：这里仅允许四方向，不允许对角线。若题目允许八方向，只需要扩展邻接方向，状态定义和记忆化框架不变。
- **负数没有特殊性**：算法只依赖相对大小，不依赖值非负，也不做加法累积，所以负数和极端 `int` 值不会引入算术溢出问题。
- **复杂度**：每个格子真正展开一次，每次检查最多 4 个邻居，时间 `O(mn)`；`memo` 占 `O(mn)`；递归调用栈最坏可达 `O(mn)`。
- **规则矩阵**：Java 的 `int[][]` 可以是锯齿数组。本实现显式拒绝锯齿输入，避免用 `matrix[0].length` 访问其他行时产生隐含错误。

## 原理机制

可以把矩阵转换成一个有向图：每个格子是节点，如果相邻格子的值更大，就从当前节点连一条边到更大的节点。因为每条边都让数值严格增加，这个图不可能有有向环。

于是问题变成 DAG 上的最长路径。记忆化 DFS 是“按需做动态规划”：第一次进入节点时递归计算所有后继，并把最长结果写入 `memo`；之后任何前驱再次需要这个节点的结果时直接复用。另一种等价思路是显式计算每个节点在“从小到大”图中的入度，从所有局部最小点开始做分层拓扑 BFS；每剥掉一层，就代表路径长度增加 1。

## 项目经验版

来源没有真实项目背景，不能虚构“线上用过该算法”。如果在真实图像、地形或网格计算任务中遇到类似问题，我会先确认邻接规则、是否允许相等、矩阵规模和栈深限制，再选择记忆化 DFS 或迭代拓扑方案；若矩阵可能非常大，迭代方案通常更容易控制调用栈风险。这些是落地时的检查项，不是本题来源事实。

## 常见追问

- 问：为什么不用 `visited` 防止重复访问？答：记忆化负责消除跨起点的重复计算；而严格递增保证状态图无环，所以不需要路径级 `visited` 来防环。
- 问：为什么时间复杂度不是指数级？答：虽然代码写成递归 DFS，但每个格子的完整递归只执行一次，之后命中 `memo`；每个格子最多检查 4 条边，所以总工作量是 `O(mn)`。
- 问：如果允许走相等元素怎么办？答：当前无环证明不再成立；需要重新定义状态或处理相等值形成的强连通关系，不能只把 `>` 改成 `>=` 就沿用同一证明。
- 问：递归栈会不会溢出？答：最坏情况下可以有一条覆盖所有格子的递增链，深度达到 `mn`；对大矩阵可改为拓扑 BFS，保留 `O(mn)` 时间而避免深递归。
- 问：如果允许八方向移动呢？答：把方向数组从 4 个扩展到 8 个即可；只要仍然严格递增，DAG 与记忆化结论不变。
- 问：能不能从大值往小值搜？答：可以，只要重新定义状态并保持转移方向一致；例如定义“以当前格子结尾的最长路径”，就可以从更小邻居转移过来。

## 易错点

- 把“严格递增”写成 `>=`，改变题意并可能破坏无环性。
- `memo` 的含义一会儿是“从这里出发”，一会儿又当成“到这里结束”，导致转移方向混乱。
- 每个起点都做无缓存 DFS，样例能过但会产生大量重复搜索。
- 用全局 `visited` 永久标记格子，错误地阻止不同起点共享合法后缀路径。
- 忽略空矩阵或 Java 锯齿数组，让边界行为由异常偶然决定。
- 只写 `O(mn)` 却漏掉最坏 `O(mn)` 的递归栈风险。
