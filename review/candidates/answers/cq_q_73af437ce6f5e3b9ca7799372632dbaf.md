# 二维区域和检索：不可变矩阵用二维前缀和

## 核心结论

来源对应 LeetCode 304“二维区域和检索 - 矩阵不可变”。矩阵不会更新、但会反复查询子矩形和时，最直接的方案是构造二维前缀和：预处理 `O(rows * cols)`，之后每次查询只用四个前缀值做容斥，时间 `O(1)`。

本答案定义一个明确接口：输入必须是非空、非 `null`、规则矩形；坐标为 0-based 且查询区间两端都包含；构造后不读取原矩阵，因此外部后来修改传入数组也不会影响查询结果。内部前缀和用 `long`，避免把一般整数矩阵的累计和无条件压在 `int` 范围里。

## 1 分钟版

- 定义 `prefix[r+1][c+1]` 为原矩阵左上角 `(0,0)` 到 `(r,c)` 的总和。
- 递推：`prefix[r+1][c+1] = matrix[r][c] + prefix[r][c+1] + prefix[r+1][c] - prefix[r][c]`。
- 查询 `(row1,col1)` 到 `(row2,col2)`：取大矩形，减掉上方、左方，再把重复减掉的左上角加回来。
- 公式：`P[row2+1][col2+1] - P[row1][col2+1] - P[row2+1][col1] + P[row1][col1]`。
- 不可变是关键：没有更新操作，所以可以一次预处理，把后续每个查询降到常数时间。
- 构造 `O(RC)` 时间、`O(RC)` 空间；每次查询 `O(1)`。

## 3 分钟版

```java
import java.util.Objects;

public final class NumMatrix {
    private final long[][] prefix;
    private final int rows;
    private final int cols;

    public NumMatrix(int[][] matrix) {
        Objects.requireNonNull(matrix, "matrix");
        if (matrix.length == 0 || matrix[0] == null || matrix[0].length == 0) {
            throw new IllegalArgumentException("matrix must be non-empty");
        }
        rows = matrix.length;
        cols = matrix[0].length;
        prefix = new long[rows + 1][cols + 1];

        for (int r = 0; r < rows; r++) {
            if (matrix[r] == null || matrix[r].length != cols) {
                throw new IllegalArgumentException("matrix must be rectangular");
            }
            for (int c = 0; c < cols; c++) {
                prefix[r + 1][c + 1] = matrix[r][c]
                        + prefix[r][c + 1]
                        + prefix[r + 1][c]
                        - prefix[r][c];
            }
        }
    }

    public long sumRegion(int row1, int col1, int row2, int col2) {
        if (row1 < 0 || col1 < 0 || row2 < row1 || col2 < col1
                || row2 >= rows || col2 >= cols) {
            throw new IndexOutOfBoundsException("invalid region");
        }
        return prefix[row2 + 1][col2 + 1]
                - prefix[row1][col2 + 1]
                - prefix[row2 + 1][col1]
                + prefix[row1][col1];
    }
}
```

多开一行一列是为了把“查询从第 0 行/列开始”的边界统一进同一个公式，不需要写 `if (row1 == 0)` 之类分支。

## 关键细节

- **容斥方向**：大矩形减上方、减左方后，左上角公共部分被减了两次，因此必须加回来一次。
- **前缀下标整体 +1**：`prefix[0][*]` 和 `prefix[*][0]` 都是 0，边界计算天然成立。
- **不可变契约**：前缀数组在构造时冻结矩阵数值；后续如果原 `int[][]` 被调用方改动，本对象查询结果仍保持构造时快照。
- **为什么不是逐查询遍历**：若有很多查询，逐次扫描区域最坏 `O(RC)`；二维前缀把重复工作前置一次。
- **为什么用 `long`**：来源没有给数值范围；多个 `int` 相加可能超过 `int`。使用 `long` 是答案侧安全选择，不冒充原题约束。
- **矩阵必须规则**：Java 二维数组可以是 jagged array，本接口显式拒绝行长度不同，避免前缀定义不完整。
- **若矩阵允许更新**：前缀和不再适合频繁更新；可考虑二维 Fenwick Tree/Segment Tree 等，但这是与“矩阵不可变”不同的问题。

## 原理机制

记 `P(r,c)` 为从原点到 `(r-1,c-1)` 的矩形和。任意目标区域可以看成一个右下大前缀矩形，减去目标上方的前缀矩形和左侧前缀矩形。两块被减区域在左上角有交集，这个交集被减了两次，所以再加一次。二维前缀和本质就是把每个查询拆成四个已经预计算的累积量。

正确性也可以从构造不变量看：完成 `prefix[r+1][c+1]` 后，它恰好覆盖原矩阵 `[0..r] x [0..c]`。递推式用上方和左方两个前缀覆盖目标大矩形，再减去它们重复覆盖的左上部分，最后加入当前单元格。

## 项目经验版

来源只有算法题，没有真实项目背景，因此不虚构线上使用经历。如果工程里是静态热力图、离线统计表等“写一次、读很多次”的矩形聚合，二维前缀是典型思路；若数据持续更新，则要重新评估更新/查询比例和数据规模，而不能机械套用不可变矩阵方案。

## 常见追问

- 问：为什么查询是 O(1)？答：目标矩形只依赖四个已经预计算的前缀值，查询阶段不再遍历区域元素。
- 问：为什么多一行一列？答：人为增加全 0 边界，让所有原矩阵坐标都统一使用 `+1` 后的公式，消除首行首列特判。
- 问：空间能降吗？答：如果必须支持任意二维区域的 O(1) 查询，通常需要保留二维累积信息；只保留逐行前缀可把查询降到 `O(height)`，是在空间/查询时间之间换取折中。
- 问：如果矩阵会修改怎么办？答：当前来源明确“不可变”。有更新时二维前缀一次改动可能影响大量后缀单元，通常改用支持增量更新的数据结构。
- 问：为什么返回 long？答：来源没有保留元素与矩阵大小约束，答案侧用 `long` 防止普通 `int` 累加溢出；若目标平台固定要求 `int`，再按平台约束适配签名。
- 问：外部修改传入数组会怎样？答：本实现只在构造期读取原数组并保存 prefix，不持有原数组作为查询来源，因此结果保持构造时数据。

## 易错点

- 容斥最后忘记把左上角交集加回来。
- `row2/col2` 是包含端点，却漏掉 `+1`。
- 只算行前缀却声称任意二维区域都 O(1)。
- 矩阵可更新时仍用静态 prefix，却不更新受影响区域。
- 用 `int` 存累计和且没有证明不会溢出。
- Java jagged array 未校验，导致某行访问越界。
