# 单次向前扫描翻转链表区间：只改指针，不额外复制节点

## 核心结论

仓库原始面经 `note_desc/67dcc3ec000000001c007e3a.txt` 保留下来的算法题是：**遍历一次，翻转从 m 到 n 的链表结点**。原始记录没有保存下标从 0 还是从 1 开始、非法区间如何处理、空链表行为，以及是否允许修改原链表等 API 细节。

下面的候选实现把这些缺失部分明确收窄为实现契约：链表非空；`m`、`n` 使用 **1-based 且两端都包含**；调用方保证 `1 <= m <= n <= 链表长度`；允许原地修改 `next` 指针。它们是候选 API 选择，不冒充原题逐字条件。

在这个契约下，可以先从头走到第 `m-1` 个结点，再把区间内后续结点逐个“头插”到区间最前面。每个用于定位或翻转的指针都只沿链表向前取得下一结点，不需要第二次从头扫描，也不需要数组、栈或新链表。时间复杂度 `O(n)`（若以链表总长 `L` 计则为 `O(L)` 上界），额外空间 `O(1)`。

## 1 分钟版

我会加一个 dummy 结点，先找到区间前驱 `before`，让 `current` 指向原来的第 `m` 个结点。

之后重复 `n-m` 次：取出 `current.next` 这个待移动结点，把它从当前位置摘下，再插到 `before.next` 前面。`current` 不动，因为它始终是尚未处理区间的尾部；每次被取出的结点都会被放到已翻转区间的最前面。

例如 `1->2->3->4->5`，翻转 `[2,4]`：先得到 `before=1,current=2`；把 3 插到 2 前得到 `1->3->2->4->5`；再把 4 插到最前得到 `1->4->3->2->5`。只改常数个指针，所以空间是 `O(1)`。

## 3 分钟版

关键是不把“翻转区间”写成先截取、复制、再拼回去，而是在原链表上维护一个稳定不变量。

进入翻转循环前：

- `before.next` 指向当前已翻转区间的第一个结点；
- `current` 指向原区间第一个结点，并且它会逐渐变成已翻转区间的最后一个结点；
- `current.next` 是下一次需要搬到区间前端的结点。

每轮做三步：

1. `moving = current.next`，记住要搬的结点；
2. `current.next = moving.next`，把它从原位置摘下来；
3. `moving.next = before.next; before.next = moving`，把它插到翻转区间头部。

执行一次后，已翻转前缀长度增加 1，而 `current` 仍是该前缀的尾结点，所以同一个不变量可以继续使用。重复 `n-m` 次后，原来的 `[m,n]` 恰好完全逆序，区间前后链路也保持连通。

`dummy` 的作用是统一 `m=1` 的情况：即使翻转从头结点开始，也始终存在一个 `before`，不需要为“头结点改变”单独写分支。

## 关键细节

- 原始材料明确的是“从 m 到 n 的链表结点”和“遍历一次”；1-based、闭区间、非空、合法范围与原地修改都是候选实现契约。
- `dummy` 只占一个固定结点，和输入规模无关，因此额外空间仍是 `O(1)`。
- 真正移动的是 `current.next`；`current` 在循环内不前进，这是头插法能连续工作的关键。
- `m == n` 时无需移动任何结点，直接返回原链表结构。
- `m == 1` 时 dummy 让算法和普通区间完全一致。
- 候选实现没有把 `n > 链表长度` 定义成稳定 API 行为，因为原题没有保留这部分约束；正式生产 API 若需要，可以在不改变核心算法的情况下增加显式校验。
- 不需要创建值数组再反写，也不需要用栈保存区间结点；这两种做法都会引入 `O(n-m)` 额外空间。

## 原理机制

```java
import java.util.Objects;

public final class ReverseBetween {
    public static final class ListNode {
        public final int value;
        public ListNode next;

        public ListNode(int value) {
            this(value, null);
        }

        public ListNode(int value, ListNode next) {
            this.value = value;
            this.next = next;
        }
    }

    private ReverseBetween() {}

    /**
     * Candidate contract: non-null head and valid inclusive 1-based range [m, n].
     */
    public static ListNode reverseBetween(ListNode head, int m, int n) {
        Objects.requireNonNull(head, "head");
        if (m < 1 || n < m) {
            throw new IllegalArgumentException("expected 1 <= m <= n");
        }

        ListNode dummy = new ListNode(0, head);
        ListNode before = dummy;
        for (int position = 1; position < m; position++) {
            before = before.next;
        }

        ListNode current = before.next;
        for (int moved = 0; moved < n - m; moved++) {
            ListNode moving = current.next;
            current.next = moving.next;
            moving.next = before.next;
            before.next = moving;
        }
        return dummy.next;
    }
}
```

正确性可以按循环不变量说明。假设已经完成 `k` 次头插，那么 `[m, m+k]` 对应的原始结点已经按逆序排列在 `before` 后面，且 `current` 是这段逆序链的尾结点；区间之后未处理的第一个结点仍是 `current.next`。下一轮把 `current.next` 摘出并插到 `before` 后，只会让已逆序部分增加一个正确的前置结点，同时保持前驱、逆序区间和剩余后缀三部分连通。因此从 `k=0` 到 `k=n-m` 归纳成立，最终整个 `[m,n]` 被逆序。

仓库中的确定性测试使用数组区间反转作为结构不同的 oracle：覆盖 7 个固定区间，并执行 5000 组固定随机种子的链表/合法区间组合；同时检查结果长度正确、无额外尾结点或环。测试还覆盖候选 API 对 `null` 和 `m < 1` 的 fail-fast 行为。该测试用于验证实现，不把这些候选 API 选择反写成原题条件。

## 项目经验版

这是算法题，源记录没有生产项目背景，不应虚构线上案例。可迁移的工程原则是：当目标是局部结构变换时，优先寻找能维持局部不变量的原地操作；这样既能把额外空间控制在常数级，也更容易证明“区间外结构不被破坏”。

## 常见追问

- 问：为什么 dummy 很重要？答：它让 `m=1` 时也有统一的区间前驱，避免单独处理新头结点。
- 问：为什么 `current` 不往前走？答：每轮都把 `current.next` 搬到区间头部，所以 `current` 会自然成为已翻转区间的尾结点；保持它不动才能持续拿到下一个待搬结点。
- 问：这算“一次遍历”吗？答：候选实现从头向前定位到区间，再继续通过当前指针取得区间内后继，不会完成一次全链扫描后再从头扫描第二遍；总指针处理量是线性的。
- 问：空间复杂度为什么是 O(1)？答：除一个 dummy 外，只维护 `before/current/moving` 等固定数量引用，没有随区间长度增长的容器。
- 问：非法的 `n` 超过链表长度怎么办？答：原题没有保存这个契约；当前候选只承诺调用方提供合法区间。若作为生产 API，应补充显式长度/边界策略并单独测试。

## 易错点

- 把 `current` 也跟着 `moving` 前进，导致后续结点无法继续头插。
- 摘下 `moving` 前没有先保存 `moving.next`，造成链表断裂。
- 忘记 dummy，结果 `m=1` 时需要额外分支甚至返回错误头结点。
- 先把区间结点放入数组/栈再逆序，违反常数额外空间目标。
- 把 1-based、闭区间、非法输入行为等候选实现约定误写成原始题目明确条件。
