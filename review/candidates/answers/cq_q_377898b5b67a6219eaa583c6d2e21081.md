# 正整数 n 变成 1 的最少操作次数

## 核心结论

原题只给出三条转换规则：正整数 `n` 为偶数时只能除以 2；为奇数时可以加 1 或减 1；目标是到 1 的最少操作次数。题源没有保存语言和整数范围。这里明确选择 **Java `int` 作为输入契约**，内部转成 `long`，避免 `Integer.MAX_VALUE + 1` 溢出。偶数没有选择，直接除 2；奇数 `n > 1` 时，除 `n == 3` 外，优先把低两位变成更多连续 0：`n % 4 == 1` 时减 1，`n % 4 == 3` 时加 1。`3` 单独减 1，因为 `3 → 2 → 1` 比 `3 → 4 → 2 → 1` 少一步。

## 1 分钟版

- 偶数路径是强制的：`n /= 2`。
- 奇数有 `+1/-1` 两条路。对大于 3 的奇数，看最低两位：`...01` 减 1 后能产生至少两个尾 0；`...11` 加 1 后能产生至少两个尾 0，因此后续可以连续右移。
- 唯一要单独处理的是 `3`：虽然二进制是 `11`，但直接减到 2 只要两步到 1。
- 输入选 `int`，计算变量用 `long`，否则 `Integer.MAX_VALUE` 做 `+1` 会溢出。
- 每一到两次操作都会明显缩短二进制有效长度，所以时间复杂度是 `O(log n)`，额外空间 `O(1)`。

## 3 分钟版

可以先写出精确递推来理解“最少”是什么意思：

```text
f(1) = 0
n 为偶数: f(n) = 1 + f(n / 2)
n 为奇数: f(n) = 1 + min(f(n - 1), f(n + 1))
```

直接递归搜索当然能求最优，但没必要真的展开两棵子树。对于奇数 `n > 1`，`n-1` 和 `n+1` 都是偶数，下一步都至少会除一次 2。除 `3` 外，其中恰好有一边能让结果继续带更多尾 0：若 `n & 3 == 1`，选择 `n-1`；若 `n & 3 == 3`，选择 `n+1`。这相当于优先制造可以连续除 2 的低位结构。

```java
public final class IntegerToOne {
    private IntegerToOne() {}

    public static int minOperations(int n) {
        if (n <= 0) {
            throw new IllegalArgumentException("n must be positive");
        }

        long x = n;
        int steps = 0;
        while (x != 1L) {
            if ((x & 1L) == 0L) {
                x >>= 1;
            } else if (x == 3L || (x & 3L) == 1L) {
                x--;
            } else {
                x++;
            }
            steps++;
        }
        return steps;
    }
}
```

例如 `7` 是二进制 `111`。如果减 1 得到 `110`，只能先变成 `11`，又回到奇数分支；加 1 得到 `1000`，随后连续三次除 2，因此 `7 → 8 → 4 → 2 → 1` 共 4 步。`3` 则必须走例外：`3 → 2 → 1` 共 2 步。

## 关键细节

- **题源边界**：题源只规定正整数和三种转换；Java、`int` 参数、异常行为都是候选实现选择，不冒充原题条件。
- **为什么内部用 `long`**：当 `n == Integer.MAX_VALUE` 时，最优路径会先执行 `+1`。若仍用 `int`，会溢出成负数；转成 `long` 后 `2147483648` 可安全表示。
- **`3` 的例外**：普通 `...11 → +1` 规则在 `3` 上不是最优；减 1 两步结束，加 1 需要三步。
- **位判断**：奇数只可能满足 `(x & 3) == 1` 或 `3`。前者减 1，后者通常加 1，目的是让下一阶段获得更多连续除 2 的机会。
- **停止条件**：到 `1` 立即结束，不能继续把奇数 1 做 `+1/-1`。
- **复杂度**：循环次数与二进制位数同阶；对 `int` 正数是 `O(log n)` 时间、`O(1)` 额外空间。
- **可验证性**：候选夹具用精确递推 oracle 对 `1..200000` 全量比对，再对 50000 个固定种子的正 `int` 随机值比对，并覆盖 `Integer.MAX_VALUE`，避免只靠几个示例证明贪心。

## 原理机制

偶数没有分支，最优解一定先除以 2。真正的决策只发生在奇数。奇数做 `+1` 或 `-1` 后都变成偶数，所以比较两条路时可以关注它们制造了多少个低位 0：低位 0 越多，就能在后续用强制的 `/2` 快速消掉更多二进制位。对大于 3 的奇数，低两位为 `01` 时减 1 会得到末尾至少 `00`；低两位为 `11` 时加 1 会通过进位得到末尾至少 `00`。`3` 是最小的 `11` 例外，因为减 1 已经直接进入 `2 → 1`。实现仍用一个精确递推 oracle 做大范围差分验证，防止把位模式直觉误当成未经验证的正确性。

## 项目经验版

这是纯算法题，仓库来源没有真实生产项目经历，因此不虚构“线上使用过”。工程实现里最值得保留的习惯是先写清数值域：输入若是 `int`，中间状态可能暂时超过 `int` 上界；如果 API 改成 `long`，又要重新定义 `Long.MAX_VALUE + 1` 的处理方式，不能机械复用当前实现。算法正确性和整数表示边界要一起测试。

## 常见追问

- 问：为什么 `7` 要加 1？答：`7+1=8` 可以连续除 2 到 1；`7-1=6` 只除一次就回到奇数 3，因此前者总步数更短。
- 问：为什么 `3` 不按 `n % 4 == 3` 加 1？答：`3→2→1` 是 2 步，而 `3→4→2→1` 是 3 步，所以它必须单独处理。
- 问：可以用 BFS 或动态规划吗？答：可以把状态图做最短路或按递推记忆化求精确答案，但状态规模和存储都更大；这里利用二进制结构把选择压成常数空间贪心。
- 问：为什么不用 `int x = n`？答：`Integer.MAX_VALUE` 是奇数且会走 `+1`，`int` 会溢出。用 `long` 保存中间状态可以覆盖整个正 `int` 输入域。
- 问：如果参数本身是 `long` 呢？答：当前实现契约不是 `long` 输入；若改成 `long`，必须处理 `Long.MAX_VALUE` 无法安全 `+1` 的表示问题，例如改用无溢出的等价递推或更宽整数类型。

## 易错点

- 奇数一律减 1，导致 `7、15、31` 等 `...11` 情况多走很多步。
- 奇数一律按 `%4` 规则处理，却忘记 `3` 是特殊例外。
- 用 `int` 保存中间状态，在 `Integer.MAX_VALUE + 1` 时溢出。
- 把题源未给出的 Java 类型和异常契约写成“原题要求”。
- 只举 `7`、`15` 两个例子就宣称贪心正确，没有用精确递推或大范围测试做交叉验证。
