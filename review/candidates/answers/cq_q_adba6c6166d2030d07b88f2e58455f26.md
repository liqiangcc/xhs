# 给一个整型数字，按三位分组并插入逗号

## 核心结论

这道题的稳定规则只有一个：十进制整数部分要从右往左每三位分一组，组之间插入逗号。来源没有保存具体语言、整数位宽、负数是否出现、是否允许调用格式化库，因此参考实现明确选择 Java `long`，保留负号，只处理整数十进制表示，不引入小数、货币符号或本地化规则。实现时先得到十进制字符串，再只对数字部分按“右侧剩余位数是 3 的倍数”插入逗号；这样不需要 `Math.abs`，也能正确覆盖 `Long.MIN_VALUE`。

## 1 分钟版

- 分组方向一定是从右往左，因为最低三位组成最后一组。
- 负号不是数字位，先单独保留，再对后面的十进制数字分组。
- 遍历数字字符串时，如果当前字符不是第一位，而且“从当前位置到末尾的字符数”是 3 的倍数，就在它前面加逗号。
- `0`、1~3 位数不加逗号；4 位开始出现第一个逗号。
- 用字符串处理可以直接覆盖 `Long.MIN_VALUE`，避免先取绝对值时溢出。

## 3 分钟版

来源只说“整型数字按三位划分并加逗号”，没有规定 API。下面把参考契约定成 `format(long value)`：输入任意 Java `long`，输出普通十进制字符串；负数保留 `-`，每三位数字之间插入 `,`。

```java
public final class Solution {
    private Solution() {}

    public static String format(long value) {
        String s = Long.toString(value);
        int start = s.charAt(0) == '-' ? 1 : 0;
        StringBuilder out = new StringBuilder(s.length() + s.length() / 3);

        if (start == 1) {
            out.append('-');
        }
        for (int i = start; i < s.length(); i++) {
            if (i > start && (s.length() - i) % 3 == 0) {
                out.append(',');
            }
            out.append(s.charAt(i));
        }
        return out.toString();
    }
}
```

例如 `1234567` 的数字长度是 7。遍历到第二个数字时，右侧连同当前位还剩 6 位，是 3 的倍数，所以先插入逗号；再往后三位，同样在剩余 3 位的位置插入逗号，得到 `1,234,567`。负数只是把数字起点从下标 0 调整到 1，分组逻辑本身不变。

## 关键细节

- **来源边界**：原题没有说明语言、位宽、负数、前导零、本地化或小数。本答案的 Java `long`、负号保留都是显式参考契约，不冒充原题条件。
- **为什么不 `Math.abs`**：`Long.MIN_VALUE` 的绝对值无法用正的 `long` 表示；直接处理 `Long.toString(value)` 没有这个溢出问题。
- **三位边界**：`999` 不变，`1000 -> 1,000`，`1000000 -> 1,000,000`。
- **负数**：`-1234567 -> -1,234,567`；负号不参与“三位”计数。
- **0**：`0 -> 0`，不会产生空分组或多余逗号。
- **复杂度**：设十进制数字位数为 d，遍历一次，时间 O(d)，输出本身也需要 O(d) 空间。
- **本地化**：有些地区不是使用逗号作为千位分隔符；题目已经明确“加逗号”，所以这里不引入 Locale/NumberFormat 的其他规则。

## 原理机制

“每三位一个逗号”本质上是按最低位对齐的分块。若从左向右看，第一个分组可能只有 1~3 位，后续每组固定 3 位；所以判断一个位置前是否加逗号，可以转化成检查它右侧剩余的数字数量。除第一数字外，只要当前位置到末尾的数字数是 3 的倍数，它就是一个新三位组的起点。

这种写法不需要反转字符串，也不需要先计算绝对值。它只依赖最终十进制字符序列，因此对正数、负数和边界整数使用同一套不变量。

## 常见追问

- 问：为什么从右边分组？答：十进制最低三位天然构成最后一组，千位、百万位等边界都由距离末尾的位数决定。
- 问：负数怎么办？答：负号单独复制，不参与数字位计数，后续数字按同样规则分组。
- 问：为什么不用 `Math.abs` 再处理？答：`Long.MIN_VALUE` 取绝对值仍然溢出；直接处理 `Long.toString` 更稳健。
- 问：能不能用 `NumberFormat`？答：如果题目允许当然可以，但它会带入 Locale 等额外语义；手写题更重要的是明确分组不变量和边界。
- 问：时间复杂度是多少？答：每个十进制字符最多处理一次，是 O(d)；结果字符串也占 O(d) 空间。
- 问：前导零怎么办？答：本参考 API 接收数值 `long`，数值本身没有前导零语义；如果输入改成数字字符串，需要另外定义是否保留前导零。

## 易错点

- 从左边固定每三位切一次，导致 `1234` 被错误分成 `123,4`。
- 把负号计入三位长度，负数的逗号位置整体偏移。
- 对 `Long.MIN_VALUE` 先取绝对值，引入溢出。
- 在 3 位数前也加逗号，产生 `,999`。
- 题目只要求固定逗号，却擅自加入货币符号、小数位或 Locale 规则。
