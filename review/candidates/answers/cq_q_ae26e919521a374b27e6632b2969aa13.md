# 任意交换两个字符，使字符串有序的最少操作次数

## 核心结论

先把“有序”和重复字符说清楚。来源只保存了“任意交换两个字符，使字符串有序，求最少次数”，没有给排序规则、重复字符语义或接口。下面采用一个可严格验证的参考契约：Java `String` 非 `null`，所有 UTF-16 `char` **互不相同**，目标是按 `char` 自然升序排列；一次操作可以交换任意两个位置。此时原位置到目标位置形成一个置换，每个长度为 `L` 的置换环恰好需要 `L-1` 次交换，因此答案是所有环的 `L-1` 之和，也就是 `n - 环数`（把长度 1 的环也计入环数）。

如果允许重复字符，某个相同字符可以对应多个目标位置，映射不再唯一；随便给重复字符编号后再数环，可能不是全局最优。因此本参考实现对重复字符显式拒绝，不把“字符互异”伪装成原题条件。

## 1 分钟版

- 复制并排序字符串，得到唯一目标序列；本参考契约要求字符互异。
- 建立“字符 -> 排序后目标下标”，于是每个原下标 `i` 唯一指向它应该去的位置 `p[i]`。
- `p` 是一个置换，可以拆成互不相交的环。
- 一个长度 `L` 的环至少要 `L-1` 次交换，也能用 `L-1` 次把整个环归位，所以正好是 `L-1`。
- 遍历所有未访问位置，统计每个环长度并累加 `L-1`；排序 O(n log n)，环遍历 O(n)，额外空间 O(n)。

## 3 分钟版

例如 `dcab` 排序后是 `abcd`。每个字符的目标位置唯一：`d->3, c->2, a->0, b->1`，所以位置映射是 `[3,2,0,1]`。沿映射走是一个长度 4 的环 `0 -> 3 -> 1 -> 2 -> 0`，因此最少交换数是 `4-1=3`。例如可以依次把 `d` 与 `a`、再把当前位置上的 `d` 与 `b`、最后与 `c` 交换，得到有序结果；具体交换顺序可以不同，但少于 3 次无法把这个 4 环拆成 4 个单点环。

```java
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

public final class Solution {
    private Solution() {}

    public static int minSwapsToSort(String s) {
        if (s == null) {
            throw new NullPointerException("s");
        }
        char[] target = s.toCharArray();
        Arrays.sort(target);

        Map<Character, Integer> targetIndex = new HashMap<>();
        for (int i = 0; i < target.length; i++) {
            if (targetIndex.put(target[i], i) != null) {
                throw new IllegalArgumentException("reference contract requires distinct chars");
            }
        }

        int[] next = new int[s.length()];
        for (int i = 0; i < s.length(); i++) {
            next[i] = targetIndex.get(s.charAt(i));
        }

        boolean[] visited = new boolean[s.length()];
        int swaps = 0;
        for (int i = 0; i < s.length(); i++) {
            if (visited[i]) continue;
            int len = 0;
            for (int p = i; !visited[p]; p = next[p]) {
                visited[p] = true;
                len++;
            }
            swaps += len - 1;
        }
        return swaps;
    }
}
```

为什么 `L-1` 既是下界又可达到？长度 `L` 的环里有 `L` 个位置处在同一置换环中；一次交换最多把一个环分裂成两个环，也就是最多让置换环数增加 1。要把一个环变成 `L` 个单点环至少要 `L-1` 次。反过来，固定环内任意一个位置，依次把应该放到当前位置的字符交换进来，每次都能确定一个位置，`L-1` 次后整个环归位。

## 关键细节

- **来源边界**：原题没有保存升序比较器、大小写规则、Unicode code point/UTF-16 语义、重复字符是否存在或具体语言；这些都不能冒充题目已给条件。
- **重复字符**：这是本题最容易被忽略的边界。字符重复时，“这个 `a` 应该去哪个 `a` 的目标位置”并不唯一，固定一种 occurrence 映射再数环可能多算交换。因此参考代码直接拒绝重复字符。
- **空串/单字符**：都没有非平凡环，返回 0。
- **已经有序**：所有位置都是长度 1 的环，返回 0。
- **任意位置交换**：环公式依赖一次操作可以交换任意两个下标；如果只能交换相邻字符，问题会变成逆序对计数，答案完全不同。
- **复杂度**：排序 O(n log n)，构造映射和环遍历 O(n)，额外数组/映射 O(n)。
- **字符模型**：Java `char` 是 UTF-16 code unit；若题目要求按 Unicode code point 或 locale 排序，需要重新定义目标序列和索引单位。

## 原理机制

排序后，每个互异字符都有唯一目标下标，因此“当前位置 -> 目标位置”天然是一张置换图：每个节点出度和入度都恰好为 1，整张图只能由若干互不相交的环组成。

最少交换问题就转成“把这些环拆成单点环”。一次任意交换相当于交换两个位置的去向；对一个非平凡环，可以选择合适的两个位置让环数增加 1。初始若有 `c` 个环，最终有 `n` 个单点环，每次最多增加 1 个环，所以至少要 `n-c` 次；逐环做 `L-1` 次又正好达到这个下界，因此它就是最优解。

## 项目经验版

来源没有提供用户真实项目中做字符串置换优化的经历，不能虚构。工程里如果出现类似问题，我会先确认“任意交换”还是“相邻交换”、排序比较器、重复元素和输入规模，因为这些条件直接决定模型：互异元素 + 任意交换适合置换环；相邻交换通常转向逆序对；重复元素则需要先解决目标 occurrence 匹配，而不能机械套唯一置换公式。

## 常见追问

- 问：为什么一个长度 `L` 的环是 `L-1` 次？答：每次交换最多让环数增加 1，从一个环变成 `L` 个单点环至少 `L-1` 次；同时可以通过逐个固定位置在 `L-1` 次内完成，所以界是紧的。
- 问：已经排好序怎么办？答：每个位置都是长度 1 的环，每个贡献 0，总答案为 0。
- 问：如果只能交换相邻字符呢？答：就不能用任意交换的环公式；对互异元素，最少相邻交换与相对目标顺序的逆序对数量相关。
- 问：有重复字符还能直接 `n - cycles` 吗？答：不能先随便给重复 occurrence 配目标下标再宣称最优，因为 occurrence 匹配本身会影响环结构；必须额外解决匹配问题。本参考契约因此明确要求字符互异。
- 问：为什么不直接模拟把每个位置换成正确字符？答：在字符互异时可以，那种模拟本质上也在逐步拆置换环；显式环分解更容易证明最优性和复杂度。
- 问：Java `char` 会不会拆开 emoji？答：会，很多补充字符由两个 UTF-16 code unit 组成。本参考契约按 `char` 排序；若题目说“Unicode 字符”，应改成 code point 数组再建置换。

## 易错点

- 没澄清“任意交换”还是“相邻交换”，直接套错模型。
- 把有重复字符的输入随意编号成唯一置换，却没有证明该 occurrence 匹配最优。
- 环遍历忘记标记访问，重复计数甚至死循环。
- 只给 `n - cycles` 结论，却没有说明环数为何提供下界且可达到。
- 把 Java `char` 当成所有 Unicode 字符的一一对应单位。
