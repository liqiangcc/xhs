# 算法手撕：Paint House II（LeetCode 265）

## 核心结论

原题只写了“Paint House、动态规划、Hard”，没有给完整约束。按题名和难度边界，最贴合的是 LeetCode 265 **Paint House II**：有 `n` 个房子、`k` 种颜色，`costs[i][j]` 是第 `i` 个房子刷成颜色 `j` 的成本，相邻房子不能同色，求总成本最小值。普通 DP 枚举上一间房所有不同颜色是 `O(nk²)`；Hard 版的关键优化是：每一行只保留上一行累计成本的**最小值、次小值以及最小值对应颜色**，于是每个状态能 `O(1)` 转移，总时间降为 `O(nk)`。

## 1 分钟版

- 定义 `dp[i][j]`：刷完 `0..i` 号房，且第 `i` 间使用颜色 `j` 的最小总成本。
- 转移是 `costs[i][j] + min(dp[i-1][c])`，其中 `c != j`。
- 直接为每个 `j` 扫一遍所有 `c` 会变成 `O(nk²)`。
- 观察到“排除一个颜色后求最小值”只需要上一行的最小值 `min1`、次小值 `min2` 和 `min1` 的颜色 `minColor`：
  - `j != minColor`，直接接 `min1`；
  - `j == minColor`，不能连续同色，改接 `min2`。
- 每行再扫描一次得到新的 `min1/min2/minColor`，所以时间 `O(nk)`，若只保存上一行累计成本则空间 `O(k)`；进一步只保留两个最小值也能做到常数额外状态。

## 3 分钟版

先写最直观的状态：

`dp[i][j] = costs[i][j] + min(dp[i-1][c]), c != j`

这个状态是对的，但如果有 `n` 个房子、`k` 种颜色，每个 `dp[i][j]` 都枚举 `k-1` 个上一行颜色，总复杂度是 `O(nk²)`。

优化点在于：对固定上一行，当前颜色 `j` 只排除一个候选 `dp[i-1][j]`。如果上一行整体最小值来自别的颜色，就直接用整体最小值；只有当整体最小值恰好来自颜色 `j` 时，才需要第二小值。因此上一行无需为每个当前颜色重新扫描。

下面的 Java 实现用 `long[]` 保存上一行累计成本，避免在中间求和时依赖 `int` 溢出行为；返回时用 `Math.toIntExact` 明确要求结果落在 `int` 范围内。仓库验证使用一个结构不同的 `O(nk²)` oracle 对随机小矩阵做差分测试。

```java
public final class PaintHouseII {
    private PaintHouseII() {}

    public static int minCostII(int[][] costs) {
        if (costs == null) {
            throw new IllegalArgumentException("costs must not be null");
        }
        if (costs.length == 0) {
            return 0;
        }
        if (costs[0] == null || costs[0].length == 0) {
            throw new IllegalArgumentException("each house must have at least one color");
        }

        int colors = costs[0].length;
        for (int[] row : costs) {
            if (row == null || row.length != colors) {
                throw new IllegalArgumentException("cost matrix must be rectangular");
            }
        }
        if (colors == 1 && costs.length > 1) {
            throw new IllegalArgumentException("no valid coloring exists with one color and adjacent houses");
        }

        long[] previous = new long[colors];
        for (int color = 0; color < colors; color++) {
            previous[color] = costs[0][color];
        }

        for (int house = 1; house < costs.length; house++) {
            long min1 = Long.MAX_VALUE;
            long min2 = Long.MAX_VALUE;
            int minColor = -1;

            for (int color = 0; color < colors; color++) {
                long value = previous[color];
                if (value < min1) {
                    min2 = min1;
                    min1 = value;
                    minColor = color;
                } else if (value < min2) {
                    min2 = value;
                }
            }

            long[] current = new long[colors];
            for (int color = 0; color < colors; color++) {
                long bestPrevious = color == minColor ? min2 : min1;
                current[color] = Math.addExact(bestPrevious, costs[house][color]);
            }
            previous = current;
        }

        long answer = Long.MAX_VALUE;
        for (long value : previous) {
            answer = Math.min(answer, value);
        }
        return Math.toIntExact(answer);
    }
}
```

官方示例 `[[1,5,3],[2,9,4]]` 的答案是 `5`，`[[1,3],[2,4]]` 的答案也是 `5`。仓库中的独立 Java 校验还覆盖单房子、相同成本、两色交替，并把优化实现与朴素 `O(nk²)` DP oracle 在固定随机种子的 5000 个合法小矩阵上逐一对比，全部一致。

## 关键细节

- 原始面经没有写 “II” 或完整输入约束，因此这里没有把模糊题干扩写成别的 Paint House 变体；选择 265 的依据是它与 “Paint House + Hard” 的题名/难度边界吻合，而基础 256 不是 Hard。
- `min2` 必须允许与 `min1` 数值相等，因为不同颜色可能有相同累计成本；我们关心的是“排除最小值颜色后仍可用的最小成本”，不是“严格第二大的不同数值”。
- 第一行没有相邻约束，累计成本就是 `costs[0][j]`。
- 当前颜色等于上一行最优颜色时必须使用 `min2`，否则会让相邻两间房使用相同颜色。
- 实现额外做了 `null`、空矩阵、非矩形矩阵和单颜色多房子的防御性检查；这些是仓库独立方法的边界，不应冒充 LeetCode 正式输入要求。
- 时间复杂度 `O(nk)`：每一行找两个最小值扫描 `k` 次，再构造当前行扫描 `k` 次；空间复杂度 `O(k)`。
- 若面试官要求常数额外空间，可以不保存完整 `previous`，而是直接维护上一行的 `min1/min2/minColor` 并在当前行计算新的三元组。

## 原理机制

优化成立的核心是“每个当前状态只禁止上一行的一个颜色”。设上一行最小累计成本是 `(min1, minColor)`，第二小是 `min2`。对当前颜色 `j`：

- 如果 `j != minColor`，全局最优 `min1` 的颜色没有被禁止，它必然还是合法候选中的最小值；
- 如果 `j == minColor`，唯一被禁止的恰好是全局最优颜色，剩余颜色中的最小值就是 `min2`。

因此每个状态无需再次遍历上一行，`O(k)` 的“排除后求最小值”被压缩成 `O(1)` 选择。再对当前行扫描一次，就能为下一轮重新建立同样的不变量。

## 项目经验版

这是算法题，不应包装成虚构项目经历。可靠的复习方式是：先写出 `O(nk²)` 状态转移，明确瓶颈是“每个颜色都重新找上一行最小合法颜色”，再推导最小值/次小值优化；实现后用朴素 DP 作为独立 oracle 做差分测试。这样能证明优化没有改变问题语义，而不是只记住一个技巧。

## 常见追问

- 问：为什么只要两个最小值？答：当前颜色只会排除上一行一个颜色；如果排除的不是最小值，用最小值，否则用次小值。
- 问：两个最小值相等怎么办？答：完全允许。只要它们来自不同颜色，排除一个最小颜色后另一个同值颜色仍然合法，所以 `min2` 可以等于 `min1`。
- 问：和 Paint House 256 有什么区别？答：256 固定三种颜色，直接写三个转移就是 `O(n)`；265 把颜色数推广到 `k`，朴素转移变成 `O(nk²)`，Hard 版通常要求进一步做到 `O(nk)`。
- 问：为什么不直接排序每一行？答：排序会引入 `O(k log k)`，而扫描一次就能找到最小值、次小值和最小值颜色，没有必要改变状态顺序。
- 问：能原地修改 `costs` 吗？答：可以把累计成本写回矩阵以省额外数组，但会破坏输入；这里保留 `O(k)` 额外空间，让函数副作用更小。

## 易错点

- 把 265 当成固定三色版本，复杂度分析仍写 `O(n)`。
- 只保存最小值，不保存它对应的颜色，导致无法判断当前颜色是否冲突。
- 把 `min2` 错写成“严格大于 `min1` 的第二个不同数值”，在并列最小时得到错误结果。
- 当前颜色与 `minColor` 相同时仍使用 `min1`，直接违反相邻不同色约束。
- 只验证官方样例，没有用朴素 DP 或穷举 oracle 检查优化后的转移。
