# SQL：找出成绩排名前十的学生

## 核心结论

原始 OCR 只保留“sql题找出成绩前十的学生”，没有表结构、成绩口径和并列规则。先把这些变成显式契约：假设 `students(student_id, name)` 保存学生，`scores(student_id, score)` 对每个有成绩的学生恰好一条非 NULL 最终成绩；“前十”表示**最多返回 10 名学生**，成绩降序，分数相同时按 `student_id` 升序稳定打破并列；没有成绩的学生不参与。这个契约下直接连接、排序、`LIMIT 10` 即可。

## 1 分钟版

- 一行结果代表一名学生；当前契约假设一名学生只有一条最终 `score`，所以主查询不需要 `GROUP BY`。
- `JOIN` 用 `student_id` 把姓名与成绩关联；INNER JOIN 自然排除没有成绩记录的学生。
- `ORDER BY sc.score DESC` 先按成绩从高到低；再加 `s.student_id ASC`，让第 10 名附近有同分时结果仍然确定。
- `LIMIT 10` 的语义是最多十**行**，并不等于“前十个名次全部包含并列”。如果面试官要求并列同名次全部返回，应改用窗口函数并先确认 `RANK` 还是 `DENSE_RANK`。
- 如果成绩表是一人多门课多行，必须先明确用平均分、总分还是某门成绩，再聚合到“一名学生一行”后排序，不能直接套本查询。
- 来源没规定 NULL、无成绩学生、MySQL 版本和索引；这些都应先确认，而不是补成原题事实。

## 3 分钟版

```sql
SELECT
    s.student_id,
    s.name,
    sc.score
FROM students AS s
JOIN scores AS sc
  ON sc.student_id = s.student_id
ORDER BY sc.score DESC, s.student_id ASC
LIMIT 10;
```

在当前“每人一条最终成绩”的契约下，这个查询返回最多十行。假设第 10、11 名都是 91 分，`student_id` 分别是 10 和 11，那么因为额外的稳定排序键，ID 10 会进入结果、ID 11 不会；这不是把 91 分判成不同排名，而是在“必须只取十行”的契约下定义确定性的截断规则。

## 关键细节

- **先定义排名对象**：如果 `scores` 中一人多行课程成绩，必须先用题目指定的 `AVG`、`SUM`、最高分等口径形成每人一条记录，再谈前十。
- **并列语义**：`LIMIT 10` 只保证十行上限。若要求“前十名次且并列都算”，MySQL 8+ 可在每人一条成绩上用 `RANK()` 或 `DENSE_RANK()`；两者在并列后的名次是否跳号不同，必须由业务口径决定。
- **确定性**：只写 `ORDER BY score DESC LIMIT 10` 时，同分行内部顺序没有被 SQL 显式定义。加入稳定唯一键可以让重复执行和测试得到一致边界结果。
- **NULL / 无成绩**：本契约让 `score` 非 NULL，且 INNER JOIN 排除无成绩学生。如果真实模型允许 NULL 或要求无成绩学生也展示，要显式定义其排序/展示规则。
- **索引与性能**：数据量大时可根据真实表结构评估成绩排序键和关联键索引，但能否避免额外排序取决于表结构、过滤条件和执行计划；不能脱离 schema 保证“有索引就一定不排序”。
- **复杂度**：逻辑正确性与执行代价分开讨论。没有合适访问路径时可能需要扫描/排序较多行；有可利用的索引时 Top-N 可更早停止。最终以目标 MySQL 的 `EXPLAIN` / `EXPLAIN ANALYZE` 验证。

## 原理机制

主查询的数据流是：先通过 `student_id` 把学生信息与唯一成绩行配对，得到“一名有成绩学生一行”；再按 `score DESC, student_id ASC` 建立全序；最后 `LIMIT 10` 截取这个有序结果的前十行。关键不在 `LIMIT` 本身，而在截取之前必须确保结果粒度和排序规则已经定义完整。

如果要“前十个分数层级全部包含并列”，可以在 MySQL 8+ 写成：

```sql
WITH ranked AS (
    SELECT
        s.student_id,
        s.name,
        sc.score,
        DENSE_RANK() OVER (ORDER BY sc.score DESC) AS score_rank
    FROM students AS s
    JOIN scores AS sc
      ON sc.student_id = s.student_id
)
SELECT student_id, name, score
FROM ranked
WHERE score_rank <= 10
ORDER BY score DESC, student_id ASC;
```

这个版本可能返回超过十行，而且 `DENSE_RANK` 表示“前十个不同分数层级”。如果业务采用比赛排名并要求并列后跳号，则应使用 `RANK`，不能把两者混为一谈。

## 常见追问

- 问：为什么一定要加 `student_id` 作为第二排序键？答：如果契约要求恰好最多十行，同分边界必须有确定的截断顺序；唯一键是常见稳定 tie-breaker，但真实题目也可以指定其他规则。
- 问：并列第十是否应该全部返回？答：来源没说。当前主查询只取十行；若要求按名次包含并列，要改窗口函数并明确使用 `RANK` 还是 `DENSE_RANK`。
- 问：一名学生有多门课成绩怎么办？答：先按业务要求聚合到学生粒度，例如平均分或总分，再对聚合结果排名；不能让多门课行直接争夺前十行。
- 问：为什么不用 `GROUP BY`？答：当前答案侧契约规定 `scores` 每名学生只有一条最终成绩，因此不需要；真实 schema 一人多行时才应按明确口径聚合。
- 问：`LIMIT 10` 很快吗？答：不一定。是否能高效 Top-N 取决于过滤、连接、索引和优化器计划，应看实际 `EXPLAIN`，不能只凭 SQL 形状下结论。

## 易错点

- 没定义一行结果是什么，就直接对课程成绩明细 `LIMIT 10`，得到的是“十条成绩”而不是“十名学生”。
- 只按分数排序，在第十名同分时产生不确定截断。
- 把“十行”与“前十名次含并列”当成同一个需求。
- 一人多条成绩时没有先明确聚合口径。
- 题目没给真实表名、字段名、NULL 规则和版本，却把示例 schema 说成来源要求。
