# 从 1 出发，每步乘 3 或加 5，到达 1024

## 核心结论

这题可以把每个整数看成一个状态，从状态 `x` 只有两条边：到 `3*x` 或到 `x+5`。因为从 1 开始两种操作都会严格增大正整数，超过 1024 后不可能再回到目标，所以搜索空间可以安全裁剪为 `1..1024`。如果只要求“找出一个解”，DFS/BFS 都可以；用 BFS 还能保证第一次到达 1024 的路径使用操作次数最少。

按下面 BFS 的扩展顺序（先 `*3`，再 `+5`），可以得到一条 11 步解：

`1 -> 3 -> 9 -> 27 -> 32 -> 37 -> 111 -> 333 -> 338 -> 1014 -> 1019 -> 1024`

对应操作：`*3, *3, *3, +5, +5, *3, *3, +5, *3, +5, +5`。

## 1 分钟版

- 状态：当前整数 `x`。
- 转移：`x -> 3*x`、`x -> x+5`。
- 两个操作对正整数都单调递增，所以 `next > 1024` 可以直接丢弃。
- 用队列做 BFS；`visited` 防止不同操作序列重复到达同一个值。
- 每个新状态记录 `parent` 和产生它的操作，命中 1024 后反向恢复完整路径。
- BFS 按层扩展，因此第一次找到目标就是最少操作次数；这里最短为 11 步。
- 状态值最多只有 `1..1024`，因此本题时间、空间都可视为 `O(1024)`；一般目标为 `T` 时是 `O(T)` 状态上界。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Collections;
import java.util.Deque;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

public final class MultiplyThreeAddFive {
    record Step(int value, String operation) {}

    static List<Step> shortestPath(int target) {
        if (target < 1) return List.of();
        if (target == 1) return List.of(new Step(1, "START"));

        Deque<Integer> queue = new ArrayDeque<>();
        Set<Integer> visited = new HashSet<>();
        Map<Integer, Integer> parent = new HashMap<>();
        Map<Integer, String> operation = new HashMap<>();

        queue.add(1);
        visited.add(1);

        while (!queue.isEmpty()) {
            int current = queue.removeFirst();
            long[] nextValues = {(long) current * 3, (long) current + 5};
            String[] operations = {"*3", "+5"};

            for (int i = 0; i < nextValues.length; i++) {
                long raw = nextValues[i];
                if (raw > target) continue;
                int next = (int) raw;
                if (!visited.add(next)) continue;

                parent.put(next, current);
                operation.put(next, operations[i]);
                if (next == target) return rebuild(target, parent, operation);
                queue.addLast(next);
            }
        }
        return List.of();
    }

    private static List<Step> rebuild(
            int target,
            Map<Integer, Integer> parent,
            Map<Integer, String> operation) {
        List<Step> reversed = new ArrayList<>();
        int current = target;
        while (current != 1) {
            reversed.add(new Step(current, operation.get(current)));
            current = parent.get(current);
        }
        reversed.add(new Step(1, "START"));
        Collections.reverse(reversed);
        return reversed;
    }
}
```

对目标 1024，恢复出的状态序列是：

`1, 3, 9, 27, 32, 37, 111, 333, 338, 1014, 1019, 1024`。

逐步验算：`1*3=3`，`3*3=9`，`9*3=27`，`27+5=32`，`32+5=37`，`37*3=111`，`111*3=333`，`333+5=338`，`338*3=1014`，`1014+5=1019`，`1019+5=1024`。

## 关键细节

- **为什么可以裁掉大于目标的状态**：从正整数出发，`*3` 和 `+5` 都严格增大；一旦超过 1024，没有任何允许操作能减小回来。
- **为什么需要 visited**：例如某些整数可能由不同路径到达。BFS 第一次到达某状态已经是最少步数，再入队只会产生冗余搜索。
- **为什么 BFS 能给最短步数**：图中每次操作成本都相同，都是 1 步；普通 BFS 正是无权图的最短路算法。
- **为什么用 long 计算 `current * 3`**：通用实现里先提升到 `long`，避免较大目标时中间乘法发生 `int` 溢出后绕回小值。本题 1024 很小，但实现边界仍应正确。
- **target=1**：零步已经到达目标，因此返回只有起点的路径。
- **不可达目标**：队列耗尽后返回空列表。题目固定目标 1024 是可达的，代码仍保留通用失败语义。

## 原理机制

本质是一个隐式有向图最短路问题。节点无需预先创建；从 `current` 动态生成两个邻居即可。BFS 的层数就是操作次数：第 0 层是 1，第 1 层是一步可达状态，依次向外扩张。第一次发现 1024 时，不可能存在更少操作数的未处理路径，因为所有更浅层状态已经先被完整扩展。

恢复路径时不必给队列里的每项复制整条历史路径，只记录 `parent[next]=current` 和 `operation[next]`。这样每个可达状态只保存常数级元数据，找到目标后再从 1024 沿父指针倒推到 1。

## 项目经验版

来源是算法手写题，没有真实项目背景，因此不虚构项目指标。若映射到工程问题，这类做法适用于“状态数量有限、每次转换代价相同、需要恢复最短操作序列”的状态搜索；如果每种操作成本不同，就应改用 Dijkstra 等加权最短路方法，而不是继续用普通 BFS。

## 常见追问

- 问：不用 BFS，能不能从 1024 倒着找？答：可以。逆操作是“如果当前值能被 3 整除则除 3”以及“减 5”，同样能搜索；但如果要证明最少操作，仍需要按层搜索或等价的最短路方法。
- 问：为什么 DFS 不够？答：只要求任意解时 DFS 足够；如果还希望保证操作数最少，普通 DFS 第一个找到的解没有这个保证。
- 问：这个解是不是唯一？答：题目只要求找出解法，BFS 返回按固定扩展顺序发现的一条最短路径；是否存在其它路径应由搜索结果判断，不能只凭这一条路径声称唯一。
- 问：怎么证明 11 步是最短？答：BFS 按操作次数逐层扩展，第一次发现 1024 时所有 0~10 步可达状态都已经被更早层覆盖，所以不存在 10 步或更短路径。
- 问：为什么不需要搜索超过 1024 的数？答：两个允许操作都只增不减，超过目标后不可能回到目标。
- 问：状态空间复杂度为什么是 O(T)？答：在正整数且只保留 `<=T` 的前提下，每个整数最多入队一次，因此最多处理 T 个状态。

## 易错点

- 盲目递归且不裁剪 `> target`，让搜索树无限增长。
- 不做去重，导致同一状态被多条路径反复展开。
- 用 DFS 找到一条路径后直接声称“最短”。
- 只输出 1024 而没有保存父节点，最后无法恢复完整操作序列。
- 通用实现直接用 `int current * 3`，忽略整数溢出。
- 把当前 BFS 找到的一条路径误称为“唯一解”。
