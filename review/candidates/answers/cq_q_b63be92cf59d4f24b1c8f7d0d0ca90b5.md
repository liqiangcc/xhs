# 零钱兑换组合数：为什么硬币在外层、金额正序遍历？

## 核心结论

这道题的关键不是“会写一维 DP”，而是先把“组合数”与“排列数”区分清楚。来源只保留“给定金额和硬币面值，求总组合数”，没有保留硬币能否重复使用、重复面值如何处理、输入异常规则或数值范围。为了形成可执行合同，本答案采用常见的无限硬币组合语义：每种正整数面值可使用任意次，同一批硬币只看使用次数、不区分拿取顺序；面值必须互不重复；金额必须非负。

在这个合同下，令 `dp[s]` 表示使用**已经处理过的面值集合**凑出金额 `s` 的组合数。初始化 `dp[0]=1`，然后“硬币在外层、金额从 `coin` 到 `amount` 正序遍历”：`dp[s] += dp[s-coin]`。硬币外层保证同一个组合不会因为硬币顺序不同被重复计数；金额正序则允许当前硬币在同一轮被重复使用。组合数可能很大，来源没有给上界，所以实现使用 `BigInteger` 而不是偷偷假设 `int`/`long` 一定不会溢出。

## 1 分钟版

- `dp[s]`：用已经处理过的硬币面值，凑出金额 `s` 的组合数。
- `dp[0]=1`：凑出 0 元有一种方式——什么都不选；这是后续转移的乘法单位/起点。
- 外层枚举硬币：每种组合只会在“按面值处理顺序加入当前硬币”的阶段被计一次，因此不会把 `{1,2}` 和 `{2,1}` 当两种排列。
- 内层金额正序：计算 `dp[s]` 时，`dp[s-coin]` 已经可能使用过当前硬币，所以允许当前面值使用多次。
- 若金额倒序，就会把当前硬币限制为本轮最多使用一次，更像 0/1 背包；若金额在外层、硬币在内层，则很容易统计成有顺序的排列数。
- 时间上有 `m * amount` 次 DP 转移，空间 `O(amount)`；`BigInteger` 的真实算术成本还与结果位数有关。

## 3 分钟版

```java
import java.math.BigInteger;
import java.util.Arrays;
import java.util.HashSet;
import java.util.Set;

public final class CoinChangeCombinations {
    public static BigInteger countCombinations(int amount, int[] coins) {
        if (amount < 0 || coins == null) {
            throw new IllegalArgumentException("amount must be non-negative and coins must be non-null");
        }

        Set<Integer> seen = new HashSet<>();
        for (int coin : coins) {
            if (coin <= 0 || !seen.add(coin)) {
                throw new IllegalArgumentException("coin values must be positive and distinct");
            }
        }

        BigInteger[] dp = new BigInteger[amount + 1];
        Arrays.fill(dp, BigInteger.ZERO);
        dp[0] = BigInteger.ONE;

        for (int coin : coins) {
            for (int sum = coin; sum <= amount; sum++) {
                dp[sum] = dp[sum].add(dp[sum - coin]);
            }
        }
        return dp[amount];
    }
}
```

不变量可以按硬币前缀来理解。处理第 `i` 种硬币之前，`dp[s]` 已经表示“不使用第 `i` 种硬币，只使用前面的面值”得到 `s` 的组合数。金额正序更新时，`dp[s-coin]` 已经包含“使用当前硬币 0 次、1 次、2 次……”的结果；给这些组合再追加一个当前硬币，就得到所有“至少使用一次当前硬币”的组合。原来的 `dp[s]` 与新增的 `dp[s-coin]` 两部分互斥且覆盖完整，因此相加不会漏也不会重。

## 关键细节

- **为什么 `dp[0]=1`**：金额 0 的空组合是递推起点。例如处理面值 2 时，`dp[2] += dp[0]` 才能生成“只用一枚 2”的组合。
- **为什么硬币在外层**：它给每个无序组合一个固定的构造顺序。即使输入硬币顺序是 `[5,1,2]`，每个面值只处理一次，组合仍按这次处理顺序被唯一构造，不会把硬币的排列作为不同答案。
- **为什么金额正序**：正序使 `dp[sum-coin]` 在本轮可以已经包含当前硬币，因此一个面值可以无限次使用；倒序会读取本轮尚未更新的旧状态，从而限制为每种硬币最多使用一次。
- **重复面值**：若输入 `[1,1,2]` 仍把两枚 `1` 当作同一种面值却分别循环两次，会人为重复计数。本合同要求面值互不重复并显式拒绝重复输入；如果业务输入允许重复，应该先明确“重复代表不同硬币种类还是脏数据”再归一化。
- **金额 0**：返回 1，即空组合；空硬币数组在金额大于 0 时返回 0。
- **大结果**：组合数增长可能超过 64 位。`BigInteger` 保证计数精确，但因此“每次加法 O(1)”并不严格；更准确地说是 `O(m * amount)` 次大整数加法，单次成本随数字位数增长。
- **数组下标**：硬币必须为正数，否则 `sum-coin` 的语义和循环终止/边界都会被破坏，所以本合同拒绝 0 和负面值。

## 原理机制

一维 DP 本质上是在压缩二维状态 `ways[i][s]`：只使用前 `i` 种面值凑出 `s` 的组合数。完整关系可以写成“完全不使用第 `i` 种硬币”加上“至少使用一枚第 `i` 种硬币”。把二维数组压成一维后，遍历方向就承担了区分“旧层状态”和“当前层状态”的职责：正序让 `dp[s-coin]` 读取当前层已经更新的值，因此允许同一硬币重复；硬币外层又保证所有组合按面值阶段而不是拿取顺序组织，所以统计的是组合而不是排列。

## 项目经验版

来源没有真实项目经历，不能虚构“支付系统里用过零钱兑换”。工程上若要统计方案数，我会先确认三个合同：物品是否可重复、顺序是否区分、计数是否允许取模或需要精确大整数。三者任何一个改变，状态转移或遍历顺序都可能变化。实现后可以用一个只面向小金额的递归枚举器作为独立 oracle，随机生成小面值集合做差分测试，专门捕获“组合误写成排列”和“完全背包误写成 0/1 背包”这两类错误。

## 常见追问

- 问：为什么金额外层、硬币内层会出问题？答：那样 `dp[s]` 会沿不同“最后一枚硬币”路径累加，`1+2` 和 `2+1` 可能被分别构造，统计更接近排列数。
- 问：为什么金额必须正序？答：因为当前硬币允许重复使用；正序时 `dp[s-coin]` 已经是当前硬币这一层的新状态，可以继续再加一枚当前硬币。
- 问：如果每种硬币只能用一次怎么办？答：那是 0/1 背包计数，金额要倒序更新，避免同一枚硬币在一轮里被重复使用。
- 问：`amount=0` 为什么是 1 不是 0？答：组合计数把“什么都不选”视为唯一空组合，它是递推生成单硬币方案的基础状态。
- 问：硬币顺序不同会影响答案吗？答：在面值互不重复且每种硬币只处理一次的合同下不会；外层顺序只改变 DP 的构造次序，不改变最终无序组合集合。
- 问：为什么用 `BigInteger`？答：来源没有保存金额、硬币数量和答案上界；为了不把一个未证明的 32/64 位上界变成隐藏前提，这里选择精确大整数。

## 易错点

- 把“组合数”写成“排列数”，通常表现为金额在外层、硬币在内层。
- 完全背包却让金额倒序，结果把每种面值限制成只能使用一次。
- 忘记 `dp[0]=1`，导致所有可达状态都无法从 0 金额起步。
- 输入包含重复面值却循环多次，若重复并不代表不同物品种类，会把同一组合重复计数。
- 使用 `int`/`long` 却没有来源约束或溢出策略，导致大组合数静默溢出。
- 把本答案采用的“无限使用、正面值、互不重复、异常处理”说成原题已明确条件。
