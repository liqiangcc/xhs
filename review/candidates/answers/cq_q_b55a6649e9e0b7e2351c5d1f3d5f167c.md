# 算法手撕：滑动窗口最大值（Sliding Window Maximum）

## 核心结论

仓库的完整来源只保留了“给定一个数组和滑动窗口大小 K，返回每个滑动窗口的最大值”，另一条合并来源只保留题名。最合适的数据结构是保存下标的单调双端队列：队首始终是当前窗口最大值的下标；新元素进入时从队尾删除所有不大于它的旧候选，并在每一步先淘汰已经滑出左边界的下标。每个下标最多入队、出队一次，所以时间 `O(n)`，队列最多保存 `k` 个下标，额外空间 `O(k)`。

## 1 分钟版

- 队列存下标，不直接存值，这样既能判断元素是否已经离开窗口，也能通过下标取最大值。
- 维护队列对应值从队首到队尾严格递减；队首就是当前窗口最大值。
- 扫描到下标 `i` 时，先删除 `<= i-k` 的队首，因为这些位置已经不属于当前窗口。
- 再从队尾删除 `nums[dq.last] <= nums[i]` 的下标：新元素更靠右且不小于旧元素，旧元素以后不可能再成为任何窗口最大值。
- 把 `i` 入队；当 `i >= k-1` 时输出 `nums[dq.first]`。
- 每个下标只会入队一次、从队首或队尾移除一次，因此总时间 `O(n)`，空间 `O(k)`。

## 3 分钟版

来源没有保存函数签名、`k` 非法时的行为或 `null` 约束。为了让实现可执行，下面显式采用本地练习合同：输入非 `null` 的 `int[] nums` 和 `1 <= k <= nums.length`；非法 `k` 或 `null` 输入抛 `IllegalArgumentException`。这些是测试合同，不冒充原题原文。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public final class SlidingWindowMaximum {
    public static int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || k <= 0 || k > nums.length) {
            throw new IllegalArgumentException("invalid input");
        }

        int[] answer = new int[nums.length - k + 1];
        Deque<Integer> deque = new ArrayDeque<>();
        int out = 0;

        for (int i = 0; i < nums.length; i++) {
            while (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.removeFirst();
            }
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.removeLast();
            }
            deque.addLast(i);

            if (i >= k - 1) {
                answer[out++] = nums[deque.peekFirst()];
            }
        }
        return answer;
    }
}
```

正确性的核心不变量是：队列中的下标都属于当前窗口候选范围，并且对应数值从队首到队尾严格递减。队尾被删除的旧元素同时满足“更早”和“不更大”，所以在新元素仍处于窗口期间它不可能成为最大值；等新元素离开窗口时，这个旧元素一定更早就已经离开，因此永久淘汰是安全的。队首则是所有仍存活候选中最大的值。

## 关键细节

- **为什么存下标**：窗口滑动依赖位置；只存值无法可靠判断哪个重复值已经过期。
- **过期条件**：扫描到 `i` 时当前窗口左边界是 `i-k+1`，因此下标 `<= i-k` 必须删除。
- **重复最大值**：这里用 `<=` 从队尾删除，让较新的相同值保留。改成 `<` 也能得到正确最大值，但会保留更多相等候选；两种策略都必须配合正确的过期逻辑。
- **输出时机**：只有扫描完前 `k` 个元素以后才形成第一个完整窗口，即 `i >= k-1`。
- **`k=1`**：每个元素自己就是窗口最大值，输出与输入相同。
- **`k=n`**：只产生一个窗口，输出整个数组最大值。
- **复杂度**：嵌套 `while` 不代表 `O(nk)`；一个下标最多入队一次，并最多从某一端移除一次，所以所有队列操作总计 `O(n)`。

## 原理机制

暴力方案会为每个长度为 `k` 的窗口重新扫描 `k` 个元素，最坏时间 `O(nk)`。单调队列把“未来仍可能成为最大值”的候选压缩保存下来。若一个旧候选 `j` 在新位置 `i` 到来时满足 `j < i` 且 `nums[j] <= nums[i]`，那么任何同时包含 `j` 和 `i` 的未来窗口里，`j` 都赢不了 `i`；而 `j` 又比 `i` 更早离开窗口，所以它从此没有成为最大值的机会，可以永久删除。这一支配关系正是单调队列能线性处理问题的原因。

## 项目经验版

来源没有真实项目经历，不能虚构线上使用。工程上遇到固定长度时间窗的最大值、峰值或最小值维护时，可以先判断是否具有与本题相同的“过期 + 支配淘汰”结构；若窗口按时间戳而不是固定元素数滑动，过期判断要改成时间条件；若还要支持任意删除、分位数或动态窗口，单调队列可能不再满足需求，需要换成堆、平衡树或其他结构。

## 常见追问

- 问：为什么队尾小于当前值的元素可以永久删除？答：它既比当前元素更早，又不比当前元素大；只要当前元素还在窗口，它就不可能成为最大值，而它会更早离开窗口，所以以后也没有翻身机会。
- 问：为什么要先删过期元素？答：队首可能已经不在当前窗口；如果直接读队首会把旧窗口的最大值带进新窗口。只要在输出前完成过期清理都可以，先清理最容易维持明确不变量。
- 问：重复值怎么办？答：本实现删除旧的相等值、保留较新的相等值。较新值寿命更长且最大值相同，所以不会影响答案。
- 问：能不能用优先队列？答：可以维护值和下标并惰性删除过期元素，通常是 `O(n log k)`；单调双端队列利用本题的顺序与支配关系可做到 `O(n)`。
- 问：为什么不是普通滑动窗口变量就够了？答：窗口左端移走的元素可能正是当前最大值，仅保存一个最大值无法知道次大候选；单调队列保存了按支配关系压缩后的候选集合。
- 问：如果题目要求滑动窗口最小值？答：结构完全对称，把队列维护方向反过来，让队首始终对应最小值即可。

## 易错点

- 只存值不存下标，重复值和过期判断容易出错。
- 把过期条件写成 `< i-k`，导致恰好离开窗口的下标多留一轮。
- 第一个窗口还没形成就开始写结果，产生数量或下标偏移错误。
- 看到嵌套 `while` 就误判为二次复杂度，没有做“每个下标只进出一次”的摊还分析。
- 把本候选采用的非法 `k`/`null` 行为说成来源已明确要求。
