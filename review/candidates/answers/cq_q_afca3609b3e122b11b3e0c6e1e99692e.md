# 原地 O(1) 空间重排链表

## 核心结论

来源明确保留了“高效重排链表、原地修改、额外空间 O(1)”，但没有保留重排后的精确顺序或方法签名，因此不能把某个具体排列冒充成原题事实。下面采用常见的参考契约来展示这些约束：把 `L0→L1→…→Ln` 原地重排为 `L0→Ln→L1→Ln-1→…`。在这个参考契约下，标准做法是三步：快慢指针找中点 → 原地反转后半段 → 两段链表交替合并；整体 O(n) 时间、O(1) 额外空间。

## 1 分钟版

- 用 `slow/fast` 找到前半段尾节点；偶数长度时让前半段不短于后半段。
- `second = slow.next` 后先 `slow.next = null`，把链表断成两段，避免后续交织形成旧链路残留。
- 原地反转后半段，使尾节点可以按 `Ln, Ln-1, ...` 顺序取出。
- 同时走 `first` 和反转后的 `second`，每次保存两边的 `next` 后交替接回。
- 全程只使用常数个指针，没有数组、栈或递归辅助空间。

## 3 分钟版

下面 Java 代码把 `L0→Ln→L1→Ln-1→…` 明确标为本答案的参考契约，而不是声称来源已经保存了这个排列：

```java
public final class Solution {
    private Solution() {}

    public static final class Node {
        public int val;
        public Node next;
        public Node(int val) { this.val = val; }
    }

    public static void reorder(Node head) {
        if (head == null || head.next == null) return;

        Node slow = head;
        Node fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        Node second = slow.next;
        slow.next = null;

        Node prev = null;
        while (second != null) {
            Node next = second.next;
            second.next = prev;
            prev = second;
            second = next;
        }
        second = prev;

        Node first = head;
        while (second != null) {
            Node firstNext = first.next;
            Node secondNext = second.next;
            first.next = second;
            second.next = firstNext;
            first = firstNext;
            second = secondNext;
        }
    }
}
```

例如 `1→2→3→4→5`：中点是 3，切成 `1→2→3` 与 `4→5`；后半段反转成 `5→4`；交替合并得到 `1→5→2→4→3`。偶数长度 `1→2→3→4` 会得到 `1→4→2→3`。

## 关键细节

- **为什么必须先断链**：找到中点后若不执行 `slow.next = null`，前半段仍指向旧的后半段入口；交替合并时更容易保留错误旧边甚至形成环。
- **中点选择**：循环条件 `fast.next != null && fast.next.next != null` 让长度 4 的前半段为 `1→2`、后半段为 `3→4`，长度 5 的前半段为 `1→2→3`、后半段为 `4→5`。
- **改指针前保存后继**：反转和合并都必须先保存原 `next`，否则一旦覆盖指针就可能丢失未处理节点。
- **奇偶长度统一**：前半段长度等于或比后半段多 1，因此 `while (second != null)` 足以完成交织；奇数时中点自然留在结尾。
- **空间复杂度**：只维护固定数量的节点引用，额外空间 O(1)；没有递归，所以也没有隐含 O(n) 调用栈。
- **来源边界**：如果面试官实际要求的是另一种“重排”（如按奇偶位置、按值分区等），应以补充的精确排列为准；这里只证明常见端点交织契约如何满足原地/O(1) 约束。

## 原理机制

不能直接从单链表尾部 O(1) 地不断取节点，因为单链表没有前驱指针。反转后半段把原来的“从尾到中点”的访问顺序转换成一次正向遍历，于是两条链分别提供 `L0,L1,...` 和 `Ln,Ln-1,...`。最后交替合并只是局部重连边。每个节点在找中点、反转、合并三个阶段都只被常数次访问，所以总时间仍为 O(n)。

## 项目经验版

来源没有真实项目场景，不能虚构生产使用。工程里如果确实要原地重排链式结构，我会先把目标顺序写成可执行样例和不变量，再重点测试空链、单节点、两节点、奇偶长度、节点不丢失和无环；如果可读性比 O(1) 空间更重要，也应比较数组收集节点后重连的更简单方案。

## 常见追问

- 问：为什么不用栈保存后半段？答：栈能简化从尾部取节点，但会使用 O(n) 额外空间，不满足来源保留的 O(1) 空间约束。
- 问：为什么不递归从两端交织？答：递归通常产生 O(n) 调用栈，也不满足严格的 O(1) 额外空间。
- 问：怎么证明不会丢节点？答：每次修改 `next` 前都保存当前两段的后继；合并循环每次恰好消费一个后半段节点，并保持未消费的两段入口可达。
- 问：怎么检查没有形成环？答：除针对期望序列逐节点比较外，再用 Floyd 快慢指针验证结果无环，并验证节点数与输入一致。
- 问：如果只有两个节点呢？答：中点是第一个节点，后半段只有第二个；断链、反转、合并后仍是原顺序，不会产生自环。

## 易错点

- 把“重排链表”未经说明就断言成唯一的 `L0→Ln→L1→…` 来源语义。
- 找到中点后不切断两段，导致旧链接参与后续合并。
- 反转时覆盖 `next` 前没有保存后继，直接丢失剩余链表。
- 合并时先改 `first.next` 或 `second.next` 却没有缓存两边原后继。
- 用栈/数组或递归实现，却仍声称满足严格 O(1) 额外空间。
