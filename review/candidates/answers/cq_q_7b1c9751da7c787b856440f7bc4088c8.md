# 删除链表所有重复数字：不使用 Map / Set

## 核心结论

来源只说“删除链表所有重复数字（不允许用 map 或 set）”，没有说明链表已排序，也没有说明“删除重复”是保留一份还是把重复值全部删除。这里采用更明确的主契约：**链表可以无序；只要某个值在原链表出现超过一次，就删除这个值的所有节点；值只出现一次的节点按原顺序保留；不使用 Map/Set，原地修改 `next` 并返回新头结点。** 在不能用哈希集合且不假设排序时，可以对每个当前值向后扫描并删除所有同值节点，发现过重复后再删除当前节点，时间 O(n²)、额外空间 O(1)。

## 1 分钟版

- 先用 dummy 头结点统一“删除原头结点”和“删除中间结点”的写法；`prev` 永远指向当前节点前一个已经确认保留的节点。
- 对 `current` 的值，用 `runner` 扫描它后面的链表；遇到同值节点就立即摘掉，并把 `duplicated=true`。
- 如果扫描结束发现过同值节点，说明 `current.val` 在原链表至少出现两次：后面的重复已经删掉，再用 `prev.next=current.next` 删除当前节点。
- 如果没有发现重复，当前值只出现一次，保留它并让 `prev/current` 同步前进。
- 外层最多 n 次、每次向后扫描 O(n)，所以最坏 O(n²)；只用固定数量指针和一个布尔值，额外空间 O(1)，solution 中没有 Map/Set。

## 3 分钟版

```java
public final class DeleteAllDuplicateValues {
    public static final class ListNode {
        public int val;
        public ListNode next;
        public ListNode(int val) { this.val = val; }
    }

    public static ListNode deleteAllDuplicates(ListNode head) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode prev = dummy;
        ListNode current = head;

        while (current != null) {
            boolean duplicated = false;
            ListNode runnerPrev = current;
            ListNode runner = current.next;
            while (runner != null) {
                if (runner.val == current.val) {
                    duplicated = true;
                    runnerPrev.next = runner.next;
                    runner = runnerPrev.next;
                } else {
                    runnerPrev = runner;
                    runner = runner.next;
                }
            }

            if (duplicated) {
                prev.next = current.next;
                current = prev.next;
            } else {
                prev = current;
                current = current.next;
            }
        }
        return dummy.next;
    }
}
```

例如 `1 -> 2 -> 3 -> 2 -> 4 -> 1 -> 5 -> 5 -> 6`，值 `1/2/5` 都出现超过一次，因此这些值的所有节点都被删掉，结果是 `3 -> 4 -> 6`。算法不依赖相同值相邻，所以不需要“链表已排序”这个来源没有提供的假设。

## 关键细节

- **语义先澄清**：本答案把“所有重复数字”解释成“重复值整组删除”。如果面试官想表达的是“去重但保留一个”，那么发现后续同值节点时只删除后续节点、不要再删除 `current` 即可。
- **不假设有序**：若题目明确链表已排序，重复值必然连续，可以用单次线性扫描做到 O(n)；当前来源没有排序条件，所以不能把 LeetCode 有序链表前提偷偷带进来。
- **为什么只向后找就够**：如果一个值在后面还有相同节点，那么第一次处理该值时就会把所有后续同值节点和当前节点一起删除；因此能够进入后续外层循环的已保留前缀，每个值都已经证明不会在剩余后缀再次出现。
- **指针安全**：删除 `runner` 时不能让 `runnerPrev` 前进，因为它仍然是新的 `runner` 的前驱；只有当前 `runner` 被保留时两个游标才一起向前。
- **dummy 的作用**：当原头值本身重复时，`prev=dummy` 让删除逻辑和中间位置完全一致，无需为 head 单独分支。
- **空间限制**：solution 没有 Map/Set，也没有把值复制到数组排序；测试代码可以使用独立频次 oracle 验证实现，但那不是提交给题目的算法。
- **输入边界**：空链表、单节点、全唯一、全重复、头尾重复和非相邻重复都需要覆盖。本答案假设输入是普通无环单链表；若可能有环，应先定义是否拒绝或先断环。

## 原理机制

核心不变量是：进入每轮外层循环时，`dummy.next ... prev` 这一段只包含最终应该保留的唯一值，`current` 是尚未判定的第一个节点。内层扫描会消除 `current.val` 在后缀中的所有其他出现，并记录它是否重复。若重复，当前节点也必须删掉，已确认前缀不变；若不重复，`current` 可以安全加入已确认前缀。这个不变量让算法即使修改链表结构，也不会漏掉后续非相邻重复。

如果允许 O(n) 额外空间，最直接的通用无序方案是先统计每个值的频次，再第二遍只保留频次为 1 的节点；但题目显式禁止 Map/Set，所以这里用时间换空间。若输入已排序，则可以利用“重复连续”这个额外结构，把 O(n²) 降为 O(n)。

## 项目经验版

来源没有真实业务链表或性能约束，不能虚构项目经历。面试现场应先问两件事：链表是否排序，以及“删除重复”到底是保留一份还是重复值全部删除。这两个条件会直接决定最优算法。如果 n 很大且链表无序，同时又严格禁止额外集合，O(n²) 是需要明确说出的时间代价；不能只强调 O(1) 空间而忽略性能。

## 常见追问

- 问：为什么不用快慢指针一次做完？答：无序链表里同值节点可能相隔很远；没有额外集合就无法只看局部状态判断某个值是否还会再次出现，所以一般需要重复扫描。
- 问：如果链表已经排序呢？答：相同值连续，可以用 dummy + 双指针按重复段扫描，一次 O(n) 删除整段重复值。
- 问：如果“重复”只是想保留第一个呢？答：内层发现同值时删除后续重复即可，处理完后保留 `current`；那是另一份输出契约。
- 问：为什么测试 oracle 可以用 Map？答：限制针对解题实现。测试需要一个独立、容易证明正确的参考实现来验证 solution；只要正式解法不依赖 Map/Set，就没有绕过题目约束。
- 问：算法会改变输入链表吗？答：会，本契约原地重连 `next`。如果要求输入不可变，就必须新建节点，空间语义也会改变。

## 易错点

- 默认链表有序，写 O(n) 连续段算法，却没有任何来源依据。
- 把“删除所有重复值”和“去重保留一个”混成同一个问题。
- 内层删除节点后仍然推进 `runnerPrev`，导致跳过连续待检查节点。
- 删除当前头结点时没有 dummy，产生大量 head 特判或断链。
- 宣称 O(1) 额外空间却偷偷把所有值复制到数组、Map 或 Set。
