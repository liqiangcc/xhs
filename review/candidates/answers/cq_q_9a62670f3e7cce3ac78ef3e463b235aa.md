# 最大无重复子串长度：滑动窗口

## 核心结论

来源明确要求：给定字符串，找出不包含重复字符的最大无重复子串长度，并使用滑动窗口。这里补充一个可执行 Java 契约：`null` 和空串返回 `0`；“字符”按 Java `char`（UTF-16 code unit）计数，返回长度也是 `char` 数量。这个 UTF-16 口径是候选实现的显式约定，不是来源原文额外给出的条件；如果题目要求 Unicode code point 或 grapheme cluster 语义，状态表示必须调整。

维护左边界 `left` 和每个字符最近一次出现的位置 `lastSeen`。右指针 `right` 每次向右移动一格；若当前字符以前出现在当前窗口内，就把 `left` 一次跳到“上次位置 + 1”。随后窗口 `[left, right]` 一定无重复，更新最大长度即可。每个位置只被右指针处理一次，左边界只单调前进，因此时间 `O(n)`；映射空间最多是不同 `char` 的数量。

## 1 分钟版

- `left` 表示当前无重复窗口的左端点，`right` 从左到右扫描。
- `lastSeen[c]` 记录字符 `c` 最近一次出现的下标。
- 如果 `c` 上次出现位置 `p >= left`，说明重复发生在当前窗口中，直接令 `left = p + 1`。
- 不能让 `left` 后退，所以通用写法是 `left = Math.max(left, p + 1)`。
- 更新 `lastSeen[c] = right`，当前窗口长度是 `right - left + 1`。
- 扫描结束返回最大窗口长度，时间 `O(n)`。

## 3 分钟版

```java
static int longestUniqueSubstring(String s) {
    if (s == null || s.isEmpty()) return 0;

    Map<Character, Integer> lastSeen = new HashMap<>();
    int left = 0;
    int best = 0;

    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        Integer previous = lastSeen.get(c);
        if (previous != null) {
            left = Math.max(left, previous + 1);
        }
        lastSeen.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

例如 `abba`：扫描第二个 `b` 时，左边界从 `0` 跳到 `2`；随后扫描最后一个 `a`，它上次出现在下标 `0`，已经落在当前窗口左侧，所以 `Math.max(left, 0 + 1)` 仍保持 `left = 2`。如果错误地直接写成 `left = previous + 1`，左边界会退回 `1`，窗口重新包含重复的 `b`，这正是常见 bug。

## 关键细节

- **窗口不变量**：每轮更新结束后，`s[left..right]` 内没有重复 `char`；这是证明正确性的核心。
- **为什么记录最近位置**：只用 `Set` 时遇到重复需要逐个移动左指针并删除；记录最后位置可以把左边界直接跳过冲突字符。两种都能做到线性复杂度，但索引表写法更直接。
- **左边界不能后退**：旧重复如果已经在窗口外，不应影响当前窗口，所以用 `Math.max(left, previous + 1)`。
- **何时更新答案**：先处理冲突并得到合法窗口，再用 `right - left + 1` 更新 `best`。
- **空值契约**：来源没有说明 `null`；这里显式选择 `null -> 0`。如果接口规范要求拒绝 `null`，可改为抛异常。
- **字符语义**：Java `char` 是 UTF-16 code unit。某些 Unicode 字符由 surrogate pair 组成；若业务定义的“字符”是 code point，应改用 `s.codePoints()` 或按 code point 下标维护窗口。
- **空间复杂度**：`HashMap` 中最多保存扫描过的不同 `char`；可写作 `O(min(n, Σ))`，其中 `Σ` 是候选字符域大小。

## 原理机制

暴力做法会枚举很多重叠子串并重复检查。滑动窗口利用了“只要当前窗口无重复，右边再加入一个字符时，唯一可能的新冲突就是这个新字符与窗口内它最近一次出现的位置”。因此不需要重新检查整个窗口，只需要知道这个字符上次在哪。

当 `previous >= left` 时，任何以当前 `right` 结尾、又包含 `previous` 的子串都会重复当前字符；所以新的合法窗口左端至少必须到 `previous + 1`。直接跳到那里不会漏掉更优解，因为所有更靠左的候选都已经不合法。若 `previous < left`，旧出现已经不在当前窗口内，保持 `left` 不动即可。

## 项目经验版

来源没有真实项目背景，不能虚构线上使用经历。落地时我会先确认“字符”的业务定义：ASCII、UTF-16 code unit、Unicode code point 还是用户感知字符；还会确认 `null`、超长输入和内存约束。算法框架仍是滑动窗口，但索引单位必须和业务字符语义一致。

## 常见追问

- 问：为什么是 `Math.max(left, previous + 1)`？答：因为 `previous` 可能已经落在当前窗口左侧；左边界只应向前，不能被历史位置拉回去。
- 问：能用 `Set` 吗？答：可以。遇到重复时不断删除 `s[left]` 并右移 `left`，直到冲突消失；每个字符最多进出集合一次，所以也是 `O(n)`。
- 问：为什么用最近一次位置而不是第一次位置？答：要消除当前冲突，真正限制左边界的是当前字符在窗口内最靠右的上次出现位置，旧得更早的位置已经被它覆盖。
- 问：`abba` 为什么能暴露 bug？答：最后一个 `a` 的历史位置在当前窗口外；若让 `left` 回退，会把两个 `b` 同时纳入窗口，破坏无重复不变量。
- 问：中文和 emoji 怎么办？答：普通 BMP 中文字符通常一个 `char`，但 emoji 等可能由 surrogate pair 组成。本候选按 `char` 计数；若题意按 Unicode code point，应改写索引单位。
- 问：时间复杂度为什么不是 `O(n^2)`？答：右指针只前进 `n` 次，索引表查询和更新按哈希表预期 `O(1)` 计；左边界只单调前进，没有嵌套回扫。

## 易错点

- 看到历史重复就直接 `left = previous + 1`，导致左边界后退。
- 更新最大长度前没有先修复重复窗口。
- 把“子串”误写成“子序列”；滑动窗口维护的是连续区间。
- 只说 `O(n)`，却解释不清窗口不变量和为什么不会漏掉最优解。
- 默认把 Java `char` 当成所有 Unicode 用户感知字符，却没有声明字符语义。
- 来源要求滑动窗口，却改成与题意不一致的全量子串枚举。
