# 判断树 B 是否是树 A 的子结构

## 核心结论

仓库原始来源明确写的是“输入两颗二叉树，判断 B 是否是 A 的子结构”，但没有规定空树语义、节点值类型、返回 API 或语言。这里显式采用候选契约：节点值为 `int`；按节点值相等判断；`B == null` 不算 A 的子结构；返回 `boolean`；算法不修改两棵树。

做法分两层：先在 A 中枚举可能与 B 根值相等的起点，再从该起点递归匹配 B。匹配时只要求 B 中存在的结构和值都在 A 中对应一致；当 B 的某个分支先到 `null` 时就说明该分支已经完整匹配，不要求 A 对应位置也为空。因此这是“子结构”而不是“完全相同子树”。最坏时间复杂度可写成 `O(|A| * |B|)`，递归栈最坏 `O(hA + hB)`。

## 1 分钟版

我会把问题拆成“找起点”和“从起点匹配”两步。

第一步遍历 A 的每个节点，把它当成 B 根的候选起点；第二步 `match(a, b)`：如果 `b == null`，说明 B 这一支已经匹配完成，返回 true；如果 `a == null` 或值不同，返回 false；否则继续同时匹配左右子节点。

关键是 `b == null` 时直接成功，而不是要求 `a == null`。这样 A 可以在 B 已经结束的位置继续有额外子节点，符合“B 是 A 的子结构”。当前候选还明确规定空 B 不算子结构，避免把未说明的空树规则冒充成原题事实。

## 3 分钟版

原始题源已经给出了两个输入树和“子结构”判断目标，所以算法主体可恢复；不能从来源恢复的是空 B 是否算子结构、值类型和具体语言接口，因此这些必须明确标为候选约定。

外层 `isSubstructure(A, B)` 负责在 A 上搜索可能起点。只要当前 A 节点能与 B 根开始匹配，或者 B 能在 A 的左/右子树中找到起点，就返回 true。内层 `matchesFrom(a, b)` 的不变量是：它判断“以当前 a 为根的 A 片段，是否覆盖了以 b 为根的 B 全部结构和值”。所以当 `b == null` 时，B 需要验证的结构已经耗尽，应该成功；反过来，当 `a == null` 但 `b != null` 时，A 不足以覆盖 B，必须失败。

这也解释了为什么不能直接用“两个子树完全相等”的比较函数：例如 A 的某个节点有额外左孩子，而 B 在对应位置没有孩子，B 仍然可以是 A 的子结构。

## 关键细节

- **题源边界**：来源支持“两棵二叉树 + B 是否为 A 子结构”；`int` 值、空 B 为 false、Java API 和不修改输入是显式候选选择。
- **值相等语义**：当前节点只按 `int value` 比较，不用节点身份。
- **子结构不是相同子树**：B 的分支结束后，A 可以继续有额外后代。
- **空树规则**：当前候选定义 `B == null` 为 false；若业务或题目另有定义，应改契约而不是偷偷改实现。
- **重复值**：A 中可能有多个与 B 根同值的节点，所以不能只尝试第一个命中点。
- **复杂度**：最坏每个 A 节点都触发一次近似完整 B 匹配，因此最坏 `O(|A|*|B|)`；典型情况下值不等会提前剪枝。
- **递归深度**：外层搜索和内层匹配都受树高影响，极深退化树应考虑显式栈。
- **可验证性**：9 组固定边界用例加 5000 组确定性随机树，与独立的“枚举 A 所有根 + 朴素匹配”oracle 比较，并序列化前后结构确认无修改。

## 原理机制

```java
public static boolean isSubstructure(Node a, Node b) {
    if (a == null || b == null) {
        return false;
    }
    return matchesFrom(a, b)
            || isSubstructure(a.left, b)
            || isSubstructure(a.right, b);
}

private static boolean matchesFrom(Node a, Node b) {
    if (b == null) {
        return true;
    }
    if (a == null || a.value != b.value) {
        return false;
    }
    return matchesFrom(a.left, b.left) && matchesFrom(a.right, b.right);
}
```

测试使用与生产实现不同的外层组织方式作为 oracle：先完整收集 A 中的所有节点，再逐个调用朴素结构匹配；固定用例覆盖双空、单边空、单节点、标准子结构命中、不匹配、重复根值、根节点单点匹配，以及 A 含额外分支但 B 仍应匹配的情况；随后生成 5000 组随机树做差分。预检输出：

```text
PASS fixed=9 randomized=5000 oracle=enumerate-roots-and-match emptyB=false mutation=none
```

## 常见追问

- **子结构和相同子树的核心差别是什么？** 子结构只要求 B 已有的节点和值在 A 中对应存在；B 到 `null` 后不要求 A 也到 `null`。相同子树则通常要求两边结构完整一致。
- **为什么外层要继续搜索 A 的左右子树？** 因为 B 的根不一定对应 A 的根，而且 A 中可能有多个相同值的候选起点。
- **空 B 为什么返回 false？** 这是当前候选明确选择的边界，不是原始来源给出的事实；若题目定义空树为任意树的子结构，应改为相应语义。
- **重复值会不会导致错误？** 不会，只会增加候选起点；每个候选都必须继续验证完整 B 结构。
- **能否优化最坏复杂度？** 对一般值树，先按根值建立候选索引可减少起点扫描，但每个候选仍需要结构匹配；是否值得取决于是否对同一 A 执行大量查询。

## 易错点

- 用完全相同子树判断，错误要求 B 结束处 A 也必须结束。
- 只在 A 根检查一次，不继续向左右子树寻找候选起点。
- 看到第一个同值节点匹配失败就直接返回 false，漏掉后续重复值候选。
- 没有声明空 B 的规则，却把某一种定义说成题源事实。
- 为匹配方便修改树结构，造成输入副作用。
