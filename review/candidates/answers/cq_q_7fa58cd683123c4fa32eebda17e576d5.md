# 链表相加：两个逆序数字链表求和

## 核心结论

题目给出两个非空链表表示两个非负整数，并说明各位按逆序存储。最直接的不变量是：从低位到高位同步遍历两个链表，当前位置只需要处理 `当前两位 + 上一位进位`；输出链表也按同样的逆序逐位追加。某个链表先结束后把缺失位当作 0，最后如果仍有进位再追加一个节点。

下面采用一个明确且最小的实现约定：每个节点的 `val` 表示一个十进制数位，节点定义为 `ListNode(int val, ListNode next)`。题目没有给具体 Java 节点类型时，面试现场把字段名替换为真实定义即可。

## 1 分钟版

- 两个数字都是低位在前，因此可以从两个头节点直接开始相加，不需要先反转链表。
- 每轮取 `a`、`b` 当前节点值；链表已经结束时该位视为 0。
- `sum = a + b + carry`，当前结果位是 `sum % 10`，下一位进位是 `sum / 10`。
- 用虚拟头节点 `dummy` 统一追加结果，避免单独处理第一位。
- 循环条件必须覆盖三个来源：`l1 != null || l2 != null || carry != 0`，否则会漏掉最高位进位。
- 若两个链表长度分别为 `m`、`n`，时间复杂度 `O(max(m,n))`；新结果链表占 `O(max(m,n))` 空间，除结果外只用 `O(1)` 辅助变量。

## 3 分钟版

```java
public final class LinkedListAdd {
    static final class ListNode {
        int val;
        ListNode next;

        ListNode(int val) {
            this(val, null);
        }

        ListNode(int val, ListNode next) {
            this.val = val;
            this.next = next;
        }
    }

    static ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        int carry = 0;

        while (l1 != null || l2 != null || carry != 0) {
            int a = l1 == null ? 0 : l1.val;
            int b = l2 == null ? 0 : l2.val;
            int sum = a + b + carry;

            tail.next = new ListNode(sum % 10);
            tail = tail.next;
            carry = sum / 10;

            if (l1 != null) l1 = l1.next;
            if (l2 != null) l2 = l2.next;
        }

        return dummy.next;
    }
}
```

例如 `2 -> 4 -> 3` 表示 342，`5 -> 6 -> 4` 表示 465：第一位 `2+5=7`，第二位 `4+6=10` 输出 0 并进 1，第三位 `3+4+1=8`，结果 `7 -> 0 -> 8`，即 807。

## 关键细节

- **为什么无需反转**：输入已经按个位、十位、百位……顺序排列，正好与小学竖式加法从低位向高位传播进位的方向一致。
- **长度不同**：较短链表耗尽后，不要停止；其后续位按 0 处理，继续遍历较长链表。
- **最终进位**：如 `9 -> 9` 加 `1`，处理完已有节点后仍有 `carry=1`，必须再生成最后一个节点。
- **输入修改**：实现只移动局部指针，不修改输入节点的 `val` 或 `next`；结果链表全部新建。
- **数值溢出**：不把整个链表转换成整数，因此数字位数可以超过 Java 基本整数类型；每轮只计算两位和一个进位。
- **节点值契约**：这里按十进制单个数位实现。如果真实题目允许节点值超出 `0..9`，必须先重新定义表示法，不能继续套用 `% 10`/`/ 10`。

## 原理机制

把两个链表看成按位展开的十进制表示。第 `i` 轮开始时，不变量是：结果链表已经正确保存了低于第 `i` 位的所有和，并且 `carry` 精确表示这些低位向第 `i` 位产生的进位。第 `i` 轮只依赖两个输入的第 `i` 位和这个 `carry`，计算出的 `sum % 10` 因而就是第 `i` 位结果，`sum / 10` 则成为下一轮唯一需要保留的跨位状态。循环结束时两个输入都耗尽且 `carry=0`，不变量就推出整个结果正确。

这种写法不需要额外栈、数组或大整数，因为“逆序存储”已经把数据方向和进位方向对齐；这正是题目表示方式带来的简化。

## 项目经验版

这是纯算法题，来源没有提供真实项目背景，因此不虚构生产经历。若把相同思路映射到工程问题，核心仍是流式处理：只保留当前元素和一个有限状态 `carry`，避免把完整大整数物化到固定宽度数值类型中。真实系统若存在非十进制、负数、校验位或持久化节点等规则，应先把这些表示约束写进契约再实现。

## 常见追问

- 问：为什么循环条件里要包含 `carry != 0`？答：已有节点全部处理完后仍可能产生新的最高位，例如 99 + 1；只判断两个链表会漏掉这个节点。
- 问：能不能先把链表转成 `long` 再相加？答：不通用，链表长度没有被题目限制在机器整数范围内；逐位相加不会有整型整体溢出问题。
- 问：两个链表长度不同怎么办？答：耗尽的一侧当前位视为 0，继续处理另一侧和进位。
- 问：为什么用虚拟头节点？答：它把第一节点和后续节点的追加逻辑统一成 `tail.next = ...`，减少分支。
- 问：如果题目改成高位在前怎么办？答：当前遍历方向就与进位方向相反，需要先反转、使用栈，或采用其他从低位获得数据的方案；不能直接复用本实现。
- 问：可以复用输入节点降低分配吗？答：可以设计原地版本，但会改变输入并增加别名/尾节点处理复杂度；来源没有要求原地，因此这里选择语义更清晰的新建结果链表。

## 易错点

- 看到“链表表示数字”就先转整数，忽略任意长度导致的溢出。
- 输入已经逆序却又额外反转，增加不必要复杂度。
- 较短链表结束时直接退出，遗漏较长链表剩余位。
- 循环结束后忘记最高位进位。
- 复用输入节点却没有说明会修改输入，造成副作用边界不清。
- 没有先确认每个节点是否真的是单个十进制数位，就机械使用 `% 10`。
