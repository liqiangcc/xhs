# 整数拆分：拆成至少两个正整数后乘积最大值

## 核心结论

题目给定 `2≤n≤53`，要求把 `n` 拆成 `k≥2` 个正整数之和并最大化乘积。动态规划可以直接刻画“必须发生拆分”这一约束：令 `dp[i]` 表示整数 `i` 至少拆一次后的最大乘积；枚举第一段 `j`，剩余 `i-j` 可以选择不再拆，也可以继续按 `dp[i-j]` 拆，因此转移是 `dp[i] = max(dp[i], j*(i-j), j*dp[i-j])`。答案为 `dp[n]`，时间 O(n²)，空间 O(n)。

## 1 分钟版

- `dp[i]` 的语义必须写清楚：`i` **至少拆成两个正整数**后的最大乘积，所以不能让 `dp[i]=i` 作为合法最终答案。
- 枚举第一段 `j∈[1,i-1]` 后，剩余的 `i-j` 有两种合法选择：到此为止，乘积 `j*(i-j)`；或者继续拆，乘积 `j*dp[i-j]`。
- 两种选择都要比较，否则会漏掉“剩余部分不拆反而更大”的小数值情形。
- 初始 `dp[2]=1`；按 `i=2..n` 递推即可。
- `n≤53` 时最大值为 `258280326`，Java `int` 也够；实现用 `long` 让乘法边界更直观。

## 3 分钟版

```java
public final class Solution {
    public long integerBreak(int n) {
        if (n < 2 || n > 53) {
            throw new IllegalArgumentException("n must be in [2, 53]");
        }

        long[] dp = new long[n + 1];
        for (int i = 2; i <= n; i++) {
            for (int j = 1; j < i; j++) {
                long stop = (long) j * (i - j);
                long keepSplitting = (long) j * dp[i - j];
                dp[i] = Math.max(dp[i], Math.max(stop, keepSplitting));
            }
        }
        return dp[n];
    }
}
```

例如 `n=10`：最优拆法可得到 `3+3+4`，乘积 `36`。DP 不需要提前知道应该拆成几个数，也不依赖“尽量拆 3”的数学结论；它在每个切分点同时比较停止和继续拆，最终覆盖所有合法拆分。

## 关键细节

- **至少拆一次**：`n=2` 必须得到 `1*1=1`，不能返回 2；这也是 `dp` 语义是否正确的最小测试。
- **为什么有 `j*(i-j)`**：`dp[i-j]` 自带“必须拆”的语义，但全局只要求 `i` 至少拆一次。第一刀已经满足约束，所以剩余部分可以保持完整。
- **为什么有 `j*dp[i-j]`**：剩余部分继续拆可能得到更大乘积，例如 10 的最优解不只是一刀两段。
- **正整数约束**：循环 `j=1..i-1`，两边始终大于 0，不会引入 0 或负数。
- **复杂度**：外层 `n` 个状态，每个状态枚举 O(n) 个第一段，时间 O(n²)；`dp` 数组 O(n)。
- **数值范围**：本题上界 53 的数学最优值是 `3^17*2 = 258280326`，小于 `Integer.MAX_VALUE`；`long` 仍可避免推导变化时过早绑定返回范围。

## 原理机制

这道题的最优子结构来自“第一刀之后，剩余整数的最优处理方式只取决于剩余值本身”。对固定 `j`，剩余部分有两个分支：不拆，值就是 `i-j`；继续拆，最优值就是已经求出的 `dp[i-j]`。因此当前最优值可以从更小整数的最优值递推得到。

也可以从数学上证明最优拆分最终只需要 2 和 3，并优先使用 3；但面试手写时 DP 更直接对应题意、边界更容易验证。若追求 O(1) 额外空间和 O(1) 计算，再使用数学分解并单独证明为什么 3 最优、余数 1 要改成 2+2。

## 项目经验版

来源是纯算法题，没有真实项目数据，不能虚构项目经历。可迁移的工程思路是：当问题含“至少做一次操作”之类约束时，要把它编码进状态语义，而不是靠最后补一个特殊判断；否则状态可能把原值这种非法方案混入最优值。

## 常见追问

- 问：为什么不能直接写 `dp[i]=max(j,dp[j])*max(i-j,dp[i-j])`？答：可以，但必须明确两侧“拆或不拆”的语义，并保证当前 `i` 已经发生了这一刀。本文固定第一段 `j` 不再拆，只让右侧选择，状态更少且仍遍历所有有序第一刀。
- 问：为什么 `dp[1]` 可以是 0？答：状态只定义“至少拆一次后的最大乘积”，1 没有合法拆分；转移中的“剩余不拆”由 `i-j` 本身承担，不依赖 `dp[1]`。
- 问：`n=3` 为什么答案是 2 不是 3？答：必须 `k≥2`，3 不能保持原样；`1+2` 的乘积 2 最大。
- 问：能否做到 O(n) 或 O(1)？答：用数学结论可直接按 3 分解做到 O(1) 计算，但需要额外证明。DP 是 O(n²)，在 `n≤53` 下非常小且更容易现场解释正确性。
- 问：为什么余数 1 时数学法不能继续保留一个 1？答：`3*1 < 2*2`，因此应把一个 3 和余下的 1 合并改成 2+2；这也是数学法的关键边界。

## 易错点

- 把 `dp[i]` 定义成“可拆可不拆”的最大值，然后直接返回 `dp[n]`，导致 `n=2/3` 返回原值。
- 只比较 `j*dp[i-j]`，忘记第一刀后剩余部分允许不再拆。
- 循环允许 `j=0` 或 `j=i`，违反正整数拆分。
- 数学法机械“全拆 3”，没有处理余数 1 的 `2+2` 修正。
- 只给一个样例，不验证 `n=2/3`、上界 53 和 DP 与独立枚举/数学解的一致性。
