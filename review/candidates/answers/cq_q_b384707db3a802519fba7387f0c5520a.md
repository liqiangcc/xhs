# 两个 int 不使用第三个变量如何交换？

## 核心结论

来源只要求“两个 int 型数，不使用第三个变量交换”，没有冻结语言。最直接的位运算做法是 XOR swap：`a ^= b; b ^= a; a ^= b;`。它利用 `x ^ x = 0`、`x ^ 0 = x` 和异或的交换/结合律，在三个赋值后让 `a`、`b` 互换；不会产生加减法的算术溢出问题。下面用 Java `int` 作为可执行参考契约。实际工程代码若没有“禁止临时变量”的约束，通常更推荐临时变量写法，因为更直观，也没有同一存储位置上的 XOR 自交换陷阱。

## 1 分钟版

```text
a = a ^ b
b = a ^ b   // = (old_a ^ old_b) ^ old_b = old_a
a = a ^ b   // = (old_a ^ old_b) ^ old_a = old_b
```

Java 可以直接写成：

```java
a ^= b;
b ^= a;
a ^= b;
```

三步之后 `a` 得到原来的 `b`，`b` 得到原来的 `a`。时间 O(1)，额外空间 O(1)。

## 3 分钟版

为了让代码可测试，下面把两个可变 `int` 字段包在一个 `Pair` 中；交换步骤本身只读写这两个字段，没有第三个 `int` 临时变量：

```java
public final class Solution {
    private Solution() {}

    public static final class Pair {
        public int a;
        public int b;

        public Pair(int a, int b) {
            this.a = a;
            this.b = b;
        }
    }

    public static void swapNoTemp(Pair pair) {
        pair.a ^= pair.b;
        pair.b ^= pair.a;
        pair.a ^= pair.b;
    }
}
```

设初值为 `A`、`B`。第一步后 `a=A^B`；第二步 `b=(A^B)^B=A`；第三步 `a=(A^B)^A=B`。所以最终正好交换。Java 的 `^` 对 `int` 做逐位异或，不涉及有符号加减溢出。

## 关键细节

- **不依赖数值范围**：`Integer.MIN_VALUE`、`Integer.MAX_VALUE`、负数、0 都可以按同一位运算规则交换。
- **两个独立变量没有别名问题**：题目说的是两个 `int` 变量；若把技巧搬到数组/指针并让两个操作数实际上指向同一个存储位置，连续 XOR 会把值清成 0，所以这种扩展必须先保证两个 lvalue 不同。
- **不要把加减法版本当成无条件通用答案**：`a=a+b; b=a-b; a=a-b;` 在部分语言/编译语义下会遇到整数溢出风险；XOR 没有这个算术问题。
- **Java 方法参数是值传递**：不能写 `swap(int a,int b)` 就期待调用者的两个局部变量被原地修改，因此可执行示例用一个可变 `Pair` 承载两个字段；面试纸笔题通常只需要展示三条赋值。
- **可读性优先**：没有题目限制时，生产代码更推荐 `int tmp=a; a=b; b=tmp;`。面试题的价值主要是验证位运算等式，不代表 XOR swap 是日常最佳实践。

## 原理机制

XOR 可以看成每一位上的模 2 加法。第一步把两个原值的信息合并到 `a=A^B`；因为同一个值再异或一次会抵消，第二步用合并值和 `B` 恢复 `A`，第三步再用合并值和已经恢复出的 `A` 恢复 `B`。整个过程只需要两个原有存储位置。

## 常见追问

- 问：两个数相等还能交换吗？答：可以。两个独立变量都为 `x` 时第一步 `a` 变 0，第二步 `b` 恢复为 `x`，第三步 `a` 也恢复为 `x`。
- 问：负数可以吗？答：可以，`int` 的位模式同样参与逐位 XOR，符号位没有特殊例外。
- 问：为什么不推荐加减法交换？答：它依赖语言的整数溢出语义；XOR 不做算术加减，更适合回答这个“无第三变量”的抽象问题。
- 问：为什么实际项目不常用 XOR swap？答：临时变量版本更容易读、审查和维护；现代编译器也不需要程序员靠 XOR swap 来做这种微优化。
- 问：数组同一个下标能直接 XOR swap 吗？答：不能照搬；如果两个表达式是同一存储位置，第一步就会把值异或成 0。先判断位置不同，或直接使用普通临时变量交换。

## 易错点

- 把 `a ^= b ^= a ^= b` 之类压成一行，依赖求值顺序并降低可读性。
- 忽略同一存储位置的 XOR 自交换问题。
- 说“加减法一定安全”，没有区分语言的整数溢出语义。
- 在 Java 中写一个 `swap(int a,int b)` 并误以为能修改调用者局部变量。
- 把面试技巧宣传成生产代码首选，而不说明可读性代价。
