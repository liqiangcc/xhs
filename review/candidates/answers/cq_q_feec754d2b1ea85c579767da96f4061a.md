# 算法手撕：二叉树之字形层序遍历

## 核心结论

原始面经明确写的是“算法题，之字形打印二叉树”，因此答案可以直接按二叉树 Zigzag Level Order 来准备：第 0 层从左到右，第 1 层从右到左，之后逐层交替。最稳妥的实现是在普通 BFS 层序遍历上增加一个方向位；队列始终按左孩子、右孩子入队，只改变当前层值写入结果的位置。这样每个节点只进队、出队一次，时间 `O(n)`，队列和结果暂存的额外空间最坏 `O(n)`。

## 1 分钟版

- 用队列做 BFS，因为题目要求按“层”输出。
- 每层开始先记录 `levelSize = queue.size()`，这能把当前层与下一层严格分开。
- 准备长度为 `levelSize` 的数组：
  - 左到右层把第 `i` 个出队节点写到 `i`；
  - 右到左层写到 `levelSize - 1 - i`。
- 子节点始终按 `left`、`right` 顺序入队，遍历语义保持普通层序；只改变输出位置，不改变下一层节点顺序。
- 当前层结束后翻转方向位。
- 每个节点处理一次，时间 `O(n)`；最宽一层的队列最多 `O(n)`。

## 3 分钟版

这题的关键不是“真的让队列一层向左、一层向右移动”，而是把**遍历顺序**和**输出顺序**拆开。BFS 队列只负责保证节点按层被访问，并按固定的左孩子、右孩子顺序维护下一层。之字形要求只作用在当前层输出，因此更简单的做法是在本层的结果数组中决定写入下标。

```java
public final class ZigzagLevelOrder {
    private ZigzagLevelOrder() {}

    public static final class TreeNode {
        public final int val;
        public TreeNode left;
        public TreeNode right;

        public TreeNode(int val) {
            this.val = val;
        }
    }

    public static List<List<Integer>> traverse(TreeNode root) {
        List<List<Integer>> result = new ArrayList<>();
        if (root == null) {
            return result;
        }

        ArrayDeque<TreeNode> queue = new ArrayDeque<>();
        queue.addLast(root);
        boolean leftToRight = true;

        while (!queue.isEmpty()) {
            int levelSize = queue.size();
            Integer[] level = new Integer[levelSize];

            for (int i = 0; i < levelSize; i++) {
                TreeNode node = queue.removeFirst();
                int targetIndex = leftToRight ? i : levelSize - 1 - i;
                level[targetIndex] = node.val;

                if (node.left != null) {
                    queue.addLast(node.left);
                }
                if (node.right != null) {
                    queue.addLast(node.right);
                }
            }

            result.add(new ArrayList<>(Arrays.asList(level)));
            leftToRight = !leftToRight;
        }

        return result;
    }
}
```

典型样例 `[3,9,20,null,null,15,7]` 输出 `[[3],[20,9],[15,7]]`；空树输出 `[]`，单节点树输出 `[[1]]`。仓库验证还覆盖完全二叉树、退化链和重复值，并用一个结构不同的 DFS oracle 先按深度收集、再反转奇数层，与 BFS 实现在固定随机种子的 3000 棵随机树上逐一对比，结果一致。

## 关键细节

- 原始面经已经明确到“之字形打印二叉树”，无需从模糊题干臆造别的算法；LeetCode 103 仅作为公开、可复核的同型题契约参考。
- `levelSize` 必须在处理本层之前冻结。如果循环条件直接依赖不断增长的 `queue.size()`，会把下一层节点混进当前层。
- 队列中的孩子仍固定按左、右入队。若同时反转入队顺序和结果顺序，很容易在下一层产生双重反转错误。
- 使用固定长度数组按目标下标写入是 `O(1)`；不要在 `ArrayList` 头部反复 `add(0, value)`，那会产生搬移成本。
- 空树直接返回空列表；单节点、单边退化树的每层只有一个值，方向翻转不影响结果。
- 如果接口要求流式打印而不是返回二维列表，可以把本层值先放入 deque，再按方向输出；核心仍是“层边界 + 方向位”。

## 原理机制

BFS 的队列不变量是：每次进入外层循环时，队首连续的 `levelSize` 个元素恰好属于同一深度。处理它们时，把孩子追加到队尾，所以这些孩子只会在下一轮被消费。

之字形只改变同一深度内的展示顺序。设本层节点按普通 BFS 被取出的次序是 `0..levelSize-1`：左到右时目标下标就是 `i`；右到左时目标下标是 `levelSize-1-i`。两种映射都是一一对应，因此既不会丢节点也不会重复节点，同时不干扰队列对下一层的维护。

## 项目经验版

这是算法题，不应包装成虚构项目经历。面试时更有价值的是说明为什么“固定 BFS + 改输出位置”比“切换队列方向”更容易维护不变量，并用 DFS 作为独立 oracle 做随机差分验证，证明方向切换没有破坏层边界。

## 常见追问

- 问：为什么适合 BFS？答：输出天然按深度分组，BFS 的队列可以直接用当前 `size` 冻结一层的边界。
- 问：可以用 DFS 吗？答：可以。递归时带 `depth`，按深度收集到二维列表，再把奇数层反转；但 BFS 对“逐层输出”更直接，也避免深树递归栈风险。
- 问：为什么不每个奇数层最后调用 `Collections.reverse`？答：也正确，复杂度仍是 `O(n)`；按目标下标写入少一次显式反转，并把方向规则集中在单个下标表达式里。
- 问：双端队列能做吗？答：能，但如果连节点扩展方向也交替，边界更容易写错。固定 BFS 队列、只改变输出通常更容易证明。
- 问：空间复杂度为什么是 `O(n)`？答：最坏情况下某一层可包含线性数量的节点，队列与该层输出都可能达到 `O(n)`。

## 易错点

- 没有在层开始时冻结 `queue.size()`，导致层边界混乱。
- 奇数层既反转输出又反转孩子入队顺序，造成双重反转。
- 用 `ArrayList.add(0, value)` 反复头插，隐藏了不必要的线性搬移。
- 空树没有提前返回，向不接受 `null` 的队列写入空节点。
- 只测完全树，不测退化树、重复值和空树。
