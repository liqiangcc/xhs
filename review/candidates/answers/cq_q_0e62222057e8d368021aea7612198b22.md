# 旋转字符串——先澄清题意，再把轮转关系化成子串关系

## 核心结论

仓库恢复出的原题只有一句“算法：旋转字符串”，没有给参数、返回值、样例或约束。因此不能把更完整的题面伪装成原始面试记录。这个名字常见的标准解释是 LeetCode 796 `Rotate String`：给定 `s` 和 `goal`，每次把 `s` 最左字符移到最右边，判断若干次移动后能否得到 `goal`。如果面试官实际问的是“把字符串左旋 k 位并返回结果”，那是另一份契约，需要先确认。

按“判断两个字符串是否互为轮转”的解释，核心性质是：若 `s = xy`，一次合适的轮转得到 `yx`，而 `s + s = xyxy` 一定包含 `yx`；反过来，长度相同的 `goal` 若出现在 `s + s` 中，它的起点对应 `s` 的某个切分位置，所以它就是 `s` 的某次循环轮转。

因此最简答案是：

```java
return s.length() == goal.length() && (s + s).contains(goal);
```

这行代码表达了正确的数学归约。若面试官进一步要求**可证明的线性最坏复杂度**，不要把 `String.contains/indexOf` 的具体实现复杂度当作语言规范保证；可以在“虚拟的 `s+s`”上用 KMP 搜索 `goal`，得到 `O(n)` 时间、`O(n)` 辅助空间，并且不必真的构造双倍字符串。

## 1 分钟版

我先确认题意：这里的“旋转字符串”是判断 `s` 能否通过不断把首字符移到末尾得到 `goal`，还是要输出左旋 k 位后的新字符串？原记录没有参数，所以这一步不能省。

如果是前者，先检查长度；长度不同一定不是轮转。长度相同时，把 `s` 写成 `xy`，任意轮转就是 `yx`。因为 `s+s = xyxy`，其中必然包含 `yx`。所以可以判断 `goal` 是否是 `s+s` 的子串。

例如 `s="abcde"`、`goal="cdeab"`，`s+s="abcdeabcde"`，里面能找到 `cdeab`，因此返回 true；`goal="abced"` 找不到，返回 false。

工程化实现里我会明确 null/空串契约。标准 LeetCode 796 约束字符串非空；如果把函数做成通用库，我可以定义两个空串互为零次轮转，null 直接失败。

## 3 分钟版

### 为什么 `s+s` 能覆盖全部轮转

设长度为 `n`，从位置 `k` 切开：

```text
s = prefix + suffix
rotation = suffix + prefix
```

而：

```text
s + s = prefix + suffix + prefix + suffix
                  └──── suffix + prefix ────┘
```

所以每个合法轮转都会作为长度为 `n` 的窗口出现在 `s+s` 里。

反方向也成立：如果 `goal` 长度也是 `n`，并且它从 `s+s` 的某个位置开始连续出现，那么把起点对 `n` 取模，就得到原字符串的一个切分位置；这个长度为 `n` 的窗口正是该切分后的循环顺序。因此“等长 + 是 `s+s` 子串”与“互为轮转”等价。

### 简洁解法和复杂度边界

直接写 `(s+s).contains(goal)` 最适合先表达思路。构造双倍字符串需要 `O(n)` 额外空间。至于子串搜索的最坏时间，不能只因为代码短就宣称 Java 规范保证 `O(n)`；如果题目明确要求最坏线性，我会改用 KMP。

KMP 对 `goal` 预处理 LPS（最长相等真前后缀），然后扫描长度 `2n` 的虚拟文本，第 `i` 个字符直接取 `s.charAt(i % n)`。失配时按 LPS 回退，不回退文本指针，因此预处理和扫描都是线性，总时间 `O(n)`、LPS 空间 `O(n)`。

### 为什么必须先比长度

没有长度检查会产生假阳性。例如 `s="abc"`，`goal="bc"` 是 `s+s` 的子串，但删除字符不是旋转操作，所以不能判 true。轮转不会改变字符数，等长是必要条件。

## 关键细节

- **来源边界**：仓库原题只写“算法：旋转字符串”；`s/goal`、逐次左移、长度限制等来自同名标准题 LeetCode 796，而不是本地面试记录逐字信息。
- **歧义处理**：中文“旋转字符串”也可能指“给定 k，返回左旋 k 位结果”。遇到真实面试必须根据入参/样例确认，不能自作主张。
- **零次操作**：若 `s.equals(goal)`，当然应该为 true；“some number of shifts”包含无需改变即可相等的情形。
- **长度不等**：必须立即 false。
- **空串**：标准 796 的约束是长度至少 1；通用实现若允许空串，可自然定义 `""` 与 `""` 为 true。
- **null**：算法题平台通常不传 null；生产函数则应明确契约。本候选实现选择 `Objects.requireNonNull` 快速失败。
- **重复字符**：`aaaa`、`abab` 等不会破坏 `s+s` 性质，也是 KMP 失配回退是否正确的重要测试。
- **字符模型**：Java `char` 是 UTF-16 code unit。标准题限定小写英文字母，不涉及 Unicode grapheme cluster；若业务语义是“用户可见字符”，要重新定义旋转单位。
- **复杂度措辞**：`s+s` 的构造明确是 `O(n)`；库函数子串搜索算法属于实现细节。需要硬性最坏界时，用显式 KMP 或其他有证明的线性匹配算法。

## 原理机制

下面给一个不实际创建 `s+s`、最坏时间可证明线性的 Java 版本：

```java
import java.util.Objects;

public final class RotateString {
    private RotateString() {}

    public static boolean rotateString(String s, String goal) {
        Objects.requireNonNull(s, "s");
        Objects.requireNonNull(goal, "goal");

        if (s.length() != goal.length()) {
            return false;
        }
        if (s.isEmpty()) {
            return true;
        }
        return containsInDoubledByKmp(s, goal);
    }

    private static boolean containsInDoubledByKmp(String s, String pattern) {
        int[] lps = buildLps(pattern);
        int matched = 0;
        int doubledLength = s.length() * 2;

        for (int i = 0; i < doubledLength; i++) {
            char current = s.charAt(i % s.length());
            while (matched > 0 && current != pattern.charAt(matched)) {
                matched = lps[matched - 1];
            }
            if (current == pattern.charAt(matched)) {
                matched++;
                if (matched == pattern.length()) {
                    return true;
                }
            }
        }
        return false;
    }

    private static int[] buildLps(String pattern) {
        int[] lps = new int[pattern.length()];
        int prefix = 0;
        for (int i = 1; i < pattern.length(); ) {
            if (pattern.charAt(i) == pattern.charAt(prefix)) {
                lps[i++] = ++prefix;
            } else if (prefix > 0) {
                prefix = lps[prefix - 1];
            } else {
                lps[i++] = 0;
            }
        }
        return lps;
    }
}
```

这里扫描 `2n` 个字符，即使允许在第二份 `s` 的起点再次匹配原串，也只会多检查一个等价的轮转起点，不影响正确性。若想把搜索域收紧到“不同起点只有 `0..n-1`”，扫描到足够容纳最后一个长度 n 窗口的位置即可；面试里通常没必要为了少一个等价起点增加边界复杂度。

验证不能只测两个题目样例。一个结构不同的 oracle 是：枚举 `shift=0..n-1`，逐字符检查 `goal[i] == s[(i+shift)%n]`。它是 `O(n²)`，但非常适合作为测试基准。固定测试覆盖：相等、不可旋转、单字符、全重复、周期字符串、空串、长度不同；再用固定随机种子生成字符串，交叉比较 KMP 实现和枚举 oracle。

## 项目经验版

原面试记录没有生产项目上下文，所以不虚构“线上曾经这么做”。这个题更有价值的工程迁移点是两个：

1. **先把操作定义转成不变量**：旋转不改变长度，也不改变环上的字符顺序，只改变起点；
2. **先做数学归约，再选搜索算法**：轮转关系归约成“双倍序列中的模式匹配”，然后可以根据数据规模选库函数、KMP 或其他匹配器。

类似思想会出现在循环缓冲区、环形日志、周期序列对齐等问题里，但业务中的“元素”可能不是 Java `char`，需要先定义比较单位和编码语义。

## 常见追问

- 问：为什么必须 `s.length() == goal.length()`？答：旋转只改变起点，不会增删字符；不等长直接不可能，而且不检查会让较短子串造成假阳性。
- 问：为什么 `s+s` 包含所有旋转？答：任何旋转都等价于把 `s=xy` 的切分换成 `yx`，而 `xyxy` 中间连续包含 `yx`。
- 问：反过来为什么成立？答：等长的匹配窗口在双倍串中的起点对应原串某个环形起点，因此就是一次合法切分后的顺序。
- 问：直接 `contains` 的复杂度是多少？答：拼接是 `O(n)`；具体 `contains/indexOf` 的最坏搜索复杂度不要脱离 JDK 实现随意保证。若面试要求确定的 `O(n)` 最坏界，我显式写 KMP。
- 问：能不能不用额外的 `s+s`？答：可以。把双倍串看成虚拟序列，第 `i` 个字符读取 `s[i % n]`，KMP 直接扫描这个视图。
- 问：如果题目其实是“左旋 k 位并返回字符串”呢？答：那就不是布尔判断；先把 `k` 归一化为 `k % n`，结果是 `s.substring(k) + s.substring(0,k)`，或者在可变字符数组上用三次反转实现。应以面试官给的输入输出为准。
- 问：KMP 为什么不会退化？答：文本下标只向前；失配只通过 LPS 改变已匹配前缀长度，每个字符的推进/回退总量受线性界约束。

## 易错点

- 看到“旋转字符串”就直接假设是某一道标准题，没有先承认本地题干缺参数。
- 只判断 `goal` 是否在 `s+s` 中，忘记等长条件。
- 用排序或字符频次判断；它们只能说明字符多重集合相同，不能保证循环相对顺序相同。
- 手工生成每一个轮转再逐个比较，时间和分配都不必要。
- 声称 Java `contains` 在所有运行时都保证某个最坏复杂度，而没有依据。
- KMP 扫虚拟双倍串时没有先处理空串，导致 `% 0` 或访问空 pattern。
- 把 UTF-16 `char` 当成所有业务场景里的“字符”，忽略 Unicode 组合字符/代理对语义。
