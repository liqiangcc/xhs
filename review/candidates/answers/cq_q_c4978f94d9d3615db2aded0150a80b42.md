# 区间合并：排序后线性扫描

## 核心结论

来源写的是“区间合并 (LeetCode 56)”，但仓库来源没有完整保留函数签名和输入约束。这里明确采用常见的最小契约：输入若干闭区间 `[start,end]`，每个区间满足 `start <= end`；返回互不重叠的合并结果，并按起点升序排列。先按起点升序、终点升序排序，再维护当前合并区间；若下一个区间的起点 `<= currentEnd`，说明闭区间有重叠或接触，扩展 `currentEnd`，否则输出当前区间并开始新区间。

## 1 分钟版

- 如果区间无序，先按 `start` 排序，这样后续只需要判断“下一个区间是否和当前合并结果相交”。
- 维护 `[currentStart,currentEnd]`。若 `nextStart <= currentEnd`，合并为 `[currentStart,max(currentEnd,nextEnd)]`。
- 若 `nextStart > currentEnd`，当前区间已经不可能再与后面的区间相交，可以安全输出，再把 next 作为新的当前区间。
- 空输入返回空结果；单区间原样返回；包含、链式重叠、重复区间和端点相接都要覆盖。
- 排序 O(n log n)，扫描 O(n)；若不计返回结果，排序副本占 O(n) 额外空间。本实现不修改调用方的输入数组。

## 3 分钟版

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.List;

public final class MergeIntervals {
    public static int[][] merge(int[][] intervals) {
        if (intervals == null || intervals.length == 0) {
            return new int[0][];
        }

        int[][] sorted = copyAndValidate(intervals);
        Arrays.sort(
                sorted,
                Comparator.comparingInt((int[] x) -> x[0])
                        .thenComparingInt(x -> x[1]));

        List<int[]> result = new ArrayList<>();
        int currentStart = sorted[0][0];
        int currentEnd = sorted[0][1];

        for (int i = 1; i < sorted.length; i++) {
            int nextStart = sorted[i][0];
            int nextEnd = sorted[i][1];

            if (nextStart <= currentEnd) {
                currentEnd = Math.max(currentEnd, nextEnd);
            } else {
                result.add(new int[] {currentStart, currentEnd});
                currentStart = nextStart;
                currentEnd = nextEnd;
            }
        }

        result.add(new int[] {currentStart, currentEnd});
        return result.toArray(new int[result.size()][]);
    }

    private static int[][] copyAndValidate(int[][] intervals) {
        int[][] copy = new int[intervals.length][2];
        for (int i = 0; i < intervals.length; i++) {
            int[] interval = intervals[i];
            if (interval == null || interval.length != 2 || interval[0] > interval[1]) {
                throw new IllegalArgumentException(
                        "each interval must be [start,end] with start <= end");
            }
            copy[i][0] = interval[0];
            copy[i][1] = interval[1];
        }
        return copy;
    }
}
```

这里先复制输入再排序，避免为了算法方便改变调用方数组的顺序。`copyAndValidate` 同时检查每项恰好有两个端点并满足 `start <= end`；这些属于候选 API 契约，不声称是来源文本中已经写明的要求。

## 关键细节

- **排序为什么足够**：按起点升序后，一旦 `nextStart > currentEnd`，后面的区间起点只会更大，所以当前区间不可能再被后续区间连接。
- **为什么用 `<=`**：本候选把区间定义为闭区间，所以 `[1,4]` 和 `[4,5]` 在端点 4 相交，应合并成 `[1,5]`。若业务使用半开区间 `[start,end)`，端点相接的语义会变化。
- **包含关系**：如 `[1,10]` 后面是 `[2,3]`，用 `max(currentEnd,nextEnd)` 可保持终点 10，不会错误缩短区间。
- **链式重叠**：`[1,3],[2,6],[5,8]` 会连续扩展同一个 current，不需要回看已经输出的结果。
- **输入副作用**：直接 `Arrays.sort(intervals, ...)` 会改变调用方二维数组的顺序；本实现复制每个二元区间后再排序，把“是否允许修改输入”变成显式选择。
- **复杂度**：主要成本是排序 O(n log n)；扫描 O(n)。复制和结果都需要 O(n) 级空间。

## 原理机制

排序建立了一个关键单调性：尚未处理区间的起点不会小于当前正在看的 nextStart。因此 current 一旦与 next 分离，就不可能与任何更后的区间重新相交，这让我们可以“在线”输出 current 而无需回溯。

扫描时的不变量是：`current` 始终等于从上一次输出之后到当前位置为止所有可连通重叠区间的并集。遇到重叠就扩展右端点；遇到间隔就封口。最终循环结束后还要补一次 current，否则最后一个合并区间会丢失。

## 项目经验版

来源没有真实项目场景，不能虚构生产使用。项目里做时间窗、预约段、日志覆盖区间或权限范围归并时，第一步反而是确认区间语义：闭区间还是半开区间、时间精度、相邻是否视为连续、是否允许无穷端点，以及输入规模是否适合内存排序。算法骨架相似，但这些边界决定比较条件和数据类型。

## 常见追问

- 问：为什么一定要先排序？答：若输入无序，当前区间与未来任意区间都可能重叠；按起点排序后，分离时可以证明 current 已经封闭，从而一次扫描完成。
- 问：如果区间已经按起点有序呢？答：可以省掉排序，直接 O(n) 扫描；前提是有可信的有序输入契约。
- 问：`[1,4]` 和 `[4,5]` 是否合并？答：本候选按闭区间契约合并，因为共享端点 4；若题目定义半开区间或“仅真正重叠才合并”，比较条件要改。
- 问：能原地做吗？答：可以排序输入并复用前部数组写回合并结果，以减少额外容器；但会修改输入，必须先确认 API 是否允许。
- 问：整数端点会不会溢出？答：本算法只比较端点和取 `max`，不做 `end-start` 算术，因此不存在由差值计算引起的整数溢出；但数据类型仍应覆盖题目端点范围。

## 易错点

- 排序后只比较相邻原始区间，而不是与“已经扩展后的 currentEnd”比较，导致链式重叠被拆开。
- 合并时直接把终点设成 `nextEnd`，遇到包含关系会把区间错误缩短。
- 循环结束忘记输出最后一个 current。
- 没定义闭区间/半开区间语义，就机械使用 `<=` 或 `<`。
- 为方便排序修改调用方输入，却没有把副作用写进契约。
