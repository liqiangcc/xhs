# 逆时针打印矩阵：先约定起点，再做四边收缩

## 核心结论

“逆时针打印矩阵”只说明旋转方向，没有说明**从哪个角开始、第一步往哪个方向走**。原始面试记录没有更多输入输出约定，因此不能把某一种序列偷偷当成唯一答案。我会先和面试官确认；下面采用常见且可验证的契约：**从左上角开始，第一步向下，按逆时针螺旋向内打印**。

在矩阵是规则矩形的前提下，用 `top / bottom / left / right` 四个边界，每一圈依次走“左列向下 → 底行向右 → 右列向上 → 顶行向左”，每走完一条边就收缩对应边界。每个元素只访问一次，时间复杂度 `O(rows * cols)`，除输出外额外空间 `O(1)`。

## 1 分钟版

先声明约定：从左上角开始向下，逆时针螺旋。

每一圈做四步：

1. `left` 列从 `top` 到 `bottom` 向下；
2. `bottom` 行从新的 `left` 到 `right` 向右；
3. `right` 列从新的 `bottom` 到 `top` 向上；
4. `top` 行从新的 `right` 到 `left` 向左。

每走完一条边就把它从未访问区域中剥掉，并在后两步前再次检查边界，避免单行、单列、奇数层时重复打印。

## 3 分钟版

四边法的核心不是背循环顺序，而是维护一个不变量：`[top..bottom] × [left..right]` 始终表示**尚未输出的矩形区域**。一轮开始时打印这个矩形的逆时针外壳；打印完左边界后 `left++`，打印完下边界后 `bottom--`，再根据区域是否仍存在决定是否打印右边界和上边界。

为什么要二次判断？例如只剩一列时，第一步已经把这一列全部输出；如果继续执行“底行/右列/顶行”，就会重复元素。只剩一行时也类似。因此每次剥掉一条边后，都必须以最新的 `top <= bottom`、`left <= right` 为准。

如果面试官约定的是“从右上角开始向左”或其他起点，逆时针的本质不变，但输出序列会发生旋转；应先锁定契约再写代码，而不是争论某个起点天然正确。

## 关键细节

- 本实现接受 `null`、0 行或 0 列并返回空结果。
- 输入必须是规则矩形；`null` 行或不同列数属于另一种数据结构语义，本实现显式抛出 `IllegalArgumentException`，避免静默越界。
- 公共边界条件是 `top <= bottom && left <= right`。
- 打印左列后先 `left++`；只有区域仍非空才打印底行。
- 打印底行后 `bottom--`；只有区域仍非空才打印右列。
- 打印右列后 `right--`；只有区域仍非空才打印顶行。
- 每个格子恰好从“未访问矩形”移除一次，所以总时间是 `O(rows * cols)`。
- 输出列表本身需要 `O(rows * cols)`；所谓额外空间 `O(1)` 是指不计返回结果后的辅助状态只有四个边界变量。

## 原理机制

```java
import java.util.ArrayList;
import java.util.List;

public final class CounterClockwiseMatrix {
    public static List<Integer> fromTopLeft(int[][] matrix) {
        List<Integer> result = new ArrayList<>();
        if (matrix == null || matrix.length == 0) {
            return result;
        }

        int cols = validateRectangular(matrix);
        if (cols == 0) {
            return result;
        }

        int top = 0;
        int bottom = matrix.length - 1;
        int left = 0;
        int right = cols - 1;

        while (top <= bottom && left <= right) {
            for (int row = top; row <= bottom; row++) {
                result.add(matrix[row][left]);
            }
            left++;

            if (top <= bottom && left <= right) {
                for (int col = left; col <= right; col++) {
                    result.add(matrix[bottom][col]);
                }
                bottom--;
            }

            if (top <= bottom && left <= right) {
                for (int row = bottom; row >= top; row--) {
                    result.add(matrix[row][right]);
                }
                right--;
            }

            if (top <= bottom && left <= right) {
                for (int col = right; col >= left; col--) {
                    result.add(matrix[top][col]);
                }
                top++;
            }
        }
        return result;
    }

    private static int validateRectangular(int[][] matrix) {
        if (matrix[0] == null) {
            throw new IllegalArgumentException("matrix rows must be non-null");
        }
        int cols = matrix[0].length;
        for (int row = 1; row < matrix.length; row++) {
            if (matrix[row] == null || matrix[row].length != cols) {
                throw new IllegalArgumentException("matrix must be rectangular");
            }
        }
        return cols;
    }
}
```

仓库测试没有用另一份“四边收缩”代码当真值，而是用“当前位置 + 方向数组 + visited”的逐格模拟器作为独立 oracle：从左上角向下，方向按“下、右、上、左”轮转，下一格越界或已访问时转向。固定用例覆盖空矩阵、单行、单列、2×2、3×4、4×3、奇数中心层和非法 ragged 输入；另外用固定随机种子生成 3000 个矩形，与 oracle 逐项比较。

## 项目经验版

这是算法手撕题，原始记录没有任何生产项目数据，因此不应包装成“项目里优化了多少性能”。工程上可迁移的点是先定义遍历契约和非法输入策略：二维数组是否保证矩形、空输入如何表示、输出是否允许流式消费，这些会影响 API，而不是螺旋算法本身。

## 常见追问

- 问：为什么逆时针不能直接给唯一序列？答：方向只约束旋转方向，起点和第一步仍需约定；这里明确采用左上角向下开始。
- 问：为什么单行或单列最容易写错？答：一条边被打印后未访问区域可能已经为空；如果不重新检查边界，后续边会重复打印同一批元素。
- 问：能不能用 visited 数组？答：可以，方向模拟更直观，但需要 `O(rows * cols)` 辅助空间；四边收缩只需常数级辅助状态。
- 问：如何证明不会漏元素？答：不变量是四个边界包围全部且仅包含未输出元素；每一步完整移除当前矩形的一条外边，直到未访问矩形为空。
- 问：如果要求边打印边消费而不是返回 List 呢？答：把 `result.add` 换成回调/消费者即可，四边状态机不变，此时算法本身可以保持 `O(1)` 辅助空间。

## 易错点

- 没有先说明起点，导致“逆时针”的输出契约含糊。
- 四条边无条件都跑一次，单行/单列出现重复。
- 更新边界的顺序和当前所打印的边不一致。
- 把返回列表的空间也忽略后笼统说“总空间 O(1)”。
- 默认 Java `int[][]` 一定是规则矩形，遇到 ragged 数组时产生意外越界。
