# 算法：给一个数组判断能否拆成两个数组，使两个数组的元素和相等

## 核心结论

仓库原始来源只保留了“给一个数组判断能否拆成两个数组，这两个数组的元素和相等”，没有规定元素是否可为负数、两个数组是否必须非空、数值范围、具体语言或函数签名。这里显式采用候选契约：输入为 Java `int[]`，元素非负，总和不超过 `Integer.MAX_VALUE`；每个输入元素恰好分到两个组中的一个；允许某个组为空；`null` 返回 `false`；不修改输入。

在这个候选契约下，问题可以转化为：总和为 `S` 时，是否存在一个子集的和为 `S/2`。如果 `S` 是奇数，必然不能等分；如果 `S` 是偶数，就做 0/1 子集和动态规划。`reachable[t]` 表示“处理到当前元素后，是否能选出若干元素得到和 `t`”。每个元素只能使用一次，所以一维压缩时必须从大到小更新。

## 1 分钟版

先求所有元素总和 `S`。`S` 为奇数直接返回 `false`，因为两个组不可能有相同整数和。

如果 `S` 为偶数，目标就是找到一个元素子集，使其和恰好为 `S/2`。定义 `reachable[t]` 表示当前已处理元素能否组成和 `t`，初始只有 `reachable[0] = true`。对每个值 `x`，从 `target` 递减到 `x` 更新：

`reachable[t] = reachable[t] || reachable[t - x]`。

必须倒序，因为正序会让本轮刚写出的状态再次参与转移，相当于同一个元素被重复使用。最终返回 `reachable[target]`。

在目标和为 `T = S/2` 的候选约束下，时间复杂度是 `O(nT)`，辅助空间是 `O(T)`。这是伪多项式复杂度；原题没有给数据范围，所以不能把它说成对所有输入都最优。

## 3 分钟版

题源只支持“拆成两个数组，使元素和相等”这个目标，并不支持“连续子数组”语义。这里把“拆”解释为对输入位置做一次完整划分：每个元素只能进入一个组，两个组的并集覆盖全部元素。这些具体规则以及 Java、非负整数、允许空组等都属于候选实现假设，不冒充原题隐藏条件。

如果两个组的和相等，而所有元素都被使用一次，那么总和 `S` 必须是偶数，并且任意一组的和都等于 `S/2`。反过来，如果能从原数组中选出一个子集和为 `S/2`，剩余元素的和自然也是 `S/2`，因此两组等和。于是问题等价于一个 0/1 子集和判定。

状态 `reachable[t]` 的不变量是：处理完前若干个元素后，`reachable[t]` 当且仅当能从这些已经处理的元素中选出一个子集，使其和为 `t`。处理新元素 `x` 时，一个可达和 `t` 要么不使用 `x`，保留原来的 `reachable[t]`；要么使用 `x`，要求之前 `t-x` 可达。因为每个输入位置最多使用一次，一维数组必须按 `t` 递减更新，确保读取的 `reachable[t-x]` 仍然代表“加入当前元素之前”的状态。

候选实现先用 `long` 累加以检测 Java `int` 总和上界；负数直接拒绝，因为当前 DP 的索引和单调倒序转移依赖非负输入。若真实题目允许负数、强制两组都非空、或数据总和极大，就需要换状态表示或重新选择算法，不能静默沿用这份候选契约。

## 关键细节

- **题源边界**：来源只支持两个数组/组“元素和相等”，不支持连续 `子数组`；元素符号、是否非空、语言、范围和 API 都未给出。
- **完整划分假设**：候选答案要求每个输入元素恰好进入其中一个组；这是把“拆成两个数组”具体化的实现选择。
- **奇偶剪枝**：总和为奇数时不可能拆成两个整数和相等的组。
- **状态含义**：`reachable[t]` 只回答“某个子集和能否到达 `t`”，不记录具体组；找到 `S/2` 后补集自动构成另一组。
- **必须倒序**：0/1 选择中正序更新会把同一元素重复使用，错误地变成完全背包语义。
- **零值与重复值**：算法按输入位置处理，零和重复值不需要特殊去重；测试覆盖两者。
- **异常边界**：候选实现把 `null` 定义为 `false`，把负数和总和超出 `Integer.MAX_VALUE` 定义为不满足候选输入契约并抛出 `IllegalArgumentException`。
- **空组语义**：候选契约允许空组，因此空数组和单个 `0` 返回 `true`；如果真实题目要求两组都非空，这个边界必须调整。
- **复杂度**：令 `T=S/2`，时间 `O(nT)`、空间 `O(T)`，属于伪多项式；题源没有规模约束，不能宣称这是无条件最优方案。
- **可验证性**：固定边界覆盖空、奇数总和、偶数但不可达、重复值、零值和负数契约；再用 5000 组确定性随机非负数组，与独立的穷举子集 oracle 对照，并确认输入未被修改。

## 原理机制

```java
public static boolean canPartition(int[] nums) {
    if (nums == null) {
        return false;
    }

    long total = 0L;
    for (int value : nums) {
        if (value < 0) {
            throw new IllegalArgumentException("non-negative elements required");
        }
        total += value;
        if (total > Integer.MAX_VALUE) {
            throw new IllegalArgumentException("total sum is outside candidate contract");
        }
    }

    if ((total & 1L) != 0L) {
        return false;
    }

    int target = (int) (total / 2L);
    boolean[] reachable = new boolean[target + 1];
    reachable[0] = true;

    for (int value : nums) {
        for (int sum = target; sum >= value; --sum) {
            reachable[sum] = reachable[sum] || reachable[sum - value];
        }
    }
    return reachable[target];
}
```

独立验证不用同一套 DP，而是对最多 12 个元素的随机数组枚举所有子集，判断是否存在子集和等于总和的一半。这样 oracle 的控制流和实现思路不同，可以发现一维 DP 遍历方向、奇偶判断或边界处理中的错误。

固定用例和 5000 组随机数组的预检输出为：

```text
PASS fixed=10 randomized=5000 oracle=exhaustive-subset-partition mutation=none
```

## 项目经验版

这是基础算法题，仓库来源没有真实生产项目上下文，因此不编造项目经历。工程中如果输入总和很大，`O(nT)` 的伪多项式 DP 可能不可接受，需要结合真实的 `n`、数值范围和是否允许负数重新选算法；如果只是面试手撕，先把输入约束和“两个数组是否必须非空”说清楚，比直接套经典题模板更重要。

## 常见追问

- **为什么能转成子集和 `S/2`？** 因为候选契约要求所有元素恰好被两组完整划分；一个组和为 `S/2` 时，补集的和也是 `S/2`。
- **为什么总和为奇数直接失败？** 两个整数和相等意味着总和是该整数的两倍，因此一定是偶数。
- **为什么一维 DP 要从大到小？** 倒序保证 `reachable[t-x]` 来自加入当前元素之前的状态；正序会让当前元素在同一轮被重复使用。
- **如果数组里有负数呢？** 当前候选契约不支持；负数会破坏从 `0..T` 的非负索引模型，需要换成带偏移的状态、集合状态或其他方法，并重新核算复杂度。
- **两个组必须非空吗？** 原题没有说明。当前候选允许空组，所以 `[]` 和 `[0]` 返回 `true`；若面试官要求非空，需要在契约和边界判断中明确加入该条件。
- **这个算法一定高效吗？** 不一定。它对目标和 `T` 是伪多项式 `O(nT)`；没有输入范围时只能把它作为一个明确假设下的可验证候选，而不是无条件最优结论。

## 易错点

- 把来源中的“两个数组”再次写成“两个连续子数组”，重新引入已经移除的错误约束。
- 忘记总和奇偶性，直接分配大 DP。
- 一维 0/1 DP 正序更新，导致同一元素被重复选择。
- 没有说明负数、空组、`null` 和总和范围，却把实现行为说成原题规定。
- 只验证经典样例，没有覆盖“总和为偶数但目标不可达”、零和重复值。
- 把 `O(nT)` 说成多项式时间而忽略它依赖数值大小，是伪多项式复杂度。
