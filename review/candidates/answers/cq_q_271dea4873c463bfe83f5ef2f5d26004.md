# 用 rand39 生成 rand51：等概率状态空间 + 拒绝采样

## 核心结论

题源只保留了“**用 rand39 生成 rand51**”，没有定义 `rand39`/`rand51` 的取值区间，也没有明确“每次独立、均匀”这些随机源前提。没有均匀性就无法保证生成均匀的 `rand51`，所以候选把常见 randN 合同明确写成**接口假设**：`rand39()` 每次独立且等概率返回整数 `[0,38]`；目标 `rand51()` 等概率返回 `[0,50]`。如果实际接口是 `[1,39]` / `[1,51]`，只需在入口/出口做一次 ±1 平移，核心证明不变。

两次 `rand39()` 可以构造 `x = a * 39 + b`。因为 `(a,b)` 的 `39^2 = 1521` 个有序对等概率，所以 `x` 在 `[0,1520]` 上均匀。要映射到 51 个结果，取不超过 1521 的最大 51 倍数：`1479 = 51 * 29`。只接受 `x < 1479`，拒绝剩余 42 个状态；对接受值返回 `x % 51`。每个结果恰好对应 29 个接受状态，因此严格均匀。

单轮接受率是 `1479 / 1521 ≈ 97.24%`，期望轮数 `1521/1479 ≈ 1.0284`，每轮调用两次 `rand39`，所以期望约 `2.057` 次源调用。空间 `O(1)`，循环以概率 1 终止。

## 1 分钟版

先声明前提：我假设 `rand39()` 独立、均匀返回 `[0,38]`，要得到独立、均匀的 `[0,50]`。

1. 调两次：`a = rand39()`、`b = rand39()`。
2. 拼成 `x = a * 39 + b`，于是 `x` 等概率覆盖 0 到 1520 共 1521 个状态。
3. 51 不能整除 1521；最大的完整桶区域是 `51 * 29 = 1479`。
4. 若 `x >= 1479` 就丢弃重来；否则返回 `x % 51`。

关键点不是“取模”，而是**取模之前必须把样本空间裁成 51 的整数倍**。直接 `x % 51` 会让前 42 个余数比后 9 个余数多一个前像，产生偏差。

## 3 分钟版

设一次 `rand39()` 的 39 个结果都具有概率 `1/39`，且两次调用独立。于是任意有序对 `(a,b)` 的概率都是 `1/39^2`。映射

`x = 39a + b`

在 `(a,b) ∈ [0,38]^2` 与 `x ∈ [0,1520]` 之间是一一对应，所以 `x` 均匀。

如果直接返回 `x % 51`，因为 `1521 = 51*29 + 42`，余数 `0..41` 各有 30 个前像，而 `42..50` 只有 29 个前像，不均匀。拒绝 `1479..1520` 后只剩 `0..1478` 共 1479 个状态，恰好能分成 51 组，每组 29 个：

`{r, r+51, ..., r+28*51}`。

因此对任意 `r ∈ [0,50]`：

`P(result=r | accepted) = 29/1479 = 1/51`。

每一轮使用新的独立源调用；拒绝只看 `x` 是否落在尾部，不偏向任何被接受余数，所以重复直到接受仍保持均匀。拒绝概率 `42/1521` 小于 3%，期望轮数是几何分布的 `1/p = 1521/1479`。

这套方法可以一般化：用足够多次 `randM` 构造一个等概率的 `M^k` 状态空间，再保留 `floor(M^k/N)*N` 个状态并对 `N` 取模。必须先确认随机源真正独立、均匀；如果上游有偏，拒绝采样不能凭空修复成严格均匀。

## 关键细节

- **题源边界**：原文只有“用rand39生成rand51”，没有区间、独立性、均匀性、API 或随机源实现。
- **候选约定**：`rand39` 为 iid uniform `[0,38]`，`rand51` 为 uniform `[0,50]`。这些是为了让题目可证明、可执行，不冒充题源原话。
- **为什么两次够**：一次只有 39 个等概率状态，小于 51；两次有 1521 个，已经足够构造至少 51 个完整等概率桶。
- **为什么不能 `rand39() % 51`**：结果只会落在 0..38，根本覆盖不了 51 个值。
- **为什么不能 `x % 51` 后直接返回**：1521 不是 51 的整数倍，会出现 42 个余数多一个前像的 modulo bias。
- **拒绝区间**：`x >= 1479`，恰好 42 个状态；接受区间的每个余数恰好出现 29 次。
- **源值校验**：候选接口若收到 `<0` 或 `>=39` 的值，说明注入的 `rand39` 违反合同，直接抛异常，而不是悄悄做 `%39` 破坏分布。
- **终止性**：每轮接受概率约 97.24%，无限拒绝的概率极限为 0；不是确定次数终止，但以概率 1 终止。
- **复杂度**：期望时间和空间都是 `O(1)`；严格最坏调用次数无有限上界，这是拒绝采样的固有性质。
- **区间换成 1-based**：输入先减 1，输出最后加 1 即可，不能把区间约定混进概率证明。

## 原理机制

```java
public final class Rand39ToRand51 {
    private Rand39ToRand51() {}

    @FunctionalInterface
    public interface Rand39 {
        int next();
    }

    public static int nextRand51(Rand39 source) {
        if (source == null) {
            throw new IllegalArgumentException("source must not be null");
        }

        while (true) {
            int a = draw(source);
            int b = draw(source);
            int sample = a * 39 + b;
            if (sample < 1479) {
                return sample % 51;
            }
        }
    }

    private static int draw(Rand39 source) {
        int value = source.next();
        if (value < 0 || value >= 39) {
            throw new IllegalStateException("rand39 must return values in [0, 38]");
        }
        return value;
    }
}
```

可执行验证分三层：第一，穷举全部 `39*39` 输入对，证明 1479 个接受状态对 51 个结果**每个正好 29 次**、拒绝状态正好 42 个；第二，用脚本随机源强制先命中拒绝区间再命中接受区间，验证真的会重采样而不是把尾部硬取模；第三，用固定种子的 iid `[0,38]` 源生成 510,000 个 `rand51` 样本，检查范围和各桶频数。夹具还验证 null 与越界源值会被拒绝。实际夹具预期输出：`PASS exhaustive=1521 accepted=1479 rejected=42 perBucket=29 sampled=510000`。

## 项目经验版

这是随机算法面试题，题源没有生产项目经历，因此不虚构线上随机服务。工程里如果随机数用于安全令牌、密码学 nonce 或公平抽签，首先要确认底层 RNG 的安全性和独立性；本题的数学变换只解决“已知均匀离散源如何无偏映射到另一个离散范围”，不把普通 PRNG 自动变成 CSPRNG。

## 常见追问

- 问：为什么必须假设 `rand39` 均匀？答：证明依赖 39 个源状态等概率；若源本身有偏，`39a+b` 的 1521 个状态就不等概率，后面的拒绝和取模也无法保证每个结果都是 `1/51`。
- 问：为什么两次调用要独立？答：否则有序对概率不一定都是 `1/1521`；例如两次总返回同一个值，只会覆盖 39 个对角状态。
- 问：为什么阈值是 1479？答：`floor(1521/51)*51 = 29*51 = 1479`，这是不超过样本空间的最大完整 51 倍数。
- 问：直接 `%51` 的偏差具体是什么？答：0..41 各有 30 个前像，42..50 各有 29 个前像，所以前 42 个结果概率更高。
- 问：拒绝后会不会仍然有偏？答：不会。保留下来的 1479 个原子状态仍然等概率，并被平均分成 51 组，每组 29 个。
- 问：最坏会调用多少次 `rand39`？答：没有有限确定上界；每轮都有约 2.76% 概率拒绝。但期望轮数约 1.0284，且无限失败概率为 0。
- 问：如果 `rand39` 返回 1..39 呢？答：先减 1 归一到 0..38，完成算法后结果加 1 得到 1..51。
- 问：能用更多次 `rand39` 吗？答：可以，但两次已经得到足够状态且接受率很高；更多次只在特定接口/性能权衡下有意义。

## 易错点

- 没有先声明 randN 的范围和均匀/独立前提，就直接给代码。
- 用 `%51` 但不处理 1521 除以 51 的余数 42，产生 modulo bias。
- 把拒绝的 42 个状态映射回某些结果，重新引入不均匀。
- 只做大样本频率“看起来差不多”的统计测试，却不做 1521 个原子状态的精确计数证明。
- 对异常的 `rand39` 输出做 `%39`“修复”，这会掩盖上游合同破坏并改变概率分布。
- 把“期望 O(1)”误说成“最坏 O(1)”。
