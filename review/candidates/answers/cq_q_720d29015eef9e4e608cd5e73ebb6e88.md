# 非递归遍历二叉树：前序、中序、后序的显式栈实现

## 核心结论

来源只写了“算法：非递归遍历二叉树的实现”，没有指定究竟是前序、中序还是后序，也没有给节点/API 契约。为避免把答案侧选择冒充成原题要求，这里明确采用：节点包含 `int value`、`left`、`right`；`null` 返回空列表；同时给出前序、中序、后序三种 **不使用递归** 的 DFS 实现。

三者的共同本质是把递归调用栈显式化：前序在弹栈时访问节点，并按“右后左先”的顺序压栈；中序不断压左链，弹出后访问，再转向右子树；后序需要知道右子树是否已经处理，因此除栈外再维护 `lastVisited`。

## 1 分钟版

- **前序 `根-左-右`**：根先入栈；每次弹出就访问，然后先压右、再压左，利用 LIFO 保证左子树先处理。
- **中序 `左-根-右`**：把当前节点一路沿左链压栈；走到空后弹出一个节点访问，再把 `current` 切到它的右孩子。
- **后序 `左-右-根`**：同样先压左链；看栈顶时，如果右孩子存在且还没访问，就转向右子树；否则才能访问栈顶并把它记为 `lastVisited`。
- 每个节点都只被有限次压栈/查看/弹栈，时间复杂度都是 `O(n)`。
- 显式栈最坏保存树高 `h` 个节点，所以辅助空间 `O(h)`；退化链表树时 `h=n`。
- 和递归相比，显式栈不会因为树很深而消耗语言运行时的递归调用栈，但容器内存仍然随树高增长。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public final class IterativeBinaryTreeTraversal {
    public static final class Node {
        public final int value;
        public Node left;
        public Node right;
        public Node(int value) { this.value = value; }
    }

    public static List<Integer> preorder(Node root) {
        List<Integer> out = new ArrayList<>();
        if (root == null) return out;
        Deque<Node> stack = new ArrayDeque<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            Node node = stack.pop();
            out.add(node.value);
            if (node.right != null) stack.push(node.right);
            if (node.left != null) stack.push(node.left);
        }
        return out;
    }

    public static List<Integer> inorder(Node root) {
        List<Integer> out = new ArrayList<>();
        Deque<Node> stack = new ArrayDeque<>();
        Node current = root;
        while (current != null || !stack.isEmpty()) {
            while (current != null) {
                stack.push(current);
                current = current.left;
            }
            Node node = stack.pop();
            out.add(node.value);
            current = node.right;
        }
        return out;
    }

    public static List<Integer> postorder(Node root) {
        List<Integer> out = new ArrayList<>();
        Deque<Node> stack = new ArrayDeque<>();
        Node current = root;
        Node lastVisited = null;
        while (current != null || !stack.isEmpty()) {
            if (current != null) {
                stack.push(current);
                current = current.left;
            } else {
                Node peek = stack.peek();
                if (peek.right != null && lastVisited != peek.right) {
                    current = peek.right;
                } else {
                    out.add(peek.value);
                    lastVisited = stack.pop();
                }
            }
        }
        return out;
    }
}
```

假设树是 `1` 为根，左孩子 `2`、右孩子 `3`，且 `2` 的左右孩子分别是 `4`、`5`：前序是 `[1,2,4,5,3]`，中序是 `[4,2,5,1,3]`，后序是 `[4,5,2,3,1]`。

## 关键细节

- **前序为什么先压右再压左**：栈后进先出，要让左节点先弹出，就必须让右节点先入栈。
- **中序不变量**：栈里保存“左子树还没完全处理、之后需要回到的祖先”；弹出一个节点时，它的左侧已经完成，因此此时正好访问根，再进入右子树。
- **后序为什么需要 `lastVisited`**：仅凭栈顶无法区分“右子树还没走”和“刚从右子树回来”。`lastVisited == peek.right` 表示右子树已完成，此时才能访问根。
- **不能直接把 `null` 压进 `ArrayDeque`**：`ArrayDeque` 不接受 `null`，所以只在孩子非空时入栈。
- **复杂度**：三种遍历都访问每个节点一次，时间 `O(n)`；显式栈最多与树高同阶，辅助空间 `O(h)`，输出列表本身另需 `O(n)`。
- **极深树**：递归 DFS 最坏调用深度也是 `h`，可能触发调用栈溢出；显式栈把这部分状态放到堆上的容器，仍需 `O(h)` 内存但不依赖递归深度限制。
- **来源边界**：原题没有要求 Morris Traversal。Morris 可以把某些遍历的辅助空间降到 `O(1)`，但会临时修改树指针，属于不同契约与权衡，不应偷偷替换成题目要求。

## 原理机制

递归遍历之所以能“自动返回父节点”，是因为运行时调用栈保存了每一层的返回位置与局部状态。非递归实现并没有消除这些状态，而是显式管理它们。

前序访问根后只需要记住尚未处理的子树，所以一个节点栈就够了；中序必须记住“左链走到底后应该回到哪些祖先”；后序最难，因为根必须等左右子树都完成后才能访问，因此状态中还要包含“右子树是否已经处理”。单栈 + `lastVisited` 就是在显式表示这个递归阶段。

## 项目经验版

来源是纯算法题，没有真实项目经历可还原，因此不虚构生产案例。工程里若树可能非常深，我会优先评估迭代遍历以避免递归深度风险；若对象规模很大，还需要根据遍历顺序、是否允许修改树、是否需要流式输出决定使用显式栈、队列或 Morris 等方案，而不是默认一种写法适用于所有场景。

## 常见追问

- 问：后序能不能用两个栈？答：可以，写法更直观，但会再维护一个结果顺序栈；这里用单栈 + `lastVisited` 展示如何显式保存“右子树是否完成”的状态。
- 问：为什么迭代一定比递归省空间吗？答：不一定。普通显式栈和递归调用栈的渐进空间都是 `O(h)`；迭代的主要优势之一是避免受语言调用栈深度限制，并让状态管理更可控。
- 问：层序遍历算不算非递归遍历？答：算，但它是 BFS，通常用队列；当前答案侧契约聚焦前/中/后序 DFS，因为这三种最直接对应递归到显式栈的转换。
- 问：能做到 `O(1)` 辅助空间吗？答：某些遍历可用 Morris 技术，但需要临时建立/恢复线索指针；是否允许修改树必须先确认。
- 问：后序里为什么不能看到右孩子就总是进去？答：从右子树返回后栈顶仍是父节点，如果不记录 `lastVisited`，就会再次进入同一个右子树形成循环。
- 问：如果节点值重复会有问题吗？答：不会。算法依据的是节点引用和树结构，不靠 `value` 判断是否访问过；`lastVisited` 保存的是节点对象引用。

## 易错点

- 前序把左孩子先压栈，导致实际访问顺序变成根-右-左。
- 中序只写“压左链”却忘记弹栈后转到右子树。
- 后序没有记录右子树是否已访问，导致重复进入右子树或过早访问根。
- 用节点值而不是节点引用判断 `lastVisited`，在重复值树上产生错误。
- 说“非递归就是 `O(1)` 空间”，忽略显式栈最坏仍为 `O(h)`。
