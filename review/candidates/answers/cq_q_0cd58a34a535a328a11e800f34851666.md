# 算法：数组逆序——先确认是否允许原地修改

## 核心结论

仓库恢复出的原题只有“算法：数组逆序”，没有给元素类型、是否允许修改输入、是否要求返回新数组、空值契约等额外约束。因此不能把这些缺失条件伪装成原题的一部分。面试中最标准的回答是先确认“能不能原地修改”；如果允许，对数组两端使用双指针交换即可：`left` 从 0 向右、`right` 从 `n-1` 向左，只要 `left < right` 就交换，直到相遇。时间复杂度 `O(n)`，额外空间 `O(1)`。

如果明确要求保留原数组，则新建同长度数组，并把原下标 `i` 映射到结果下标 `n-1-i`，时间仍是 `O(n)`，额外空间变成 `O(n)`。下面用 Java `int[]` 作为具体可运行载体，但算法本身不依赖数值大小或有序性。

## 1 分钟版

先问一句：**允许修改原数组吗？**

允许时用首尾双指针：

- `left = 0`，`right = n - 1`；
- 交换 `a[left]` 和 `a[right]`；
- `left++`、`right--`；
- 到 `left >= right` 结束。

循环不变量是：每轮开始时，区间 `[0, left)` 和 `(right, n-1]` 已经处在最终逆序位置，未处理区间只剩 `[left, right]`。每次交换同时确定两个最终位置，所以总共最多交换 `floor(n/2)` 次。

时间 `O(n)`，原地版额外空间 `O(1)`。如果不能改原数组，就分配新数组并做 `result[i] = input[n-1-i]`，空间 `O(n)`。

## 3 分钟版

这题很简单，但好的答案应该把**契约**和**正确性证明**讲清楚，而不是只写三行 swap。

源材料没有说是否允许修改输入，所以候选实现同时给两种契约。原地版 `reverseInPlace(int[])` 直接修改输入；复制版 `reversedCopy(int[])` 保留输入并返回新数组。两者都把 `null` 作为未定义题面之外的非法输入，采用 fail-fast `NullPointerException`，而不是假装这是原题规定。

原地双指针的关键不变量是：在某次循环开始时，所有 `i < left` 的元素已经等于原数组的 `original[n-1-i]`，所有 `i > right` 也已经在最终位置。交换左右端点后，这两个新位置就同时满足最终映射，然后把未处理区间向中间缩小。循环终止时不存在两个以上未处理元素；若长度为奇数，中间元素映射到自己，因此无需动作。于是整个数组满足 `result[i] = original[n-1-i]`。

复杂度方面，每个元素最多参与一次交换或一次写入，因此时间是 `O(n)`。原地版只使用常数个临时变量，所以额外空间 `O(1)`；复制版需要一个长度为 `n` 的结果数组，所以额外空间 `O(n)`。

## 关键细节

- 原题只说明“数组逆序”，没有规定 in-place 还是 copy；回答应先声明选择的契约。
- 长度为 0 或 1 时无需交换，算法自然结束。
- 偶数长度最终所有元素成对交换；奇数长度的中心元素保持原位。
- 重复值、负数、极大/极小整数都不影响算法，因为只交换位置，不做算术运算。
- 原地版不会分配与 `n` 成比例的辅助结构。
- 如果调用方还需要原数组，不能偷偷原地修改，应选择 copy 版本或显式复制后再 reverse。
- `null` 行为不是原题给出的约束；示例实现选择 fail-fast，而不是把它算成空数组。

## 原理机制

```java
import java.util.Objects;

public final class ReverseArray {
    private ReverseArray() {}

    public static void reverseInPlace(int[] values) {
        Objects.requireNonNull(values, "values");
        int left = 0;
        int right = values.length - 1;
        while (left < right) {
            int tmp = values[left];
            values[left] = values[right];
            values[right] = tmp;
            left++;
            right--;
        }
    }

    public static int[] reversedCopy(int[] values) {
        Objects.requireNonNull(values, "values");
        int[] result = new int[values.length];
        for (int i = 0; i < values.length; i++) {
            result[i] = values[values.length - 1 - i];
        }
        return result;
    }
}
```

仓库中的确定性测试覆盖空数组、单元素、奇偶长度、重复值、`Integer.MIN_VALUE/MAX_VALUE`，并用固定随机种子生成 5000 组数组。测试用独立的下标映射 `expected[i] = original[n-1-i]` 作为 oracle；原地版必须与 oracle 一致，连续 reverse 两次必须恢复原数组，copy 版还必须证明输入未被修改。`null` 两个入口均单独验证 fail-fast。

## 项目经验版

这是纯算法手撕题，原始材料没有线上业务背景，不应虚构“生产性能提升”。工程上真正重要的是 API 契约：原地修改能省空间，但会改变调用方持有的数据；copy 版本消耗额外内存，却避免副作用。若数组很大、还被多处共享，是否允许 mutation 往往比 reverse 本身更值得先确认。

## 常见追问

- 问：为什么循环条件是 `left < right`？答：两指针相等时是奇数长度的中心元素，它逆序后仍在原位，不需要交换；若 `left > right` 则已经完成。
- 问：能不能用额外数组？答：可以，若题目禁止修改原数组就应该这么做；代价是额外 `O(n)` 空间。
- 问：时间复杂度为什么不是 `O(n/2)`？答：渐进复杂度忽略常数因子，`n/2` 次交换仍记作 `O(n)`。
- 问：怎么证明代码正确？答：用“左右已处理区域已经处于最终位置”的循环不变量；每轮交换固定两个最终位置，未处理区间严格缩小，终止时整个数组完成映射。
- 问：reverse 两次有什么性质？答：逆序映射 `i -> n-1-i` 是一个 involution，应用两次回到原下标；这是很适合做回归测试的代数性质。
- 问：如果是对象数组呢？答：算法相同，只交换引用；若对象本身可变，reverse 不会复制对象内部状态，只改变数组中的引用顺序。

## 易错点

- 没确认是否允许修改输入，就默认原地改变调用方数据。
- 把交换循环写成 `left <= right`，虽然中心元素自交换通常不出错，但多做一步且不如不变量清晰。
- 交换后只移动一个指针，导致重复交换或越界。
- 用算术加减交换整数，带来溢出风险；临时变量更直接可靠。
- 复制版写错下标为 `n-i`，造成越界；正确是 `n-1-i`。
- 把 `O(n/2)` 当成不同于 `O(n)` 的复杂度等级。
