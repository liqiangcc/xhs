# 盛最多水的容器：为什么双指针只移动较短的一边？

## 核心结论

双指针的核心不是“从两边往中间扫”，而是一个可证明安全的淘汰规则。设左右端点为 `l`、`r`，当前面积是 `min(height[l], height[r]) * (r-l)`。如果左边更短或相等，那么固定 `l`、把右端点向左移动，只会让宽度变小，而高度上限仍然不可能超过 `height[l]`；因此所有继续使用 `l` 的更窄容器都不可能比当前更优，可以安全丢弃 `l`。右边更短时同理丢弃 `r`。这样每一步至少排除一个不可能成为更优答案的端点，最终只需 O(n) 次移动。

来源只保留题名和“双指针法逻辑分析”，没有语言/API/输入异常约定。本答案选择 Java，并声明输入是非负高度数组；`null` 或不足两个端点返回 `0`，负高度作为不合法输入抛出异常。面积使用 `long`，避免把未给出的高度/长度上界偷偷假设成 `int` 乘法一定安全。

## 1 分钟版

- 面积由较短边限制：`area = min(h[l], h[r]) * width`。
- 若 `h[l] <= h[r]`，固定 `l` 再把 `r` 往左移，宽度一定更小，而且有效高度最多仍是 `h[l]`，所以不可能超过当前面积；因此可以直接 `l++`。
- 若 `h[l] > h[r]`，对称地 `r--`。
- 每次只淘汰一个已经证明“不可能与内侧端点组成更优解”的端点，所以不会漏掉全局最优解。
- 两个指针总共最多移动 `n-1` 次，时间 O(n)，除输入外额外空间 O(1)。

## 3 分钟版

```java
public final class ContainerWithMostWater {
    public static long maxArea(int[] height) {
        if (height == null || height.length < 2) {
            return 0L;
        }
        for (int h : height) {
            if (h < 0) {
                throw new IllegalArgumentException("height must be non-negative");
            }
        }

        int left = 0;
        int right = height.length - 1;
        long best = 0L;

        while (left < right) {
            long width = right - left;
            long boundedHeight = Math.min(height[left], height[right]);
            best = Math.max(best, boundedHeight * width);

            if (height[left] <= height[right]) {
                left++;
            } else {
                right--;
            }
        }
        return best;
    }
}
```

证明左边较短时为什么能移动左指针。当前 `h[l] <= h[r]`，当前面积是 `h[l] * (r-l)`。对任意新的右端点 `k`，其中 `l < k < r`，面积满足 `min(h[l], h[k]) * (k-l) <= h[l] * (k-l) < h[l] * (r-l)`。因此，所有仍使用 `l` 的内侧组合都严格不可能超过当前组合；既然当前组合已经计入 `best`，就可以淘汰 `l`。右边较短时完全对称。

## 关键细节

- **为什么不是移动较高的一边**：移动较高边后，较短边还在，容器高度上限不提高、宽度却缩小，没有产生更优解所需的机会；真正可能提升高度上限的是丢掉当前较短边。
- **两边等高**：移动任意一边都安全。本实现统一在 `<=` 时移动左边；因为固定任一等高端点再缩窄宽度都不可能超过当前面积。
- **面积溢出**：来源没有约束范围，所以乘法先提升为 `long`。如果平台明确保证结果在 32 位整数内，可按平台签名改为 `int` 返回。
- **输入域**：经典题通常讨论非负高度。这里把这个前提写成显式契约，并拒绝负值；不是把负高度当成来源事实。
- **边界**：`null`、空数组、单元素没有两个端点，返回 0；全 0 也返回 0；重复高度、单调数组不影响证明。
- **复杂度**：负值校验一趟 O(n)，双指针再一趟 O(n)，总时间仍 O(n)；额外空间 O(1)。

## 原理机制

这是“证明后淘汰候选”的贪心。暴力法会枚举所有 O(n²) 对端点；双指针并不是随便少看一些组合，而是在每一步利用当前较短边给出的面积上界，一次排除以该端点为一侧的整批内层组合。因为被排除的组合都有严格上界不超过已经看过的当前组合，删掉它们不会删除尚未观察到的更优解。这个单调淘汰不变量把搜索空间从所有端点对压缩到一条长度 O(n) 的指针轨迹。

## 常见追问

- 问：为什么左边较短时可以确定左边以后没用了？答：固定左边，任何更内侧右端点都会让宽度变小，而有效高度最多还是左边高度，所以面积严格小于当前组合。
- 问：为什么移动较高边不行？答：保留较短边时高度上限没有提升，宽度却缩短；这种移动没有消除当前瓶颈，不能获得比当前更高的上界。
- 问：两边一样高时移动哪边？答：任意一边都安全；本实现固定移动左边，证明对称。
- 问：双指针为什么不是 O(n²)？答：每轮恰好让一个指针向内一步，两个指针合计最多移动 `n-1` 次，不会回退。
- 问：怎么验证贪心没有漏掉某个奇怪数组？答：证明负责一般正确性；测试上可对大量小数组把 O(n) 结果与枚举所有端点对的 O(n²) 参考结果做差分。
- 问：如果高度或数组很大怎么办？答：算法的步数仍是 O(n)，但面积乘法应按约束选择足够宽的数值类型；本答案用 `long` 防止隐含的 `int` 乘法溢出。

## 易错点

- 只背“移动短板”，却解释不出固定短板时所有内侧组合的面积上界。
- 面积计算后才转 `long`，导致 `int * int` 已经先溢出；应让乘法操作数先进入 `long`。
- 同时移动两个指针，虽然某些样例能过，但破坏了“一次只淘汰一个已证明安全端点”的标准推理链。
- 把 `left <= right` 写成循环条件，导致同一点形成宽度 0 的无意义容器；正确条件是 `left < right`。
- 来源没有语言、异常和数值范围约束，却把某个平台的函数签名当成题目原文。
