# 加减 2 的幂把整数变为 0：最少操作数

## 核心结论

仓库保留下来的原题是：**给定一个数，每次可以加或减 `2^n`，求把它变成 0 的最少操作次数，并实现代码**。题源没有说明整数范围、`n` 的取值范围、语言/API，也没有说明负数和 0。候选把这些缺口明确落成接口约定：输入为 Java `int`，允许正数、负数和 0；每一步可选择任意非负整数 `n`，执行 `x += 2^n` 或 `x -= 2^n`；返回最少操作次数。实现先用 `long` 取得绝对值，因此 `Integer.MIN_VALUE` 也不会在取绝对值时溢出。

这个问题等价于：**用最少个带符号的二进制位 `±2^k` 表示 `|x|`**。偶数最低位一定是 0，可以只右移；奇数最低位必须贡献 `+1` 或 `-1`。当奇数的低两位是 `01` 时选择减 1，当低两位是 `11` 时选择加 1，使下一层尽量带更多尾随 0；`1` 是终止特例。这样得到无相邻非零位的 signed-binary / NAF 形式，它具有最小非零位数，因此计数就是最少操作数。时间 `O(log |x|)`，额外空间 `O(1)`。

## 1 分钟版

把当前绝对值记作 `v`，但要注意“右移”只是算法在缩放子问题，不是题目允许的真实操作。

- `v` 是偶数：最低位不需要任何 `±2^k`，直接 `v >>= 1`。
- `v` 是奇数：最低位必须选 `+1` 或 `-1`，所以操作数加 1。
  - `v == 1`：直接结束；
  - `v % 4 == 1`：选 `-1`，然后除以 2；
  - `v % 4 == 3`：选 `+1`，然后除以 2。

为什么看低两位？奇数只能是 `...01` 或 `...11`。选择让它变成 4 的倍数的方向，下一层会多消掉一个 0 位，避免连续使用两个相邻的非零 signed bit。最终形成 NAF；NAF 在所有 `{-1,0,1}` 二进制表示里非零位最少，因此操作次数最少。

例如 `15`：低两位是 `11`，选 `+1` 得到 `16`，所以只需两步：`15 + 1 = 16`，再 `16 - 16 = 0`。如果按普通二进制拆成 `8+4+2+1` 则要四步。

## 3 分钟版

令 `f(v)` 表示把非负整数 `v` 表成若干个 `±2^k` 之和时，最少需要多少个非零项。原题对负数是对称的，因此只需研究 `|x|`。

如果 `v = 2u`，所有幂的指数整体减 1 就得到 `u` 的表示，反过来整体加 1 又能恢复 `v`，所以：

`f(2u) = f(u)`。

如果 `v` 是奇数，任何 signed-binary 表示的最低位都不可能是 0，否则总和会是偶数；最低位只能取 `+1` 或 `-1`。去掉这个最低位并整体右移后，只有两个完备分支：

`f(v) = 1 + min(f((v - 1) / 2), f((v + 1) / 2))`。

迭代实现没有同时搜索两个分支，而是使用 NAF 的标准局部规则：对于大于 1 的奇数，若低两位是 `01`，选择 `-1`；若是 `11`，选择 `+1`。这个选择会令去掉最低 signed bit 后的商为偶数，从而保证下一个 signed bit 是 0。不断重复后得到“任意两个非零位不相邻”的表示。

为什么这不只是启发式？如果一个 signed-binary 表示存在相邻的非零位，可以用进位/借位把这两个相邻贡献改写到更高位，使非零位数量不增加；反复消除后总能得到 NAF。NAF 对整数是唯一的，并且在 signed-digit 集合 `{-1,0,1}` 中具有最小 Hamming weight。因此，逐位构造 NAF 得到的非零位个数就是 `f(v)`。

候选测试没有拿同一个贪心再复制一遍当“oracle”。测试里的独立 oracle 直接实现上面的**双分支最优递推**，每遇到奇数同时计算 `+1` 和 `-1` 两条路径并取最小值，再用 memoization 控制重复子问题；它与生产实现的低两位贪心规则不同。

## 关键细节

- **题源边界**：原文只明确“一个数”“每次加或减 `2^n`”“最少多少次变为 0”“代码实现”；没有给整数宽度、负数策略、`n` 的范围或 API。
- **候选的指数约定**：`n` 取任意非负整数；也就是允许 `1,2,4,8,...`。这是为了把题意落成可执行合同，不声称题源明确写了该范围。
- **负数对称**：若一组 `±2^k` 能把 `v` 归零，把每个符号反过来就能把 `-v` 归零，所以最少次数只依赖绝对值。
- **`Integer.MIN_VALUE`**：不能直接 `Math.abs(int)`，因为 `-2^31` 的相反数超出 `int`；先转成 `long` 再取绝对值。它本身就是一个 2 的幂，所以答案是 1。
- **右移不是操作**：代码中的 `/2` 或 `>>1` 是利用 `f(2u)=f(u)` 缩小证明子问题；实际允许的操作仍只有加/减某个 2 的幂。
- **为什么不能只数普通二进制的 1**：`7` 的 popcount 是 3，但 `7 = 8 - 1`，只需要 2 次；signed representation 可以通过借位/进位减少非零项。
- **复杂度**：每一轮至少右移一位，偶尔先加/减 1 再右移，因此最多与 `int` 位数成正比，时间 `O(log |x|)`；只保存 `long v` 和计数器，额外空间 `O(1)`。
- **不会无界搜索**：生产实现不做 BFS，也不枚举所有幂组合；每轮都缩小位长度。

## 原理机制

```java
public final class MinPowerOfTwoOperations {
    private MinPowerOfTwoOperations() {}

    public static int minOperations(int value) {
        long v = Math.abs((long) value);
        int operations = 0;

        while (v != 0) {
            if ((v & 1L) == 0L) {
                v >>= 1;
                continue;
            }

            operations++;
            if (v == 1L) {
                break;
            }

            if ((v & 3L) == 1L) {
                v = (v - 1L) >> 1;
            } else {
                v = (v + 1L) >> 1;
            }
        }
        return operations;
    }
}
```

可执行夹具覆盖 `0`、正负数、连续 1 位模式、2 的幂、`Integer.MIN_VALUE/MAX_VALUE`，并使用固定随机种子对 **20,000 个** Java `int` 与独立的“双分支 signed-binary 最优递推” oracle 做差分。oracle 对奇数同时求 `(v-1)/2` 与 `(v+1)/2`，因此不会把被测实现的 `mod 4` 贪心判断复制成预期值。实际夹具预期输出：`PASS fixed=18 randomized=20000 oracle=two-branch-signed-digit-dp`。

## 项目经验版

这是算法面试题，题源没有生产项目背景，因此不虚构项目案例。面试现场更重要的是先澄清 `n` 是否允许 0、输入范围是否可能超过 64 位、是否要求给出具体操作序列而不仅是次数。如果要返回操作序列，可以在每个奇数位记录本轮选择的是 `+2^k` 还是 `-2^k`；如果输入扩大到任意精度整数，同样的逐位规则可以改用 `BigInteger`。

## 常见追问

- 问：为什么 `7` 不是 3 次？答：因为允许“加”一个 2 的幂，`7 + 1 = 8`，再 `8 - 8 = 0`，只要 2 次。
- 问：为什么偶数可以直接除以 2，题目又没有除法操作？答：这是对子问题做尺度归一化。`v` 的所有 signed powers 指数整体减 1，就与 `v/2` 一一对应，不代表真实执行了一次除法。
- 问：奇数为什么只有两个分支？答：最低位必须是非零 signed bit；在 `{-1,0,1}` 中只有 `+1` 或 `-1`。去掉它后剩余部分全是 2 的倍数，所以恰好变成 `(v-1)/2` 或 `(v+1)/2`。
- 问：为什么 `v % 4 == 3` 时倾向 `+1`？答：`...11 + 1` 会产生进位并得到至少两个尾随 0；选择 `-1` 只得到 `...10`，下一位仍是 1，会形成相邻非零 signed bit。`v=3` 两边同为 2 次，选 `+1` 仍然最优。
- 问：负数怎么办？答：操作集合关于符号对称，先用 `long` 取绝对值求次数即可。
- 问：如果要证明而不是背贪心规则？答：先写精确递推 `f(2u)=f(u)` 和奇数的双分支公式，再说明消除相邻非零 signed bit 会得到最小 weight 的 NAF；这样局部规则来自表示结构，而不是经验猜测。
- 问：能用 BFS 吗？答：有限小范围可以拿 BFS 做验证，但直接在整数轴上做无界 BFS 不适合作为正式解法；逐位方法天然把状态规模压到位数级。
- 问：`Integer.MAX_VALUE` 呢？答：它是 `2^31-1`，可以写成 `2^31-1` 两个 signed powers，所以答案是 2；代码用 `long` 处理中间的 `2^31`。

## 易错点

- 把答案误成 `Integer.bitCount(x)`，忽略“可以加一个 2 的幂”带来的借位/进位优化。
- 对奇数无条件减 1；像 `15` 这样连续低位为 1 的数会因此走出更多操作。
- 把证明中的右移误说成题目允许的一次操作，混淆“子问题缩放”和“真实动作”。
- 直接对 `int` 的 `Integer.MIN_VALUE` 取绝对值，得到仍为负数的溢出结果。
- 题源没给 `n` 的范围，却把某个平台题目的隐藏约束当成原题事实。
- 用与被测实现完全相同的贪心规则做测试 oracle，导致实现和测试可能一起犯错。
