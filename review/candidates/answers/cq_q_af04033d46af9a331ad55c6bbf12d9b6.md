# 二叉树中序遍历：递归与非递归实现

## 核心结论

中序遍历的顺序是 **左子树 → 当前节点 → 右子树**。来源明确要求同时手撕“递归与非递归实现”，但没有保存节点类型、返回形式、空树语义或语言。下面用 Java 定义最小参考契约：`TreeNode` 持有 `int val/left/right`，两种方法都返回新的 `List<Integer>`，`root == null` 返回空列表，并且不修改树。

递归实现直接把定义翻译成调用顺序；非递归实现用显式栈模拟递归调用栈：不断把当前链的左节点压栈，走到空后弹出最近一个节点访问，再转向它的右子树。两者时间都是 O(n)；额外空间都与树高 h 相关，递归使用 线程调用栈 O(h)，迭代使用显式栈 O(h)。

## 1 分钟版

- 中序不变量：一个节点只有在它的左子树已经处理完后才能输出，输出后才进入右子树。
- 递归：`dfs(left) -> add(node) -> dfs(right)`。
- 迭代：`current != null` 时持续压左链；到空后 `pop`、输出，再令 `current = node.right`。
- 外层条件必须是 `current != null || !stack.isEmpty()`，否则走到最左边的空指针时会提前结束，栈里的祖先还没访问。
- 空树返回空列表；两种实现都只读节点，不修改结构。

## 3 分钟版

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public final class Solution {
    public static final class TreeNode {
        public int val;
        public TreeNode left;
        public TreeNode right;
        public TreeNode(int val) { this.val = val; }
    }

    private Solution() {}

    public static List<Integer> inorderRecursive(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        dfs(root, out);
        return out;
    }

    private static void dfs(TreeNode node, List<Integer> out) {
        if (node == null) return;
        dfs(node.left, out);
        out.add(node.val);
        dfs(node.right, out);
    }

    public static List<Integer> inorderIterative(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode current = root;
        while (current != null || !stack.isEmpty()) {
            while (current != null) {
                stack.push(current);
                current = current.left;
            }
            TreeNode node = stack.pop();
            out.add(node.val);
            current = node.right;
        }
        return out;
    }
}
```

迭代版可以理解为手动保存“递归返回后还要访问谁”。当沿左链下降时，每个被压栈的节点都处于“左子树还没处理完，所以自己暂时不能输出”的状态；一旦 `current == null`，说明最深左子树结束，弹出的节点就是下一位应该访问的节点。访问后转向右子树，再重复完全相同的规则。

## 关键细节

- **来源要求两种实现**：不能只给递归或只给栈实现。
- **空树**：本参考契约返回空列表；来源没有保存空树返回值约定。
- **栈类型**：`ArrayDeque` 适合做栈；这里只存非 `null` 节点。
- **循环条件**：外层是“当前节点还没走完 **或** 栈里还有待访问祖先”，内层只负责压完整左链。
- **不修改树**：两种实现都不改 `left/right`。Morris 中序可以做到 O(1) 额外空间，但会临时建立线索并恢复结构；来源没有要求 O(1)，这里优先清晰实现。
- **复杂度**：每个节点恰好输出一次，时间 O(n)。递归调用深度和显式栈峰值都为 O(h)；平衡树 h=O(log n)，极端单链树 h=O(n)。
- **递归风险**：极深偏斜树可能触发 Java 栈溢出；迭代版用堆上的容器承载待访问节点，更适合深树。

## 原理机制

递归和迭代并不是两套不同算法，而是同一个状态机的两种栈实现。递归时，递归调用帧隐式保存“处理完左子树后回到当前节点，再去右子树”的续点；迭代时，把这些尚未访问的当前节点显式放进 `Deque`。

中序遍历最核心的顺序约束是：任一节点 `x` 的左子树所有节点先于 `x`，`x` 又先于右子树所有节点。递归调用顺序直接满足它；迭代算法通过“先压尽左链，空了才弹栈访问”的不变量满足同一约束。

## 项目经验版

来源没有提供用户在真实项目中实现树遍历的经历，不能虚构。工程里如果要在很深的语法树、目录树或索引结构上遍历，我会先评估最大深度和是否允许修改结构：深度不可控时倾向显式栈；若有严格 O(1) 额外空间要求才考虑 Morris，并补结构恢复测试。

## 常见追问

- 问：为什么迭代版要先一直向左压栈？答：因为中序要求左子树先于当前节点；只要还有左孩子，当前节点就不能输出。
- 问：外层为什么是 `current != null || !stack.isEmpty()`？答：`current` 为空只代表左链走到底，栈里仍可能有尚未访问的祖先；两者都为空才真正结束。
- 问：递归和迭代空间复杂度一样吗？答：渐进上都是 O(h)，一个用调用栈，一个用显式容器；但递归受线程调用栈上限影响，极深树更容易 StackOverflowError。
- 问：能做到 O(1) 额外空间吗？答：Morris 遍历可以，通过临时线索复用空右指针并恢复树；代价是实现更复杂且会短暂修改结构。
- 问：如果是二叉搜索树，中序有什么额外性质？答：在 BST 排序不变量成立且比较规则一致时，中序输出按键有序；但本题只要求一般二叉树遍历，代码不依赖 BST 性质。
- 问：如何证明每个节点只访问一次？答：节点被沿左链压栈一次，弹栈并输出一次；弹出后只进入其右子树，不会再次把该节点压回去。

## 易错点

- 递归顺序写成“根左右”或“左右根”，变成前序/后序。
- 迭代循环只写 `while (current != null)`，到最左空节点时提前退出。
- 弹栈输出后忘记转向 `node.right`，漏掉右子树。
- 为了声称 O(1) 空间临时改树，却没有恢复指针。
- 忽略极深偏斜树的递归栈溢出风险。
