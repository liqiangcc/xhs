# 算法：手写单向链表并完成增删改查

## 核心结论

仓库原始题源明确要求“手写代码实现单向链表的结构体，完成增删改查”，但没有保存语言、API 形态、按值还是按下标操作、是否维护尾指针、是否允许 `null` 等细节。这里把这些未保存条件显式做成候选契约：使用 Java 实现泛型单向链表，提供尾部追加 `add`、按下标插入 `insert`、查询 `get`、修改 `set`、删除 `remove`，并维护 `head`、`tail`、`size` 三个状态。

关键不变量是：空表时 `head == null && tail == null && size == 0`；非空时 `head/tail` 都非空、`tail.next == null`，从 `head` 沿 `next` 恰好能访问 `size` 个节点且最后一个节点就是 `tail`。只要每次增删都维护这些不变量，CRUD 的边界就不会靠“碰巧跑通”维持。

## 1 分钟版

我会先说明题源只要求“单向链表 + 增删改查”，具体 API 没保存。这里按“Java 泛型链表 + 下标语义”实现。

节点只保存 `value` 和 `next`；链表保存 `head`、`tail`、`size`。尾部 `add` 利用 `tail` 做到 `O(1)`。按下标 `insert/get/set/remove` 需要从头找到目标或前驱，所以一般是 `O(n)`；在下标 0 的头部插入/删除是 `O(1)`。

删除最容易出错：删头时更新 `head`，删掉唯一节点还要把 `tail` 清空；删尾时要把 `tail` 改成前驱。插入尾部直接复用 `add`，避免维护两套尾指针逻辑。所有下标先做边界检查：读取/修改/删除要求 `0 <= index < size`，插入允许 `0 <= index <= size`。

## 3 分钟版

实现单向链表时，我不会先堆 CRUD 方法，而是先固定表示不变量。节点是 `(value,next)`；容器维护 `head`、`tail`、`size`。空表三者必须同步为空/0；非空时 `tail` 必须是从 `head` 可达的最后一个节点，并且 `tail.next` 必须为 `null`。这样每个操作都可以按“操作前不变量成立 → 修改有限几个指针 → 操作后不变量仍成立”来检查。

新增分两种：`add(value)` 尾插时，新节点接到旧 `tail.next`，再移动 `tail`；空表则 `head`、`tail` 同时指向新节点。`insert(index,value)` 如果 `index == size` 直接走 `add`；如果插到头部，新节点的 `next` 指向旧 `head` 再替换 `head`；中间插入先找到 `index-1` 的前驱，把新节点接在 `prev` 与 `prev.next` 之间。

查询和修改都先定位第 `index` 个节点。查询返回值；修改保存旧值后替换并返回旧值。删除头结点时让 `head = head.next`；若删除后 `size == 0`，同步令 `tail = null`。删除非头结点时找到前驱并做 `prev.next = removed.next`；如果删的是旧尾结点，再令 `tail = prev`。

复杂度上，尾部追加因为保存了 `tail` 是 `O(1)`；按下标定位在单向链表里一般是 `O(n)`，所以 `get/set/remove/中间 insert` 都是 `O(n)`；节点本身只增加常数指针空间，总存储是 `O(n)`。如果题目要求“按值查找/删除”，接口需要改成遍历比较值；如果要求高频随机访问，就不该选单向链表，数组或 `ArrayList` 更合适。

## 关键细节

- **题源边界**：题源只支持“手写单向链表结构并完成增删改查”；Java、泛型、按下标 CRUD、允许 `null`、维护尾指针都是候选实现选择，不冒充原题隐含条件。
- **表示不变量**：`size == 0` 当且仅当 `head/tail` 都为空；非空时 `tail.next == null`；从 `head` 可达节点数必须等于 `size`，最后可达节点必须是 `tail`。
- **插入边界**：元素下标的合法区间是 `[0,size)`，但插入位置是 `[0,size]`，因为允许在尾后追加。
- **删除头部**：不需要前驱；删除唯一节点后必须同时清空 `tail`，否则会留下悬空的尾引用。
- **删除尾部**：单向链表不能从尾结点反向找到前驱，因此仍需从 `head` 遍历到 `index-1`；删除后把 `tail` 指向该前驱。
- **尾部追加**：维护 `tail` 让 `add` 为 `O(1)`，代价是每次删尾、清空最后一个节点等路径都必须同步维护它。
- **空值**：候选实现允许节点值为 `null`，结构正确性不依赖值本身；若业务不允许 `null`，应在 API 边界显式拒绝。
- **复杂度**：`add` 为 `O(1)`；头部 `insert/remove` 为 `O(1)`；需要按下标定位的 `get/set/remove/insert` 最坏 `O(n)`；链表节点总空间 `O(n)`。
- **可验证性**：固定用例覆盖空表、单节点、头/中/尾插入、查询、修改、头/中/尾删除、越界和 `null`；再执行 5000 次确定性随机 CRUD，与 `ArrayList` 做差分 oracle，并在每一步检查 head/tail/size/无环不变量。

## 原理机制

```java
import java.util.ArrayList;
import java.util.List;

public final class SinglyLinkedList<T> {
    private static final class Node<T> {
        private T value;
        private Node<T> next;

        private Node(T value) {
            this.value = value;
        }
    }

    private Node<T> head;
    private Node<T> tail;
    private int size;

    public int size() {
        return size;
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public void add(T value) {
        Node<T> node = new Node<>(value);
        if (tail == null) {
            head = tail = node;
        } else {
            tail.next = node;
            tail = node;
        }
        size++;
    }

    public void insert(int index, T value) {
        checkPositionIndex(index);
        if (index == size) {
            add(value);
            return;
        }

        Node<T> node = new Node<>(value);
        if (index == 0) {
            node.next = head;
            head = node;
            if (tail == null) {
                tail = node;
            }
        } else {
            Node<T> prev = nodeAt(index - 1);
            node.next = prev.next;
            prev.next = node;
        }
        size++;
    }

    public T get(int index) {
        checkElementIndex(index);
        return nodeAt(index).value;
    }

    public T set(int index, T value) {
        checkElementIndex(index);
        Node<T> node = nodeAt(index);
        T old = node.value;
        node.value = value;
        return old;
    }

    public T remove(int index) {
        checkElementIndex(index);
        Node<T> removed;
        if (index == 0) {
            removed = head;
            head = head.next;
            size--;
            if (size == 0) {
                tail = null;
            }
            return removed.value;
        }

        Node<T> prev = nodeAt(index - 1);
        removed = prev.next;
        prev.next = removed.next;
        size--;
        if (removed == tail) {
            tail = prev;
        }
        return removed.value;
    }

    public List<T> toList() {
        List<T> result = new ArrayList<>(size);
        Node<T> current = head;
        while (current != null) {
            result.add(current.value);
            current = current.next;
        }
        return result;
    }

    private Node<T> nodeAt(int index) {
        Node<T> current = head;
        for (int i = 0; i < index; i++) {
            current = current.next;
        }
        return current;
    }

    private void checkElementIndex(int index) {
        if (index < 0 || index >= size) {
            throw new IndexOutOfBoundsException("index=" + index + ", size=" + size);
        }
    }

    private void checkPositionIndex(int index) {
        if (index < 0 || index > size) {
            throw new IndexOutOfBoundsException("index=" + index + ", size=" + size);
        }
    }
}
```

仓库候选验证夹具还包含一个仅供测试调用的 `assertInvariants()`：每次随机操作后检查空表状态、`tail.next == null`、可达节点数等于 `size`、最后节点等于 `tail`，并用“遍历次数不能超过 `size`”检测可能的环。5000 次确定性随机 CRUD 同时与 `ArrayList<Integer>` 的结果逐步比较。

## 项目经验版

这是手写数据结构题，仓库来源没有生产项目上下文，所以不编造项目经历。面试中如果继续追问工程选择，我会说明：单向链表适合已拿到节点/前驱后的局部插删或顺序遍历，但随机访问是 `O(n)`；如果业务主要按下标访问，数组结构通常更合适。如果需要线程安全，也不能仅给 CRUD 方法加一句“加锁即可”，而要先明确并发语义、迭代一致性与锁粒度。

## 常见追问

- 问：为什么已经有 `head` 还要维护 `tail`？答：为了让尾部追加从遍历到尾部的 `O(n)` 降为 `O(1)`；代价是删除尾结点、删除唯一节点时必须同步修正 `tail`。
- 问：为什么插入允许 `index == size`，但查询不允许？答：`index == size` 表示插到当前最后一个元素之后，是合法位置；但当前位置还没有元素，所以 `get/set/remove` 必须限制在 `[0,size)`。
- 问：删除唯一节点时最容易漏掉什么？答：只做 `head = head.next` 会让 `head` 变空，但旧 `tail` 还指着已删除节点；因此当删除后 `size == 0` 必须把 `tail` 也清空。
- 问：为什么删尾还是 `O(n)`，不是已经有 `tail` 吗？答：单向链表的尾结点没有前驱指针；要把新 `tail` 设成旧尾的前驱，仍需要从 `head` 找到它。若删尾是核心需求，可考虑双向链表。
- 问：如何证明随机 CRUD 没把链表结构悄悄破坏？答：除了把每一步的值序列与 `ArrayList` 对比，还检查可达节点计数、最终尾节点、`tail.next` 和遍历上界；这样内容正确与结构不变量同时被验证。

## 易错点

- 空表第一次插入只更新 `head`，忘记同步 `tail`。
- 删除唯一节点后遗留旧 `tail`；或删除尾节点后没有把 `tail` 指向前驱。
- 把元素下标 `[0,size)` 和插入位置 `[0,size]` 混为一谈，导致尾插越界或查询越界未报错。
- 中间插入时覆盖 `prev.next` 前没有先让新节点指向原后继，造成链表后半段丢失。
- 维护了 `size` 却没有让每条增删路径恰好增减一次，最终导致边界检查与真实链长不一致。
- 为了让代码看起来“完整”而擅自假定题源要求按值、按下标或线程安全，却没有把这些实现选择与原题边界区分开。
