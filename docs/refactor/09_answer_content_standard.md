# 09 分题型答案内容标准

> 本文定义 Answer 的内容质量标准。`answer validate --strict` 是结构底线，本文是人工与 Agent 审查 ready 内容的语义标准。

---

## 1. 通用口述结构

所有答案继续保留八个二级章节：

```text
核心结论
1 分钟版
3 分钟版
关键细节
原理机制
项目经验版
常见追问
易错点
```

通用要求：

- 核心结论在 20–30 秒内说明本质。
- 1 分钟版只保留 3–5 个主干点。
- 3 分钟版补齐原理、取舍、场景和边界，不重复 1 分钟版。
- 关键细节写事实和阈值；原理机制写因果链路。
- 项目经验版只使用真实经历，未获得用户事实时改写成“项目映射提示”。
- 常见追问至少 3 个，每个追问必须带 1–3 句短答。
- 易错点必须能指出“哪里容易说反、说绝对或漏掉边界”。
- 版本敏感内容写明适用版本或核对日期。

---

## 2. Concept：概念与对比题

适用：定义、区别、优缺点、选型类问题。

答案必须包含：

1. 一句话定义比较对象。
2. 统一比较维度，而不是分别背两段定义。
3. 选择条件和不适用边界。
4. 至少一个反例或容易混淆点。
5. 追问短答覆盖底层原理、选型和实际使用。

推荐 1 分钟骨架：

```text
结论 -> 维度一 -> 维度二 -> 选择条件 -> 边界
```

---

## 3. Mechanism：原理与源码题

适用：底层实现、执行流程、源码、协议机制类问题。

答案必须包含：

1. 核心数据结构或参与组件。
2. 从入口到结果的主流程。
3. 关键状态变化和并发/一致性保证。
4. 时间、空间或资源开销。
5. 关键版本差异，避免把旧版本结论当成通用事实。
6. 故障或性能边界。

推荐 3 分钟骨架：

```text
目标 -> 数据结构 -> 主流程 -> 保证机制 -> 开销 -> 版本与边界
```

---

## 4. Scenario：场景与系统设计题

适用：高并发、系统设计、导入、缓存一致性、排障方案类问题。

答案必须包含：

1. 需求假设：用户量、QPS、数据量、一致性和延迟目标。
2. 核心数据流，而不是只罗列组件。
3. 数据模型、幂等和一致性方案。
4. 容量评估与关键瓶颈。
5. 超时、重试、降级、补偿和灾备。
6. 可观测指标、压测和上线策略。
7. 至少一个替代方案及其代价。

推荐 3 分钟骨架：

```text
澄清目标 -> 估算容量 -> 画主链路 -> 保证一致性 -> 处理故障 -> 观测与取舍
```

---

## 5. Coding：算法与手撕题

适用：数据结构、算法、SQL 手写和编码题。

答案必须包含：

1. 输入输出和约束。
2. 解题不变量或状态定义。
3. 可直接复述的步骤。
4. Java 实现；SQL 题提供可运行 SQL。
5. 时间与空间复杂度。
6. 空输入、单元素、重复值、溢出等边界用例。
7. 至少一个变体及处理差异。

禁止只写伪代码后把答案标为 ready。

---

## 6. Project：项目深挖题

适用：项目介绍、技术难点、架构选型、事故排查、性能优化。

答案是表达框架，不是虚构故事。必须引导用户补齐：

```text
真实背景与规模
个人职责
约束与目标
备选方案
个人决策与理由
实施过程
量化结果
风险、失败或复盘
```

如果缺少真实项目事实，答案保持“项目映射提示”，不得使用“我负责”“我优化到”等确定口吻。

---

## 7. Behavior：行为与 HR 题

适用：冲突、挑战、规划、优缺点、公司选择和团队协作。

答案必须：

- 使用真实 STAR 证据。
- 强调个人动作，而不是只说团队做了什么。
- 结果尽量量化。
- 给出反思和下一次改进。
- 与岗位要求相关，但不编造公司偏好或个人经历。

未获得用户事实时，只提供提问清单和组织框架，不生成 ready 的个人故事。

---

## 8. Ready 人工审查清单

### 事实

- [ ] 核心结论正确。
- [ ] 版本和阈值没有过期或绝对化。
- [ ] 没有把常见实践写成唯一方案。
- [ ] 没有虚构个人经历、指标或事故。

### 表达

- [ ] 1 分钟版能实际口述完。
- [ ] 3 分钟版比 1 分钟版增加原理和取舍。
- [ ] 每个列表项都能解释 why。
- [ ] 不使用空泛的“提升性能、保证高可用”而没有机制。

### 追问

- [ ] 至少 3 个追问。
- [ ] 每个追问有短答。
- [ ] 至少一个追问检查边界或失败场景。
- [ ] 追问若已成为独立大问题，改建 Canonical 而不是塞进当前答案。

### 复习

- [ ] 易错点可用于下一次回炉。
- [ ] 原题变体都能由当前答案覆盖。
- [ ] `answer validate --strict --noWrite` 通过。
- [ ] `answer sync` 后 Canonical 状态一致。
